## 追加（用户点名）：两个长期未达成的水效果根因（报告 §11）

### B1 水下光束 —— 链路闭合，是量级问题不是接线问题
链路：composite2 → `scattering.fsh:39` 写 colortex1 → composite3 →
`water_composite.fsh:19` 读 → `solas_water_composite`。全部正确。
四个衰减源：
1. **主因** `light_shafts.glsl:52-54` visibility 被 `pow(VoU,1.5)` 与 VoL 两个
   **几何互斥**因子相乘：太阳在上方，VoU 要朝下看、VoL 要朝上看太阳。
   最优 0.107 vs 理论上限 0.85（损失 8 倍）；水平朝太阳仅 0.042（20 倍）。
2. 采样只覆盖 1.4~18.6 格（名义 40），步距 2.86 格 → 光柱断裂成斑块。
3. `:77` 用 `length(pos.xy*2-1)>=1` 圆形判据剔除方形 shadow map，损失 21.5% 面积。
4. `solas_water.glsl:100` 旧角向亮晕 `glare*16` **未被 SC-33 移除**，与光束同向
   竞争：正对太阳时 fog 被放大到 1.59，光束占比只剩 10.4%。
理想条件下 shafts 贡献 23%~42%（gamma 域 0.07~0.17）——理论可见，但真实场景叠加
遮挡/剔除/稀疏采样后显著衰减。**不宣称"看不见"，只给可离线定位的衰减源。**

### B2 水上看水下青绿→深蓝 —— 效果已在 WATER_COLD 档，默认档方向相反
- `absorption.glsl:28` 默认 BALANCED 系数 (1.000, **0.060**, **0.100**)：
  绿衰减 < 蓝衰减 → **越深越绿**，深处色相 (0, 0.65, 0.35)，绿/蓝=1.90。
- `WATER_COLD`(0) 系数 (1.000, **0.220**, **0.080**)：绿衰减 > 蓝衰减 →
  0 格 (0.18,0.38,0.44) 青 → 15 格 (0.00,0.10,0.90) **深蓝**。
  **用户要的效果已存在，只是不在默认档。**
- 叠加：`appearanceDepth` clamp 到 16 → 15 格以上色相冻结；
  `water_surface_medium` 只有吸收无 in-scattering → 深处发黑不发蓝。
- 最小改动：默认档改 (1.000, 0.100, 0.060)（蓝衰减 < 绿衰减）。

## 再追加：整体性能优化建议（报告 §12）

关键发现 —— 三个全屏 pass 在典型场景（相机不在水中 + BALANCED 档）不干活，
1080p 单帧约 207 万像素：
- `composite2`：`scattering.fsh:43-49` 全屏**写 vec4(0)**（BALANCED 档 !GODRAYS）。
  讽刺点：水下光束让 `colortex1=1.0`，把这个空转 pass 也抬到全分辨率。
- `composite3`：`water_composite.fsh:12-26` 非水下时是**全屏纯拷贝**（读 colortex0 写 colortex0），
  `program.composite3.enabled=true` 硬编码。
- `composite4`：`water_bloom.fsh` 非水下时全屏 **discard**。

**最大黑洞 composite4 + colortex7**：
- `properties` 没有 `size.buffer.colortex7` → 默认**全分辨率**；
- `computeBloom` 调 `getBloomTile` 4 次 × 6×6=36 次采样 = **144 次/像素**；
- `water_bloom.fsh:5` `colortex0MipmapEnabled=true` → **主缓冲 colortex0 恒开 mipmap**；
- 水下 1080p = 207万 × 144 ≈ **2.98 亿次采样/帧**，是主 bloom（170 万次）的 **175 倍**；
- 根因：Solas 原作 computeBloom 跑在低分辨率 bloom tile 上，适配时挂在全屏 pass
  但分辨率约定没跟着降 —— **适配时的分辨率失配**，不是算法问题。

**执行顺序（先低风险拿基线）**：
1. `size.buffer.colortex7=0.25 0.25` → 2.98亿 降到 ~1860万（收益最大，一行改动）
2. `colortex1` 水下光束降 `0.5 0.5`（4 抽头重建本来就在做）
3. `deferred.enabled` 条件化 + `ASTRA_SCENE_COPY` 同步（省 ~16.6 MB/帧 写带宽）
   —— 落地后**立即测一次帧率拿首个真实基线**
4-6（中风险，拿到基线后再评估）：合成并入 final 删 composite3 /
   rainy_air 降分辨率（雨天掉帧主因，10 步×云噪声+阴影）/ getBloomTile 改 mip 采样。

强调：项目至今**零帧率数据**，没有基线前任何优化都无法证明收益。

- **C5** 我 §11.1.5 的光束量级**漏算** `astra_water_caustics_shaft_at`(c³)，
  23-42% → 应下调为 3-15%（不可见边缘）。GLM/Qoder 都比我准。
- **C6(性能)** 焦散取样链：solas_water_height 2 → wave_normal_at 4×2=8 → focus 3×3×8=**72**；

  **比 composite4 的 144 次还大 3.5-5 倍**。Qoder 的 72 正确，GLM 的 18 漏算。
