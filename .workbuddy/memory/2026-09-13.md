## Astra 光影全量代码级审查（只读，未改任何代码）

在 `docs/2026-09-13-astra-full-audit.md` 末尾追加了 §11「第二轮：代码级审查」。
原报告 §0–§10 是元层面（结构/工具链/台账/性能启发式），§11 下沉到 GLSL 源码。

### 主要发现

- **N1 (P2) `ENTITY_SHADOW_DISTANCE` 是假控件**。GUI 可调、三档预设各异，但没有任何 GLSL 消费它；
  实际是 `lib/settings.glsl:230` 硬编码 `entityShadowDistanceMul = 0.5`。
  实际值 = SHADOW_DISTANCE×0.5 = 96/128/128，界面显示 48/64/96（偏差 2×、2×、1.33×）。
  注释 "All three profiles resolve to 0.5 (48/96, 64/128, 96/192)" 也是错的（真实比值 0.25/0.25/0.375，且第三对应为 96/128）。
  `check_pack` 漏掉是因为它只校验 properties ↔ settings，不校验"选项是否被消费"。
- **N2 (P2) 全局非常量初始化器 5 处**（bloom_resolve.glsl:2-3、bloom_capture.glsl:2-4），
  用 uniform 初始化全局变量。NVIDIA 驱动宽容通过，AMD/Intel/Mesa 有风险。
- N3 `#if 2 == 0` 死分支（bloom_resolve.glsl:30）
- N4 nether_volume.glsl:89/146-147 恒假分支内调用**不存在的** `LPV_FOG_ILLUMINATION`，一旦宏被定义即编译失败
- N5 三维度入口壳 120 个文件手工复制，去掉 `#define DIMENSION_*` 后 40/40 完全相同
- N6 `apply_vibrance` 权重可 >1 外插；默认 VIBRANCE=100 时完全空转
- N7 闪电天光路径 normalize 无防御（同文件点光路径有）
- N8 6 个枚举 token 从未引用（靠 #else 兜底）
- N9 deferred.fsh:118 分支内取 dFdx/dFdy，末地星点边缘大小会跳变

### 已核查排除（别再重复查）

- `MC_HAND_DEPTH` 是 **Iris 标准注入宏**（值 0.125），Astra 用法与 Iris 文档一致，非缺陷
- `lit.fsh` 的 `gl_FragData[1]` 双写不冲突（water pass 同时定义了 ASTRA_TRANSLUCENT）
- 体素光写读锚点一致（代入方块中心都得到 k+32）
- compute 链 ping-pong 正确，最终落在 A，消费端只读 A
- 末地 294 槽分配正确

### 方法沉淀

静态扫描脚本思路（很有用，可复用）：
1. 选项引用图——settings.glsl 声明的选项 vs 其余代码中的引用次数，零引用即假控件
2. include 解析——展开每个入口的 include 图，查同名函数是否冲突
3. 三维度壳归一化比对——grep -v DIMENSION_ 后 md5
4. 全局非常量初始化器——正则匹配文件作用域 `float x = <含标识符>;`
