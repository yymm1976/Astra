## 2026-09-07 深夜 · SC-37 回退我引入的 bug（用户极度不耐烦）

### 我引入的 bug 与修复

**bug 1：阴影闪烁**（"经常闪烁，变化形状大小，有时出现有时消失"）
- 原因：SC-36 把 caustics 搬进 shadow pass。但 Solas 的 caustics 依赖 TAA
  平滑，**Astra 无 TAA（design.md 2.4 明确）**，48 格细节层的高频噪声直接闪。
  我把一个依赖 TAA 的效果搬进了无 TAA 系统，是架构性错误。
- 处理：**完整回退** caustics shadow-pass（shadow.vsh/fsh/shadowmap.glsl），
  恢复 lit pass caustics（用户最初的稳定状态）。

**bug 2：水下看水面"异常泛白"**
- 原因 A：fresnel 水下（eta=1.333，水→空气）也用 Steadfast 的 F0=0.1。
  物理上水→空气 F0=0.0204，0.1 让水下看水面有 10% 镜面反射。
- 原因 B：水下看水面 reflection 用了带 16x glare 的水体色（glare 本该只用于
  水下雾，不是水面镜）。
- 处理：fresnel 区分 from air（F0=0.1）/from water（F0=0.0204）；水下反射
  改用不带 glare 的散射基底；glare 时间映射 sunProgress→lowSun 修正
  （正午 glare 从 16x 降到 4.8x，Solas 用 timeBrightness 正午≈0.3）。

**bug 3：沙子边缘白光（caustics 半影亮环）**
- lit caustics 的 `smoothstep(0.35, 0.90, 阴影可见度)` 在 PCF 半影区形成亮环。
- 处理：收紧到 `smoothstep(0.85, 1.0, ...)`，只在全光照区显示。

### 诚实结论（用户需要拍板）

追平 Solas/Steadfast 靠"借鉴+东改西改"是**追不平的**——它们是多年打磨的
完整水系统，Astra 是从零移植的半成品。差距的根源不是几个参数，而是：

1. **无 TAA** 是硬约束：Solas 的 caustics、水面 SSR 高频、体积光抖动全靠 TAA
   平滑。Astra 设计明确无 TAA → 这些效果要么不做、要么闪烁。
2. **水面合成是两套体系**：Steadfast 的 translucent.glsl（alpha 加法合成 +
   折射辅助吸收）与 Astra 的 water.glsl（mix 合成 + alpha 恒 1）是结构性不同，
   不是参数能补。
3. **许可**：Steadfast GPLv3、Solas undeclared。**直接整段照搬** = 包必须转
   GPL（Steadfast §7 附加条款）/ Solas 完全不能发布。THIRD-PARTY.md 已标
   publish gate（SC-14 待用户决策）。

## 2026-09-07 深夜 · SC-36 三处结构性修复（用户指出"思考混乱"后的对齐）

用户纠正图对应：水面=Astra图2 vs Steadfast图3、水下=Astra图1 vs **Solas图6**、
整体=Astra图5 vs Steadfast图4。此前我把图6误认为 Steadfast，重新按
"水下=Solas、水面=Steadfast、整体=Steadfast"对齐。

### 根因 1：白光 + 阴天是同一个 bug

Steadfast `diffuse.glsl:299` 普通方块用**风格化光照**：
`smoothstep(-0.05, 0.05, ndotl)`（朝向光的面几乎全亮）。
Astra `diffuse.glsl:129` 用**纯 Lambert** `max(ndotl, 0.0)`。

掠射角 ndotl=0.1 实测：普通地面 0.10，矮草丛（SSS 保留 0.65 底线）0.685
—— 草地比地面亮 6.9 倍 = 方块边缘白光；Lambert 让所有受光面只有部分亮度
= 晴天变阴天。**一处改动同时解决用户第 1、4 点**。

改：`diffuse.glsl` else 分支改用 Steadfast 的 smoothstep。

### 根因 2：caustics 在错误的 pass

Solas 在 **shadow pass**（program/shadow.glsl:52-54）把 caustics 写进
`shadowcolor0`，水底地形的焦散是"透过水面的彩色阴影"，随光投影。
Astra 却在 **lit pass** 按水底方块自身坐标算，且 `shadow.fsh:43` 把水面
阴影强制为纯白 → 水底永远没有焦散。

改（Solas 机制）：
- `caustics.glsl` 加 `water_caustics_shadow_tint()`（tint 表达式自写）
- `shadow.vsh` 加 `shadowWorldPos` varying（playerSpacePos + cameraPosition）
- `shadow.fsh` 水面写 caustics 到 GBA
- `shadowmap.glsl` 水面时读 GBA 不再强制白
- `lit.fsh` 移除旧 caustics（避免与 shadow tint 双重计数）

Solas 常量 BUMP 0.4/DETAIL 0.40/SPEED 1.50/OFFSET 0.5 与 Astra 一致（此前移植
正确），错的是消费位置与公式。

### 根因 3：折射扭曲被自己的保护压制

`water.glsl:81` `refractionContinuity = 1 - smoothstep(0.25, 0.65, lightingEdge)`。
它用折射前后亮度差做边缘保护，但**波浪扭曲正好产生亮度差**，保护把扭曲
本身当成"采到前景"压平了 = "水下方块完全不随波浪扭曲"。

改：阈值 (0.25,0.65) → (0.55,0.90)，正常涟漪通过，只有真正的前景剪影才回退。

### 验证

- compile_glsl 三档 + 关 caustics/阴影组合：225+75+75 组全 0 失败
- check_pack 0 FAIL / 2 WARN / 9 PASS
- sync 7 文件复校 0 差异

## 2026-09-07 晚 · SC-35 结构性修复（用户否决"只调数值"）

用户原话：「单纯调数值绝对不能解决问题，尤其是复杂的水面和水下，深度研究
solas 的水下和 steadfast 的水面实现」。此前 SC-34 只调数值被判定为偷懒。

深读两份源码后定位到**结构差异**，不是数值差异。

### 水面：Steadfast translucent.glsl vs Astra water.glsl

| 项 | Steadfast | Astra（改前） |
|---|---|---|
| 菲涅尔 F0 | 0.1（注释：0.02 too see-through） | 0.0204 完整菲涅尔 |
| 反射门控 | × skyLight | 无门控 |
| 基础 alpha | 0.25×(1−天光)，露天≈0 | 1.0 恒不透明 |
| 吸收 红:绿:蓝 | 16:3:1（exp(depth×−vec3(16,3,1))） | 6:1.7:1 |

实测入射角 cos=0.5：Steadfast 0.128 vs Astra 0.060 —— 差 2.1 倍，这是水面发灰的主因。
16 格水深处 Astra 仍透过 46% 红光 → 永远到不了清澈青蓝。

### 水下：Solas waterFog.glsl / volumetricLight.glsl

三样 Astra 完全没有的：
1. **方向性 glare** — 水下雾色随 `dot(视线, 光源)` 增强至 16×，转头能看出光从哪来
2. **体积光放大** — `finalVL *= 水色 × (4 + sunVisibility×8)`，且水下采样步长减半
3. **sqrt 感知空间混合** — `mix(sqrt(a), sqrt(b), f)` 再平方回去，避免线性空间发浑

### 改动（6 文件）

1. `program/water.glsl`
   - 新增 `WATER_F0 = 0.1`，菲涅尔改用 Steadfast 的 Schlick（全反射仍精确）
   - `fresnel *= skylight`（天光门控）
   - 头部补 GPL 声明（引用 Steadfast 触发 check_pack #8）
2. `global/water/absorption.glsl`
   - 吸收光谱比改为 Steadfast 的 16:3:1：BALANCED (0.080, 0.015, 0.005)
     COLD (0.080, 0.025, 0.005)、TROPICAL (0.130, 0.013, 0.005)
   - scattering 0.024 → 0.016（散射是中性色，会稀释刚买来的色彩选择性）
3. `program/scene.glsl`
   - `astra_underwater_color()` → `astra_underwater_color(vec3 viewDir)`
   - 加方向性 glare（**自写 pow(toward,10)**，非 Solas 有理式移植，保持 idea 级）
   - 两个调用点同步传 `direction`
4. `program/water.glsl` — 水下反射调用点传 `normalize(view_player(viewPos))`
5. `global/water/light_shafts.glsl`
   - `WATER_SHAFT_MAX_DISTANCE` 48 → 96（Solas 是 128；雾变薄后 48 不够）
   - 新增 `shaftGain = 2.0 + 4.0 * sunProgress * skyVisibilityDay`（Solas 是 4~12，先给一半）
6. `lib/settings.glsl` + `shaders.properties` — 修正 SC-34 遗留的两个 FAIL

### 教训（重要）

- **并发对同一文件多次 Edit 会被静默吃掉**。SC-34 的 FOG_DENSITY / SKY_FOG_STRENGTH
  两处 Edit 没生效（只有 UNDERWATER_FOG_DENSITY 生效），导致本轮 check_pack 报
  「值不在自身枚举列表」FAIL。同一文件必须串行改，改完 grep 复核。
- **滑条默认值必须落在其 `[...]` 枚举列表里**，否则 check_pack #1/#2 FAIL。
  42 → 40、18 → 15 都是这个原因。
- 引用 GPL 来源（Steadfast）必须在文件头写 GPL 声明，否则 check_pack #8 FAIL。
- Solas 只能 idea 级借鉴。Solas 的 glare 有理式我最初直接移植了，违反
  design.md 9.2，已改写为自写 pow 曲线（对比数据写在注释里）。
