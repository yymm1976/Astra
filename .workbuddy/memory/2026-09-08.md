## 第四轮只读根因 + 修复计划（不动代码）

依据：杨间当前 6 张实机图（Astra 水下/水面/远景×2 + 模范光影 ×2）。
材料：当前 Astra 包内 `program/scene.glsl`、`global/water/light_shafts.glsl`、`global/water/absorption.glsl`、`global/lighting/shadowmap.glsl`，对照 Steadfast 0.8.0、Solas V2.2b、Mellow 3.4 三份源码。

**P0（最致命）**：水下 shafts `astra_water_sun_source` 在 `scene.glsl:79-82` 把 `shadowcolor0.r ≥ 0.999` 视为非水 → return 0。但水下视线积分每个 sample 投影到 sun 视角后水平方向几乎都命中水底地形（waterHeight=1.0），所以整条视线积分累加接近 0；水下画面昏黑、无 shafts。修复方向：仿 Solas `volumetricLight.glsl:60-89`，每个 sample 直接 `player_shadow(samplePos)` + `shadow_read_tap` 比对 shadowtex0/1，不再依赖 waterHeight 编码。

**P1**：水色偏黑。
- `astra_water_incident(eyeSky)` 把 sky_ambient × 0.01 后作为 incident（scene.glsl:58），强度不足。
- `astra_underwater_color` 用 `incident × σ_s / σ_t`，σ_s < σ_t，颜色暗。
- 修复方向：仿 Solas `waterFog.glsl:5-15`，sky_ambient 直接做 base，加 `(0.5 + 0.5×eBS)` 提亮、朝太阳 `glare = 0.01/(1−0.99×VoL) − 0.01` 加亮。

**P2**：阴影"靠近才出现"。
- `shaders.properties:126-128` profile 默认 PERFORMANCE=96/BALANCED=128/ULTRA=192，但 MC 26.2 Fabric 实例默认 renderDistance=256 blocks，超出 shadowDistance 的位置 `shadow_box_distance` (L∞) > 128，`shadow_map_fade=0`，无阴影。
- 修复方向：BALANCED 128→256、PERF 96→192、ULTRA 192→256（已对齐到选项上限 [64..256]）。

产出：`docs/2026-09-08-fourth-round-rootcause-and-fixplan.md`。修复未启动，等杨间裁决。

## Codex 半成品只读审查（16:5x，未改任何代码）

Codex 16:24–16:28 改了 8 个文件、新增 4 个，随后限额中断。

**它的方案（与我的不同但方向对）**：不取消 shadow 采样，而是把"水面高度"换成屏幕空间水体状态。
`gbuffers_water(lit.fsh:97-99) 写 colortex5: 打包水面世界高度` → `composite(water_state.fsh) 搜 20×12 网格写 colortex6` → `scene.glsl:104 / light_shafts.glsl:48 / diffuse.glsl:177 用 water_volume_state() 读`。
配套 `scene.glsl:88` 改 `visibility = tap.opaqueVisibility`（水不挡太阳，只有地形挡）——这一条正确。原 composite 散射逻辑移到新 `composite2` pass（转发 `program/scattering.fsh`）。

**达成度**：
- 水下阳光 🟡 架构就位，P0 根因已解除，未实测
- 水色 🟡 只调了 absorption/scattering 系数，`incident` 的 ×0.01 和 σs/σt 反推都没动。新 underwater_color = (0.008, 0.190, 0.247)，蓝>绿偏蓝青，亮度仍差 Solas ~3 倍
- 阴影 🔴 **完全没做**：`SHADOW_DISTANCE` 仍 128、profile 未改、`shadow_map_fade` 未改；只动了 `shadowDistanceRenderMul 1.0→1.5`（这只管 culling 不管接收端 fade）。`water.glsl`(13:52) 和 `shadowmap.glsl`(14:31) 都没被碰过

**发现的问题**：
- P0-1 `size.buffer.colortex6=1 1` 疑似全分辨率（Iris: ≤1 当比例），water_state 240 次 texelFetch/像素 → 性能灾难；消费端只读 ivec2(0)。需实测帧率，若是则改成明确像素尺寸
- P1-1 gbuffers 读 colortex6 有 1 帧延迟（composite 在 gbuffers 之后），入水首帧回退旧坏路径
- P2-1 `program.composite.enabled=true` 无条件，shafts 关了也跑
- P2-2 `astra_water_segment` 传 `start.y+cameraPosition.y` 作 surfaceHeight，隐含"start 必须是入水点"契约未写注释；水下向上反射 ray.y>0 → depth<0 → source=0，全反射区偏暗
- P2-3 20×12 固定网格深水可能漏检
- colortex5/6 未登记 design.md §2.3

**编译全绿**：BALANCED linked=76 failed=0；PERFORMANCE+ULTRA linked=152 failed=0（RTX 4050 / GL 4.6 / 572.83）。日志 `qa/glsl-codex-check-{balanced,profiles}.log`。
**已确认 OK**：无断链 include；colortex5 的 SRC_ALPHA blend 因 alpha 二值(0/1)退化为选择，不破坏 16-bit 高度编码。

产出：`docs/2026-09-08-codex-halfdone-review.md`。
