## 三、可以直接抄的 8 条（按性价比排序）

每条固定写六项：机制 / 出处 / Astra 现状证据 / 怎么落地 / 风险与前置核实 / 许可。**排在前面的不是"效果最华丽"，而是"代价小、风险可控、Astra 确实没有"。**

### 1. 主世界方块光屏幕空间遮挡（火把光被墙挡住）

**机制。** Astra 的方块光现在只按"离光源多远"衰减，不判断中间有没有墙，所以隔着墙也能看到火把把墙照亮。Velocity 的做法完全不查阴影图：先把每像素的"火把光占比"写进缓冲，再取它周围 8 个方向的差值，得到一个"光从哪边来"的二维方向（gradient）；然后从这个像素沿这个方向在屏幕上走 8 步，如果某一步踩到的像素比当前像素更靠近相机、且深度差落在设定区间内，就判定被遮挡，按遮挡比例把光乘暗。它用 `1 - 0.6*T` 让远处的遮挡弱一点，用 `0.12 + 0.03*Depth*T` 让远处要求更大的深度差，避免自遮挡（物体自己边缘把自己判成阴影）。

**出处〔读源码〕。**
- `_analysis/batch5_unpack/velocity-shaders/shaders/global/blocklight_shadows.glsl:9-17`（光占比）、`:23-33`（8 方向梯度）、`:35-49`（8 步屏幕行进与深度差判定）、`:51-58`（应用）。
- 调用点 `…/velocity-shaders/shaders/program/deferred1.fsh:88`、`…/gbuffers_terrain.fsh:183`；开关 `…/shaders.properties:131`、`…/lib/settings.glsl:360`。
- Velocity 是 MIT 许可（`_analysis/batch5_unpack/velocity-shaders/LICENSE:1-3`，2026 TheCMK），主体是 Mellow 的分支。

**Astra 现状证据〔实测工具〕。** `Astra/shaders/global/lighting/blocklight.glsl` 对 `occlu|gradient|depth_|screen.?space` 0 命中；全树 `wispy-shader/verlixia/kute` 同族包的 `cas/smaa` 也没进 Astra。下界有 64³ 局部体素光（`global/dimension/nether_colored_light.glsl`），但那是下界专用，主世界没有遮蔽判断。

**怎么落地（第二轮补充）。** Astra 已经在 `colortex19`（格式 `R11F_G11F_B10F`，`Astra/shaders/lib/surface_buffers.glsl:14`）里带方块光颜色。**不要照抄 Velocity 往 colortex0 的 alpha 里塞光强**：Astra 的 colortex0 没有 alpha 通道，照抄会静默丢数据（Astra 文档里已经有同类陷阱的记录：往 `colortex0` 写 `.a` 读回来恒为 1.0）。正确落点是把"光占比"追加到与方块光同源的缓冲，或直接在消费端用 lightmap 的方块光分量（`lightmap.x`）算梯度——见第六节待核实项。代价估算：8 次颜色缓冲取样 + 8 次深度取样，只在梯度非零（约一半屏幕）时执行。未验证。

**风险。** 屏幕空间方法的固有缺陷：光源在屏外时判不出来（相机会转头就闪），薄墙后面会漏光。必须做 A/B，并保留强度滑杆。

**许可。** MIT，可直接改代码，保留版权行。

### 2. 完整 SMAA 1x 抗锯齿（替代现在的 FXAA 档）

**机制。** 现在 Astra 的抗锯齿两档是 FXAA 和 TAA。FXAA 便宜但会把细纹理糊掉；TAA 清晰但有拖影和鬼影风险。SMAA 走第三条路：先用"红均值"颜色差（一种按人眼对红绿蓝敏感度加权的颜色距离）找出边缘方向，再查两张预先算好的查找表（一张给边缘图案混合权重，一张给搜索范围），沿边缘方向做带权重的邻域混合。Grindstone 这版还加了三个 Astra 完全没有的细节：**局部对比度自适应**（附近对比度更高就跳过这条边，省算力也减伪影）、**对角搜索**（对角线方向单独处理）、**角点圆化**（把尖角做一点倒角，更像真实抗锯齿）。

**出处〔读源码〕。**
- `shader_research/ref-sources/grindstone/assets/grindstone_smaa/shaders/post/0_edge_detect.fsh`（边缘检测，含 `sq_redmean` 与 LCA 比较，`:27-45`）、`1_bw_calc.fsh`（混合权重与对角搜索）、`2_blend.fsh`（最终混合）、`include/redmean.glsl`、`include/config.glsl`（`SMAA_THRESHOLD / SMAA_LCA / SMAA_SEARCH / SMAA_SEARCH_DIAG / SMAA_CORNER` 五个可调参数）。
- 查找表：`assets/grindstone_smaa/textures/effect/area.png`（160×560）、`search.png`（64×16），在 `assets/minecraft/post_effect/end_of_frame.json` 里以 `location` 绑定。
- 同族 Iris 版实现另见 `_analysis/batch5_unpack/velocity-shaders/shaders/global/post/smaa.glsl:1-88`（MIT，可直接对照接线方式）与 `kute/shaders/global/post/smaa.glsl`（MIT）。

**Astra 现状证据〔实测工具〕。** `Astra/shaders` 全树 `smaa` 0 命中；抗锯齿只有 `program/display.fsh` 里的 FXAA 与 `program/taa_resolve.fsh`。

**怎么落地。** SMAA 需要一两个额外全屏 pass 和两张查找贴图（Astra 已有 `customTexture` 机制，`shaders.properties` 里有 12 处先例）。目标是把 `ANTIALIASING` 从"关/FXAA/TAA"扩成"关/FXAA/SMAA/TAA"，或在 FXAA 档内部升级。**额外收益**：SMAA 不依赖历史帧，和 TAA 不冲突，可以做 TAA 的兜底。代价估算：2 个半分辨率～全分辨率全屏 pass，未验证。

**风险。** 需要两张 PNG 查找表随包分发；SMAA 对尖锐细线（栅栏、蜘蛛网）效果不如 TAA。先做单帧对比截图。

**许可。** Grindstone 的原始实现 MIT；**但 `redmean.glsl` 单独的许可是 CC BY-SA 3.0**（文件头写明基于 compuphase "Colour metric"）。若搬运该文件必须保留署名与 CC BY-SA 3.0 声明。若不想引入 CC BY-SA 文件，用标准 SMAA 的 `max(|Δr|,|Δg|,|Δb|)` 或普通欧氏距离改写这一处即可（只差一个颜色度量函数）。

**顺带一条同源发现**：Grindstone 的 CAS 锐化（`assets/grindstone_cas/shaders/post/3_cas.fsh`，含"软最大/软最小"与 `sqrt(saturate(min(minimum,2-maximum)/maximum))` 振幅）是 FidelityFX CAS 1.2 的实现，Astra 也没有。它与 SMAA 是同一个包里的两个 pass，可以一起评估；单独做锐化属于观感偏好，不列为独立缺口。

### 3. PCSS 式变半影软阴影（影子边缘近实远虚）

**机制。** Astra 现在的阴影模糊半径是固定的：不管是半格外的栏杆还是二十格外的墙，影子边缘的模糊程度一样。PCSS 分两步：先在阴影贴图里搜一圈采样点，只统计"确实比被照面更靠太阳"的点，求它们到被照面的平均距离（遮挡体搜索）；再用这个距离放大模糊半径；如果一个遮挡体都没搜到，说明这个像素本来就该全亮，直接返回，省掉整轮模糊。这一刀"搜不到就返回"是 PCSS 里最划算的部分。

**出处〔读源码〕。**
- `reference_shaderpacks/arc-shader/shaders/lib/shadows/csm_render.glsl:118-153`（`FindBlockerDistance`）与 `:155-167`（`GetShadowing` 的 PCSS 分支）。关键三行：`:144-146` 取 `shadowtex0` 深度并算 `hitDist = max((shadowPos.z - bias) - texDepth, 0.0)`；`:148-149` 累加 `hitDist*(far*3.0)` 与计数；`:165` `pixelRadius *= min(blockerDistance * SHADOW_PENUMBRA_SCALE, 1.0)`。
- 参数：`reference_shaderpacks/arc-shader/shaders/lib/common.glsl:132-141`（`SHADOW_PCF_SAMPLES 4`、`SHADOW_PCSS_SAMPLES 4`、`SHADOW_PENUMBRA_SCALE 0.1`）。
- 采样点圆的生成：`reference_shaderpacks/arc-shader/shaders/lib/ssbo/vogel_disk.glsl` 与 `program/setup.csh`（Vogel 圆盘，用黄金角把采样点铺得比随机均匀）；无 SSBO 时退化为旋转步进 + 哈希半径（`csm_render.glsl:125-141`）。
- Photon 的独立实现：`reference_shaderpacks/photon-shader/shaders/include/lighting/shadows/pcss.glsl`。

**Astra 现状证据〔实测工具〕。** `penumbra|blocker` 全树 3 命中，全是无关注释；`shadowcolor1` 0 命中；`csm|cascade` 0 命中。阴影取数固定 4/8/16 角点核（`global/lighting/shadowmap.glsl`）。

**怎么落地（第二轮已定位到具体落点）。** 现在 Astra 的阴影模糊量在 `Astra/shaders/global/lighting/diffuse.glsl:302-305` 算出 `spread`，随后在 `:324-337` 用固定四瓣偏移取样；`:315-317` 已经把"世界纹元宽度"`worldTexel` 与软半径 `softRadius` 算好并 clamp 到 `[0.5*spread, spread]`。PCSS 只需要在 `:317` 之后、`:324` 之前插一小段"遮挡体搜索"，把 `softRadius` 换成"平均遮挡距离 × 系数"，其余不动。代价是每像素多 4 次 `shadowtex1` 单点取数（拿不到现有 `textureGather` 的合并收益），**0 个新附件、0 个新 pass、0 条新 properties 声明**。此外仍需在 `Astra/shaders/global/lighting/shadowmap.glsl` 增加一个可选的"遮挡体搜索 → 变半径"分支，作为 `SHADOW_FILTER_MODE` 的第三个取值（现在是 0 软件 / 1 硬件）。**注意**：遮挡体搜索要读不透明深度，Astra 主世界阴影贴图目前只读 `shadowtex1`（1 处）与彩色阴影（5 处），是否已有可用的"不透明深度"通道需要先核实（见第六节）。

**风险。** 直接代价是每像素多一轮（约 4–16 次）阴影图取样，对 144 FPS 目标是硬成本。PCSS 在低阴影分辨率下会产生"漏光"（light leak），需要配合偏置。**必须 A/B 对比现有 16 角点核**，不能默认更优。

**许可。** Arc 是 MIT（`reference_shaderpacks/arc-shader/LICENSE`），可直接改；Photon 是有条件再分发许可，只能参考思路，代码级借用要按 `Astra/THIRD-PARTY.md` 现有流程登记。

### 4. 用"上一帧已经画好的画面"当环境光来源（屏幕空间环境光/SGGI）

> 本节在第二轮深挖后补了一条更省的落地路径：Astra 在 TAA 档下**已经有一张"未抖动的上一帧 HDR 画面"**（`colortex15`，RGBA16F、不清理、文件头自述 unjittered HDR output，见 `Astra/shaders/program/taa_resolve.fsh:1-22`），正好对应 Arc 消费的那张"上一帧"缓冲。详见下文本条。

**机制。** 阴影算的是"这个点有没有被太阳直接照到"，环境光算的是"光从别处弹一次过来又多了多少"。不追真实光线，只在屏幕上做：从当前像素的半球里发射几条射线，在屏幕空间里步进，命中处直接采上一帧已着色画面（`colortex3`）的颜色当"间接光"，再把多帧的结果累积起来。它的妙处是**不需要光源列表、不需要体素结构、不需要硬件光追**，只需要 1 条屏幕射线 + 位计数。

**出处〔读源码〕。**
- 最完整的现代实现：`_analysis/batch5_unpack/luster-shaders/shaders/include/lighting/indirect_lighting/sspt.glsl:440-520`（`traceIndirect`：余弦半球采样 `:58-70`、R2 低差异序列 `:459-479`、屏幕空间光追 `:92-206`、命中发光 `:208-260`、直射光弹射 `:312-388`），半分辨率累积 `program/d5_sspt_accumulate.fsh`、降噪 `program/d6_sspt_filter.fsh`（五次 a-trous 方差引导滤波 = SVGF 思路）。
- 更省的另一条路线（可见性位掩码）：`reference_shaderpacks/…` 之外，前几批记录过 `dercode` 的 `GI_SSIL_Bitmask` 与 `sundial-lite` 的 SSVBM（每像素 1 条射线、16 步、每步把遮挡角区间映射成 32 位掩码的位）。本轮未重读这两个包（已不在本地），只按旧报告转述。

**Astra 现状证据〔实测工具〕。** `ssgi|ssil|indirectDiffuse` 0 命中；`bounce` 只在 `global/lighting/wind.glsl:192` 注释里。Astra 只有半分辨率 12 点 SSAO + bent normal（`program/ssao.fsh`、`lib/ao_resolve.glsl`）。

**怎么落地。** 大工程：新增半分辨率历史缓冲、重投影、射线步进 pass、降噪 pass，并接入环境光。**建议先只做"上一帧画面当一次弹射"的最简版**（1 条射线、不做降噪），看画面是否值得，再决定是否上 SVGF。代价估算：半分辨率 1 条射线 × 8–24 步 + 每帧重投影，未验证。

**风险（第二轮补充的硬约束）。** 上面说的 `colortex15` 历史缓冲**只在 TAA 档（`ANTIALIASING=2`）被分配**（`Astra/shaders/program/taa_resolve.fsh:10-20` 整段包在 `#ifdef ASTRA_TAA` 内，properties 也按档给尺寸）。TAA 关闭时那张图只有 1 个纹素，没有历史可用。所以复用 colortex15 这条路要么要求用户开 TAA，要么另开一张只在 GI 开启时才分配的历史缓冲——后者会与只剩 colortex7 空闲的附件约束冲突（见 shader_research/2026-10-17-Iris1.11.2引擎能力实测.md）。

另外 Astra 的投影带抖动（TAA 的 Halton 相位），而 Arc 的螺旋采样假设没有抖动，搬过来必须按 Astra 的抖动相位改写，否则 GI 会随抖动漂移。屏幕空间 GI 在屏外或背后信息缺失时也会闪烁；需要时域累积，而累积又会引入拖影。Astra 的 TAA 是选开项，GI 若依赖 TAA 会改变画质组合。

**许可。** Luster 的许可**允许学习与个人使用，但禁止再分发衍生作品**（`_analysis/batch5_unpack/luster-shaders/LICENSE:12` 允许 "Examine and learn from"，`:17-25` 禁止在 Modrinth 等平台分发衍生），且 Luster 本身基于 Photon（`LICENSE:33`）。**只能学思路，不能搬代码。** 若要代码级实现，用 Arc 的 SSGI（MIT）或自己写。

### 5. 阴影末端淡出到 lightmap（少一次硬切换）

**机制。** 阴影贴图只覆盖一定距离（Astra 均衡档 96 格）。超出这个距离，阴影判断必须"交还给"原版光照，否则会出现一圈生硬的明暗分界。Velocity 的做法是按"天空可见度 + 距离"把阴影值平滑淡到 lightmap 值，并对静态物体走一条更便宜的路径。

**出处〔读源码〕。** `_analysis/batch5_unpack/velocity-shaders/shaders/global/shadows.glsl:1-6,26-31`、`global/lighting.glsl:172-185,206`（此处是调用点——旧报告说"无调用点"，**是错的**）。

**Astra 现状证据〔读源码〕。** Astra 已有"主世界立方淡出"与"末地光平面淡出"（`global/lighting/shadowmap.glsl` 附近，见 `_analysis/2026-10-05-astra-status-inventory.md` §7 记录），但用的是自己的距离淡出。**这一条可能已有等价实现，属于"待核实"而不是确定缺口**——我把它放在这里是因为它的淡出公式把 lightmap 纳入，而 Astra 的淡出是否也这样做我还没读那段源码。**如果 Astra 已经是同一个思路，就删掉这条建议。** 〔未验证〕

**许可。** MIT。

### 6. 用引擎的硬件阴影比较器（`SEPARATE_HARDWARE_SAMPLERS`）

**机制。** Iris 有一组"可选特性"开关，光影包必须在 `shaders.properties` 里声明才会开启。其中 `SEPARATE_HARDWARE_SAMPLERS` 会额外绑定 `shadowtex0HW/shadowtex1HW` 这几个"硬件比较采样器"——采样时由显卡直接做深度比较，并且**能对彩色阴影缓冲用 `textureGather`**。Astra 现在只有一处用 `texture(shadowtex1,…)`，彩色阴影用 `textureGather(shadowcolor0,…)`（3 处），没有声明这个特性。

**出处〔读源码/工具〕。** 本机 Iris 1.11.2 的 `FeatureFlags` 类反编译（`javap` 实测）列出 14 项：`SEPARATE_HARDWARE_SAMPLERS / HIGHER_SHADOWCOLOR / CUSTOM_IMAGES / PER_BUFFER_BLENDING / COMPUTE_SHADERS / TESSELLATION_SHADERS / ENTITY_TRANSLUCENT / REVERSED_CULLING / BLOCK_EMISSION_ATTRIBUTE / CAN_DISABLE_WEATHER / SSBO / FADE_VARIABLE / TEXTURE_FILTERING`（+ `UNKNOWN`）。Astra 当前只声明了 `iris.features.optional=CUSTOM_IMAGES COMPUTE_SHADERS`（`Astra/shaders/shaders.properties:883`）。

**Astra 现状证据〔实测工具〕。** Astra 全树 `IRIS_FEATURE` 0 命中，即从未使用这些宏；`shadowtex0HW|shadowtex1HW` 0 命中。

**怎么落地。** 在 properties 里加声明，并把阴影采样改写成 `#ifdef IRIS_FEATURE_SEPARATE_HARDWARE_SAMPLERS` 双路径（Arc 的 `csm_render.glsl:6-17` 就是标准写法）。**收益不确定**：硬件比较省掉软件比较的指令，但会影响采样的过滤质量与兼容性。属于"低成本待实测"，不是确定优化。

**风险。** 声明 required 特性会让不支持的老 GPU 直接无法加载该包，建议放 optional 并写双路径。**必须实测才能判断收益。**

**许可。** 引擎特性本身无许可问题。

### 7. 三点同源的小改进（打包成一条）

这三条都来自 MIT 的 Velocity/Kute 系与 Arc，代价小、互相独立：

1. **TAA 历史取样改 Catmull-Rom 插值**：Astra 的 `program/taa_resolve.fsh` 用双线性取样历史帧；Kute 用 Catmull-Rom（四点插值），在相同混合权重下更锐。出处〔读源码〕`_analysis/batch5_unpack/kute/shaders/global/post/taa.glsl:27,94`（MIT）；Astra 全树 `catmull|bicubic` 0 命中。
2. **TAA 方差裁剪**：用邻域 3×3/5×5 的方差决定历史帧的接受范围，比 Astra 现在的 YCoCg 钳制更抗鬼影。出处〔读源码〕`_analysis/batch5_unpack/luster-shaders/shaders/post_processing/taa.glsl:142-166`（**Luster 禁止搬代码，只可学思路**）；Astra `variance` 3 命中全在注释。
3. **曝光/亮度统计放顶点或单像素**：Luster 有局部曝光与直方图自动曝光（`program/camera/local_exposure.glsl`、`c19_color_grading.fsh:122-123`）。Astra 已有 8×8 对数域 64-tap 测光 + 1×1 历史（默认关）。**这条价值最低，可以先不做。**

**风险。** 都属后处理，改动影响全屏观感，必须截图 A/B。TAA 默认关，改动只影响选开 TAA 的配置。

### 8. 从"新抓的在线源码"里得到的、本地没有的方法

- **Iris 的 `flip.*` 指令**：可以逐个 pass、逐个缓冲指定"这个 pass 读到的历史是上一帧内容"，Iris 会替你翻页，不用手写双缓冲。Astra 已有一处利用 Iris 缓冲翻页读前帧历史（云历史），但 `flip` 关键字本身在 properties 里只有 2 处提及（实测）。**价值：工程整洁，不是性能点。**
- **自定义 3D 噪声纹理**：Iris 的 `customTexture` 支持 `TEXTURE_3D`。本地实证：`_analysis/batch5_unpack/escheridia/shaders/shaders.properties:80` 写 `customTexture.blueNoiseTex = /textures/stbn.bin TEXTURE_3D RGB8 128 128 64 RGB UNSIGNED_BYTE`（该包把 `CUSTOM_IMAGES` 列为 required）。Astra 全树 `blueNoise` 0 命中，抖动用的是别的方式。**价值：中等**，是"低差异噪声抖动"这条通用优化路线的前置能力（GTAO/PCSS/SMAA 都用得上）。
- **R32UI 体素 image**：Escheridia 用 `image.voxelization = voxelMap RED_INTEGER R32UI … 256 256 256`（`:19-66`）。Astra 下界已有 `image3D` 体素链（`program/nether_light.csh`），所以这属于"格式可选项"而非新能力。

## 四、明确不建议做的（附理由，避免重复调查）

1. **再提"关闭阴影图 mip 生成"**：旧报告已驳回（本机 Iris 默认就是 `generateShadowMipmap=false`）。本轮未重测，**按旧结论维持**。
2. **Photon 的 GTAO（按地平线角积分）**：第二轮核对清楚了一点——Astra 的 `bentNormal`（`lib/ao_resolve.glsl:39-48`）是采样方向加权平均，**不是** GTAO 的切片地平线角平均，所以不能用已有 AO 一句话否掉。但它要每切片 2×步数 次深度取数（按 2 切片 8 步算约 32 次，是现有 12 点的约 2.7 倍），且 Photon 同时需要两张 AO 历史缓冲，与只剩 colortex7 直接冲突。**结论：不建议作为下一步**，除非先把附件与 144 FPS 预算算清。（Photon 许可是有条件再分发，不是 MIT。）：Astra 已有半分辨率 AO + bent normal（`lib/ao_resolve.glsl:13-52`、`global/lighting/diffuse.glsl:425-427,493`）。要改成 GTAO 得先证明现有 AO 有具体缺陷（噪点、接触处丢失），目前没有证据。
3. **棋盘格/半速率云上采样（Photon `checkerboard`）**：与 Astra 现有的时域云历史同向，用户已反馈云边缘噪点，加大时域权重会加重问题（旧结论已记录）。
4. **FSR/TAAU/整帧渲染缩放**：旧结论已否决（全链坐标/历史/后处理契约要重写），本轮无新证据。
5. **路径追踪（`phoxel-pt`、`dirt-rt`、`soft-voxels` 类）**：Astra 已有"不引入 PT"的既定决策。
6. **`muuf` 的 RSM**：其源码自述未完成（`settings.glsl:209` 原文 "isn't done yet, still have a bug!"）。
7. **`tilde` 的世界弯曲、`wispy` 的 FSR**：旧结论已否决，未变。
8. **纯风格滤镜**（body-camera、cursed-fog、ctrvcr、motion-blur-fx、ch-motion、thunders-mb、aquarium 等）：要么是主题滤镜、要么是单功能覆盖包（`aquarium` 解压后根本没有 `shaders/` 目录），不提供可迁移机制。

## 七之补、引擎层面本轮读实的三条（其中一条只适用于非下界维度）

以下三条来自对 844 个 .class 的反编译（完整记录见 `shader_research/2026-10-17-Iris1.11.2引擎能力实测.md` 与 `shader_research/subagent-A-iris-capability.md`）。

**(1) `gbuffers_terrain_solid`：分开实体与镂空地形，找回地形被 discard 关掉的 early-Z。**

机制：显卡有一个"先画前面的东西，后面的像素被挡住就直接丢掉"的加速机制（early-Z）。只要着色器里出现 `discard`（镂空的树叶、草、铁栏杆靠它把透明像素丢掉），**整个程序**的这个机制就失效——因为显卡不能确定后续会不会被丢掉。Iris 提供了一对程序名 `gbuffers_terrain_solid` / `gbuffers_terrain_cutout`，允许把"不会有镂空"的实体地形单独走一个不含 `discard` 的程序，把加速机制要回来。

Astra 现状〔读源码〕：地形走共享的 `Astra/shaders/program/lit.fsh`，里面有四处镂空 `discard`：`:290`、`:297`、`:300`、`:305`（实测 grep）。也就是说**所有地形（含石头、泥土这些完全实体不透明的）共用同一个含 `discard` 的程序**，early-Z 全程失效。

收益与代价：**未验证，但这是本轮唯一直接冲着填充率去的优化**。代价是新增一个地形专用入口（Astra 已有按材质分支的架构，可复用），难点是"哪些材质属于 solid"的判定与 Iris 的实际判定规则（本轮未读到规则源码，列为未确认）。不建议直接照 Iris 文档推断；先用一个最小实验程序验证 Iris 的确切判定，再决定投入。

**(2) `allowConcurrentCompute`：不适合在 Astra 声明。**

机制〔读源码/字节码〕：Iris 默认在每次 compute 分发前插一道内存屏障（`GL_SHADER_STORAGE_BARRIER_BIT`，常量 8232），保证上一个 compute 写的数据对下一个可见；properties 里写 `allowConcurrentCompute: true` 则不插。默认 false，且**这是引擎开关，只能由光影包声明**。

为什么对 Astra 不适用：Astra 下界的体素彩光恰好是**九阶段串行依赖**——`program.world-1/shadowcomp` … `shadowcomp8`（`Astra/shaders/shaders.properties:860-878`）每步读上一步写出的体素光，是真实的数据依赖。声明它为 true 等于向引擎声称"各阶段互不依赖"，**属于正确性风险而不是性能选项**。结论：不建议声明；除非未来把下界 compute 重构成"每阶段只碰自己的区域"。

**(3) 三条纠正（避免后续再犯同样的误判）。**

- `centerDepthSmooth` 在本机版本是**采样器**（CenterDepthSampler），不是 uniform；按 uniform 去找会误判为缺失。
- `cloudHeight` / `logicalHeightLimit` 存在，但定义在嵌套类 `IrisExclusiveUniforms$WorldInfoUniforms` 里；用扁平 uniform 名清单 0 命中会得出错误结论。
- 本机 844 个 class 里 **atmosphere 与数组纹理（TEXTURE_2D_ARRAY）确实 0 命中**，即这一版不支持数组纹理。
- SSBO 合法索引：字节码是 bipush 12（0–12 共 13 个），与网上文档写的 0–8 不一致——以本机字节码为准。
