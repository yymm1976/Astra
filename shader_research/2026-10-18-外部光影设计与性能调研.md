## 第一部分：执行摘要

### 1.1 十句话结论

1. **Astra 的阴影正确性高于所有已查外部包**：逐角参考深度平面重建、shadowtex0/1 双深度配对、逐角 caster 身份、硬件/软件双 gather、过滤半径按世界纹元宽度收敛、畸变核按世界方块锚定——这六项在 photon / Complementary / Bliss / mellow 四包里**一项都没有**（[A]，A-报告 §2）。不要为"对齐外部"而拆掉它们。
   > **一处需要收窄的旧说法**："水面焦散写 shadowcolor0" **不是 Astra 独有**——Photon（`program/shadow.fsh:110-164`）与 Complementary（`program/shadow.glsl:125-151`）同样在阴影 pass 写 shadow-side 缓冲、床面按水深取回。Astra 独有的是**单次解析 Hessian 求曲率 + 有界输出**（C-报告 §3.4.3）。A-报告 §Q7 的措辞据此修正。
2. **Astra 真正缺的是"变半径"而不是"更多采样"**：外部用 blocker search 让半影宽度随遮挡物距离变化；Astra 的半影宽度是用户常数。这是可见差异，但直接移植与 Astra 的逐角参考深度结构冲突（Photon 的 VPS 用**单一**参考深度做全部比较，等于放弃 Astra 的优势）。**[A]**，不建议照搬。
3. **最便宜且有真实外部对照的性能候选是"消除无贡献计算"，不是降低采样**。已确认的外部实例有三个：Photon 覆盖率图的球壳外提前拒绝（`cumulus.glsl:40-57`）、Bliss 体积云的包围盒+零密度跳过（`volumetricClouds.glsl:354,361,388`）、Photon 可变步数 PCF 的全亮/全暗提前返回（`pcss.glsl:155-160`）。Astra 在云侧**已经做了同类**（`cloud_screen.fsh:140-143` 逐 tile 不透明剔除、`clouds_planar.glsl:241-246` 水平射线裁剪、`:417-422` 细节倍频饱和门控），但在**体积雾与水下光柱**侧尚未找到等价物。
4. **Astra 的云不需要换步长分布**：Astra 的 `planeDistanceDif` 天然携带仰角自适应（等于 Photon 显式混合步数的效果），高画质档用的是**段积分**而非点采样，漏采风险低于 Photon 的均匀点采样（[A]，B-报告 §问题 2）。"减少采样/模糊云体"不是本次推荐方向。
5. **Astra 的末地黑洞在架构上领先所有已查外部包**：Astra 用**离线预计算的 Kerr 转移图集**（`qa/tools/build_end_transfer.py` 生成，运行时只做图集查询，见 `global/dimension/end_kerr.glsl:1-4`），外部包没有任何一个做引力透镜（[A]，grep 全缓存仅命中 lens flare 与注释）。黑洞方向应"保持并精修"，不是"学习外部"。
6. **最值得学的是色彩体系的分层组织方式，而不是某个 tonemap 函数**。Photon 把调色拆成"tonemap 前（线性域亮度/对比/饱和/白平衡）+ tonemap 算子 + tonemap 后（HSL 分色相饱和度 + 增益 + 抖动）"三段（`c19_color_grading.fsh:65-128`），Bliss 用 AgX（`color_transforms.glsl:249-282`），CR 用**按天气/时段逐项写死的调色板表**（`lightAndAmbientColors.glsl:6-78`）。Astra 目前是 `grading.glsl` 单层 + `tonemap.glsl` 可选算子，**缺少 tonemap 后的分色相二次校正层**。
7. **Astra 已有、外部没有的水体正确性不要回退**：`water_fresnel` 用真实介质折射率并处理全反射（`global/water/optics.glsl:5-18`），外部四包全部用 Schlick 近似或直接的艺术 F0。Astra 的 `water_surface_transfer` 把吸收与散射合成一次仿射传输、并让吸收/散射开关彼此独立（`absorption.glsl:94-118`），也是外部没有的记账精度。
8. **Astra 未接入资源包 LabPBR 材质**（全仓搜 `labpbr`/`normals` 只命中注释；Photon 有完整解码 `include/surface/material.glsl:39-102`）。这是真实缺口，但 Astra 的材质路线是方塊 ID 表（`block.properties`），移植 LabPBR 属于**架构决策**而非优化项，列为 P3。
9. **本次调研**已完成 8 个外部仓库的源码深读（photon / ComplementaryReimagined / Bliss / Steadfast / mellow / renderpearl / minecraft-miniature / rethinking-voxels）与另外 8 个的初步筛选，覆盖任务要求的"至少 12 个候选、至少 6 个深研"。
10. **没有任何性能数字是实测的**。报告里出现的所有"省 N 次采样""少一个 pass"都是**[源码推断]**，附带了假设与适用条件；没有 FPS、毫秒或百分比收益。

| 序 | 事项 | 类型 | 证据 | 建议 |

## 第三部分：视觉技术横向研究

本部分按**技术主题**组织，不按项目组织。每条给出：技术目标 → 不同项目思路 → 关键源码证据 → 优缺点 → 性能开销 → Astra 现状 → 适用性 → 推荐方向。

### 3.1 光照与色彩体系

#### 3.1.1 核心发现：优秀光影的"协调感"来自**让不同消费者共享同一个函数**，而不是调更多的 RGB 系数

**Photon 的做法（最值得学的一条）**：直射光颜色不是常量表，而是**把太阳光谱透过与天空同一个大气函数**得到：

```glsl
// photon-main/shaders/include/lighting/colors/light_color.glsl:62-77
vec3 get_light_color() {
    vec3 light_color
        = sunlight_color * atmosphere_transmittance(light_dir.y, planet_radius);
    light_color = atmosphere_post_processing(light_color);
    light_color *= mix(
        get_sun_exposure() * get_sun_tint(),
        get_moon_exposure() * get_moon_tint(),
        step(0.5, sunAngle)
    );
    light_color *= clamp01(rcp(0.02) * light_dir.y);   // 昼夜过渡淡出
    light_color *= 1.0 - 0.25 * pulse(abs(light_dir.y), 0.15, 0.11);
    return light_color;
}
```

`atmosphere_transmittance` 与天空共用同一份大气实现（`include/sky/atmosphere.glsl`）。**黄昏时天空变红、直射光同时变红，是因为它们是同一个函数的两个取值，而不是两处分别调参。** 这就是"为什么看起来协调"的直接机制——Astra 目前是分别维护天空色与光色，两者靠人工对齐。

**Photon 的"蓝调时刻"是一个显式设计事件**：

```glsl
// light_color.glsl:13-19, 22-34
float blue_hour = linear_step(0.05, 1.0, exp(-190.0 * sqr(sun_dir.y + 0.09604)));
float daytime_mul = 1.0 + 0.5 * (time_sunset + time_sunrise) + 40.0 * blue_hour;
...
vec3 blue_hour_tint = vec3(0.95, 0.80, 1.0);
blue_hour_tint = mix(vec3(1.0), blue_hour_tint, blue_hour);
```

`exp(-190·(y+0.09604)²)` 是一个**极窄的高斯带**：只有太阳高度角在 −0.096 rad（约 −5.5°）附近时才触发，此时曝光乘 40、色温偏蓝紫。这解释了 Photon 日落前后那段特别"高级"的十几秒。**[A]**：Astra 的 `lib/twilight.glsl` 有黄昏处理，但本轮**未逐行核对**它是否有等价的高度角窄带事件，标为待确认。

**Complementary 的做法完全不同——它是显式调色板表**：

```glsl
// ComplementaryReimagined-main/shaders/lib/colors/lightAndAmbientColors.glsl:6-17
#ifndef COMPOSITE1
    vec3 noonClearLightColor = vec3(0.65, 0.55, 0.375) * 2.05; //ground and cloud color
#else
    vec3 noonClearLightColor = vec3(0.4, 0.75, 1.3); //light shaft color
#endif
vec3 noonClearAmbientColor = pow(skyColor, vec3(0.75)) * 0.85;
vec3 sunsetClearLightColor = pow(vec3(0.64, 0.45, 0.3), vec3(1.5 + invNoonFactor)) * 5.0;
vec3 sunsetClearAmbientColor = noonClearAmbientColor * vec3(1.21, 0.92, 0.76) * 0.95;
```

**同一时刻的地面光、云光、光束颜色是三个不同的常量**（`ground and cloud color` 用暖白 `(0.65,0.55,0.375)`，`light shaft color` 用青蓝 `(0.4,0.75,1.3)`）。这是一个**刻意的分层设计**：体积光束是散射主导（偏蓝，瑞利），地面是透射主导（偏暖）。Astra 目前的光束与地面共用同一套直射光色，**缺少这种按"消费者物理性质"分组的能力**。**[A]**

CR 的完整调色板覆盖：正午/日落/夜晚 × 晴天/雨天 ×（可选）雪地/干旱/丛林生物群系修正，共约 20 个显式常量（`lightAndAmbientColors.glsl:6-78`）。

**Bliss 用 AgX 做色域压缩**：`lib/color_transforms.glsl:249-282` `ToneMap_AgX`（AgXInsetMatrix → `agxDefaultContrastApprox` → `agxLook` → AgXOutsetMatrix），来源注释明确指向 iolite-engine 与 `sobotka/AgX`、three.js。AgX 的特点是**高光向白色去饱和**（而不是像 ACES 那样保留色相），这是 Bliss 画面"柔和不刺眼"的来源。

**Photon 的三段式调色链**（`program/c19_color_grading.fsh`）：

| 段 | 位置 | 做什么 | 源码 |
|---|---|---|---|
| ① tonemap 前 | 线性 ACEScg 域 | 亮度 ×0.83、**log2 域对比**（围绕 `log2(0.18)`）、饱和度、**白平衡矩阵**（rec2020→xyz→WB→rec2020） | `:65-93` |
| ② tonemap | 10 个可选算子 | ACES full/fit、Hejl 2015、Hejl-Burgess、Lottes、Uncharted2、Tech(Lux)、Ozius、Reinhard、Reinhard-Jodie | `include/post_processing/tonemap_operators.glsl:8-120` |
| ③ tonemap 后 | 感知域（先 `sqrt`） | **HSL 分色相饱和度**：橙色 30°±20、青色 210°±20、绿色 90°±44（还可平移色相）；再 `gain(rgb,1.05)`；最后 `sqr` 回线性 | `c19_color_grading.fsh:97-128` |

```glsl
// c19_color_grading.fsh:108-127（节选）
vec3 hsl = rgb_to_hsl(rgb);
float orange = isolate_hue(hsl, 30.0, 20.0);
hsl.y *= 1.0 + orange_sat_boost * orange;
float teal = isolate_hue(hsl, 210.0, 20.0);
hsl.y *= 1.0 + teal_sat_boost * teal;
float green = isolate_hue(hsl, 90.0, 44.0);
hsl.x += green_hue_shift * green;
hsl.y *= 1.0 + green_sat_boost * green;
rgb = hsl_to_rgb(hsl);
rgb = gain(rgb, 1.05);
return sqr(rgb);
```

**为什么有效**：饱和度是"全局旋钮"，一调就同时影响皮肤、植被、天空；而**按色相选择性加饱和**可以只强化"橙（日落/火把）+ 青（水面/阴影）"这对互补色，同时不动绿色植被。这是"电影感"最常见的来源之一，且**计算量极小**（一次 rgb↔hsl + 三次色相隔离）。

**Astra 现状**：`global/post/grading.glsl` 是**单层**链：色温（`:162-173`）、vibrance+饱和度合并计算（`:221-234`）、对比（`:244-246`）、三段式 tonal balance（`:201-211`）、vignette、抖动。`lib/tonemap.glsl` 提供 Uchimura（`astra_natural_uchimura`）、AgX、ACES、Reinhard-Jodie。**缺少 tonemap 之后的分色相二次校正层**，也缺少白平衡矩阵。

**适用性**：分色相第二次校正在 Astra 的 `grading.glsl` 末尾插入即可，位于 `apply_tonal_balance` 之后、`clamp` 之前，不依赖任何新缓冲区。**[A]**

**推荐方向**：P1。先做**只读对照实验**（不改默认值）：新增一组 `LOOK_*_HUE_*` 选项，默认全部为 100（= 关闭），让用户 A/B。风险是 HSL 往返会引入轻微色偏，Photon 用 `sqrt`/`sqr` 做感知域往返正是为了压制这一点。

#### 3.1.2 环境光与天空辐照度

- **Photon**：`get_ambient_color()` 来自 SH（球谐）天空光照，并用 bent normal 重估方向分量（`include/lighting/diffuse_lighting.glsl:317`）。
- **CR**：`noonClearAmbientColor = pow(skyColor, vec3(0.75)) * 0.85`（`:10`）——**直接把天空色开 0.75 次方当环境光**，一行解决天空↔环境光的一致性。
- **Astra**：`colortex18` 存 SH9（`shaders.properties`），`lib/ao_resolve.glsl:70-95` 用 bent normal 只替换 SH 的方向相关份额（`skyBent - skyGeometry`）。A-报告 §Q6 已确认**这是 Astra 比 Photon 更细的记账**，Photon 的 bent normal 只喂 IBL，不做份额分离。

**推荐方向：不需要改动。** Astra 在这一点上领先。

**Astra 的 Uchimura 自然版有一处值得保留的设计（[A]）**：峰值在 `[0.22, 0.532)` 区间**恒等返回**，肩部按 `mappedPeak/peak` **等比缩放整条 RGB**（色相与饱和度不漂移），只有亮度 >1 才 `smoothstep(1,8)` 趋白。**白点口径与 Photon/CR 一致（都是 8）**，但高光去饱和的路线不同：CR 是"趋白 + 暗部去饱和"、AgX 是矩阵内缩、Astra 是等比 + 超 1 趋白。→ **分类"采用不同方案"，不是缺失。**

```
auto-exposure(可选) → apply_exposure → apply_scene_grading(线性、绕 18% 中灰)
→ tonemap → srgb_encode → apply_grading(显示空间：色温带蓝色保护 → vibrance/saturation 合并仿射

```

**由此推出的两条纪律（防止后续把数值照搬）**：
1. **不同包的中灰枢轴点不同，数值不可照搬**：Astra 用 18% 中灰的**幂曲线**（`grading.glsl:190-196`）、CR 用 `log2(0.18)`、mellow 用 0.5 为轴。同一个"对比度 1.05"在三者上改的是不同亮度区间的斜率。
2. **线性域做饱和会顺带改亮度**：Photon 在 `c19_color_grading.fsh:79-81` 用 `mix(vec3(lum), rgb, saturation)` 显式保亮度；Astra 的 `grading.glsl:221-234` 也是共享原亮度做仿射合并。**新增任何线性域颜色操作时必须一并保亮度。**

**外部有、Astra 没有的三条（都是小项，[候选]）**：
- **显示空间选择性色相饱和度**（Photon `c19_color_grading.fsh:108-123`）——见候选 1。
- **PBR Neutral 作为第 4 个可选算子**（mellow；Astra `settings.glsl:252` 目前只有 `[0 1 2 3]`）。
- **用曝光值调制泛光/光散射**（Bliss `composite11.fsh:138,141`）——**Astra 的 `global/post/bloom.glsl` 本次未读，尚不能确认是否已有**（D-报告明确标为未验证）。**在核实之前不得写成缺口。**

**CR 的"暗部提升 + 暗部去饱和"（`composite5.glsl:66-84`）不应直接引入**：它与 Astra 既定的"不给暗部加灰色底"取向冲突（`tonemap.glsl:81-83`），只能作为**可选项**，且需要用户决策。

**雾与空气透视（[A]）**：三家的雾色都源自天空——Photon 直接调用大气模块（`fog/overworld/analytic.glsl:6,75,84`）、CR 取天空调色板（`mainFog.glsl:95-107`，含 `VdotS` 方向项）、Astra 的返回契约就是"雾色 + `skyColor×skyFogStrength`"（`global/atmosphere/fog.glsl:89-92`），且已有雨天加厚与弱雾归零省开销（`:166-182`）与方向项 `fog_air_perspective`（`:203-209`，注释对照 BSL `fogColorM`："朝阳偏暖/侧向中性/背光略冷"）。→ **Astra 已有同类实现 + 两项附加，不要重复建议。**

#### 3.2.2 外部领先的一项：**变半径（半影宽度随遮挡物距离变化）**

**技术目标**：贴着地面的阴影应该锐利，高柱子投到地面的阴影应该柔和。恒定过滤半径做不到这一点，画面会显得"所有阴影一样假"。

**Photon 实现**（`include/lighting/shadows/pcss.glsl`）：

1. blocker search（`:29-62`）：用 Vogel 盘 3 步（SSS 材质 12 步）在阴影图上找平均遮挡深度；半径随太阳高度角收缩。
2. 半影公式（`:245-252`）：
```glsl
float penumbra = 16.0 * SCALE * (z_receiver - z_blocker) / z_blocker;
penumbra *= 5.0 - 4.0 * cloud_shadows;   // 阴天半影更宽
```
3. 可变步数 PCF（`:104-111`）：把 penumbra 换算成采样步数，下限 `SHADOW_PCF_MIN_STEPS = 6`，上限 12。
4. 全亮/全暗提前返回（`:155-160`）：
```glsl
if (shadow > 4.0 - eps) return color;      // 四点全亮 → 不再循环
else if (shadow < eps) return vec3(0.0);   // 四点全暗
```
5. 小半影锐化（`:176-183`）与防漏光（`:203-207`，来自 CR）。

**代价（[源码推断]，附算术）**：
- blocker search：**+3 次 `texelFetch`**（`:49`）。
- 可变步数 PCF：**6~12 次采样**（含彩色阴影时同时读 `shadowcolor0`）。
- 与 Astra 当前成本对比：Astra 默认档 `lobeCount = 4`（`diffuse.glsl:309`）× 2 次 gather（shadowtex1 + shadowtex0）= **8 次纹理操作 = 32 次纹元比较**。
- 若用 Photon 结构替换：3 + 6 = **9 次**（比 8 次多 1 次，**约 +12%**）；SSS 材质 3 + 12 = **15 次（+87%）**。
- 若在 Astra 现有逐角结构上**叠加** blocker search 而不替换：3 + 8 = **11 次（+37%）**，收益只有半影宽度。

**结论 [A，含结构冲突]**：Photon 的 VPS 用**单一**参考深度 `shadow_screen_pos.z` 做全部比较。Astra 的逐角参考深度恰恰是它优于 Photon 的地方，VPS 会把这份优势丢掉；若保留逐角参考深度，PCF 循环每步都要重算 4 个参考深度（4 次平面外推），成本翻倍。**两者不能简单叠加，属架构冲突，不建议照搬。**

**可分离的低成本子项（推荐）**：只借 `penumbra *= 5.0 - 4.0*cloud_shadows` 这一项——阴天时有效光源从点光源变成整个天穹，半影物理上就该更宽。**但它有一个实现前提**：Astra 的 `spread` 被 `clamp(softRadius/worldTexel, 0.5*spread, spread)` 双向夹住（`diffuse.glsl:327`），单纯放大 `spread` 会被上界吃掉，必须同时放宽夹取。**这是"需要改两处"，不是改一行。** 另外 `surface_shadow_light()` 当前签名（`diffuse.glsl:286`）只有 playerPos/shadowPos/skyLight 三个参数，云透射率**必须从调用方传入**。**[B]**

#### 3.2.3 Astra 缺失、外部有二项

- **屏幕空间接触阴影 SSRT**（Photon `include/lighting/shadows/ssrt.glsl:9-107`）：仅用于阴影距离外的假阴影（调用点 `program/d4_deferred_shading.fsh:504-520`），代价是 10 次 `texelFetch` + 10 次逆投影，每像素。**硬前提：需要 TAA 抹噪点**；Astra 的 `ANTIALIASING` 默认 1（`lib/settings.glsl:287`，取值 `[0 1 2 3]`），TAA 是 `== 2` 才开——**无 TAA 配置下 SSRT 会明显噪。** **[B]**
- **AO 的多弹射近似**（Photon `include/lighting/ao/gtao.glsl:156-160`）：
```glsl
const float albedo = 0.2;
ao /= albedo * ao + (1.0 - albedo);
```
**代价：1 次乘加 + 1 次除法，零采样。** 效果是角落不再死黑。Astra 落点 `program/ssao.fsh:125` 的 `visibility` 之后。**风险**：Astra 的 `visibility` 已被 clamp 到 `[0.25,1]`（`ssao.fsh:125`），该修正会进一步收窄值域，可能让 AO 弱到看不见，**需要同时调 `AO_STRENGTH` 补偿**。**[A 级对照，B 级收益]**

#### 3.2.4 AO 降噪策略横向对比（A-报告 §Q6 原表）

| 项目 | 采样数 | 法线 | bent normal | 时域 | 降噪 |
|---|---|---|---|---|---|
| Photon GTAO | 2 slices × 2 dir × 3 steps = 12 | 有 | 有 | **有（10 帧）** | Catmull-Rom 上采样 + 深度/边缘拒绝 + slerp |
| Photon SSAO | 12 | 有（TBN） | 无 | 有 | 同上 |
| CR SSAO | 8（默认 `SSAO_QUALI 2`） | **无** | 无 | 无 | 无，直接乘 |
| Bliss GTAO | 12 | 有 | 无 | 无 | 与 vanilla AO 取 min |
| mellow SSAO | 8（poisson disk） | 有（深度导数） | 无 | 无 | 无 |
| **Astra** | **12（固定黄金角圆盘）** | 有（colortex20） | 有（colortex26） | **无** | **2×2 双边重建（深度+法线双拒绝）** |

**关键差异不是采样数（都是 12），而是降噪路径**：Photon 用 10 帧时域累积换低单帧采样；Astra 只有空间重建。Astra 的 `pow8(agreement)`（`lib/ao_resolve.glsl:39`）对法线不一致极其严格（差 30°→权重 0.32；差 45°→0.004），接近硬拒绝，**更干净但可能留有空洞**。**[A]**


### 3.3 云层、天空与天气

#### 3.3.1 Photon 的"局部覆盖率图"：省的是什么，Astra 该不该跟

**机制**（[A]）：
- 写入：`program/p0_clouds_prep.fsh:100-109`，`RENDERTARGETS: 8`（colortex8），同一 pass 顺带烘焙云影图：
```glsl
fragment_color.xy = render_cloud_shadow_map(uv);
#ifdef CLOUDS_CUMULUS_PRECOMPUTE_LOCAL_COVERAGE
fragment_color.z  = render_clouds_cumulus_coverage_map(uv);
#endif
```
- 规格：`shaders.properties:317` `size.buffer.colortex8 = 512 512`，RGB8，**每帧更新，无时域累积**。注意 `include/buffers.glsl:12` 的注释写 "256x256"，与属性文件**对不上**，以属性文件为准。
- 投影带径向畸变，让近处占更多纹元：`include/sky/clouds/coverage_map.glsl:56-69` `uv /= 0.8 * length(uv) + 0.2;`
- 消费：`include/sky/clouds/cumulus.glsl:40-57`，源码注释原文 **"saves 1 sample and some maths"**。被替换的 `clouds_cumulus_local_coverage`（`coverage_map.glsl:9-54`）每次调用要 **2 次 noisetex 采样 + 一组 mix/linear_step/cubic_smooth 分支**。

**Astra 已有同类预计算，但目标不同，收益小得多**（[A]）：
- Astra 的 `program/cloud_shadow_cache.fsh` 写 `colortex14`（`RENDERTARGETS: 14`，格式 `R16`），分辨率 `shaders.properties:92-100`：`CLOUD_QUALITY == 0` → 128²，否则 256²；锚点按 2 格对齐（`shaders.properties:1110`）；覆盖 `ASTRA_CLOUD_SHADOW_EXTENT = 512.0` 格（`global/atmosphere/cloud_shadow_cache.glsl:7`）。
- 消费端有**边缘回退**，避免把世界查询夹到图边界（`cloud_shadow_cache.glsl:34-43`）：边缘 ≤0.5 纹元直接回落实时场，≥8 纹元用缓存，中间 `smoothstep(0.5,8.0,edge)` 混合。
- Astra 的密度查询本身就只要 **1 次采样**：`global/atmosphere/clouds_planar.glsl:93-97` `textureLod(complementaryCloudNoise, astra_rounded_cloud_coord(pos, ASTRA_CLOUD_ROUNDNESS), 0.0).b`。Photon 替掉的是"2 次采样 + 两套分支"，Astra 替掉的是"1 次采样 + 一次取整坐标计算"。
- Astra 还已经用另一种方式砍掉了大头——**细节倍频在饱和时直接跳过**（`clouds_planar.glsl:417-422`）：
```glsl
float saturation = max(saturationBase, densityGate + 0.02);
float noise = densityCoarse;
if (noise < saturation) {
    vec2 detailUv = mat2(0.8,-0.6,0.6,0.8)*tracePosM.xz*2.7+vec2(31.7,9.3);
    noise += 0.22*astra_2d_cloud_sample(detailUv);
}
```

**判定：作为首要优化"不适合移植"**。若将来要做，正确做法是把覆盖率塞进**已有的 colortex14 的空闲通道**，而不是新开一张图；收益上限是"每次查询省一次采样的一部分 ALU"，**[候选]** 未验证。

**必须一并修掉的上游缺陷 [A]**：`program/d0_sky_map.fsh:115` 与 `program/d1_clouds.fsh:110` 都有一条**无条件**的 `#define CLOUDS_USE_LOCAL_COVERAGE_MAP`，而 `d0_sky_map.fsh:117-119` 的 `#ifdef CLOUDS_CUMULUS_PRECOMPUTE_LOCAL_COVERAGE` 只是重复定义同一个宏。结果是：用户在菜单关掉该选项后，p0 不再写覆盖率通道，但 d0/d1 仍然采样 colortex8，读到**旧值或未初始化值**。这是"照抄该机制时必须修掉"的地方。

#### 3.3.2 步进策略：Astra 不需要改（B-报告 §问题 2）

| 维度 | Photon | Astra |
|---|---|---|
| 主步进 | **均匀**（`cumulus.glsl:255` 附近 `ray_length * rcp(primary_steps)`） | 段积分：每段取两端 coarse 值、线性插值出占用边界（`clouds_planar.glsl:325-353`） |
| 仰角自适应 | 显式按 `abs(ray_dir.y)` 在"水平 40 步 / 天顶步数"间线性混合（`:220-222`） | 隐式——`planeDistanceDif` 本身就是"平板厚度 / |dir.y|" |
| 按消费者分档 | `PROGRAM_DEFERRED0` 时两个步数**都减半**（`:201-207`） | 按 `CLOUD_QUALITY` 与是否写天空缓存分档（`clouds_planar.glsl:280-302`） |
| 指数步长 | **只用于光学深度探针** `clouds_cumulus_optical_depth`（`:117-130` `step_growth = 2.0`），主步进不是 | 无 |
| 水平射线裁剪 | 无 | `clouds_planar.glsl:241-246` 把 slab 夹到水平可视圆柱内——**"以前水平射线把 64 个采样铺在几乎看不见的空间里"** |

**关于指数探针的算术（[源码推断]）**：第 i 步长 = `0.1·T/n · 2^i`，n 步总和 = `0.1·T/n·(2^n−1)`。

- n=2（`CLOUDS_CUMULUS_AMBIENT_STEPS` 默认 2，`settings.glsl:210`）→ 总和 **0.15·T**，只探到 15% 厚度——**这是刻意不完整的近似，不是 bug**；
- 分布前密后疏：第一步 0.0167·T，最后一步 0.53·T。

**判定：Astra 的采样策略在"防漏采"上优于 Photon 的均匀点采样，在"防过采样"上打平。不建议改步长分布。**

#### 3.3.4 多重散射：Photon 用代数级数替代多次光线步进

```glsl
// photon-main/shaders/include/sky/clouds/cumulus.glsl:164-185（节选，8 次循环）
for (uint i = 0u; i < multiple_scattering_iterations; ++i) {
    scattering += light_color * phase * light_transmittance * transmittance * scattering_amount;
    ...
    anisotropy *= 0.5;
    scattering_amount *= 0.5;
    light_transmittance = sqrt(light_transmittance);
}
```
**8 次迭代 × 4 个 `exp()` + 3 个 HG，零纹理采样、零额外步进。** [源码推断] 量级约等于"一次密度采样"。这是"用便宜代数换体积感"的范例：它不提高空间精度，只补上"光在云里被多次散射"的能量，让云底不那么死黑。

Bliss 用的是另一种写法（`lib/volumetricClouds.glsl:365-380`）：3 次太阳阴影采样 + 跨层阴影。

**判定：Astra 目前没有等价的多次散射级数，这是 P1 候选（见第六部分 C2）。**

#### 3.3.5 天空与大气

- **解析雾 vs 步进雾有明确分流判据**（`include/fog/overworld/analytic.glsl` 与 `raymarched.glsl`）：能解析求的就走解析，只有需要体积感时才步进。

#### 3.4.1 波浪：外部全是"有限差分求法线"，Astra 是"解析导数 + 屏幕足迹过滤"

| renderpearl | 无水体模型（`world_default/gbuffers_water.fsh:1-4` 直接复用 `/prog/lit.fsh`） | — | — |

#### 3.4.3 折射与焦散

- **折射配对**（[A]）：Astra 用 `colortex4`（延迟不透明色）+ `depthtex1`（不含半透明）**同纹素配对**，再额外配对 `colortex28` 晚期实体深度，侧向接口还有 2cm 接收带（`global/water/refraction.glsl:24-37,61-124`）。Photon 走 MRT `refraction_data` 跨 pass；CR 用噪声 UV 位移 + 材质 ID/深度双检。**Astra 的配对维度更多。**
- **焦散不是 Astra 独有**：Photon（`program/shadow.fsh:110-164`）与 CR（`program/shadow.glsl:125-151`）同样在阴影 pass 写 shadowcolor0 类缓冲、床面按水深取回。差别在算法：Astra 用**解析 Hessian 波面聚焦**（`lib/water_wave_lens.glsl:7-19,44-48`，输出有界），Photon 要跑一次完整水法线 + 屏幕面积雅可比，CR/Bliss 用噪声导数/噪声整形。
  > 这一条修正了"Astra 独有水面焦散写 shadowcolor0"的过强表述：**同族机制外部也有，Astra 独有的是"单次解析求曲率 + 有界输出"。** A-报告 §Q7 的说法应据此收窄。
- **Astra 独有：逐帧 1024² 波场通量场** `colortex29`（`program/itt_water_normal_cache.fsh:17-26`，覆盖 64×64 格，1 纹元 = 1/16 格，mip LOD0~4）+ 20×12 界面状态扫描（`program/water_state.fsh:26-107`）+ 水的时间重投影（`global/water/temporal.glsl:75` 权重 0.85）。**外部全部包都是静态噪声逐像素求值，无一包做逐帧波场 pass。**

#### 3.4.4 水下体积光：Astra 结构更细，外部更省

- **Photon**（`include/fog/water_fog_vl.glsl`，154 行**全文已读**）：`min_step_count = 16`、`max_step_count = 25`，步数按射线长度线性增长 `min + 0.5*ray_length`（`:44-46`）；每步 **2 次阴影取样（shadowtex0 + shadowtex1）+ 2 次噪声焦散采样**；再做 **4 次多重散射迭代**（`:125-142`，`anisotropy *= 0.5`、`scattering_amount *= 0.5`、`light_transmittance = sqrt(light_transmittance)`）。射线长于 50 格直接截断（`:9,39-41`）。作者明确把不变量移出循环（`:65-75`：`step_transmittance = exp(-extinction_coeff * step_length)` 只算一次）。
- **Complementary**（`lib/atmospherics/fog/waterFog.glsl`，**19 行**）：只有解析距离雾，`fog = lViewPos/48; fog *= fog; return 1-exp(-fog)`（有光束时）或 `/32`（无光束时）。**没有光束、没有相位函数。**
- **Astra**：Beer-Lambert 光谱吸收 + 单散射项（`global/water/absorption.glsl:14-74`，吸收与散射**各有独立用户控制**）；水下体积光 7 区间 × 4 高斯节点 = 最多 **28 个可见度节点**，每节点再积分 8 点波场通量 → **最坏 224 次 colortex29 读取**，但有三处早退（`global/water/light_shafts.glsl:148-188,243-274`，注释明确 `irradiance==0` 是精确 0）。

**判定**：结构上 Astra 更细（确定性体积光、不依赖 TAA 去噪，`light_shafts.glsl:143-147`）；成本上外部更省。**"光束 28×8 最坏取样"是 P1 待核实项**，但必须先量出 underwater 场景里有多少像素真的走到最坏路径（早退命中率未知，**[未验证]**）。

### 3.7 其他值得纳入的技术发现

以下四项是任务清单（第四部分 A–F）之外、但确有差异性的发现。

#### 3.7.1 renderpearl：把光照做成"每帧清空的 GPU 光源队列"（本报告里架构最独特的一个）

**机制**（[A]，逐行读源码）：
- 24 个 compute shader（`.csh`）。
- **光源队列 buffer**（`buf/llq.glsl`，全文 5 行）：
```glsl
layout(std430, binding = 2) restrict buffer lightListQueue {
    uint len;
    uint[LL_CAPACITY] data;
    uint16_t[LL_CAPACITY] color;
} llq;
```
- 入队（`lib/push_to_llq.glsl:5-72`）：**9 位打包世界坐标**——`bitfieldInsert(bitfieldInsert(x, y, 9, 9), z, 18, 9)`（`:7`）把三个坐标压进一个 uint；颜色压进一个 `uint16_t`（G 6 位 + R 5 位 + B 5 位，`:15-17`）。
- **子组内先去重**（`:20-40`）：用 `subgroupBallot`/`subgroupBallotFindMSB/LSB` 在 wave 内比较光源，重复的只入队一次。这是本报告里唯一使用**子组（subgroup）扩展**做性能优化的实现。
- **原子计数也用子组摊薄**（`lib/sg_incr.glsl`）：`subgroupElect()` 只让一个 lane 做 `atomicAdd(counter, sg_size)`，其余 lane 用 `subgroupBroadcastFirst` 拿到的基址 + `subgroupBallotExclusiveBitCount` 得到各自索引——**把 N 次原子操作压成 1 次**。
- 光照用**球面高斯（SG）**表示（`lib/sg_incr.glsl` 同目录、`lib/push_to_llq.glsl` 的 `f16vec3`/`int16_t` 路径），并提供 `INT16` 与 `SUBGROUP_ENABLED` 两条编译分支。

**为什么值得记录**：它展示了 Iris 1.8+ compute shader 能力的另一种用法——**不是把光烘进体积纹理，而是把光源列表写成结构化 buffer 交给后续 pass 消费**。对 Astra 的含义：Astra 的下界彩光走"每帧全量重建 64³ 体积"（2.36M cell/帧），renderpearl 走"每帧重建一个小得多的光源队列 + 每像素解析求值"。**这是两种成本形态的对比，属于 P2 级研究线索**，但它依赖 `subgroupBallot` 等扩展（Astra 目前没有使用子组内建的代码），且 `f16vec3` 需要 GLSL 的 16 位浮点支持，**移植前提应逐项核实 Iris 版本与驱动**。

#### 3.7.2 Alpha-Piscium：编号 setup 序列 + 极线重投影（补充：compute 编排）

- **全包 112 个 `.csh`，其中 `begin*.csh` 13 个**；`pass/` 按 begin / composite / general / geometry / setup / shadowcomp **六层**组织。**阶段编排本身被当作一等设计对象。**
- `begin1.csh` 全文只有 4 行（薄壳 + include）；`pass/begin/UpdateGlobalData.comp.glsl` 用 `local_size_x = 1` + `workGroups = ivec3(3,1,1)`——**每帧只派发 3 个工作组**更新全局矩阵。
- 它的 `_a/_b/_c` 辅助派发命名与 Astra 在 `shaders.properties:906` 记录的 Iris 约定**完全一致**——两家独立得出同一套规避做法，可互相印证。
- `techniques/atmospherics/air/UnwarpEpipolar.glsl`：极线（epipolar）重投影——把上一帧沿极线方向重采样以避免遮挡错误。这是本报告在"时域复用"方向上看到的**除方差裁剪/邻域钳制之外的第三种拒绝策略**。**[C]**：只读到文件名与所在目录，**未读实现**，仅作为线索记录。

#### 3.7.3 Steadfast：把着色器参数在**宿主语言侧**预编译成 uniform

- `src/java/` 下有 `NoiseWave.java`、`Caustic.java` 等生成器，波/焦散参数在 Java 侧预编译成 uniform 常量（C-报告 §问⑦）。配合 `generators/`、`pipeline/`、`build.sh`，Steadfast 用生成器脚本 + 源码模板产出 `shaders/`。

#### 3.7.4 I-Like-Vanilla 与 MakeUp Ultra Fast：风格化与“小模块”两种路线

### 4.5 Pass 与程序调度

**这一条是本报告里最容易"凭名称臆断"的地方，因此只写有源码证据的部分。**

- **整段 pass 靠 properties 的 `program.<name>.enabled` 关闭，不是运行时 `if`**：
  - Photon `shaders.properties`：`program.world0/composite5..18.enabled = BLOOM`、`composite21 = FXAA`、`composite3 = TAAU`、`composite20 = MOTION_BLUR`、`setup/shadowcomp = COLORED_LIGHTS`、`deferred4_a = SH_SKYLIGHT`（[A]）。
  - Astra `shaders.properties` 有 **129 处** `program.` 行（`grep -c`），含 `program.composite6/7/8/10/11.enabled`、`prepare3`、`world-1/deferred2`、`world1/deferred1`、`composite1`、`prepare4` 等多组三维度同时开关的条目（[A]）。
- **Astra 在下界显式关掉 9 个 compute 阶段并留了实测注释**（`shaders.properties:902-911`），理由是不这样写会**空派发 512 个工作组写入无人配置的 image**（F-报告 §3.6.3）。这是"Pass 调度优化"的真实案例，而且是外部包没有的维度。

### 4.5.1 补充发现：Iris 的 `clrwl_` 程序族（"一个程序承担多个 vanilla 程序名"）

**计数**（`find <pack>/shaders -name 'clrwl_*' | wc -l`）：

| 包 | `clrwl_` 文件数 |
|---|---|
| renderpearl | **66** |
| Photon | **30** |
| Complementary Reimagined | **24** |
| mellow | **20** |
| **Astra** | **0** |
| Bliss | 0 |

**机制**（读 Photon 原文）：`photon-main/shaders/world1/clrwl_gbuffers.fsh` **全文只有 8 行**，同时定义 `PROGRAM_GBUFFERS_TERRAIN` + `PROGRAM_GBUFFERS_BLOCK` + `PROGRAM_GBUFFERS_ENTITIES` + `COLORWHEEL`，然后 include 同一份 `/program/gbuffers_all_solid.fsh`。也就是**一个 Iris 程序同时承担多个 vanilla 程序名**，几何着色只写一份，材质分派从"编译期宏"变成"运行时 ID"。renderpearl 是极端案例：`prog/` 只有 7 个文件，整个几何阶段只有 3 个片段程序（`lit` / `unlit` / `none`）。

**Astra 现状**：root 层 **23 个 `gbuffers_*.fsh`**，`world1/` 另有 36 个 `.fsh` + 36 个 `.vsh`；全仓库检索 `clrwl` **命中 0**。

**能确定 / 不能确定**：
- **能确定**：程序数量与重复度是可数的静态事实（23 个 gbuffers 入口 vs renderpearl 的 3 个几何片段程序）。
- **不能确定**：**编译时间与运行收益都没有实测**；`clrwl` 的 Iris 版本门槛**本轮未核实**；迁移会改变材质分派方式，属架构改动。

**证据等级：B。推荐结论：值得深入研究（但在意的是"光影包加载/编译时间"，不是帧时间）。** 如果用户在意加载慢，这是目前唯一找到的成规模外部先例。**不得**写成"能提升 FPS"。

### 4.8 其他经源码证实的优化

- **prefiltered 环境图代替解析天空**：Astra `colortex11` 每帧预滤波（`program/sky_reflection_cache.fsh:14-30` 含云透射率 A 通道），消费端按粗糙度选 LOD（`lib/sky_reflection_cache.glsl:53-70`）。对比 Photon 的 `bicubic_filter(colortex4, project_sky(ray_dir))`（16 次纹元读取）：**Astra 用一次 `textureLod` 换掉了每像素 16 次读取**，代价是每帧一张 128×64 或 256×128 的预滤波 pass。**[A]**
- **同一效果按消费者分组给不同参数**（非性能项，但影响"要不要多算一遍"）：CR 的 `ground and cloud color` 与 `light shaft color` 是两个常量（`lightAndAmbientColors.glsl:6-9`）。Astra 目前只用一套直射光色。
- **子组内去重把 N 次原子操作压成 1 次**：renderpearl `lib/sg_incr.glsl`（`subgroupElect` + `atomicAdd(counter, sg_size)` + `subgroupBroadcastFirst`）。**前提：需要 `GL_KHR_shader_subgroup` 类扩展**，Astra 目前无使用，移植前必须核实 Iris 版本与驱动。**[A（外部源码）/ C（Astra 适用性）]**

### 5.3 已经实现、但确实存在改进空间的能力

**这一类每一条都必须是"Astra 已实现 + 能指明真实差异"，不允许写成"缺失"。**

1. **TAA 缺少二阶矩方差裁剪**（[A]）：Astra 已有 min/max 包围盒 + 有界衰减 + 逐角深度拒绝（`taa_resolve.fsh:150-169`），但没有 Photon `c4_taa_exposure.fsh:217-234` 那条"9 邻域一阶/二阶矩 + `gamma = mix(0.75,1.25,linear_step(0.25,1.0,distance_factor))`"的方差裁剪。**成本：复用已有的 9 邻域样本，不新增采样。** 风险：`gamma` 调不好会拖影；且只在 `ANTIALIASING==2` 时生效。
   > `taa_resolve.fsh:167` 的注释写着 "SUMMARY idea (Photon/Kappa/Mellow)"——**Astra 已经主动比对过这些包**，本条是"补一套"，不是"发现缺口"。
2. **AO 缺少多弹射近似**（[A 级对照]）：`program/ssao.fsh:125` 之后加 `ao /= albedo*ao + (1-albedo)` 即可，**1 次乘加 + 1 次除法**。但 Astra 的 `visibility` 已 clamp 到 `[0.25,1]`，需同时调 `AO_STRENGTH` 补偿。
3. **云缺少多重散射级数**（[B]）：Photon `cumulus.glsl:164-185` 是零纹理采样的纯代数迭代。**先要确认 Astra 的云在当前配置下是否已通过别的方式补了能量**（B-报告 §问题 4 未查完，标为待确认）。
4. **半影不随云影变化**（[B]）：Astra 的 `spread` 只由 `SHADOW_SOFTNESS` 与世界纹元宽度决定（`diffuse.glsl:311-327`），云影只乘强度（`program/scene.glsl:379-382`）。**需要改两处**（传入云透射率 + 放宽 `spread` 上界）。
5. **体积光束的最坏路径取样数**（[未验证]）：7 区间 × 4 高斯节点 = 28 个可见度节点，每节点 8 点波场积分 → 最坏 224 次 colortex29 读取。**早退命中率未知**，必须先量出 underwater 场景里有多少像素真走到最坏路径。
6. **自动曝光已实现但默认关闭，且源码自述中灰标定未验证**（[A]）：见候选 13。`lib/settings.glsl:256` 注释掉 `AUTO_EXPOSURE`；`global/post/exposure.glsl:47-48` 原文 "UNVERIFIED: needs an in-game check that an ordinary daylight frame settles near gain 1.0"。**这是"已实现但可改进"的典型：不是缺功能，是缺一次验证。**
7. **硬编码阈值未做成设置**（[候选]）：`program/water.glsl:1012` 的 0.36/0.50 门限、`refraction.glsl:101` 的 32 格上限、`program/water.glsl:1211` 的 24 格深水回退。

### 5.4 尚未实现且有明确价值的技术

**只有三条能进这一类，其余都在"待确认"或"不适合"。**

1. **云的多重散射级数**：零纹理采样，机制清楚，视觉收益明确（云底不再死黑）。**[B]**
2. **阴影半影随云影变化**：物理依据清楚（阴天光源从太阳变成整个天穹）。**[B]**（需改两处）
3. **AO 多弹射近似**：成本极低。**[A 级对照，B 级收益]**

> **"屏幕空间接触阴影 SSRT"没有被列入这一类**——它的硬前提（必须有 TAA 抹噪点，而 Astra 的 TAA 默认关闭，`lib/settings.glsl:287` `ANTIALIASING` 默认 1）使它更适合放在"待确认"。

### 候选 1：tonemap 之后的分色相二次校正层

**技术名称：** HSL 分色相饱和度校正（橙色 / 青色 / 绿色三通道隔离）+ 感知域往返

**外部参考：** Photon `main` @ `57d46781627ee69c005c0d6499b3825cd05d267a`，`shaders/program/c19_color_grading.fsh:97-128`（`grade_output`）。上游出处：注释原文 "HSL color grading inspired by Tech's color grading setup in Lux Shaders"（`:101`）——**这不是 Photon 原创，是 Lux/Tech 的调色setup**。

**核心原理：** 先把线性 rec.709 色彩做 `sqrt` 进入近似感知域，转 HSL，用 `isolate_hue(hsl, 中心角, 半宽)` 分别隔离橙（30°±20）、青（210°±20）、绿（90°±44）三个色相带，只对这三个带的**饱和度**（`hsl.y`）乘增益，绿色还可平移**色相**（`hsl.x`）。然后 `gain(rgb, 1.05)` 做一条轻 S 曲线，最后 `sqr` 回线性。**关键点：饱和度只在选定色相带内改变，肤色/植被/天空各自独立。**

**Astra 当前状态：** **部分已有，缺这一层。** `global/post/grading.glsl` 是单层链：`apply_color_temperature`（`:162-173`）→ vibrance+saturation 合并增益（`:221-234`）→ `apply_contrast`（`:244-246`）→ `apply_tonal_balance`（三段亮度，`:201-211`）→ clamp。**全是全局旋钮，没有按色相选择的能力。** `lib/tonemap.glsl` 提供 AgX/ACES/Uchimura/Reinhard-Jodie 算子切换。

**拟改进位置：** `Astra/shaders/global/post/grading.glsl` 的 `apply_grading()`（`:213-250`）末尾、`clamp` 之前插入一层；新增选项常量放在同文件顶部（与 `GRADING_TINT_WARM/COOL`（`:87-88`）并列）；调用链见 `program/display.fsh` 的显示变换段。

**预期视觉价值：** 只强化"橙（日落/火把）+ 青（水面/阴影）"这对互补色而不动绿色植被——这是"电影感"最常见的来源。**同时保持现有全局饱和度控制不变**（新增层默认增益为 1.0）。

**性能影响：** [源码推断] 每像素新增一次 rgb↔hsl 往返 + 三次色相隔离（各含少量 mix/smoothstep）+ 一次 `gain`。**没有新增纹理采样、没有新增 pass。** Photon 把它放在 c19 里，与它同档。**不是"减少 GPU 工作"的优化，是纯视觉项。**

**副作用和风险：**
- HSL 往返引入的轻微色偏（Photon 用 `sqrt`/`sqr` 感知域往返正是为了压制）。
- `clamp(color, 0, 1)` 已在 `apply_grading` 末尾（`:248`），新增层若改变饱和可能让部分像素先触顶，需把 clamp 放在新层之后。
- 与 `DEBUG_DISABLE_COLOR_GRADE`（`:214-218`）的旁路语义要一致。

**实施难度：** **低。** 唯二难点：一是确定三个色相带的中心角与半宽（Photon 的选择是给 Minecraft 调的，不一定适合 Astra 的美术方向）；二是决定默认值（建议全部默认"关闭"，让用户 A/B）。

**依赖条件：** 无。不需要新缓冲、新 pass、新配置项结构（现有 `settings.glsl` 常量表足够）。

**证据等级：** **A**（外部实现逐行已读；Astra 现状逐行已读；对照点明确）。

**推荐结论：** **优先尝试。** 这是本次调研中"视觉收益明确、风险最低、无架构影响"的一条。

### 候选 2：云的多重散射级数（代数迭代，零纹理采样）

**技术名称：** 云内多次散射的几何级数近似

**外部参考：** Photon `include/sky/clouds/cumulus.glsl:135-188`（`clouds_cumulus_scattering`），核心循环 `:164-185`；同族写法也见于 `include/fog/water_fog_vl.glsl:125-142`（4 次迭代）。

**核心原理：** 不做额外的光线步进，而是对同一步内的散射项做**等比衰减的级数求和**：每轮把散射按 `scattering_amount *= 0.5` 累加、把各向异性 `anisotropy *= 0.5`（相位函数逐渐趋于各向同性）、把透射率开方（`sqrt`）让后续轮次"衰减变慢"。8 轮后叠加出"光在云里被多次散射"的能量，主要效果是**云底与厚云内部不再死黑**。

**Astra 当前状态：** **待确认。** B-报告 §问题 4 未把 Astra 云光照的完整实现查完（只读到 `clouds_planar.glsl` 的段积分与光照项），**因此不能断言"Astra 完全没有"**。Astra 已有 `colortex12` 云低频谱表（65²/129²/257²）与 `colortex24/25` 云历史，可能已有别的能量补偿方式。

**拟改进位置：** 待确认后定位——云光照在 `Astra/shaders/global/atmosphere/clouds_planar.glsl` 的散射累加段（与 `:325-353` 段积分相邻）。

**预期视觉价值：** 云底与厚云内部的能量层次；这是"云看起来有体积"而不是"一块亮斑"的关键之一。

**性能影响：** [源码推断] Photon 是 8 次迭代 ×（4 个 `exp()` + 3 个 HG）**零纹理采样、零额外步进**。量级约等于一次密度采样。**新增成本存在于每一条命中云的射线上**，因此与云覆盖率成正比。

**副作用和风险：** 迭代次数是艺术参数，过多会让云变成"发光的棉花"；Astra 的云是**段积分**结构，级数实现要嵌入段内而不是步内，需要重新设计而不是照抄。

**实施难度：** **中。** 难点不在数学，而在与 Astra 段积分结构的耦合。

**依赖条件：** 需要先完成"Astra 云光照现状核实"（见第八部分待核实清单）。

**证据等级：** **B**（外部已验证，Astra 侧待确认）。

**推荐结论：** **值得深入研究**（先做现状核实，再决定）。

### 候选 3：阴影半影宽度随云影（云透射率）变化

**技术名称：** 阴天半影展宽

**外部参考：** Photon `include/lighting/shadows/pcss.glsl:245-252`：`penumbra *= 5.0 - 4.0 * cloud_shadows;`。**注意源码注释只给了艺术理由（"nice overcast look"），没有物理推导。**

**核心原理：** 晴天时太阳是点光源（角直径约 0.53°），阴影边缘锐利；阴天时太阳被云遮挡，有效光源变成**整个天穹的面光源**，半影在物理上就应该更宽更软。用云透射率（0=全遮挡，1=无云）线性插值半影倍率。

**Astra 当前状态：** **已有实现但无此联动。** 云影已经算出并用于**强度**：`program/scene.glsl:379-382` 云影只乘 `params.directLightSurface`。半影宽度由 `global/lighting/diffuse.glsl:311-327` 的 `spread` 决定，只与 `SHADOW_SOFTNESS` 和世界纹元宽度有关，**两者不相交**。

**拟改进位置：**
1. `global/lighting/diffuse.glsl:286` 的 `surface_shadow_light()` **签名**（当前只有 playerPos/shadowPos/skyLight 三个参数）——需把云透射率从调用方传入；
2. `diffuse.glsl:311-327` 的 `spread` 计算——**且必须同时放宽 `:327` 的 `clamp(softRadius/worldTexel, 0.5*spread, spread)` 上界**，否则放大 `spread` 会被夹掉。

**预期视觉价值：** 阴天/雨天时阴影更柔和，与"光线被云散射"的直觉一致；这是"画面在不同天气下显得可信"的一个细节。

**性能影响：** [源码推断] 若只放大 `spread`，采样次数不变（Astra 是固定 4 lobe × 2 gather）；若同时让步数随半影变化，则回到候选 6 的结构冲突问题。**建议只改宽度，不改采样数**，此时**性能影响接近零**（多一次乘法）。

**副作用和风险：**
- 放宽 `spread` 上界会同时影响**所有**阴影（不再只是阴天），需要保证在云影=1 时行为与现在完全一致。
- 展宽后 4 lobe 的固定采样会在更大范围内取点，可能出现采样不足的条带——**这是主要风险**，需要实测。

**实施难度：** **中**（签名改动 + 两处逻辑 + 回归测试）。

**依赖条件：** 云透射率已经存在（`global/atmosphere/weather.glsl:131` 的 `astra_cloud_transmission`），无需新缓冲。

**证据等级：** **B**。

**推荐结论：** **值得深入研究。**

### 候选 4：AO 的多弹射近似（成本最低的一条）

**技术名称：** AO 多弹射能量补偿

**外部参考：** Photon `include/lighting/ao/gtao.glsl:156-160`：
```glsl
const float albedo = 0.2;
ao /= albedo * ao + (1.0 - albedo);
```

**核心原理：** 单次追踪得到的 AO 只算了"一次遮挡"，把所有暗部压得过黑。这条公式把 AO 视作"一次弹射后的余量"，用固定的反照率把多次弹射的能量加回去，结果是暗部变亮、AO 曲线变平。**它不产生任何新的遮蔽信息，只改变映射曲线。**

**Astra 当前状态：** **已有 AO（12 次采样 + 2×2 双边重建 + bent normal 参与 SH 重估），无此补偿。** 落点 `program/ssao.fsh:125` 的 `visibility` 计算之后。

**拟改进位置：** `Astra/shaders/program/ssao.fsh:125` 附近；若 AO 重建在 `lib/ao_resolve.glsl`，需确认补偿应放在**生产端还是重建端**（放在生产端更省，因为重建端是 2×2 上采样，会重复计算 4 次）。

**预期视觉价值：** 角落不再死黑，AO 曲线更平缓。这是"暗部有层次"的典型来源。

**性能影响：** [源码推断] **1 次乘加 + 1 次除法，零采样，零新 pass。** 如果放在重建端，成本 ×4（每像素 4 个邻域样本各算一次）；**建议放生产端**。

**副作用和风险：** Astra 的 `visibility` 已被 clamp 到 `[0.25, 1]`（`ssao.fsh:125`），该修正会进一步收窄值域，**可能让 AO 弱到看不见**，需要同时调 `AO_STRENGTH` 补偿。**因此不能只加这一行就交差。**

**实施难度：** **低**（但需要一次视觉回归）。

**依赖条件：** 无。

**证据等级：** **A**（外部实现与 Astra 落点都已逐行核对）；**收益为 B**（机制合理，量级未验证）。

**推荐结论：** **优先尝试**（若同时调整 `AO_STRENGTH` 并做 A/B）。

### 候选 5：TAA 的二阶矩方差裁剪

**技术名称：** 9 邻域一阶/二阶矩方差裁剪（variance clipping）

**外部参考：** Photon `program/c4_taa_exposure.fsh:217-234`，注释自述出处 "An Excursion in Temporal Supersampling"；同文件 `:205-215` 是软 min/max（"Hybrid Reconstruction Antialiasing"）、`:236-241` 是 YCoCg AABB（clip_aabb 注明来自 "INSIDE" 论文）。

**核心原理：** 用当前像素 3×3 邻域的一阶矩（均值）与二阶矩（平方均值）算出标准差 σ，把历史颜色钳制在 `mean ± gamma·σ`。Photon 的 `gamma = mix(0.75, 1.25, linear_step(0.25, 1.0, distance_factor))`——**距离越近 gamma 越小（越激进地裁剪、越不拖影），越远越宽容（越稳）**。注释自述 gamma 越大越稳但拖影越多。

**Astra 当前状态：** **部分已有。** `program/taa_resolve.fsh:150-165` 已有"颜色统计只约束被接受的历史" + `clamp(historyColor, lo, hi)`，用 3×3 的 **min/max 包围盒**与**相对亮度**统计（`:144-146`），外加 `taa_reactive_neighbourhood`（`:34-52`）、按运动长度衰减（`:166`）、双线性历史 + 逐角深度拒绝（`:169`）。**缺的是基于 σ 的那一套。**

**拟改进位置：** `Astra/shaders/program/taa_resolve.fsh` 的历史钳制段（`:150-165`）。

**预期视觉价值：** 高对比边缘处的鬼影/闪烁抑制更精确（min/max 包围盒在窄边上的约束过松）。**这是"稳定性"而非"画质清晰度"的改善。**

**性能影响：** [源码推断] **复用已有的 9 邻域样本**（Astra 已经在算 3×3 统计），只是把一阶矩换成"一阶矩 + 二阶矩"。**不新增采样。** 新增几条 ALU。

**副作用和风险：** `gamma` 调不好会拖影；TAA 只在 `ANTIALIASING == 2` 时启用（`lib/settings.glsl:287` 默认 1），**收益人群有限**。

**实施难度：** **低。**

**依赖条件：** 无。

**证据等级：** **A。**

**推荐结论：** **优先尝试**（前提是接受"只在 TAA 档生效"）。

### 候选 6：blocker search → 可变半影（含结构冲突说明）

**技术名称：** 基于遮挡物距离的可变半影（PCSS 的 blocker search 部分）

**外部参考：** Photon `include/lighting/shadows/pcss.glsl:29-62`（搜索）、`:245-252`（半影公式）、`:104-111`（可变步数）。

**核心原理：** 在阴影图上用少量采样（Vogel 盘 3 步，SSS 材质 12 步）估计该像素周围遮挡物的**平均深度**，用"接收面深度 − 遮挡物深度"除以遮挡物深度得到半影大小，再把半影换算成 PCF 的采样步数。结果是贴着地面的阴影锐利、高柱子投到地面的阴影柔和。

**Astra 当前状态：** **没有。** Astra 的半影宽度是用户设定的常数（`diffuse.glsl:311-327` 的 `spread`，只由 `SHADOW_SOFTNESS` 与世界纹元宽度决定）。

**拟改进位置：** `global/lighting/shadowmap.glsl` 的采样结构 + `global/lighting/diffuse.glsl:286-346`。

**预期视觉价值：** 半影宽度真实变化，是"阴影看起来真实"的核心之一。

**性能影响（[源码推断]，含算术）：**
- 原方案（Astra 默认档）：`lobeCount = 4` × 2 次 gather（shadowtex1 + shadowtex0）= **8 次纹理操作 = 32 次纹元比较**。
- 若用 Photon 结构替换：blocker search **+3 次 `texelFetch`** + PCF 6~12 次 = **9 次（+12%）**；SSS 材质 3+12 = **15 次（+87%）**。
- 若在 Astra 现有逐角结构上**叠加**：3 + 8 = **11 次（+37%）**，收益只有半影宽度。

**副作用和风险（这是关键）：**
> Photon 的 VPS 用**单一**参考深度 `shadow_screen_pos.z` 做全部比较。Astra 的**逐角参考深度**（`shadowmap.glsl:206-227`）恰恰是它优于 Photon 的地方，直接套用 VPS 会把这份优势丢掉；若保留逐角参考深度，PCF 循环每步都要重算 4 个参考深度（4 次平面外推），成本翻倍。**两者不能简单叠加，属架构冲突。**

**实施难度：** **高**（要重新设计"逐角参考深度"与"变半径 PCF"的共存方式，不是移植而是重构）。

**依赖条件：** 需要先决定是否接受"放弃逐角参考深度"。

**证据等级：** **A**（含明确的结构冲突判定）。

**推荐结论：** **暂缓。** 先做候选 3（只改宽度、不改采样数），如果半影展宽的效果已经足够，就不必付这个架构代价。

### 候选 7：让直射光色与天空色共享同一个大气函数

**技术名称：** 大气透射率驱动的光色（统一色彩体系）

**外部参考：** Photon `include/lighting/colors/light_color.glsl:62-77` + `include/sky/atmosphere.glsl`。

**核心原理：** 直射光颜色不再是独立的常量/曲线，而是**太阳光谱乘上大气透射率函数**——与天空颜色使用同一个函数。黄昏时天空变红、直射光同时变红，是同一个函数在"视线方向"和"太阳方向"上的两个取值。另有显式的**蓝调时刻窄带**：`blue_hour = linear_step(0.05, 1.0, exp(-190.0*sqr(sun_dir.y + 0.09604)))`（见源码 `:13-19`），只在太阳高度角约 −5.5° 附近触发，此时曝光 ×40、色温偏蓝紫。

**Astra 当前状态：** **采用不同方案。** Astra 的天空色与直射光色分别维护（`global/atmosphere/sky_*.glsl` 与 `global/lighting/diffuse.glsl` 的 `LightParams`），靠人工对齐。**未确认 Astra 的 `lib/twilight.glsl` 是否有等价的高度角窄带事件**（见第八部分）。

**拟改进位置：** 属**架构级**改动，涉及 `global/lighting/diffuse.glsl` 的光色来源与 `global/atmosphere/` 的多处。

**预期视觉价值：** 日出/日落/蓝调时刻的色彩一致性自动成立，而不是靠人工调两处对齐。**这是"为什么优秀光影看起来更协调"的最直接机制。**

**性能影响：** [源码推断] 取决于 Astra 现有大气函数的成本。Photon 的做法是每次求光色时多调一次大气透射率（若 LUT 已缓存，增量很小；若解析求，增量明显）。**需要在 Astra 上具体评估，不能照搬结论。**

**副作用和风险：** **所有依赖光色的效果都会变**（阴影冷暖、方块光混合、水色、云光、体积光束）。这是全画面级改动，**会改变 Astra 现有视觉风格**，必须用户决策。

**实施难度：** **高**（架构级 + 视觉风格风险）。

**依赖条件：** 需要先确认 Astra 现有大气函数是否有可复用的透射率接口。

**证据等级：** **B**（外部 A 级；Astra 侧只确认了"分别维护"这一事实，未评估改造可行性）。

**推荐结论：** **暂缓**（价值高但风险高、属架构级；建议作为一次独立的"色彩体系"专项，而不是与其它候选混做）。若要推进，第一步是只读对照实验：不改 Astra，先在纸面上算清 Photon 的 `get_light_color()` 在 Astra 的太阳高度角范围内会给出什么颜色序列。

### 候选 8：按"消费者物理性质"分组的光色（地面 / 云 / 体积光束）

**技术名称：** 光束色与地面光色分离

**外部参考：** Complementary Reimagined `lib/colors/lightAndAmbientColors.glsl:6-9`（`#ifndef COMPOSITE1` 用暖白 `(0.65,0.55,0.375)*2.05` 给 "ground and cloud"；`#else` 用青蓝 `(0.4,0.75,1.3)` 给 "light shaft"）。

**核心原理：** 同一个时刻，**体积光束**是散射主导（瑞利散射偏蓝），**地面**是透射主导（偏暖）。用两个独立常量而不是一套光色，可以让光束明显偏蓝而不让地面变蓝。

**Astra 当前状态：** **已有实现但共用一套颜色。** `global/post/godrays.glsl` 与 `global/water/light_shafts.glsl` 使用与地面相同的直射光色。

**拟改进位置：** `Astra/shaders/global/post/godrays.glsl`、`global/water/light_shafts.glsl` 的入射光色取值处。

**预期视觉价值：** 光束的"青蓝感"与地面的"暖金感"同时成立，不需要用全局色温折中。

**性能影响：** [源码推断] **若只是把已有的入射光换成另一个常量，成本为零**（同一份数据换一个系数）。若要做成"随时间/天气变化的第二条曲线"，则需要多一份求值。

**副作用和风险：** 低估时看不出效果，高估时光束会"发蓝发光"；需要与雾/大气保持一致。

**实施难度：** **低。**

**依赖条件：** 无。

**证据等级：** **A。**

**推荐结论：** **优先尝试**（低风险、可 A/B）。

### 候选 9：把云覆盖率并入已有的 colortex14（数据流优化，非新增缓冲）

**技术名称：** 云影 + 覆盖率合并到同一张低频图

**外部参考：** Photon `program/p0_clouds_prep.fsh:100-109` + `shaders.properties:317`（一张 512² RGB8 同时存云影 `xy` 与覆盖率 `z`）。

**核心原理：** 云影图与覆盖率图都是"云密度按高度层投影到 XZ 平面"的低频结果，天然可以同图不同通道。

**Astra 当前状态：** **已有 colortex14 存云影透射率**（`program/cloud_shadow_cache.fsh`，R16，128²/256²）。**没有覆盖率通道。**

**拟改进位置：** `Astra/shaders/program/cloud_shadow_cache.fsh` + `global/atmosphere/cloud_shadow_cache.glsl` + `global/atmosphere/clouds_planar.glsl:93-97`（密度采样点）。

**预期视觉价值：** **零**（这是纯性能候选）。

**性能影响：** [源码推断] Astra 的密度查询只有 **1 次纹理采样 + 一次取整坐标计算**（`clouds_planar.glsl:93-97`）。若改用覆盖率图，**省的是这一次采样的一部分 ALU**（Photon 那边省的是 2 次采样 + 两套分支，收益比 Astra 高一倍以上）。**收益上限很低**，且覆盖率图本身的投影计算要按云密度查询次数摊销。另外要把 colortex14 从 `R16` 换成至少 `RG16`（多一个通道 = 多一份带宽）。

**副作用和风险：** 改变 colortex14 的格式与写入端，会影响云影缓存的边缘回退逻辑（`cloud_shadow_cache.glsl:34-43`）。**收益与风险不成比例。**

**实施难度：** **中。**

**依赖条件：** 无。

**证据等级：** **A**（双方源码都已核对）。

**推荐结论：** **无需采用**（除非将来云密度查询次数显著增加；当前只有 1 次采样，不值得）。

### 候选 10：屏幕空间接触阴影（SSRT）

**技术名称：** 阴影距离外的屏幕空间接触阴影

**外部参考：** Photon `include/lighting/shadows/ssrt.glsl:9-107`，调用点 `program/d4_deferred_shading.fsh:504-520`。

**核心原理：** 对阴影距离之外的像素，沿太阳方向在深度缓冲里做屏幕空间步进，找到局部遮挡就压暗。Photon **只**用它替代阴影距离外的假阴影，不用于近处。

**Astra 当前状态：** **没有。** Astra 的距离外走 `static_shadow(skyLight)`（`shadowmap.glsl:417`），是纯光图查表。Astra 的 AO 是半球遮蔽（不知道光方向），**不能替代**。

**拟改进位置：** `Astra/shaders/global/lighting/diffuse.glsl:286-298` 的回退路径。

**预期视觉价值：** 阴影距离外（默认 96 格，`lib/settings.glsl:82`）的物体不再"假装有阴影"，近处几何的自遮挡更自然。

**性能影响：** [源码推断] 10 次 `texelFetch` + 10 次逆投影，每像素；Photon 只在 `shadow_distance_fade > 0` 的像素上执行。Astra 若加需要同样的门控。

**副作用和风险（硬前提）：** **需要 TAA 抹噪点。** Astra 的 `ANTIALIASING` 默认 1（无 TAA），**无 TAA 配置下 SSRT 会明显噪**。这是移植的硬约束。

**实施难度：** **中**（步进本身不难，难在无 TAA 时的噪点与"屏幕边缘无信息"的处理）。

**依赖条件：** TAA（`ANTIALIASING == 2`）或另一套降噪手段。

**证据等级：** **B。**

**推荐结论：** **暂缓**（前提条件在 Astra 的默认配置下不成立）。

### 候选 12：30 个 colortex 的生产者—消费者—生命周期台账（调研任务）

**外部参考：** 不适用（这是 Astra 自身的工程任务）。

**Astra 当前状态：** **30 个 distinct colortex 引用**（`shaders.properties` 中的 `colortex1..31`，去掉 0 与 4），**62 条 `size.buffer`**（多数是同一 buffer 按画质档写不同尺寸的 `#if/#else`）。对照：Photon 9、CR 6、Bliss 6、mellow 4。**但没有任何一个 buffer 做过生产者→消费者核对。**

**副作用和风险：** 台账本身可能发现"某个 buffer 只在某档写入"之类的可清理项，**但也可能发现全部都有活跃消费者**——两种情况都是有效结论。

### 候选 13：自动曝光的默认开关与中灰标定验证

**技术名称：** 自动曝光的标定验证（不是新实现）

**外部参考：** Photon `program/c4_taa_exposure.vsh:35-46`（EV100 标定，K=12.5 / ISO100 / 1.2）、`:139-171`（SIMPLE 取 mip 一纹元 / HISTOGRAM 32 桶中位数、NaN/Inf 回退、变速 2.0/1.0、`exp(-rate*frameTime)` 帧率无关）；Bliss `lib/settings.glsl:584` 默认开，并用 `pow(exposure.a, 0.2)` 调制泛光（`composite11.fsh:138,141`）；Photon 与 mellow 默认固定曝光。

**核心原理：** 用场景亮度测量驱动曝光增益，使画面在洞穴/夜晚/水下不会过暗或过亮。

**Astra 当前状态：** **已完整实现，但默认关闭，且源码自述标定未验证。**
- 实现：`global/post/exposure.glsl:36-69`（8×8 = 64 点加权几何平均、`AE_KEY 0.18`、增益界 0.60..2.20、单点上限 4.0、速率 2.5/0.5 每秒、log 域平滑 + snap、合法性标志、**水下冻结历史** `:122-126`）。
- 默认：`lib/settings.glsl:256` `//#define AUTO_EXPOSURE`（注释掉 = 关），`:254` `EXPOSURE 100`。
- 门控：`shaders.properties:54-57`（`colortex10 = 1 1`）与 `:366-370`（`program.composite5.enabled = AUTO_EXPOSURE`，只在地表启用）。
- **关键：** `exposure.glsl:47-48` 原文 "UNVERIFIED: needs an in-game check that an ordinary daylight frame settles near gain 1.0"。

**拟改进位置：** 不改代码；需要一次**游戏内验证**——确认普通白天画面的增益稳定在 1.0 附近（否则开启后整幅画面的亮度基线会偏移）。

**预期视觉价值：** 若能开启且标定正确，进出洞穴/水下/夜晚的亮度过渡会更自然。

**性能影响：** [源码推断] Astra 测光 = 一个 1×1 pass + 64 次 `texelFetch`（由 `program.composite5.enabled` 门控，只在 AUTO_EXPOSURE 开启时执行）。**相对 Photon 的 SIMPLE 档（一次 mip 采样）更贵，相对 HISTOGRAM 档（32 桶）量级相近。** 具体到帧时间的影响**未测量**。

**副作用和风险：** 标定不准会让**整幅画面的亮度基线偏移**（这是全局效果，比任何局部效果都更显眼）；另有"自动曝光在快速明暗切换时呼吸"的常见问题（Astra 用 log 域平滑 + snap 应对，但 `snap` 行为未验证观感）。

**实施难度：** **低（验证）** / **中（若需重新标定）**。风险全在"验证不通过"这一侧。

**依赖条件：** 需要一次游戏内检查（不是代码改动）。

**证据等级：** **A**（双方源码都已逐行核对；结论是"实现存在但标定未验证"）。

**推荐结论：** **值得深入研究**（先做验证，**在验证通过前不建议开启默认**）。

## 第七部分：优先级与后续开发路线

### 7.1 优先级划分

**划分依据是 Astra 当前实际情况（源码事实 + 现有架构 + 用户已确认的美术方向），不是外部项目"高级程度"。**

#### P0：高价值、低风险，或能直接消除明显冗余

| 序 | 项目 | 为什么是 P0 | 证据 |
|---|---|---|---|
| P0-1 | **AO 多弹射近似**（候选 4） | 1 次乘加 + 1 次除法，零新采样、零新 pass。属于"消除死黑"这类没有争议的改进 | A（对照） |
| P0-2 | **光束色与地面光色分组**（候选 8） | 把已有的入射光换成另一个常量，成本为零，可 A/B，不动管线 | A |
| P0-3 | **TAA 二阶矩方差裁剪**（候选 5） | 复用已有的 9 邻域统计，不新增采样；Astra 的注释显示它已主动比对过 Photon | A |
| P0-4 | **colortex 生产者—消费者—生命周期台账**（候选 12） | 纯盘点、零代码改动。**必须在任何"合并 buffer / 删除 pass"的设想之前完成** | A（数量）/ 结论待做 |

> P0-1 与 P0-3 都需要一次视觉回归（P0-1 要同时调 `AO_STRENGTH`，P0-3 只在 TAA 档生效）。P0 不等于"改一行就行"，而是"风险可控、收益可判断"。

#### P1：视觉收益明显、工程上可行，或性能改进潜力较大

| 序 | 项目 | 为什么是 P1 | 前置 |
|---|---|---|---|
| P1-1 | **tonemap 后分色相二次校正**（候选 1） | 视觉收益明确、无架构影响、无新缓冲。**本报告最推荐的视觉项** | 需确定三个色相带的中心角与半宽 |
| P1-2 | **阴影半影随云影展宽**（候选 3） | 物理依据清楚、性能影响接近零（只改宽度不改采样数） | 需改 `surface_shadow_light()` 签名 + 放宽 `spread` 上界 |
| P1-3 | **云的多重散射级数**（候选 2） | 零纹理采样的纯代数迭代，视觉收益明确 | **必须先核实 Astra 云光照现状**（见 8.2） |
| P1-4 | **水下体积光束的最坏路径核实**（5.3 第 5 条） | 若确认最坏路径（28×8 次 colortex29 读取）真的会发生，这是本报告里唯一有明确"减少工作量"依据的性能项 | 需要运行时统计早退命中率 |

#### P2：值得研究但需要架构调整、存在质量风险或收益不确定

| 序 | 项目 | 为什么是 P2 |
|---|---|---|
| P2-1 | **blocker search → 可变半影**（候选 6） | 与 Astra 的逐角参考深度**结构冲突**，不是移植而是重构 |
| P2-2 | **SSRT 屏幕空间接触阴影**（候选 10） | 硬前提是有 TAA 降噪，而 Astra 的 TAA 默认关闭 |
| P2-3 | **让直射光色与天空色共享大气函数**（候选 7） | 架构级、全画面级视觉风格改变，需要用户决策 |
| P2-4 | **下界体积雾复活**（F-报告 F-1） | 视觉收益明确，但属**新增效果**（当前下界零 raymarch），需用户点头；且退役文件 :9-13 已警告"与齐次雾叠加会二次吸收" |

#### P3：代价过高、与 Astra 方向冲突、缺乏充分证据或现阶段不值得实施

| 序 | 项目 | 理由 |
|---|---|---|
| P3-1 | **LabPBR 材质接入** | 架构决策而非优化项；会改变材质语义与美术方向；Astra 走方块 ID 路线（`block.properties`） |
| P3-2 | **CR 体素世界空间反射** | 需要几何体素化 + 额外显存；Astra 现有 64³ 体积只服务下界光照 |
| P3-3 | **末地低成本涡旋回退档** | 与 Astra 既定美术方向（真实天文观感的大型黑洞）冲突 |
| P3-4 | **按帧时间自适应降档**（候选 11） | **无外部先例**；Iris 侧计时能力未核实；画质波动风险 |
| P3-5 | **云覆盖率并入 colortex14**（候选 9） | 收益上限是"每次密度查询省一部分 ALU"，而 Astra 的密度查询只有 1 次采样；且要改 colortex14 格式 |

### 7.2 建议的推进顺序与依赖关系

```
[第 0 步] colortex 台账（P0-4）
    │  零代码改动，产出事实清单
    ▼
[第 1 步] 三项互相独立、可并行的低风险项
    ├── AO 多弹射近似（P0-1）
    ├── 光束色分组（P0-2）
    └── TAA 二阶矩方差裁剪（P0-3）
    │
    ▼
[第 2 步] 视觉专项（互相独立）
    ├── 分色相二次校正（P1-1）← 需要先决定色相带参数
    └── 半影随云影展宽（P1-2）← 需要改签名 + 放宽 clamp
    │
    ▼
[第 3 步] 现状核实（都是"先查清再决定"，不是实施）
    ├── Astra 云光照现状核实 ──► 决定 P1-3 是否推进
    └── 水下光束早退命中率统计 ──► 决定 P1-4 是否推进
    │
    ▼
[第 4 步] 需要用户决策的架构级议题（各自独立成专项）
    ├── 色彩体系：光色是否改为大气透射率驱动（P2-3）
    ├── 阴影：是否接受"放弃逐角参考深度"换可变半影（P2-1）
    ├── 下界：是否新增体积雾（P2-4）
    └── 材质：是否接入 LabPBR（P3-1）
```

**依赖关系说明：**
- **P0-4（台账）必须在任何"合并/删除 buffer"设想之前完成**——E-报告明确说明没有任何 buffer 做过生产者/消费者核对，因此当前**没有任何依据**说哪个 buffer 冗余。
- **P1-3（云多重散射）依赖"云光照现状核实"**——在不知道 Astra 是否已用别的方式补能量之前，无法判断这是"缺失"还是"已有不同实现"。
- **P1-4（光束最坏路径）依赖运行时统计**——没有早退命中率，"224 次读取"只是上界而不是典型值。
- **P2-1（可变半影）与 P1-2（半影展宽）互斥优先级**：如果 P1-2 的效果已经让人满意，P2-1 的架构代价就不必付。
- **P2-3（色彩体系）与 P1-1（分色相校正）有耦合但不冲突**：P1-1 是"在现有色彩体系上追加一层"，P2-3 是"改变色彩体系本身"。**建议先做 P1-1**，因为它是可逆的（默认可关闭），而 P2-3 会改变全画面。

### 7.3 明确不建议做的事（防止方向被带偏）

1. **不要为了"对齐 Photon"而拆掉 Astra 的阴影结构。** 逐角参考深度、双深度配对、双 gather 路径、过滤半径按纹元收敛——这四项没有一项在外部包里存在（A-报告 §Q7）。
2. **不要把"减少云的采样数/分辨率"当作优化。** Astra 的段积分在防漏采上优于 Photon 的均匀点采样；高画质档 `CLOUD_QUALITY == 2` 的 512 段上限是设计上限，不是默认（`clouds_planar.glsl:280-302`）。
3. **不要宣称"末地可以学外部"。** 外部 15 个包对引力透镜的命中数是 **0**（F-报告）。Astra 的离线 Kerr 图集是这批项目里唯一的实现。
4. **不要把"Astra 没有某个算法名字"当成"缺少该技术能力"。** 本轮已用源码证伪三例：
   - "Astra 缺 TAA 方差裁剪"→ `taa_resolve.fsh:162-164` 有 3×3 mean/σ 裁剪；
   - "Astra 缺硬件阴影比较"→ `ASTRA_SHADOW_FILTER_MODE` 有 sampler2DShadow 路径；
   - "Astra 缺云影缓存"→ `cloud_shadow_cache.glsl` + `colortex14` 已有。
   另外本报告新收窄一条：**"水面焦散写 shadowcolor0"并非 Astra 独有**——Photon（`program/shadow.fsh:110-164`）与 CR（`program/shadow.glsl:125-151`）同样在做，Astra 独有的是"单次解析 Hessian 求曲率 + 有界输出"。
5. **不要拿 Steadfast 当"精简管线"的目标。** 它只有 4 个 composite 类入口，是因为它不做水下合成/SMAA/TAA/散射——省的是功能不是管线。
6. **不要在台账完成前预估"能省多少显存/带宽"。** 报告里只写了数量事实（30 / 62 / 129），没有写任何一个"可合并"的结论。

### 8.5 与 Iris、驱动或硬件相关的技术风险

1. **Iris 补丁后的实际程序与原始 GLSL 不同**：常量折叠、循环展开、`#include` 展开后的行号漂移都未验证（例如 `for (int i=0;i<ASTRA_SURFACE_RIPPLE_LAYERS;i++)` 是否完全展开）。**所有"源码表面上的重复操作"未必是编译器留下的重复工作。**
2. **`program.*.enabled` 的实际生效行为依赖 Iris 版本**：Astra `shaders.properties` 的注释标注其"显式写 false"的结论来自 **iris-fabric-1.11.2+mc26.2** 上的实测。换版本需要重新确认。
3. **子组（subgroup）扩展**：renderpearl 的 `subgroupBallot` / `subgroupElect` / `subgroupBroadcastFirst` 依赖 `GL_KHR_shader_subgroup` 类扩展，**本轮未核实** Astra 目标平台与 Iris 版本是否提供；`f16vec3` 还需 GLSL 16 位浮点支持。
4. **opaque/island/planet 等末地图集依赖自定义纹理**（`shaders.properties:596-599` 绑 4 张 PNG，最大 4096×4096）→ 显存占用与驱动对超大纹理的支持边界未评估。
5. **`IRIS_FEATURE_CUSTOM_IMAGES`**：CR 的体素彩光明确要求该扩展**且排除 macOS**（`lib/common.glsl:33-35`）。这提示"3D image"类功能在平台上有硬边界——Astra 的下界彩光也用了 `3D image`（`shaders.properties:946-950`），**其平台适用边界本轮未核实**。
6. **无运行时抓帧证据**：本报告**没有**任何 RenderDoc/抓帧数据，因此**不能断言任何 pass "编了但不执行"**。唯一例外是 C-报告与 F-报告共同核实过的 `global/dimension/nether_volume.glsl`（全仓零引用 + `shaders.properties:886` 有退役说明）。
