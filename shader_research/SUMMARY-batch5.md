# Astra × 参考光影包调研汇总（第五批：引擎配置面与新机制缺口）

写作日期 2026-10-16。只汇编调研，不授权实施；不含任何代码改动。

> 范围：Modrinth 全量 1001 个 shader 项目枚举去重（890 个新 slug、442 个技术向候选），其中 33 个新包下载解包在 `_analysis/batch5_unpack/<slug>/`（zip 在 `_analysis/zips_batch5/`，子代理任务书全文在 `_analysis/BRIEF_batch5.txt`）。前四批与夜空批见本目录其它 SUMMARY。
> 引擎证据：`_analysis/irispk/` 是 iris-fabric-1.11.2+mc26.2 解包，共 844 个 .class（全在 `net/irisshaders/iris/` 子包内，顶层 0 个）；`_analysis/cla2.mjs` 可解析 .class 常量池取 `orElse` 默认值。Iris 文档站 `shaders.properties/current/*` 全站 404，可用替代为 `raw.githubusercontent.com/IrisShaders/ShaderDoc/master/{iris-features,README,const-directives,uniforms}.md`（`_analysis/shaderdoc_iris-features.md` 已存）与 1.20.6 分支 Java。
> 口径：只列 Astra 现在没有的东西。每条 Astra 侧「没有」都给关键词与命中数（`Astra/shaders` 全树正则）。参考包侧路径相对 `_analysis/batch5_unpack/`。
> 证据强度：**本批全部结论为源码级/字节码级推断，无一项有实机帧时或画面对照。** 未验证项集中在 ⑥ 节。

## ① 执行摘要

1. 差距主要不在某个效果，而在两类：一是**引擎配置面几乎没用**（13 个 Iris 支持的 shaders.properties 键 Astra 零使用，含可能让两个已有程序白写的 separateEntityDraws）；二是**屏幕空间相机效果整段空白**（景深、运动模糊、镜头光晕、局部曝光、锐化全部 0 命中）。
2. 硬约束先说：扫 Astra 全树统计被引用的 colortex，**0-6、8-31 全部在用，32 槽只剩 colortex7 空闲**。凡需新增全分辨率附件的机制（多色方块光 2 张、共享低精度深度 1 张、SMAA 2 个中间目标、时序 AO 历史 2 张小缓冲、VFX 粒子层 1 张）都不是「代价高」，而是「现在排不进去」，立项前要先做附件规划。
3. 同一约束的已知陷阱有 Astra 自有记录：`Astra/shaders/program/deferred.fsh:295-299` 写明 colortex0Format 是 R11F_G11F_B10F（RGB 格式），**写 .a 被丢弃、读回恒 1.0**，掩码已改走 colortex3.a（RGBA8）。参考包凡用 alpha 编码信息的做法，照搬都会在 Astra 静默失效。
4. 许可是硬边界，且本批出现「许可假象」：TrueLightFX 挂 MIT 但整包文件头是 BSL（Capt Tatsu 自定义许可），MIT 不覆盖上游；Muuf 简报中的 GPL-3 在包内找不到依据，实际无 LICENSE 且 README 禁分发；Verlixia、Prismarine 无任何许可文本（Verlixia 仅 note.txt 自述 BSL fork）。可代码级借用：kute / wispy / escheridia / realisticallyoptimized / smaa-mc / velocity-shaders / lumeau（MIT 系）、ctrvcr（Apache-2.0）、relumination / raincore（GPL-3）、highframes-plus（CC BY 4.0）、CAS 的 AMD 原始实现、Photon 上游片段（有条件再分发，付费平台另有限制）。例外：smaa 的 redmean.glsl 是 CC BY-SA 3.0（share-alike，建议自写那 8 行）。
5. 两次同类假阳性已实证：**关键词命中不等于机制存在**。Wispy 的 DOF/SMAA/焦散全是空 `#ifdef` 脚手架；Luster 的 SMAA 唯一命中是 `include/utility/bicubic.glsl:126` 的出处注释。因此本文件任何「某包有 X」都要求追到 pass 与消费者；BRIEF 里的预扫描特征表只能用于圈定调查范围。

## ⑨ 反面缺陷库（Astra 自检清单，不是借鉴项）

1. 矩阵式编译检查必须覆盖每个 profile 的全部开启组合。body-camera 与 cursed-fog 的 AUTO_EXPOSURE 分支写 `color = color / vec3(TONEMAP_WHITE), vec3(1.0/TONEMAP_WHITE);`（GLSL 无逗号运算符）→ 该分支从未编译通过。门控允许某分支不等于该分支被编译过。现行 qa 编译矩阵是否覆盖全部开启组合本会话未核。
2. 开关名与宏名必须一致且有测试保证。muuf PHYSICS_OCEAN_SUPPORT（settings.glsl:265）对 ifdef PHYSICS_OCEAN（4 处）→ 202 行 oceanPhysics 与泡沫全链不编译；escheridia shaders.properties:15 写 separteAo = true 拼错（Astra 拼写正确）；菜单项引用被截断的 FUN_MOD（应为 FUN_MODE）→ 该项不产生任何开关。三例同型，且都能在只读源码时被「看起来有实现」骗过。
3. 每个 screen 项与 profile 行的宏名都要能追到 GLSL 真实读取点。kute shaders.properties:33,35 暴露 DIRECTIONAL_LIGHTMAP / DYNAMIC_HANDLIGHT / SOFTEN_SHADOWS / SHADOW_SOFTNESS 四项在 program 与 global 里 0 文件命中；wispy program/final.fsh:77-79 调 getFSRScale() 与 performUpscalingAndSharpening() 全项目无定义，FSR_UPSCALING 与 FSR_QUALITY 无定义却在 lang/en_US.lang:125-133 有完整文案；wispy README.md:50 声称 Fast gamma correction 但 FAST_GAMMA 未在 settings 定义 → 恒走 pow(color,1/2.2)；wispy profile 写 ATM_FOG_STRENGTH=0.10/0.20 而雾路径要求 ATMOSPHERIC_FOG（global/fog.glsl:76）且它默认未定义、profile 行也没写取反 → 档位改的是没人读的强度；luster settings.glsl:888-892 暴露 indirectResReduction [1 2 3 4] 而 temporal.glsl:5-11 把 bufferScale=0.5 写死（选另三档会让重投影与缓冲尺寸对不上）；luster deferred12.fsh 复用 PROGRAM_DEFERRED11 宏（改该 ifdef 分支同时影响两遍 pass）；luster 有 6 条 enabled=false 指向不存在的 setup/shadowcomp 文件；escheridia lib/common.glsl:32 VISUALIZED_DATA 5 无消费者且默认开着；kute settings.glsl:231-235 是 ifdef GODRAYS 与 ifdef SMAA 的空块占位。**本会话未对 Astra 做全量核验，因此不断言 Astra 干净。**
4. 关闭一个可选特性时要检查它的 image 与纹理是否仍被分配、其它程序是否仍在采样。escheridia FLOODFILL 开着时 8 个 gbuffer 程序各加 2 次 3D 采样并常驻 4 张 3D 图（VOXEL_AREA 256 时约 384 MiB，按其 shaders.properties:19,31,45,57 尺寸直算，推断；Astra 64^3 三张约 3.5 MiB）；TrueLightFX 的 DIRTY_LENS 有菜单有贴图但 composite5 从不采 dirt（该包 program 内 dirt 0 命中），texture.composite.depthtex2 与 uniform sampler2D depthtex2 仍常驻（composite5.glsl:36、gbuffers_water.glsl:55）；luster screen 24 的四个 godray 子屏只配一个 program.*.enabled。Astra 自检点：主世界无体素（只下界 64^3），此风险目前不存在，但 A30/A31 若实施就会引入。
5. 门控必须三入口同步。body-camera 与 cursed-fog 门控只写 world0（shaders.properties:33-36）；verlixia shaders.properties:105-106 只给 world0 与 world1 挂 LIGHT_SHAFT 门控。子代理自测的 Astra 槽位分布（根到 composite9 且有 deferred1-3 与 prepare1-4，world-1 到 composite9，world1 只到 composite8）本会话未复核，新增门控时须自己核对。
6. Luster 作者自己四档 profile 有 19 项全 OFF（shaders.properties:1-4）：LENS_FLARE、POM 全家（POM_SHADOW / POM_SLOPE_NORMALS / POM_DEPTH_WRITE）、MOTION_BLUR、COLOR_GRADING、EDGE_HIGHLIGHT、DIRECTIONAL_LIGHTMAPS、DISTANCE_VIEW、TONEMAP_COMPARISON、BLOCKY_CLOUDS、GALAXY、BLOOMY_FOG、SNELLS_WINDOW、PIXELATED_SHADOWS、VANILLA_SUN/MOON、LENS_FLARE_HALO、WEATHER 相关等。推论：不能因为包里有实现就当它是作者验证过的可行路径。这条压住本文的镜头光晕（B06）、运动模糊（C05）与 POM，它们要标为未验证机制。同理 TrueLightFX 的 ultra 档不加阴影分辨率、只把 SHADOW_PCF_STEPS_MIN/MAX 从 8/12 提到 32/32 并把 SSS_STEPS 提到 24（shaders.properties:1-4）→ 极端档把预算花在更多次同样模糊的采样上，性价比可疑；Astra 的 32 基点加 size.buffer 分档思路更值得保持。muuf 所有 profile 含 low 都保留 MOTION_BLUR=true，且 profile.high 的 shadowMapResolution=2642 非 2 次幂（对投射贴图精度与采样对齐不利），crumb 用 2642/6234 一类非 2 幂值配合档位 → 跨档不可比。
7. 同一缓冲格式两处声明冲突：Verlixia shaders.properties:137-138 的 colortex8/9Format=RGBA16F 对 program/final.glsl:33-34 的 const int colortex8Format=RGB8 与 colortex9Format=RGB16F → 谁生效取决于 Iris 版本，彩色光的 HDR 范围靠运气。Astra 走 GLSL 单一来源（见 ⑧），保持。
8. 为骗过选项扫描而留死代码：luster program/d6_sspt_filter.fsh:21-29 保留一个空操作 ifdef，注释说明「只在 shaders.properties 的 program.*.enabled 里引用的 define 不会被 Iris 登记为可切换选项」。这是真实的 Iris 行为，值得记；子代理称本会话核查过 Astra 的门控名能在 .glsl 源里检索到、未踩这个坑（我未复核）。
9. 按显卡厂商特判后又被注释掉：luster shaders.properties:104-108（及 world0/world1 对应块）里 MC_GL_RENDERER_INTEL 包住 composite22 的写法全部注释掉，三维度一致；velocity lib/distant_horizons.glsl:70-72,100-102 用 MC_GL_RENDERER_RADEON 把 Depth<=0 钳成 1.0（驱动特定补丁）。Astra MC_GL_RENDERER 0 命中；若将来做厂商分档，不要用 properties 注释临时关。
10. 发布卫生：.bak 随包分发（TrueLightFX lib/settings.glsl.bak 约 133KB、shaders.properties.bak、lang/en_US.lang.bak；verlixia 整棵 bsl_source_code/ 随包发布，27763 行约一半是副本）→ Astra 应禁止打包 .bak 与源码副本。拼写错名必须全库一致才生效（ctrvcr MOON_LIGHT_STRENGHT 14 处一致所以能跑）→ 新增键时核对 shaders.properties:583 的 sliders 命名。
11. 声明 gl_FragDepth 会放弃 early-Z：smaa-mc 2_blend.fsh:7 与 3_cas.fsh:9 声明 gl_FragDepth 靠 discard 补偿。Astra program/shadow.fsh:40 用 layout(depth_greater) 的保守深度写法正确。
12. smooth() 槽号跨版本分支重复复用：TrueLightFX 与 Prismarine 的 slot 1 到 13 每个都被复用 2 次（分别落在 MC_VERSION>=11800 与 else 分支），slot 11 复用 4 次（isCold 的 windswept 项、isBasalt、isCold 的 yCold1 项、isBasalt；行号 TL :173,186,189,202；PM :162,175,178,191）。Iris 的 smooth 缓存按槽号索引，同号跨变量有历史值污染风险（是否每次重初始化取决于 Iris 版本，未实测）。子代理自测 Astra：8 个 smooth 槽、重复 0 处（我未复核）。值得写成提交检查：槽号全局唯一，跨 MC 版本分支也要换号。
13. 其他可复用反面样本：fireflies.glsl（91 行体素噪声）在 TrueLightFX/Prismarine 全树零 include 且无 FIREFLIES 定义、lib/pbr/integratedEmissionEntities.glsl 零引用；velocity 的 shadow_fade()（shadows.glsl:1-6）与 get_shadow_static()（:26-31）无调用点 → README 承诺的阴影末端淡出实际不存在；muuf 三个 (Copy) 文件零引用、pathtrace/RayTraceHit.glsl 与 Voxel.glsl 只被注释行引用、InternalLib/Composite1.glsl 的 NvidiaDLSS.glsl（211 行）无 include 且 :1,:166 自述 just a joke 命名误导；GlobalIllumination.glsl:169-170 声明后从不赋值且 :204 结尾整项乘 0.0、:121 用 vec3(1.1) 当未命中哨兵而 :161 返回 vec3(1.0) 两种编码混用；Composite1.glsl:92 的 const int SAMPLES=8 与 :113 的 Decay*=0.88 写死，使 SUNRAYS_QUALITY 与 SUNRAYS_DECAY 两个滑条无消费点；verlixia shaders.properties:182-198 数字群系 ID 的 else 分支在现代 MC 不可达（17 行死配置）、lib/settings.glsl:469-474 空 ifdef 脚手架；raincore 与 wither-rose 各一处把 elif 写成 else 加像素比较；wither-rose main/final.fsh:4 声明 uniform sampler2D gColor 而包里没有任何 gColor 附件（恒为未定义行为）、且没有 shaders.properties；escheridia composite90.fsh:106 用 historyWeight=1.015 自激。对照：Astra 已有同类自觉记录（shaders.properties:832 写着 no customTexture binds it and no shader samples it；lib/settings.glsl:456 写着 noisetex/noise.png were removed 因 nothing sampled them），保持这个习惯。
