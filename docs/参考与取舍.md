## 新增外部光影调研的采用范围

用户已要求直接落实[外部光影设计与性能调研](../shader_research/2026-10-18-外部光影设计与性能调研.md)中的适用项。实际回读其DSH缓存中的Photon main `include/utility/bicubic.glsl`、`include/sky/clouds/cumulus.glsl`、`program/c19_color_grading.fsh::grade_output`、`include/lighting/shadows/pcss.glsl`及ComplementaryReimagined main `lib/colors/lightAndAmbientColors.glsl`；缓存为报告取得的分支快照，不代表发布版本。采用光束与地面分开配色、颜色家族独立调整及云下适度柔化的思路，由Astra自行编写亮度归一的微暖光束色、无需HSL的RGB色彩选择和最多25%的半径联动。水下已有光谱染色保留，未照搬蓝色光束常量、橙青电影风格、5倍阴影倍率或Photon八轮云散射。水面省算来自包内当前方向与高光公式复用。

报告候选5及P0中的TAA二阶矩裁剪与当前taa_resolve.fsh重复，不重新实施；temporal.glsl水面历史明确退役，不算现有能力。Photon双三次过滤为四条textureLod查询，不能与16个邻近纹理像素混为16条查询；没有纹理查询也不证明八轮散射便宜。可变半影与逐角参考深度不构成原理互斥，但增加遮挡物搜索尚无当前水面成本收益依据。AO补偿只抬亮且默认AO关闭，独立水下光束在默认/均衡未开启，均不直接解决岸上水面低帧。未新增全套附件总表或重接退役效果；现有附件按实际准备改动的生产者和消费者核对，不能据数量判断浪费。原报告保留，当前行为以实现与限制及源码为准。

### 源码取证版的核对与实际采用

已全文阅读[源码取证版](../shader_research/2026-10-18-外部光影设计与性能调研-源码取证版.md)，回读其Photon main快照的`include/lighting/shadows/pcss.glsl:98-185`、`include/fog/end_fog_vl.glsl:9-21`、`include/surface/water_normal.glsl:75-82`，并核对Astra可达调用、预设与附件。引文位置能够帮助导航，但不能证明报告推论成立。报告原文保留，以下为当前采用判断。

| 候选 | 核对结果与实际处理 |
|---|---|
| A1 阴影硬下限 | 不采用。spread的单位为影图像素，worldTexel为世界格/影图像素；建议的max(0.5*spread,2*worldTexel)混用单位，且可能令clamp下限大于上限。Photon半径在未畸变坐标中定义，不能直接等同于Astra的spread。没有“小于2像素必然闪烁”的通用结论 |
| A2 过滤后锐化 | 不采用。不能保证同时消除闪烁并保住细叶；对含彩色透射的结果直接反压还会改颜色/能量。现有固定16角点及深度配对保留 |
| A3 散射跳过 | 部分采用。rainy_air本来已拒绝夜间、失明、低雨量与无天光，且在deferred原生尺寸阶段，不是报告所称的附件1四分之一尺寸。实际补上太阳源与SUNLIGHT_STRENGTH为零的判断，并把共用条件和颜色移到顶点；保留逐位置遮挡，不用端点阴影证明整条视线无光。完整体积雾本来已有零直射时不查可见度 |
| A4 消费端颜色 | 部分采用。雨雾原硬编码暖色确与新树隙光源色分离，已改为共用太阳源函数并接入AIR_SHAFT_COLOR。云使用原始天空函数后加一次晨昏/增益，与天空入口相同次序，不据其存在额外函数就认定重复染色 |
| A5 八轮云散射 | 不采用。当前云已有环境补光且首次着色后复用，报告逐采样重复执行的预算不对应Astra；Photon有指数、平方根与相位计算，不能称免费或按几条乘加估算。缺少当前云体照明的视觉依据 |
| A6 像素龄mip | 不采用。Astra高档云为原生四子样本，并非Photon棋盘式缺像素重建；不存在可直接省去的额外模糊查询。直接给历史加mip还会在自身深度接受前混入邻居，损失原生边缘与孔隙 |
| A7 下界彩光分档 | 已有。流畅关闭、均衡/精细开启，传播和消费已由同一有效条件限制。Solas/Photon关闭的是空气体积光，不等于它们关闭表面彩光；不违背用户此前要求关闭下界彩光 |
| A8 末地高度与星格 | 采用高度结构的思路，自写宽包络与三点平均，保留原远端渐隐，增加END_HEIGHT_FOG开关；不复制Photon指数密度函数。不裁减3×3星表邻域，避免纬度格边界漏星。黑洞转移图静态不妨碍盘面流动、热点与喷流动画，现有动画保留 |
| A9 分辨率深度余量 | 不采用。缺少随档位变化的具体异常依据，深度精度、斜率和世界像素宽度不能只由贴图分辨率倒数代替 |
| A10 法线取样重排 | 不采用。六层ITT只服务对应水下/波场入口，不是岸上水波路径；集中六组临时量可能增加寄存器压力，编译器也会调度独立查询，没有当前收益依据 |
| A11 AO历史 | 不采用。默认AO关闭，当前静态样本不靠逐帧噪声生成；新增历史会增加读写和拒绝计算，不直接回应水面低帧 |
| A12 可变半影/接触阴影 | 保留为研究方向，未接入。需要额外遮挡物搜索/步进；不以算法名称或报告排名替代当前质量与成本依据 |

额外纠错：ANTIALIASING的FXAA/TAA/SMAA是互斥选项，不是相加运行；TAA已经消费植物前帧位置数据，不能概括为纯相机运动；下界采样次数随方向感开关与有效范围变化，不能对所有像素固定计7次。报告对NobleRT是否硬件光追的总表与正文也互相矛盾。整体适合作为源码位置索引，直接实施建议仍需重做作用域、单位与数据流核对。

## 调色方案与Derivative

研究目标是保留主世界清新自然、青蓝水色及多彩银河，同时减少不必要的显示开销。以下采用“源码能说明做了什么、游戏画面才能说明最终观感”的证据范围；没有取得同场景的运行画面或GPU分项，不按参考包的宣传判断Astra会更快或更好看。

### Derivative的实际研究对象

直接读取本地`_analysis/video-2026-10-01/derivative/source/`，现有来源记录对应[Derivative main 25.1.0发布包](https://www.curseforge.com/minecraft/shaders/derivative-main/files/8529690)。网上另有[v26.0.0b1发布项](https://www.curseforge.com/minecraft/shaders/derivative-main/files/9089584)，本次没有把其代码与本地副本混为同一版本，也没有据此概括早期HaringPro版的全部行为。Octocode仓库发现没有提供可直接读取的Derivative仓库，主要实现依据为本地发布源码。

| 已读位置 | 源码行为与对Astra的意义 |
|---|---|
| `program/Post/Grade.glsl:79`、`lib/Post/ACES.glsl:211` | 默认TONEMAP为AcademyFit，先乘1.4，再做RRTSweeteners、RRT/ODT拟合及饱和度处理，随后接亮度、对比度、Gamma、可选白平衡和sRGB输出。RRT/ODT可理解为把场景光量转成屏幕图像的两段处理；Sweeteners还修饰颜色。因此它不等同于Astra现有的简化ACES拟合，不能把“切到ACES”说成复现Derivative |
| `program/Post/Grade.glsl:2068`、`Settings.glsl:1000` | 所查默认定义包含Bloom、Bloomy Fog和自动曝光；主合成先叠加所选泛光/雾，再乘曝光、添加已启用的镜头效果并调用显示曲线。柔光与曝光会共同改变可读性和亮部观感，不能把这些全部归功于调色，也不能把所有可选泛光分支当作同时执行 |
| `program/Post/Grade.glsl:1245` | 非6500K时使用Bradford色适配矩阵处理白平衡，默认6500K编译排除。它适合说明真正白平衡和显示端暖冷染色的区别；Astra现有色温滑杆是带蓝色保护的显示端染色，不在本轮悄悄改义 |
| `program/ReflectionFilter.frag:15`、`world0/composite1.fsh:349` | 按材质是否反光、粗糙度和有效数据决定过滤；所查过滤器至多读取八个邻居，并结合深度、法线和反射记录权重。反射材质判定值得参考，但整套过滤有额外读取和幂/指数运算；Astra已有材质门槛和下界重建，不重复叠一套 |
| `lib/Atmosphere/Fogs.glsl:66` | 空间重建用四个邻近结果，以深度差给权重。这说明雾的分辨率与轮廓保护需一起设计；不能将其直接替换Astra水下分段光路或据循环次数外推画面 |
| `program/Post/Final.glsl:12`、`:332`、`:463` | DLSS_MODE用于配合手动Render Scale的锐化配置；实际末级按MC_RENDER_QUALITY选择CAS或文件内空间放大函数。名称本身不证明接入NVIDIA DLSS。降低内部渲染尺寸换帧率涉及细节取舍，本轮未改变Astra原生尺寸 |

以上只用于比较职责、默认选择和成本，没有移植Derivative代码、参数或素材；本地包内`License.txt`与网页许可标签不能合并推定为其他版本的片段授权。

### 调色路线比较与当前选择

色调映射负责把超过屏幕范围的光量压进可显示范围；白平衡、对比度和饱和度负责进一步决定外观。二者应区分，避免通过整体加饱和掩盖水体吸收或光源颜色的问题。

| 路线 | 颜色表现与计算代价 | 当前选择 |
|---|---|---|
| Astra自然Uchimura | 先对最大RGB分量求曲线，RGB共用缩放，强高亮再渐趋白；只需一条标量曲线。暗部和高亮过渡仍需非线性计算 | 保留默认。本轮仅将严格等于输入的线性区间直接返回，并在最大分量≤1时跳过无贡献的趋白计算；没有更换曲线或抬高曝光 |
| 现有ACES拟合 | 两次颜色矩阵和逐通道有理曲线，行为来自当前`lib/tonemap.glsl`；饱和高亮的色相变化与Astra自然曲线不同。[BakingLab原实现](https://github.com/TheRealMJP/BakingLab/blob/master/BakingLab/ACES.hlsl)说明其拟合来源 | 已有选项继续保留。Derivative的额外修饰和1.4倍率未加入，不将其作为默认替代 |
| 现有AgX | 可系统处理强高亮颜色，但当前实现包含颜色矩阵、逐通道log2、对比多项式和输出幂，不能因不读贴图就当作免费。[Filament main](https://github.com/google/filament/blob/main/filament/src/ToneMapper.cpp)的AgxToneMapper展示输入变换、对数、曲线、外观和线性化的分工 | 保留可选，不自动切换。输入色域、输出线性化和最终sRGB编码须配套，不能混用不同实现的片段 |
| Khronos PBR Neutral | [官方GLSL](https://github.com/KhronosGroup/ToneMapping/blob/main/PBR_Neutral/pbrNeutral.glsl)在低亮度区直接返回，亮部用有理压缩和渐褪色，无纹理、log或幂；但其暗部偏移和高亮阈值会改变现有外观 | 可作为以后独立可选曲线的候选，本轮未接入。源码短不等于在当前GPU上必然比默认曲线快 |
| 3D LUT调色查表 | 把固定的多步变色预先存为颜色表，再用纹理过滤查询。[Filament ColorGrading](https://github.com/google/filament/blob/main/filament/include/filament/ColorGrading.h)允许CPU生成该表，并明确曝光、白平衡、分区颜色、对比度及显示转换的顺序。以32³ RGBA16F为例，原始表约256 KiB，另有查询、过滤、输入范围和插值误差成本 | 当前Astra默认调色多为少量公式，中性选项已编译排除；不足以认定新增表能提速。不添加资源，也不将光量历史或空间效果塞进固定颜色表 |

建议继续让当前自然曲线负责高亮，使用已有阴影/中调/高亮分区与日光/环境光颜色表达冷暖关系，后续根据明确画面偏差决定参数。本轮调研不替用户决定新色彩风格；实例已有SATURATION=90、VIBRANCE=90继续保留。若以后需要真正的场景白平衡，应单独定义用途和输入范围，按帧准备矩阵，不能把现有色温滑杆直接换成另一种含义。该建议尚未实施。

## 新增汇总的使用边界

已读[最终汇总](../shader_research/SUMMARY-final.md)与[第五批](../shader_research/SUMMARY-batch5.md)。前者实际范围是前四批与夜空，不包含第五批；两者均不能作为已证明的游戏帧率收益。以下结论来自当前Astra源码、直接读取本机安装的Iris 1.11.2+mc26.2字节码及必要规范，没有修改报告原文或据此新增效果。

| 报告条目 | 当前判断与依据 |
|---|---|
| 最终汇总第一级1：未声明阴影mipmap会默认生成 | 不成立。本机实例`mods/iris-fabric-1.11.2+mc26.2.jar`的`PackShadowDirectives$SamplingSettings`构造函数以`iconst_0`初始化mipmap；当前Astra也没有开启它的指令。因此补false不能算新增省算。[在线26.1对照源码](https://github.com/IrisShaders/Iris/blob/26.1/common/src/main/java/net/irisshaders/iris/shaderpack/properties/PackShadowDirectives.java)只作旁证 |
| 最终汇总第一级3：无世界尺度过滤、阴影噪声靠TAA | 无独立阴影模糊阶段属实，但其他推论不成立。`global/lighting/diffuse.glsl`已有世界尺度到畸变阴影像素宽度的换算及固定四组过滤，默认FXAA，无需TAA收敛随机阴影核。PCSS遮挡搜索仍是另一项未接入的增强 |

| 第五批V1/V5：separateEntityDraws与ENTITY_TRANSLUCENT缺失使入口无效 | 不能据此成立。本机`IrisPipelines.getTranslucent`直接选择透明实体/方块实体ShaderKey，不读该开关；`ShaderKey.ENTITIES_TRANSLUCENT`映射至`ProgramId.EntitiesTrans`，后者对应`gbuffers_entities_translucent`。此证据回答入口选择，不代替实际绘制先后顺序调查。[ShaderDoc](https://github.com/IrisShaders/ShaderDoc/blob/master/iris-features.md)也将ENTITY_TRANSLUCENT标为建议声明、非必要条件，不支持“没声明就不分离”的绝对说法 |

| 第五批A03：textureGatherOffsets可直接省16角点查询 | 收益未成立。该指令一次返回4个值，偏移须为整数常量，不会一次返回4组共16个角点；Astra已用普通gather一次取4角，核位置与畸变/接收面比较还有自己的约束。[Khronos定义](https://github.com/KhronosGroup/OpenGL-Refpages/blob/main/gl4/textureGatherOffsets.xml)不支持把新指令名称直接换算成省算 |
| 第五批A18：已有currentRenderedItemId，所以手持光只缺颜色 | 部分成立。按手持物分色可以做，但currentRenderedItemId标识正在绘制的物品，并不在绘制地形时提供玩家左右手物品身份；现有astraHeldLightBase只保留两手最大光级。仍需手持物身份与两手强度的输入，不能将现有物品模型分类当作完整手持照明输入 |
| 第五批A02：CAS只需在display尾部加调用 | 集成成本描述不足。当前display尾部才生成显示颜色，周围纹理输入仍是HDR；CAS需要相邻像素同一显示阶段的颜色。FXAA组合已有附件13可用作显示输入，但CAS与FXAA的先后及组合读取成本仍需明确，不能据“0新阶段”推导近乎零成本 |

用户已授权落地筛选后保留的候选。V2、A28、A18、A05及限定输入范围的A01已写入源码，行为和成本统一见[实现与限制](实现与限制.md)。V2使用stars=false：本机ShaderProperties将stars交给handleBooleanDirective，报告的off写法不适用。A18按[ShaderDoc手持物输入](https://github.com/IrisShaders/ShaderDoc/blob/master/uniforms.md)接入两手身份，关闭旧主手替换规则；不是将当前绘制物品ID当作两手身份。A01已直接读取本地TrueLightFX的directionalLightmap.glsl，它从屏幕导数估计的方向主要在表面切平面内；Astra当前平面法线不能据此可靠推得完整光源方向。因此自写手持位置方向与下界已有三维场梯度，没有复制BSL谱系的方向光表达式，也没有宣称普通标量方块光已方向化。

C02暂不采用。已直接读本地_analysis/batch5_unpack/velocity-shaders的program/deferred.fsh、global/water.glsl及shaders.properties：每边四分之一尺寸的深度只对四个偏移样本取最大值，水面搜索和细化也使用该低分辨率结果。它不是完整4×4区域的保守深度范围，最远值也不能代表区域内所有细叶；不能据此跳过Astra原始四角交点。安全的共享范围另需完整覆盖、深度精度和消费者改造，新增生成/读取成本目前没有收益依据。当前默认岸上SSR关闭，更不能把这项直接当作水面100降到75 FPS的修正。没有新增粗深度附件或削弱原始深度、实体和颜色配对。

PCSS、GTAO、CAS及镜头效果仍是各自可选增强，不能因列在报告前面就排到水面降帧与入水问题之前。报告中未在此核对的参考包实现和许可仍只是调查入口。

## 2026-10-17新增机制报告核验

已完整阅读[机制报告](../shader_research/2026-10-17-可参考机制调研-Astra缺口.md)、[引擎报告](../shader_research/2026-10-17-Iris1.11.2引擎能力实测.md)，并按问题读取三份subagent分项记录、参考源码与本机Iris 1.11.2+mc26.2的相关字节码。原报告未改，未据报告新增光影功能或变更引擎开关。下面是对报告成立范围的修正，不代表游戏画面或GPU收益已确认。

| 主报告第三节1：主世界光照仅按光源距离，屏幕空间遮挡可修复隔墙火把光 | Astra放置光源读取的是游戏传入的lightcoord.x，经local_light_components的pow4处理；只有独立手持光自己计算距离。不能据此宣布普通火把不经墙体处理。Velocity的blocklight_shadows.glsl根据屏幕光占比梯度和前景深度估计遮挡，最后将整幅Color乘暗，不是实际光源到接收面的可见性判断。可以作为局部观感增强研究，尚未证实Astra存在对应隔墙缺陷，不列为必修或最便宜方案 |

| 主报告多处：只有colortex7空闲，故额外双附件不能做 | 沿用前文裁决：全树编号出现与某一维度/组合中的同时占用不同。当前非TAA的15/16/17/22、非SSAO的19/20/21/26/27已缩为小图；能否复用须按具体生命周期与格式判断。不能据并集阻断功能，也不能因此直接覆盖已有用途 |

实体地形入口拆分与SMAA已按后续授权落地，当前行为及代价见[实现与限制](实现与限制.md)；PCSS和Catmull-Rom仍为较低优先候选。研读的Grindstone end_of_frame.json包含边缘、权重、混合三个阶段，随后还有独立CAS，不能把其阶段数量直接当作Astra新增成本。Astra实际采用SMAA官方内核，没有搬其CC BY-SA的redmean.glsl；来源登记在THIRD-PARTY。

PCSS是视觉增强，不是树影闪烁的已证实修正；四个搜索点未发现遮挡不证明原16角点范围全亮，不能借此取消已有细叶覆盖。Arc::FindBlockerDistance还将hitDist先max到0，再用step(0,hitDist)计数，会把零距离也计入分母；报告将它描述为仅统计真实遮挡的平均距离并不准确，不应原样移植。屏幕空间间接光、3D噪声及显式flip仍为按用途选择的候选，缺少名称不构成必须补齐的功能，也不改变水面帧率与入水反馈的优先级。

## 不重新尝试的旧方案

- SSR共享搜索、直接屏幕推进和空段加速的既有适配没有取得值得采用的收益；沿几何水面搜索会削弱波浪扭曲，收益不足。无新证据不重复开展同一候选。
- 单像素倒影取色会损失边缘过滤，减少四角补漏、缩短细化和提前削减细波也没有足够收益依据；保留已选单像素折射，不把折射取舍扩成所有倒影取色。
- Photon仍每帧搜索，再取历史颜色和雾，不能当成省掉本帧搜索；MakeUp固定距离投影损失真实位置与遮挡，不采用。
- 主世界阴影不新增纹元跳变或透明裁切抖动，避免周期移动和树冠密度变化；不反转植物锚点、不删径向平方、不因全包同名声明就判断维度附件冲突。
- 云历史的消费坐标需要消除生产端网格偏移；平滑天空底色表不应塞入消费端高亮和调色，避免重复施加。高档云优先质量，不采用棋盘格替代四射线。
- 已有零贡献裁减、缓存和紧凑格式不重复列为新增功能；代码更短、读取更少或外部包宣传更快，都不能证明Astra整帧收益。
