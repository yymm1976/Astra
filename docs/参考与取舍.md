## 水体参考

当前要求水下整体氛围向ITT 3.2看齐，不再以“强度比ITT轻”为上限；水面/光源衔接、错误随视角转位和静态图层感仍沿用已确认的修正方向。位置由真实水面折射决定，保留动态细节与周期、长短深浅变化、晴天增强及近处可读。

本地ITT源码目录：`_analysis/video-2026-10-01/iterationt/source/shaders/`。按具体机制定位：

| 需要参考什么 | 源码入口 | 使用边界 |
|---|---|---|
| 水路深度、消光与水雾 | `composite1.fsh` 的水雾组合 | 先分清相机水下与从空气看水底的路径；不照搬强度或重复叠雾 |
| 水下体积光与波面法线缓存 | `Lib/IndividualFounctions/UnderwaterVolumetricFog.glsl`、`deferred.fsh`、`composite5.fsh`、`Lib/IndividualFounctions/WaterWaves.glsl`、`Lib/Programs/CompositeVS.glsl` | 保留ITT动态波纹、阴影方向与线性合成；当前解析法线缓存与逐点入水遮挡由Astra适配，相机不摆放发射点，晴天不靠积分步数增加数量 |
| 动画波纹与界面法线 | `Lib/IndividualFounctions/WaterWaves.glsl`、`Lib/Programs/Gbuffers/Water_FS.glsl` | 保留Astra既有水色、水深过渡和介质身份 |
| 水下天空窗口与全反射组合 | `composite1.fsh`、`composite2.fsh::CalculateSpecularReflections` | 先核对第三人称相机、玩家与界面坐标；不直接接受旧“随视角移动”说明为正确表现 |

已按相关源码查明：ITT的朦胧主要来自随距离消光、分颜色吸收与入射散射，水下体积光另参与组合，不是从这段水雾代码搬一个屏幕模糊。`composite1.fsh` 的水雾基础密度分别为水上0.29、水下0.04，另受 `WATERFOG_DENSITY` 控制；这些数值处在ITT自身的距离、色彩与合成方式中，不能与Astra参数直接等同比较。

Astra普通水下采用ITT WaterFog的分色吸收、标量距离透射、介质色、湿天气灰化及上下视线响应；亮度按Astra照明单位适配，不复制无遮蔽太阳峰，光束保留实际遮挡。参考Final.glsl的线性场景混合只用于较轻的两级窄柔化，不能把参考深度增益与空气泛光宽核直接拼成厚重屏幕模糊。水下HDR单独在主世界空闲附件9合成，水面快照4不为它升格。冰密度、40格体积范围及整套显示曲线不照搬；已认可的26格积分、八点路径和48格消费标记保持。ITT波面、碰撞光量立方、光源投影及线性加光的既有来源保留；具体参数只维护于[实现与限制](实现与限制.md)，最新帧率及画面状态只维护于[当前工作](当前工作.md)。

本轮阅读 `reference_shaderpacks/solas-shader/shaders/lib/atmosphere/volumetrics.glsl`：其水下实现通过距离范围、沿途衰减、昼夜光强及影图透光组织体积光，没有显式半圆锥发射点。当前采用世界水面入光，Solas的距离/光强分工登记为思路参考，不能写成已移植其半圆锥代码。用户所指Solas画面的具体版本仍未确定。其他相关入口如下：


| 参考入口 | 与当前问题相关的实际机制 | 本轮采用范围 |
|---|---|---|
| `_analysis/video-2026-10-01/solas-shader/source/shaders/lib/atmosphere/volumetrics.glsl` | 水下主要用透明影与不透明影之间的透光色调；纯无遮挡光的基础项只用于空气，源的分离先于累计 | 用于对照稀疏透光与普通水雾的职责；本轮没有移植其光束源 |

| `reference_shaderpacks/photon-shader/shaders/include/fog/water_fog_vl.glsl` | 光照向水中传播与观察路径分别消光，散射含归一化相位；焦散在固定光空间中变化 | 用于核对空间与光量分工；没有引入其多次散射或新水位估计 |

这些参考用于理解采样、遮挡和光量分工；最新重写目标优先，不把旧ITT移植范围当成必须保留的实现，也不将不同机位截图当成相同条件的强度比较。

Steadfast 0.8.0相关入口为 `shaders/lib/raytrace.glsl`、`environment/lighting/translucent.glsl`、`environment/water/refraction.glsl` 及 `surface_noise.glsl`，本地查阅位置为 `_analysis/steadfast-2026-10-02/source/`。其`Raytrace`在视空间将步长乘2，命中后退回原区间、减速再走，细化用尽时保留最近成功记录；接受厚度随步长增长，并拒绝朝相机方向的射线。这些近似可能遗漏薄物体、拉伸远处倒影或失去朝相机的有效倒影，不能直接作为Astra的接受规则。`TranslucentLighting`在透明片元中调用搜索，命中后读取同帧`colortex4`场景副本并处理雾；不是低分辨率合成SSR。折射由背景深度直接推进，四角深度都接受后只做一次双线性颜色读取；这项四角规则属于折射，不应记成其SSR四角交点补漏。它的解析噪声梯度同时得到高度和坡度，Astra保留该梯度求法线，但视差位移已取消。Astra的晚绘身体、界面侧及逐路径介质配对保持，水底透射按自身的单配对像素决定；具体窗口深度与光学容差判断为Astra适配。既有波场本身仍是Steadfast派生，不能将整个实现改记为原创或把省读取当成实际FPS。本轮在线Steadfast源码未取到，结论限于已登记的本地副本。

Photon本地副本（未确认发布版本号）的水面入口是`world0/gbuffers_water.fsh → program/gbuffers_all_translucent.fsh → include/lighting/specular_lighting.glsl::get_specular_reflections`，仍在透明片元执行。`include/misc/raytracer.glsl::raymarch_depth_buffer`投影一次得到屏幕方向，粗段按固定屏幕步长推进、用深度容差接受，再二分细化；水面走单条镜面射线，粗糙多射线分支排除水面。`trace_specular_ray`用本帧深度搜索，命中后逆投影并重投影到上一帧，读取`colortex5`颜色与`colortex7`旧雾散射，再沿反射路径处理雾；不是复用上一帧SSR命中，也不能由此宣称减少当前搜索。动态物体、遮挡变化与重投影越界存在历史颜色局限。已在线核对作者[main射线源码](https://raw.githubusercontent.com/sixthsurge/photon/main/shaders/include/misc/raytracer.glsl)、[镜面源码](https://raw.githubusercontent.com/sixthsurge/photon/main/shaders/include/lighting/specular_lighting.glsl)与[透明入口](https://raw.githubusercontent.com/sixthsurge/photon/main/shaders/program/gbuffers_all_translucent.fsh)的同类分工；分支与本地具体实现有差异，不视为同一发布版本。TAAU是场景整体缩放，不是仅降低水面SSR分辨率，本轮不采用。

MakeUp本地9.5f的`shaders/lib/water.glsl::fastRaymarch`先按指数距离推进，找到穿越后改为折半推进；越界标记并不立即结束整个循环。`reflection_calc`在`SSR_TYPE==0`时跳过深度搜索，直接投影`fragpos + reflected×76`（远景模组分支×768），读取场景副本并做边缘衰减；`REFLECTION_SLIDER==1`选择这一近似，2选择射线搜索。作者[master水面源码](https://raw.githubusercontent.com/javiergcim/MakeUpUltraFast/master/shaders/lib/water.glsl)仍有两条路线，但不冒称本地9.5f就是当前版本。固定距离近似损失真实物体距离、位置与遮挡，Astra不采用；其普通命中取色也不能作为重接已退出单像素倒影采样的理由。

上述三包只有源码执行路径依据，未取得包间独立GPU对照或游戏对照，不据查询次数、代码长度或作者性能宣传排序。屏幕坐标直接推进和空段加速的两项Astra具体适配已完成独立计量，未见值得采用的收益，结果与适配边界见[当前工作](当前工作.md#当前目标与最新实测)；它们均未进入项目源码，不再安排重复比较。

## 低配仓库报告的采用范围

用户提供的六仓库报告未读取Astra源码，Minecraft 1.16～1.20与Java控制层只是报告假设，不成为项目现状。当前Astra为Iris光影包，开发实例版本见包README。用户已明确允许降低默认画质，优先提高帧率；据此采用整程序开关、分档阴影预算、低档独立缓存尺寸、水波层数和预设继承。源码与具体画面损失维护于[性能档与资源调度](实现与限制.md#性能档与资源调度)，没有从这些仓库复制新GLSL。

预设继承采用Iris现有 `profile.<name>` 引用与后置选项覆盖，程序开关使用已有 `program.<name>.enabled`，缓存用 `size.buffer`；语义来源为Iris当前[选项说明](https://shaders.properties/current/reference/shadersproperties/shader_settings/)、[程序调度](https://shaders.properties/current/reference/shadersproperties/ordering/)和[缓冲尺寸说明](https://shaders.properties/current/reference/shadersproperties/rendering/)，读取日期2026-10-13。数值比较、禁用消费者与共享附件仍须由Astra自己的条件分支决定。

报告其余建议按适用条件处理：主HDR已有32位浮点格式，Bloom与预算云已有四分之一尺寸，不能重复认作新增；Astra表面法线直接求值，没有可压成RG8的独立水法线缓冲。实体深度/颜色配对、FXAA显示精度与末地天空附件有独立用途，不为“紧凑缓冲”统一降格。Java自动硬件调档需要新增宿主项目；FSR/TAAU与内部主分辨率缩放涉及主场景、深度、投影抖动、透明实体及输出坐标，当前不新增这条链。没有GPU分项依据时不宣称快速数学近似更快，不重做forward/deferred架构或已退出的SSR搜索候选。关闭SSR提供直接省工作选择，但不是修复树叶遗漏或屏外倒影。

## 性能与整体调色研究报告的采用范围

两份外部Agent研究均未读取Astra；固定版本源码提供的是机制依据，不证明本包缺少实现。逐项结论维护于[报告核实](审查/2026-10-14性能与调色报告核实.md)。本轮借鉴Photon的映射前/后调色分工及Complementary的真正高亮趋白思路，使用包内既有MIT来源Uchimura的标量特化和Astra自行编写的比例/亮度处理，不复制两包调色函数或色表。报告建议的云相交裁减、粗略二次照明、风速感知历史和主要资源压缩已经存在；继续消除恒定颜色累加、空云旧帧读取及晨昏固定量重复求值，实际GPU收益未知。

用户要求云清晰稳定优先，保留原生四射线与云段积分，不采用棋盘格。Astra覆盖偏移是天气标量，没有Photon覆盖图所替代的两层天气噪声，不另建缓存。统一背光/低天光拒绝会影响叶片透光、水及半透明的现有遮挡，不采用；新增CAS、绿色材质修色、固定地面反弹比例、强制自动曝光及更多风格档位均缺本轮适用事实。现行自然风格取消隐藏提亮和额外增色，具体映射与滑条含义见[主世界预算与配色](实现与限制.md#主世界预算与配色)。

## 已有轻量取舍为何保留

此前 Steadfast 审计报告未读到 Astra 源码，只作为工程策略线索。按报告条目对照当前实现的短映射：报告 P0 的“减少显存带宽”和“取消无消费者 pass/工作”此前已落地，分别是 Bloom 采集统一到附件2、空气散射附件1收紧为 RG16F、平面云影缓存无消费者时顶点裁剪；报告 P2 的“每帧 CPU 预计算”此前已落地在空气透视的水平太阳方向。水波解析梯度、主世界水上水平主路径的 O(1) 单像素折射、Nyquist 足迹渐退与八点积分此前已具备，本轮不重复移植；主世界水下界面仍走 ITT 波面，其它维度水下保留 Solas 路径。主世界主要水路的视差位移不重新接回，其它维度水下支路仍保留 Solas 四步视差与有限差分；SSR 加速候选此前已独立计量并退出；forward 重写不实施；天空已有 Minishita 路径，不据报告替换；Distant Horizons 与 Voxy 不新增适配。报告未给出 Astra 源码事实，其数值与其它包实现不作为 Astra 参数。

- Steadfast方向：共享连续背景的光学传输、按倒影贡献分配追踪预算、远处细波渐退。省重复工作和远端细节，保留近岸主要倒影与水路配对；不能把单包速度归为Astra已取得的收益。
- 天空底色插值、倒影云有限预算、远处植被风摆/投影渐退：让稀少且远离玩家的细节少做工作，近处普通植物、树叶、实体与接触影仍需保留。
- 下界稀疏倒影与末地粗糙倒影缓存：用已有连续重建与缓存减少重复求值，插值及边界近似保留。没有新偏差不重写其他维度，但实际问题出现时回到具体路径处理。
- 云保留独立历史，光束使用同帧ITT法线表和线性亮度，独立亮度历史仍退役。短时累计不是所有动态问题的通用解；噪点加重不能只用更长历史或更大模糊遮掩，更不能把当前修正记成已成功。

来源与真实采用范围从 [参考调研](archive/参考调研.md)、[实现与取证](archive/实现与取证.md) 按原文件名查，代码与素材的许可不在这里复制。

全包优化中保留末地星表FP32存在值，未采用进一步降精度，避免改变阈值附近的星点身份。冕层在 `outside<0.001` 时已有整段返回，不再把它列作缺少零贡献裁减。下界传播的进一步接收组裁减缺少可安全跳过的实际区域依据，保留现有同帧传播。

独立阴影意见中“几何导数在2×2像素跨不同图元时会混入邻面”未采用：当前导数来自本图元插值，边外辅助片元仍用于同图元的导数，不读取相邻已写场景深度。低太阳角的误差按原始NDC精度处理，不凭此假设加大偏移。纹理矩阵非单位及Voxy大面投射都缺当前入口事实，未写成已确认根因；平行斜线仍需实际画面。GLSL辅助片元依据见[官方规范](https://registry.khronos.org/OpenGL/specs/gl/GLSLangSpec.4.60.pdf)。

阴影组内投影网格表达式的进一步参数化未采用：两处同一表达式可由编译器复用，新增参数与活跃状态的实际收益不明。后处理保留已有FXAA搜索、TAA历史拒绝、泛光核和显示分工；不为缺少现场证据的任意NaN/Inf增加全屏逐分量检查，优先修正已有依据的生成源。

云历史偏移翻转的审查意见未采用：生成端给UV加网格偏移，逆投影查历史与同帧消费必须减去偏移。天空底色缓存没有漏存完整天空，它有意只保存平滑底色；远云目标缺少消费端配色增益则在云端补齐，不能把高亮层、晨昏或配色写入共享表，让其他消费者重复施加。

水面失败共享后保存四角水柱和雾化的候选未采用：新增八个跨循环活跃数值会增加寄存器压力，缺少足以确认收益的依据。本轮只复用一个相机距离，并在水柱不连续时省掉无用的雾化判断。预算档的单足迹锥节点、权重和半径表达式可由已有编译常量消除，不再叠加重复宏分支；光束缓存的距离标记和颜色/深度配对保持，未把有效空光量改判为缓存错误。

## 尚未进入本轮的方向

| 候选 | 可能带来什么 | 代价、未满足条件与后续安排 |
|---|---|---|
| 完整多层透明介质 | 改善复杂玻璃、冰、水重叠 | 需要额外层数据与合成成本；先修真实跨界身体问题，再决定实际需要多少层 |
| 更完整云介质积分 | 云前后空气关系更一致 | 增加计算与数据需求；先定位太阳前薄云抖动，不因物理名称重写整套云 |
| 水面独立历史 | 可能稳定部分动态倒影 | 旧链已退役、附件用途变化，须重新安排生产与消费，不能直接打开旧开关 |
| 体素格式压缩 | 可能减少彩光存储与带宽 | 共享读取优化已有，压缩另涉及精度和传播；有明确开销事实再独立选择 |
| Voxy远景 | 看更远地形 | 当前适配骨架尚空，需说明远景光照、透明水、雾及近远交界；不是已有可用功能 |
| LUT调色 | 统一外部调色工具流程 | 是新增调色管线，有资源、色彩空间与选项设计成本，当前性能/光束问题不需要它 |
| 水下颗粒分层光照 | 丰富装饰颗粒的光照层次 | 不是当前降噪任务，须核对参考真实机制和许可，不以增加颗粒改善噪点 |
