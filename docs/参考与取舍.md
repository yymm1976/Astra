## 新增汇总的使用边界

已读[最终汇总](../shader_research/SUMMARY-final.md)与[第五批](../shader_research/SUMMARY-batch5.md)。前者实际范围是前四批与夜空，不包含第五批；两者均不能作为已证明的游戏帧率收益。以下结论来自当前Astra源码、直接读取本机安装的Iris 1.11.2+mc26.2字节码及必要规范，没有修改报告原文或据此新增效果。

| 报告条目 | 当前判断与依据 |
|---|---|
| 最终汇总第一级1：未声明阴影mipmap会默认生成 | 不成立。本机实例`mods/iris-fabric-1.11.2+mc26.2.jar`的`PackShadowDirectives$SamplingSettings`构造函数以`iconst_0`初始化mipmap；当前Astra也没有开启它的指令。因此补false不能算新增省算。[在线26.1对照源码](https://github.com/IrisShaders/Iris/blob/26.1/common/src/main/java/net/irisshaders/iris/shaderpack/properties/PackShadowDirectives.java)只作旁证 |
| 最终汇总第一级3：无世界尺度过滤、阴影噪声靠TAA | 无独立阴影模糊阶段属实，但其他推论不成立。`global/lighting/diffuse.glsl`已有世界尺度到畸变阴影像素宽度的换算及固定四组过滤，默认FXAA，无需TAA收敛随机阴影核。PCSS遮挡搜索仍是另一项未接入的增强 |
| 最终汇总第二级2：末地没有引力透镜 | 不成立。`end_kerr.glsl::end_lensed_background`已偏折背景方向，`end_blackhole_system`实际消费它；属于现有效果，不能重新列为从无到有 |
| 第五批V1/V5：separateEntityDraws与ENTITY_TRANSLUCENT缺失使入口无效 | 不能据此成立。本机`IrisPipelines.getTranslucent`直接选择透明实体/方块实体ShaderKey，不读该开关；`ShaderKey.ENTITIES_TRANSLUCENT`映射至`ProgramId.EntitiesTrans`，后者对应`gbuffers_entities_translucent`。此证据回答入口选择，不代替实际绘制先后顺序调查。[ShaderDoc](https://github.com/IrisShaders/ShaderDoc/blob/master/iris-features.md)也将ENTITY_TRANSLUCENT标为建议声明、非必要条件，不支持“没声明就不分离”的绝对说法 |
| 第五批C01：colortex3.a无消费者，可改存方块光份额 | 不成立。`program/deferred.fsh`读取surface.a控制积水反射；末地Bloom开启且END_STONE_GLOW大于0时，`global/post/bloom.glsl`也消费该通道的发光遮罩。相关旧注释写“无消费者”已经落后于同一文件实际读取，不能据它覆盖用途 |
| 第五批附件硬阻断：只有7空闲，所以双附件功能排不进去 | 全树编号的并集不能证明所有组合的同时占用。非TAA组合中15/16/17/22缩为1×1，composite6/7关闭；不同维度也有各自用途。任何具体复用仍需按启用组合、格式、尺寸和最后读取位置判断，目前未据此分配新附件 |
| 第五批A03：textureGatherOffsets可直接省16角点查询 | 收益未成立。该指令一次返回4个值，偏移须为整数常量，不会一次返回4组共16个角点；Astra已用普通gather一次取4角，核位置与畸变/接收面比较还有自己的约束。[Khronos定义](https://github.com/KhronosGroup/OpenGL-Refpages/blob/main/gl4/textureGatherOffsets.xml)不支持把新指令名称直接换算成省算 |
| 第五批A18：已有currentRenderedItemId，所以手持光只缺颜色 | 部分成立。按手持物分色可以做，但currentRenderedItemId标识正在绘制的物品，并不在绘制地形时提供玩家左右手物品身份；现有astraHeldLightBase只保留两手最大光级。仍需手持物身份与两手强度的输入，不能将现有物品模型分类当作完整手持照明输入 |
| 第五批A02：CAS只需在display尾部加调用 | 集成成本描述不足。当前display尾部才生成显示颜色，周围纹理输入仍是HDR；CAS需要相邻像素同一显示阶段的颜色。FXAA组合已有附件13可用作显示输入，但CAS与FXAA的先后及组合读取成本仍需明确，不能据“0新阶段”推导近乎零成本 |

用户已授权落地筛选后保留的候选。V2、A28、A18、A05及限定输入范围的A01已写入源码，行为和成本统一见[实现与限制](实现与限制.md)。V2使用stars=false：本机ShaderProperties将stars交给handleBooleanDirective，报告的off写法不适用。A18按[ShaderDoc手持物输入](https://github.com/IrisShaders/ShaderDoc/blob/master/uniforms.md)接入两手身份，关闭旧主手替换规则；不是将当前绘制物品ID当作两手身份。A01已直接读取本地TrueLightFX的directionalLightmap.glsl，它从屏幕导数估计的方向主要在表面切平面内；Astra当前平面法线不能据此可靠推得完整光源方向。因此自写手持位置方向与下界已有三维场梯度，没有复制BSL谱系的方向光表达式，也没有宣称普通标量方块光已方向化。

C02暂不采用。已直接读本地_analysis/batch5_unpack/velocity-shaders的program/deferred.fsh、global/water.glsl及shaders.properties：每边四分之一尺寸的深度只对四个偏移样本取最大值，水面搜索和细化也使用该低分辨率结果。它不是完整4×4区域的保守深度范围，最远值也不能代表区域内所有细叶；不能据此跳过Astra原始四角交点。安全的共享范围另需完整覆盖、深度精度和消费者改造，新增生成/读取成本目前没有收益依据。当前默认岸上SSR关闭，更不能把这项直接当作水面100降到75 FPS的修正。没有新增粗深度附件或削弱原始深度、实体和颜色配对。

PCSS、GTAO、CAS及镜头效果仍是各自可选增强，不能因列在报告前面就排到水面降帧与入水问题之前。报告中未在此核对的参考包实现和许可仍只是调查入口。

## 2026-10-17新增机制报告核验

已完整阅读[机制报告](../shader_research/2026-10-17-可参考机制调研-Astra缺口.md)、[引擎报告](../shader_research/2026-10-17-Iris1.11.2引擎能力实测.md)，并按问题读取三份subagent分项记录、参考源码与本机Iris 1.11.2+mc26.2的相关字节码。原报告未改，未据报告新增光影功能或变更引擎开关。下面是对报告成立范围的修正，不代表游戏画面或GPU收益已确认。

| 报告位置 | 核验结论与依据 |
|---|---|
| 主报告第三节1：主世界光照仅按光源距离，屏幕空间遮挡可修复隔墙火把光 | Astra放置光源读取的是游戏传入的lightcoord.x，经local_light_components的pow4处理；只有独立手持光自己计算距离。不能据此宣布普通火把不经墙体处理。Velocity的blocklight_shadows.glsl根据屏幕光占比梯度和前景深度估计遮挡，最后将整幅Color乘暗，不是实际光源到接收面的可见性判断。可以作为局部观感增强研究，尚未证实Astra存在对应隔墙缺陷，不列为必修或最便宜方案 |
| 主报告第三节1、第六节2：19已有方块光颜色，可直接提供光占比 | 不成立。surface_buffers.glsl中19为R11F_G11F_B10F环境光，20为法线及接收资格/顶点AO；diffuse.glsl在加入局部光之前保存ambientLighting，lit.fsh写入对应ambientRadiance。19/20还仅在SSAO组合启用，默认均衡没有可直接读取的全屏方块光占比 |
| 主报告第三节5、第六节1：阴影末端是否衔接lightmap未明 | 已有等价分工。shadowmap.glsl::static_shadow以原版天光得到替代遮挡，shadow_coverage随距离和贴图边界渐弱；diffuse.glsl::surface_shadow_light按coverage混合替代遮挡与真实阴影。STATIC_SHADOW_FALLBACK开启时生效；水下无覆盖处按现有规则禁止无依据的直射光。不是新增缺口 |
| 主报告第三节6：缺SEPARATE_HARDWARE_SAMPLERS意味着缺硬件阴影比较 | 当前已按ASTRA_SHADOW_FILTER_MODE声明sampler2DShadow并使用带参考深度的textureGather/texture。新特性可用于分别提供原始深度和硬件比较采样器，不是从无到有的硬件比较能力；不能凭缺少HW后缀认定现有比较全在软件执行 |
| 主报告第三节7.2：TAA缺邻域方差裁剪 | 不成立。taa_resolve.fsh现有3×3邻域mean/second统计，sigma=sqrt(second/9-mean²)，以mean±1.25sigma收紧YCoCg范围后再钳制历史。Catmull-Rom插值是另一项尚未接入的增强，但当前taa_history还对四个历史像素分别核对深度，替换时须保留表面有效性处理 |
| 主报告第七之补1：实体地形入口与early-Z收益 | 入口真实存在。本机ProgramId有TerrainSolid/TerrainCutout，ShaderKey的原生及Sodium两种地形路由分别映射到它们，Solid使用AlphaTests.OFF、Cutout使用HALF_ALPHA。lit.fsh列出的四处透明裁切中三处属于天气条件，并非都进入地形程序；地形仍有共用alphaTestRef裁切。分开无裁切地形程序值得保留，但不能将discard影响扩大为所有GPU上全部提前深度剔除必然失效，亦不能据此宣布收益最大。[NVIDIA说明](https://docs.nvidia.com/jetson/l4t/Tegra%20Linux%20Driver%20Package%20Development%20Guide/graphics_opengl.html)明确限定部分平台，当前实际驱动收益未取得 |
| 主报告第七之补2、分项A：allowConcurrentCompute的两种相反结论 | 本机ShaderProperties解析键确为allowConcurrentCompute，ComputeProgram.dispatch在关闭时增加8232可见性屏障；8232为多个标志的组合，不是单独SSBO标志。ShadowCompositeRenderer.renderAll在每个有计算任务的编号阶段结束后，仍执行8232屏障，再进入下一阶段。Astra的shadowcomp到shadowcomp8是独立编号阶段，因此不能仅凭九步串行依赖推导该开关必然破坏九步顺序，也不能推导九步将并行加速。首阶段捕获写入到计算读取及其他阶段依赖尚需完整核对，当前保持开关未声明。[Iris阶段说明](https://shaders.properties/current/reference/programs/overview/)也区分同一阶段的_a至_z与不同编号阶段 |
| 主报告第七之补3：centerDepthSmooth是采样器而非uniform | 混淆作者接口与引擎内部。直接读取本机CompositeDepthTransformer.transform确认，它匹配uniform float centerDepthSmooth，注入sampler2D iris_centerDepthSmooth，再把引用改写成texture(...).r。作者仍按浮点uniform声明，内部用纹理实现；不能据CenterDepthSampler类名否定公开输入。[Iris输入文档](https://shaders.properties/current/reference/uniforms/camera/#centerdepthsmooth)同样保留浮点声明 |
| 主报告多处：只有colortex7空闲，故额外双附件不能做 | 沿用前文裁决：全树编号出现与某一维度/组合中的同时占用不同。当前非TAA的15/16/17/22、非SSAO的19/20/21/26/27已缩为小图；能否复用须按具体生命周期与格式判断。不能据并集阻断功能，也不能因此直接覆盖已有用途 |

实体地形入口拆分与SMAA已按后续授权落地，当前行为及代价见[实现与限制](实现与限制.md)；PCSS和Catmull-Rom仍为较低优先候选。研读的Grindstone end_of_frame.json包含边缘、权重、混合三个阶段，随后还有独立CAS，不能把其阶段数量直接当作Astra新增成本。Astra实际采用SMAA官方内核，没有搬其CC BY-SA的redmean.glsl；来源登记在THIRD-PARTY。

PCSS是视觉增强，不是树影闪烁的已证实修正；四个搜索点未发现遮挡不证明原16角点范围全亮，不能借此取消已有细叶覆盖。Arc::FindBlockerDistance还将hitDist先max到0，再用step(0,hitDist)计数，会把零距离也计入分母；报告将它描述为仅统计真实遮挡的平均距离并不准确，不应原样移植。屏幕空间间接光、3D噪声及显式flip仍为按用途选择的候选，缺少名称不构成必须补齐的功能，也不改变水面帧率与入水反馈的优先级。

## 第六批两份报告的采用范围

对应[第六批未覆盖功能](../shader_research/2026-10-17-第六批调研-Astra未覆盖功能.md)和[文件名标2026-10-18的新参考包调研](../shader_research/2026-10-18-第六批-新参考包调研-Astra缺口.md)。前者在本轮读取期间补写的P组建议、已有能力及末尾说明已一并纳入。用户授权按适用性直接修改，不受改动规模限制；报告建议仍需与源码和当前目标对应，不能把未实现的新功能一律当成缺陷。

本轮采用三维度地形入口拆分，以及此前保留的SMAA 1x。后者复用现有显示准备与final，新增两个阶段并交替使用附件7的两侧图像；完整实现、格式和资源开销只在实现说明维护。默认画质仍使用关闭/FXAA，没有把所有新增效果捆入均衡预设。以下为其余条目的判断与接续条件。

| 条目 | 当前决定与依据 |
|---|---|
| 第六批P1：地形实体/镂空拆分 | 已落地。保留镂空与旧入口的裁切及全部照明、材质、AO和元数据；实体键自身为OFF-alpha。减少裁切需求不等于所有显卡上必然恢复某种提前剔除，也没有本轮游戏收益数据 |
| 第六批P2：所有手写裁切入口alphaTest=off | 未批量采用。实体键自身已OFF，不依赖新增键；其他程序原始贴图透明度与最终输出透明度不是同一数据，不能凭都有discard认定两判断等价。报告称weather/particles没有手写裁切也与当前共享lit入口不符。保留原阈值与引擎状态，避免将去重扩大成裁切行为改变 |

## 不重新尝试的旧方案

- SSR共享搜索、直接屏幕推进和空段加速的既有适配没有取得值得采用的收益；沿几何水面搜索会削弱波浪扭曲，收益不足。无新证据不重复开展同一候选。
- 单像素倒影取色会损失边缘过滤，减少四角补漏、缩短细化和提前削减细波也没有足够收益依据；保留已选单像素折射，不把折射取舍扩成所有倒影取色。
- Photon仍每帧搜索，再取历史颜色和雾，不能当成省掉本帧搜索；MakeUp固定距离投影损失真实位置与遮挡，不采用。
- 主世界阴影不新增纹元跳变或透明裁切抖动，避免周期移动和树冠密度变化；不反转植物锚点、不删径向平方、不因全包同名声明就判断维度附件冲突。
- 云历史的消费坐标需要消除生产端网格偏移；平滑天空底色表不应塞入消费端高亮和调色，避免重复施加。高档云优先质量，不采用棋盘格替代四射线。
- 已有零贡献裁减、缓存和紧凑格式不重复列为新增功能；代码更短、读取更少或外部包宣传更快，都不能证明Astra整帧收益。
