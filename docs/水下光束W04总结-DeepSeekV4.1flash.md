## 0. 一页结论

1. **病因一致**：五份意见独立得出同一结论——束形由预烘 2D 图的 `pow(envelope,6~10)` 门控决定，而不是由「阳光方向上的真实遮挡」决定；叠加「源图细波层被抗混叠清零」「区间两端式遮挡」「消费端 mip 预滤」「0.25× 体积缓冲」四层压制。几何投影本身**没有错**（三份独立证明），不要再动它。
2. **执行线已是 step5**（工作页指定）：先做 step5 §9 的三个零成本验证（强制 `resolved=1`／包络幂降到 1／`colortex1` 提到 0.5），用画面确认归因，再选路径 A 或 B，默认 B。
3. **但路径 B 必须同时修消费端 LOD，否则只兑现约一半（本次复算发现，见 §4-d）**。逐级核算「有效细节下限」（生产者 `resolved` 与消费端 mip 读的有效核一起算）：

   | 配置 | 生产者后含哪些层 | 消费端有效核 | 消费端后含哪些层 | 有效细节下限 |
   |---|---|---|---|---|
   | 现状（512²/128 格，CELL=0.25，`lod≈1.9`） | L3–L6 | 0.92 格 | **只剩 L5/L6** | **≈1.58 格** |
   | 路径 B 仅改生产者（1024²/64 格，CELL=0.0625） | L1–L6 | `lod` 被夹到上限 3 → 0.50 格 | L3–L6 | ≈0.66 格 |
   | 路径 B + 消费端 LOD 改屏幕足迹（近处 lod≈0） | L1–L6 | ≈像素足迹（0.01～0.1 格） | **L1–L6** | **≈0.11 格** |

   即：现状的可见细纹实际只来自 L5/L6（1.58/3.16 格）——这正是「无质感」的量化含义；只做路径 B 能把它推进到 0.66 格，**再补上 LOD 修正才能拿到 L1/L2（ITT 那种流动细腻感）**。两项是配套的，缺一项就少一档。
4. **性能与画面都还没有读数**：五份文档的「成本可能更低」都只是预期；144 FPS 目标与观感都要实机测量，尤其路径 B 的生产端成本翻四倍（1024²）。

## 1. 症状 → 归因（含实测值）

复算方法：Node v22 + 真实 `Astra/shaders/textures/itt-water-noise.png`（64×64，REPEAT），在 128×128 格窗口、0.25 格步长上重建 `itt_water_waves.glsl` 的六层波场与 `itt_water_beam_envelope`；脚本与复现要点见[复核报告](水下光束同类意见复核-DeepSeekV4.1flash.md)附录 A。

| 用户症状 | 机制 | 实测数字 |
|---|---|---|
| **像柱子** | 光量图是 XZ 的二维函数，采样点沿视线的横向位移只有几格，远小于纹距；且决定束形的 G 通道与真正的光量 R 几乎不相关 | 特征间距 **11.5 格（x）× 25 格（z）**；`corr(G,R)=0.046`；动态度 G:R = **4.4×10³ : 1.1×10²** |
| **位置乱七八糟** | 亮带位置由包络纹路决定，与上方遮挡无关；门控取 6～10 次幂后只剩少数大块连通亮区 | `pow(env,6)`：mean 0.265，`>10%·max` 覆盖 **62% 面积但只有 5 个连通区**；`pow(env,10)`：40% 面积 / 19 区 |
| **固定** | 场是世界锚定的二维图案，与太阳/云/遮挡无关；而真正快的成分（L1/L2、R 的 0.5～2.5 格结构）分别在生产者与消费端被滤掉 | 包络漂移实测 **1.5 格/秒**（层 5/6 各 1.03/1.73，约 8 秒一个纹距）；R 的细结构被 0.92 格 mip 模糊压制 |
| **毫无质感** | 两级滤波串联：生产者按 0.25 格足迹的 Nyquist 判据把 **L1 清零、L2 只剩 0.101**；消费端再按积分足迹预滤到 **lod≈1.9（有效核 0.92 格）**，把 L3/L4 也一并抹掉——**净效果是可见细纹只剩 L5/L6（1.58/3.16 格）** | 逐层 `resolved@0.25`：L1 0.000 / L2 0.101 / L3–L6 1.000；消费端 0.92 格核下 L3 1.40、L4 1.31 均已归零、L5 0.586（存活 0.97）；层胞元 0.11 / 0.23 / 0.66 / 0.71 / 1.58 / 3.16 格 |

补充事实（都影响修法）：

- **碰撞光量与太阳方向无关**：`landingOffset`（因而 `caustic³`）只由波面法线决定 → 图案形状不随太阳移动，验收不能用「朝光变亮」当判据。
- **软限幅不是主因**：实测 `caustic³` 范围 0.008～**6.13**（中位数 0.100），过 `e/(1+0.25e)` 只压缩高端约 2.5 倍（→2.42），中位数几乎不变（0.098）。ITT 同式的中位数是 0.107。**这一项应降到可选低优先。**
- **闭式**：ITT 的碰撞距离 `dist = |tan2θ|`（`R/R.y` 的 y 恒为 1，`lookupCenter` 的 +1 正好抵消）；hy4 的 `2|n_xz|` 是小角近似，本场倾角 ≤15°，`dist` 误差 <11.5%、立方后峰值差约 34%。

## 2. 五份意见的共同结论（可直接采纳）

1. **删掉 `itt_water_beam_envelope` 与 `pow(6~10)` 门控**，束形交还「碰撞光量 × 真实遮挡」——这是各份一致、且被实测支持（相关系数 0.046）的第一优先项。
2. **相位改回整帧固定的折射太阳方向**，用 ITT 的 `MiePhaseFunction(0.7,·)`；现版本（逐 texel 波面斜率 + g=0.45 + 60% 各向同性）的方向性只有 **4.3:1**，ITT 是 **182:1**（hy4 复算，本次逐值复核通过）。
3. **遮挡改为逐样点**（或至少加中点查询）；现版本只在 7 个区间的两端各查一次、区间内线性插值，细于 3.71 格的遮挡（树叶、栏杆、船底）整段漏掉。
4. **补回水面透光项**：现体积只读 `shadowtex1`（不透明），丢掉 `design.md:297` 原设计要求的「`shadowtex0`/`shadowcolor0.R` 确认光线经过水面」；Solas 的水下项正是 `shadow1·(1−shadow0)`。
5. **距离改连续**：删 `1−smoothstep(14,26,d)`，用 ITT 的 `1/max(3,0.1d)`，范围提到 32～40 格；近端淡出保留但 ≤1 格。
6. **不要时域抖动**：水下 TAA 退出（`taa_jitter.glsl:11,28` 返回零抖动、`taa_resolve.fsh:101` 放弃历史），逐帧抖动只会变永久噪点；要细节靠密度 + 空间抖动（Solas 的 `exp2(dither)·2^i` + 静态空间噪声即可）。
7. **删死代码** `global/water/shaft_history.glsl`；不复活固定光圈、四水深聚光表、局部反求、逐格 DDA；不靠加步数做「晴天更多更亮」。
8. **保留 Astra 正确的部分**：真实水位的逐点入射投影（比 ITT 把投影面设在 y≈0 更准）、薄水/侧流水跳过、Solas 的距离/昼夜/天气强度链、消费端深度加权重建。

## 4. 执行线：step5 为主线 + 本文复核的七处修正

**step5 §9 的三个零成本验证（先做，它们是分派依据）**

1. 把 `itt_wave_noise` 的 `resolved` 临时强制为 1.0 → 看细碎感是否回来。不成立就**不要**照路径 A/B 实施，先重新归因。
2. 把 `pow(envelope,mix(10,6,clearDay))` 改成 `envelope`（1 次幂）→ 看硬边亮条是否变宽软带（单项收益最大、风险最低）。
3. 把水下光束的 `size.buffer.colortex1` 从 `0.25 0.25` 提到 `0.5 0.5`，同时记帧率 → 看轮廓阶梯与帧率代价。

**在此基础上执行 step5 的路径 B（默认）**，但先修正/补齐下面七点：

| # | 修正/补充 | 依据 |
|---|---|---|
| a | **L2 的 `resolved` 是 0.101**，不是 0.20（L1 0.000 一致） | §1 实测；step5 的「跨越 1.10」是对的，只是查表查错 |
| b | **1080p 下 `colortex1` 是 480×270**（0.25×），不是 270×152 | `shaders.properties:18-33`；四个出厂档案 `OVERWORLD_BUDGET=1` |
| c | 路径 B 的 1024²/64 格（0.0625 格/纹素）下，**L1 的 `resolved` 是 0.97**（step5 写 0.89），L2–L6 = 1.00 | `footprint·f`：0.58 / 0.28 / 0.09 / 0.09 / 0.04 / 0.02 |
| d | **必须同时改消费端 LOD（本文新增的关键发现）**：`sourceLod = clamp(log2(sourceFootprint/CELL),0,3)`（`light_shafts.glsl:146-147`）随 `CELL` 减小而顶到上限 3；`CELL=0.0625` 时有效核 = 0.5 格 → L1/L2 被再次抹掉，路径 B 只能兑现「有效下限 1.58 格 → 0.66 格」的一半收益。改为**屏幕足迹驱动**（`textureGrad` 或用 `dFdx/dFdy` 推 lod）或近处 lod 0，才能拿到 L1/L2（0.11/0.23 格）；远处仍由足迹自然增长抗混叠。三项配套表见 §0 第 3 条 | §1 逐级核算 |
| e | **路径 B 第 2 条「遮挡仍由现有区间两端查询负责」与它自己 §2.5 的归因冲突**：保留了自己认定的根因。至少按它的最小改动集第 4 项补区间中点查询；更彻底是各份共同意见的逐样点遮挡（含 Solas 的 `V1−V0` 透光项） | step5 §2.5 vs §4 路径 B |
| f | **云影默认不参与**：ITT 无条件乘整帧云影标量（`UnderwaterVolumetricFog.glsl:93`），Astra 只在 `CLOUD_MODE==CLOUD_PLANAR && CLOUD_SHADOWS` 时于入水点取一次，而 `CLOUD_SHADOWS` 在出厂档默认关闭——「固定感」的另一半在这里。建议体积内无条件调用现成 `astra_cloud_transmission`（非平面云会自动返回 1） | `light_shafts.glsl:105-108`、`shaders.properties:559-562` |
| g | **mip 声明位置**：`colortex29MipmapEnabled` 现写在消费它的 composite2 内（`light_shafts.glsl:70`），Iris 在该 pass 结束后才重建 → 同帧读到上一代 mip。若保留 mip 通路，声明应移到生产者 | `_analysis/iris-runtime/CompositeRenderer.txt:331-350,587-618` |

**路径 A 的取舍**：step5 已自行否决「把 L1/L2 频率降一半」（会让层数从 6 退化为 5），并把「放宽 `resolved` 判据」定位为「只能减幅、不能造信息」——这两点正确。路径 A 的净效果是「去掉柱状孤岛」，**拿不回 ITT 质感**；若用户要的是质感，只能走 B。

**其它可选（不建议本轮做）**：统一波场（把 `shadowcolor0.a` 的焦散 focus 改由 ITT 波面算，使床面/界面/体积同源）——收益是三者位置一致，代价是改床面观感、且 ITT 的 crest 层只有 C¹ 分段（Hessian 不连续需额外平滑）；`fract` 平铺（GLM P1-2 首选）应否决，128 格世界对齐图不该引入周期重复。

## 5. 验收判据（合并各份，标注有效性）

**可用**：① **锚定**：桥/树/船下的束纹边界必须与这些遮挡物投到水下的边界一致；移动相机时束纹世界位置不变、只被新遮挡改变。② **光源**：遮住太阳或推到夜晚，体积光应基本消失。③ **动态**：静观 10 秒，束纹应随波面流动（现状包络仅 1.5 格/秒）。④ **数量与宽度**：晴天亮纹数量增加且变宽，不是「亮点变多」。⑤ **近处**：手、方块边缘、水草在 1～2 格内不被糊掉。⑥ **帧率**：原生 1080p、均衡档、同一水下机位，30 秒均值与 95 分位，改动前后对比；**不接受源码推断**。⑦ **不回归**：浅青→深蓝过渡、深水遮蔽、手部排除、Bloom 两条路径一致。

**不可用**（本次复核新增）：① 「朝太阳看变亮」不能证明结构正确（图案与太阳无关）；② 「上下移动相机光束不跳」不能证明窗口改动有效（本来就不跳）；③ 水下「抖动后是否噪点」不能判断采样质量（无 TAA 必然有噪点）。

**建议新增一个只读调试视图**：水下直接把 colortex1 显示为黑底亮束，并单通道显示「入水透光项」与「碰撞光量」——这轮反复的根因就是没有能直接看见「束形归谁」的手段。

## 6. 需要用户裁决 / 需要实测

**裁决**：① 走路径 A 还是 B（默认 B，但要接受生产端成本翻四倍）；② `UNDERWATER_SHAFT_DISTANCE` 是改语义（真正的远距上限）还是改标签（近处淡出）；③ 光量图 R 是否保留 Fresnel 因子（保留则与 Solas 透光项略有重复计数）；④ 云影是否无条件参与；⑤ 是否统一波场（改床面焦散观感）。

**实测**（目前全部空白）：改动后的质感/数量/动态；路径 B 生产端 1024² 的成本；`colortex1` 0.5× 的帧率代价；无 TAA 档下空间抖动的可接受度；立方峰值对 Bloom 的影响。

**回填约定**（step5 §10 + [docs/README](README.md)）：改动完成并按 §5 验收后，结论并入 [实现与限制](实现与限制.md) 与 [当前工作](当前工作.md)；专题意见稿只在仍有分步讨论价值时保留。

## 10. 当前实现与原意见的区别（主代理增补，2026-10-11）

原意见中的“已指定按step5执行”和第9节的线性斜率缓存描述不作为现行要求。各条已由主代理核对并分别决定，用户随后要求的九份独立审查也已收齐，确认项在报告收齐后统一实施；详细裁决见[主审裁决](审查/2026-10-11全量审查/主审裁决.md)。

现行源图缓存同帧非线性碰撞光量，普通像素R、零号RG窗口元数据，使用RG16F；界面直接计算同一波场。非线性变换与mip平均不能交换，因此它与原线性斜率方案不是滤波意义上的数学等价。格式压缩比较的是同一光量从RGBA16F/B改存RG16F/R，保留半精度；不混同这两种比较。波场细层可解析性、光量过滤顺序、八点积分、覆盖保护及完整mip计时由[实现与限制](实现与限制.md)统一维护，不沿用本稿旧矩阵或阶段数字说明现在的状态。
