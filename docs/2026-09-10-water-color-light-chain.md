# 水体颜色与水下亮度：实际链条及本轮改动

用户已确认阴影问题修好。本轮目标是水外青色、水下 Solas 光感，以及准备其他部分的并行开发目录。阴影投射数据输出的修复保持原样；当前尚不能宣称画面与参考完全一致。

## 从外面看水：颜色在哪里产生

实际顺序为：方块纹理和生物群系颜色 → 解码 → 水底环境光与直射光 → 主颜色缓冲 → deferred 复制到 colortex4 → 波场法线与折射命中 → 对命中点施加水深吸收 → 与天空／地形反射混合 → 相机空气雾 → 明暗映射 → 输出。

其中水深吸收为：`T = exp(-clamp(垂直水深+1,0,16) * (1,0.1875,0.0625))`，默认比例与 Steadfast 的 `(16,3,1)` 配套深度归一化完全相同。它只是逐通道乘数，不是直接输出青色的调色器。对已经缺少绿色、被截断或主要由蓝色反射构成的输入重复乘这个系数，不会恢复参考输入。

本次明确看到的差异：

1. Astra 用自己的天空环境光和太阳色照亮水底。Steadfast 的 `skyAmbientMinishita`、`directLightSurfaceMinishita` 由另一套大气计算生成，环境项含太阳反弹光，直射项还有水底天空光衰减。仅复制吸收常量没有复制这段输入。
2. Astra 的 `colortex0`、`colortex4` 没有声明 HDR 格式；Steadfast 的主颜色与折射背景都明确为 `R11F_G11F_B10F`。线性场景若进入默认归一化缓冲，超过范围的颜色分量在吸收前就丢失，之后调色无法还原其通道比例。此前文档把缓冲称作 HDR，并不等于实际配置如此。
3. 最后的反射来自 Astra 自写的天空模型。即使透射已变青，蓝色天空反射仍会参与最终像素；吸收函数不会处理反射那一支。
4. 原有组合器忽略入参的水面自身颜色，仅组合透射与反射。Steadfast 在室外满天空光时该自身项权重为零，但地下和水侧面不是零；这些边界的完整对应仍需继续处理，不能用室外公式覆盖全部场景。

## 为什么多轮修改仍然蓝

- 早期同时存在入射吸收、界面吸收和蓝色体积散射，改其中一个末端系数无法统一它们。
- 随后虽然删除了重复吸收并移植参考比例，水底照明和反射仍是 Astra 的输入，颜色自然没有自动变成参考结果。
- 上一轮新噪声名字注册错误，使波浪与折射失去正确输入；该错误已在用户确认阴影修好之前修正。
- 更早的格式错误被误归因为 Iris 不支持格式声明，因此全部删除。Steadfast 当前可用源码中实际有 `const int R11F_G11F_B10F = 0;`，再用该名字声明目标格式。Iris 读取名字，GLSL 也需要名字有定义；原先只写一个未定义的格式名，或干脆删掉整个格式声明，都不是完整接法。

本次改动位置：

- `global/water/reference_light.glsl`：移入 Steadfast 的天空积分和配套入射光计算，名称限定在水体模块。
- `program/scene.glsl`：从水面阴影元数据确认位于水柱内的接收点，空气侧采用参考入射光；公共陆地光色接口保留。
- `program/water.glsl`：空气侧水面反射使用参考天空计算。
- `lib/water_buffer_formats.glsl`：主世界主颜色、折射背景使用参考 HDR 格式，补足 GLSL 名称定义。

这解释了应改的是“进入吸收的光与缓冲、反射支路”，而不是继续猜一组三通道水色常量。上述阴影水柱识别对被其他投射物遮住的水底并不完备，这部分也不宣称已完全对应参考。

## 水下为何还有夜视感：哪些照明分支仍不相同

旧链条为：部分 Solas 环境／直射公式 + Astra 最低环境光和局部光 → Astra 水面天空反射 → Astra 泛光相加 → Solas 水雾与光束 → Solas 明暗映射 → Astra 调色。

因此它此前是混合链条，不能因为函数叫 Solas 就称为完整移植。具体差异包括：

- 缺少阴影覆盖时，Astra 允许天空光生成直射后备值；Solas 的 `getFakeShadow` 在水下明确返回零。现已按参考关闭这条无实际遮挡依据的水下直射来源。
- Astra 默认最低环境光为 `(0.00264,0.0064,0.008)`；Solas 默认由 `(125,130,135)*0.4/255` 平方再乘 0.1 得到，约 `(0.00384,0.00416,0.00448)`。原先绿色和蓝色暗部被抬高；现接入参考最低光。
- 水下水面的反射原先仍来自 Astra 天空。现接入 Solas `sky.glsl` 的日夜大气表达式，按世界坐标适配。该函数保留其颜色域，避免再额外解码一次。
- 原先泛光是对雾前颜色做高亮提取，再相加。Solas 对水雾、光束之后的场景做四层纹理块模糊，采用亮度对比域混合。现按参考的层级、36 个采样权重、编码、重建和混合公式接入。
- 原先使用即时雨量，现水下参考颜色与光束使用 Iris 的 wetness；晴天不因此改变。

当前顺序：水底照明 → 水面合成 → composite2 光束积分 → composite3 水雾与光束合成 → composite4 Solas 四层泛光 → final 泛光混合、明暗映射及显示输出。新增阶段仅在主世界启用；泛光关闭时不读取该结果。

## 尚不能宣布完成的部分

仍未得到本次改动后的运行画面，不能把源码对应和编译结果替代视觉结论。Solas 的 AO、体素局部光、材质高光、时间重映射生成的光方向、完整反射缓存及 TAA 尚未一并移植；地下、水侧面、被屋顶遮挡的水底，以及 HDR 对其他主世界亮物的影响也缺少本轮画面证据。“一模一样”目标保持未完成。

五个独立 worktree 已建立，区域和可复制提示词见 [并行开发说明](parallel-development/README.md)。这些目录是供用户另开任务的工作区，未自动启动其他开发任务。

本轮 234 对着色程序经 NVIDIA OpenGL 编译链接，失败数为 0；改动文件已更新到现有整合包。该结果仅证明编译链接，不代表 Iris 运行时画面已与参考一致。
