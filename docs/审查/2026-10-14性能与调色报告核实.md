# 性能与整体调色报告核实

本轮根据用户提供的两份研究报告核对当前源码并实施适用部分。报告一为《Astra 光影可借鉴的性能优化与整体调色实践》，报告二为以“我无法直接访问”开头的研究意见。两位作者均明确没有读取Astra；报告一提供固定版本文件，报告二主要依据搜索及仓库主页。因此报告提出的是调查问题，不能据此宣布Astra缺少相应机制。原附件保留，不改写作者结论。

本轮以当前源码及必要调用方为依据，并在线读取报告一固定版本的Photon调色、云覆盖图，Complementary后处理和Solas云密度源码。核对得到：主要云调度、资源压缩和光照分工已有实现；实际需要处理的是隐藏的自然风格提亮/增色，以及可消除的重复运算。用户已要求云质量优先、水下沿用水面青色；这两项继续成立。

| 报告对应建议 | 核实结果与处理 | 依据与限制 |
|---|---|---|
| 一：云相交、地形端点、空密度先行；二：云零贡献裁剪 | 已有，不重复实施 | `clouds_planar.glsl::astra_cloud_interval/astra_planar_cloud`先求区间，真实端点截断，粗密度通过后才读细节及光照；几乎完全遮蔽后退出。保留原0.995阈值，不照抄0.99 |
| 一：主射线细节与二次光照分预算 | 已有，不再次降质 | 高档密度保留细节，首个可见位置的两次照明查询只读粗噪声；后续位置复用照明。Solas相似分工不证明Astra还需改写 |
| 一：风速感知、距离与遮挡的历史重建 | 已有 | `cloud_temporal.glsl`按相机前帧矩阵、云自身每秒沿Z移动1格的位移和代表距离筛选历史，维护帧连续性和尺寸；不是只混合两帧颜色 |
| 一：静止时跳过3×3历史夹取 | 所指开销在当前云路径不存在 | 云历史用2×2配对颜色/距离筛选，没有无条件3×3邻域，不引入新结构。场景TAA独立，不因云建议删除其拒绝条件 |
| 一：棋盘格更新高档云 | 不采用 | 会让部分像素依赖旧帧补齐；当前用户要求云清晰稳定优先，保留每像素四条当前帧射线。不以另包机制保证Astra无画质代价 |
| 一：低频覆盖图缓存 | 当前不适用 | Photon所缓存的是两次天气噪声及混合；Astra覆盖偏移只有天气标量，直接粗噪声查询本身就是主体形状。另建图会增加写入与读取，并引入插值误差，不能把Photon省一次读取套到Astra |
| 一：重复计算；二：每帧固定量移出像素 | 部分已有，继续实施剩余项 | 太阳、天气、基础云色、风摆相位等已在CPU准备；本轮把晨昏太阳色、晨昏色彩插值、未偏移太阳水平长度/方向移到同处。方向相关天空计算保留，数据不受空气透视开关控制 |
| 一：重复工作与条件历史读取 | 新增省算 | 高档逐段颜色恒定，不再重复累加同色并归一化；透明度及代表位置仍完整累计。高档空云在元数据读取前返回，省一次旧距离附件读取。浮点运算组织改变，未取得游戏GPU收益 |
| 二：背光/低天光统一跳过阴影 | 不采用统一门槛 | `diffuse.glsl`已有按材质和入射方向的裁减。叶片透光、半透明及水路不能统一用正面朝向或低天光拒绝，否则会改变遮挡与逆光表现 |
| 二：SSR粗糙度/Fresnel裁剪 | 已有相关取舍，不扩大 | 物体倒影默认关闭，开启时沿用0.36～0.50贡献窗口及真实深度/颜色配对。不照搬阈值进一步丢失倒影 |
| 二：实心独立阴影、HDR降格、无消费者阶段停用 | 已有 | 实心阴影不读透明纹理/丢弃片元；主场景和水面快照已有32位浮点色；Bloom及各可选模块按实际消费者调度。含透明度历史、实体配对和高精度水下颜色不统一降格 |
| 二：Bloom金字塔、CAS合并；一：全屏阶段合并 | 已有低尺寸Bloom，不新增CAS或硬合并 | Bloom使用四分之一尺寸mip链且默认关闭；CAS锐化会改变边缘。关闭Bloom的水介质已合并进显示，FXAA前显示与最终噪声分工保留，不为减少阶段破坏读写顺序 |
| 一、二：源光颜色与全局调色分开 | 已有并保留 | `overworld.glsl`分别生成直射与环境光，自然日光/环境增益不是全屏黄蓝滤镜；天空、云及水有各自照明消费者。不新增一套重复白平衡 |
| 一、二：高亮柔和压缩、趋白 | 实施自然Uchimura变体 | 用最大分量进入包内原Uchimura标量曲线，共用比例压缩RGB，真正高亮才逐渐趋白。AgX等保留；没有复制Complementary函数。具体阈值为Astra艺术参数，画面是否符合清新仍缺用户反馈 |
| 一：18%灰中心的映射前对比度 | 实施亮度版本 | 自然风格在手动曝光后、映射前调整亮度，共用RGB增益，100直接退出。借鉴分工而非照搬Photon逐通道表达式；原配色及其他维度保持原显示曲线，旧非100值会呈现不同明暗 |
| 一、二：避免灰暗部、过度增色 | 实施已确认的隐藏处理移除 | 自然风格原有固定0.10暗部/中间调抬升，且饱和度按手动值102%计算；两者取消。纯黑仍为零，Uchimura本身暗部形状仍在。中文/英文说明修准 |
| 一、二：饱和度与自然饱和度分开 | 已有 | `apply_vibrance`照顾低饱和颜色，现有两个滑条保留；不强制增加8%或改成仅对植被的材质补丁 |
| 一：绿色选择性修色；二：植被去绿、天光反弹与固定直射比例 | 本轮不采用未经标定的数值 | 植被透光及可选方向性天光已有。缺少当前材质/照明画面，不能把建议RGB比例称为精确色温，也不能保证局部绿色修饰不影响其他绿色方块；不新增逐材质调色 |
| 一：慢速曝光；二：自动曝光窄幅并开启 | 保留手动默认，不强制自动 | 自动曝光已有固定小网格、历史平滑和上下限，默认关闭。报告两种建议并不相同，不靠自动改变整图亮度解决当前配色 |
| 一：更多阴影/高光控件和风格；二：三套方向 | 沿用清透自然方向，不加档位 | 用户此前明确嫌设置杂乱和档位过多。现有曝光、四种映射、色温、饱和度、自然饱和度及分层RGB足以承载本轮调整 |

## 参考文件与使用边界

- [Photon固定版本的调色入口](https://github.com/sixthsurge/photon/blob/15458c0937f8647c37eb6a501bef5eb3bf3da31b/shaders/program/c19_color_grading.fsh)：`grade_input`在映射前处理曝光相关量与中灰对比度，`grade_output`处理选择性色相。本轮只借鉴职责分开。
- [Complementary固定版本的显示入口](https://github.com/ComplementaryDevelopment/ComplementaryReimagined/blob/c09950df0650b27dac260c1b0f69afc11387aa6f/shaders/program/composite5.glsl)：`DoCompTonemap`有高亮趋白及暗部处理；并非要求Astra复制全部曲线或数值。本轮没有复制该函数。
- [Photon固定版本的云覆盖图](https://github.com/sixthsurge/photon/blob/15458c0937f8647c37eb6a501bef5eb3bf3da31b/shaders/include/sky/clouds/coverage_map.glsl)：缓存前需查询天气覆盖/形状两种噪声，与Astra的覆盖标量不同。
- [Solas固定版本的云密度](https://github.com/Septonious/Solas-Shader/blob/ea1b4db6ea2e405674168baba3806c747079463d/shaders/lib/atmosphere/volumetricClouds.glsl)：完整查询与低细节照明查询分开。Astra既有两次粗查询已经符合此方向。

Steadfast报告一的新`src/`结构与报告二/本地0.8.0不是同一版本；Mellow仅有搜索信息的段落也不视为读到源码。本轮没有照抄它们的新实现，也没有新增依赖、纹理或代理调用。报告二关于“零损失”“可以忽略开销”“公开算法无许可限制”等概括不采为工程或许可事实；实际出处维护于包内THIRD-PARTY。

## 交付与未确认项

源码修改由主Agent直接完成，按既有授权提交远程并同步开发实例。实例已有手动饱和度90、自然饱和度90，保留这些值，不重置用户调色；其余旧值也按现有选项保留。自然风格且选择Uchimura时才使用新高亮处理，选择其他曲线仍得到取消隐藏增色、提亮及新对比度的变化。

本轮依据为源码和参考文件读取，没有取得修改后的Iris实际画面或整帧读数。不宣称帧率增加某个百分比、所有云视角无锯齿或调色已获用户认可。用户此前抬头看天空约160 FPS不能作为本轮效果。下一轮若有画面偏差，沿现行照明、映射及显示分工定位；不据本报告恢复棋盘格、降低高档云质量或改回独立灰色水雾。

## 第三份补充报告的核实

用户随后提供《Astra 光影：进一步性能优化与整体调色源码调研》。作者称读取了远程目录，但自述没有保留能够复核的GLSL正文，表格仍把具体问题列为未知；不能把目录枚举当成逐行审查。报告给出的固定快照下`Astra/shaders/program/display.fsh`原始文件链接本次返回404，因此不认定该快照与本地现态一致，也不据此指控作者编造；核实以当前本地源码为准。报告“云清晰稳定已获用户认可”的说法超出本轮已收到的反馈：当前只有质量保留要求，没有新版实际画面的认可，工作页继续保留未知边界。

本轮重点读取`deferred`、`display`、`scattering`、水下合成及其雾、AO、Bloom、云缓存/历史调用，结论如下：

| 补充报告建议 | 当前核实与处理 |
|---|---|
| 同一端点距离、坐标共用 | 找到一处小范围重复：`scene.glsl::astra_fog_path`的失明、边界雾与普通雾分别计算同一`playerPos`长度。改为入口计算一次，再交给内部普通雾助手；对外入口保持。主世界部分失明且边界雾开启时，源码长度求值由三处集中为一处。原方向、距离响应、满失明提前返回及各维度介质分工保持；编译器可能已经合并原运算，不能把整理量当作GPU收益 |
| 共享所有深度、方向、水路距离 | 不统一合并。水下合成距离来自实际像素中心、手部修正及投影视点；最终Darkness采用自己的原视图距离，水下粒子已有同纹元距离复用；两类长度不相同。云轮廓导数需要在统一控制流准备，不能直接挪入地形条件分支 |
| 云时间域复用与可信度筛选 | 当前已有距离/相机/云风速筛选及空云拒绝，不增加棋盘格、历史模糊或减少四射线。补充报告没有提出新的可定位错误 |
| 循环不变量、重复纹理读取 | 晨昏固定量、云首个可见位置照明和后续颜色复用已在前述轮次处理；AO先拒绝深度/法线不匹配再读方向数据，雨雾阴影射线已在循环外投影。不新增局部大数组或附件缓存；不同LOD、偏移、纹元配对的读取不能据函数名相似合并 |
| 关闭后处理仍产生附件工作 | 程序与尺寸按消费者启用；Bloom强度为零时相关链退出，自动曝光只在开启时调度，空气散射与水下光束共享附件按实际用途保留。未发现报告所指“关闭效果仍写完整专用附件”的新增实例 |
| 先调日光、天光，最后调成像 | 与现行分工相同：日光和环境增益独立，水体同源青色，显示取消隐藏提亮/增色并使用自然高光处理。没有新画面偏差，不再盲改太阳、叶片或天空常数；不把报告推荐方向写成用户已确认审美 |
| GPU分项与运动画面计划 | 属后续取证建议，本轮未实施其采集流程，未新增依赖或计量工具。实际帧率、运动中云轮廓和调色认可仍未知 |

第三份报告未提供新增的Astra缺陷证据；本轮只落实上述已定位的同端点距离复用，其余沿用前述裁决。没有新增调色档位、外部源码或子代理调用。交付状态由当前工作维护。
