# Steadfast 0.8.0：性能结构、未完成部分与 Astra 适用性

日期：2026-10-02。对象是用户指定的游戏实例中的压缩包：

`D:\zhenhebao\.minecraft\versions\生电优化整合包 (Fabric)\shaderpacks\Steadfast-0.8.0.zip`

本次直接读取这份 199742 字节的压缩包，源码展开在 `_analysis/steadfast-2026-10-02/source/`。没有修改原压缩包或 Astra 的着色器。本报告依据源码及包内 README；帧率排名、具体驱动画面和用户实际启用的选项不由源码分析确定。以下“默认”指包内选项原始值，不代表游戏当前保存的设置。

## 1. 结论

Steadfast 很值得参考，尤其适合研究主世界的内存带宽、阴影绘制范围和重复计算。它在前向光照阶段完成大部分工作，使用紧凑 HDR 与单通道辅助缓冲，只保留少量全屏处理，并把大量与像素位置无关的表达式交给 Iris 的 CPU 自定义 uniform。

它的速度优势同时包含效果选择：这份包默认没有云，没有 Bloom、TAA、独立屏幕空间 AO 或体素彩光；植被阴影不随风摆动，玻璃也不投射彩色阴影。因此用户看到它比 Mellow 快是有架构依据的，但不能把所有差距都归为同画面下的算法优势。

作者在包内 README 明确承认默认配置水下仍有问题，下界和末地也缺少专门调校。源码另外注明流水、倾斜水法线及 Distant Horizons 衔接未完成，能找到两个具体的数值边界风险。适合按模块研究，整体水体或维度链路不宜直接搬入 Astra。

## 2. 性能来自哪里

以下 Steadfast 路径均相对于本次展开的 `source/shaders/`。

### 2.1 少量全屏阶段与小格式缓冲

默认帧内的主要全屏阶段是 `deferred`、`composite` 和 `final`。几何光照在 `program/world/lit.fsh` 内完成，`deferred` 负责背景副本及雾，`composite` 产生近似光束，`final` 平滑光束、调色及输出。没有为完整 PBR 材质建立多张大型 G-buffer，也没有 TAA 历史链。

| 资源 | 格式 / 大小 | 内容 | 源码依据 |
|---|---|---|---|
| `colortex0` | `R11F_G11F_B10F`，32 位 RGB 浮点 | 主场景 HDR | `program/post/postprocessing.fsh:30` |
| `colortex4` | 同上 | 不透明背景副本，供反射 / 折射使用 | `program/post/copy_and_fog.fsh:25` |
| `colortex2` | `R8`，8 位 | 天光强度 | 同文件 `:26` |
| `colortex5` | `R8`，8 位 | 背景天光副本 | 同文件 `:27` |
| `colortex1` | `R8`，宽高各一半 | 屏幕空间光束标量 | `program/post/noisy_godrays.fsh:97`、`shaders.properties:56` |
| `shadowcolor0` | `R16_SNORM`，16 位 | 编码的水面高度 | `program/shadow/shadow.fsh:26` |

相对于 RGBA16F 的 64 位颜色，32 位紧凑 RGB 的单张纹素占用减半；这只是格式层面的数量关系，不等于整帧耗时减半。半宽半高的光束目标只有全屏四分之一像素，且每像素只写一个标量。阴影颜色缓冲存的是水高度，不承担玻璃 RGB 透射色。

原始默认的 `REFRACTION_ASSISTED` 水吸收会让 `deferred` 输出 `405` 三个目标：原背景、加雾后的场景和天光副本（`copy_and_fog.fsh:101–138`）。它也有全屏复制成本，不能将“前向渲染”理解为没有辅助缓冲。

按效果关闭整个阶段的条件已有明确配置：

- `shaders.properties:27`：`program.composite.enabled=GODRAYS`。
- `shaders.properties:30`：`deferred` 由 SSR、折射或折射辅助吸收开启。
- `shaders.properties:79`：不绘制 DH 的远景阴影。
- `environment/clouds/cirrus.glsl:22`：平面云层默认 0；原版云也由 properties 关闭。

### 2.2 CPU 预计算覆盖面很大

`shaders.properties` 中的表达式包含日月进度、调色结果、直射光色、环境光色、水下雾色、屏幕倒数、光源方向变换、光束曝光、风相位以及 Minishita 的光照强度。

| 预计算内容 | 依据 | 意义 |
|---|---|---|
| 日月 / 直射颜色、介质相关调色 | `shaders.properties:379–449` | 减少片元里重复执行混色、亮度及天气修正 |
| 屏幕尺寸倒数 | `:775–783` | 用 uniform 乘法替代每片元重复构造倒数 |
| 风的共同时间相位 | `:969–984` | 与顶点位置无关的三角函数不必逐顶点重复计算 |
| Minishita 的日月照明与环境强度 | `:1230–1469` | 球体光照近似的一部分在 CPU 求值 |
| 日月方向的世界空间变换 | `:1490–1520` | 所有片元共享同一方向结果 |

天空不是全部交给 CPU：`environment/sky/minishita.glsl:389–567` 仍然在 GPU 计算视线相关相位、两处视线采样、对应的太阳 / 月亮光程及消光。两个视线位置使用 0.15 / 0.65 的非均匀取样；不能把依赖视线方向的积分直接移动到统一的 CPU 常量中。

此方法对高分辨率和大量可见地形很有意义，但会增加 Iris 的 CPU 表达式工作。生电整合包若已经受 CPU 帧时间限制，收益也会不同。优先转移高频重复且帧内一致的内容，避免为了数量而增加没有实际消费者的 uniform。

### 2.3 阴影覆盖范围与功能都很克制

默认分辨率 1536、距离 160、`shadowDistanceRenderMul=1.0`，实体距离比例 0.25（配置乘积为 40 格）。普通实体阴影开启，方块实体阴影默认关闭，DH 阴影关闭。

依据：`environment/lighting/shadowmap.glsl:53–59`、`environment/lighting/diffuse.glsl:47–54`、`shaders.properties:32–42,79`。

`SOFTER_SHADOWS` 默认开启，每次阴影查询有 **4 次硬件比较采样**（`shadowmap.glsl:62–81`）。四次采样各自带硬件过滤，不能当成只有 4 个底层纹素。相反，Astra 目前中档已采用 8 个成对深度 / 透射角点，它们的功能和成本都不同，不能只比较表面上的“4”和“8”。

另外两处省开销的方式很直接：

- 普通表面不能接收直射光时，在阴影查询前返回；玻璃和散射材质保留各自处理（`diffuse.glsl:286–308`）。
- 阴影范围之外先返回，最后 5 格淡出到静态近似（`shadowmap.glsl:208–216`）。

阴影顶点程序没有植被风摆动调用，而主场景有。它减少了阴影阶段的工作，同时导致摆动植被的投影与实际位置并不完全同步。这是效果取舍，不能当作免费优化。

### 2.4 小循环、有范围限制、低贡献直接返回

| 效果 | 实现 | 依据 |
|---|---|---|
| 水面视差 | 最多 4 次高度查询，达到高度后退出；默认 48 格内逐渐减弱 | `water/parallax.glsl:58,70–117`、`lighting/translucent.glsl:99–114` |
| 焦散 | 默认约 48 格范围；无可见贡献时在水高度与噪声采样前返回 | `lighting/shadowmap.glsl:109–117` |
| SSR / 折射求交 | 总循环上限 24，空处步长按 2 倍增长，命中后缩小步长，最多 4 轮细化 | `lib/raytrace.glsl:52–89,110–219` |
| 光束生成 | 半宽半高，每像素 1 次初始深度查询 + 8 次循环查询 | `program/post/noisy_godrays.fsh:53–82` |
| 光束平滑 | final 内 1 次初始查询 + 8 次循环查询；曝光为零则跳过 | `program/post/postprocessing.fsh:55–84,132–145` |
| 透明片元 | 低 alpha 先剔除；接近零贡献时不执行完整光照 | `program/world/lit.fsh:423–425,495–522` |

SSR 的 24 是包含细化过程的总循环预算，不能写成“24 粗步再加 4×4 细步”。DH 开启且近景查询失败时会再走一次远景查询，最多额外消耗一个同样的预算；这一回退还没有按失败原因细分。

光束本质上是屏幕深度向日月位置的径向采样，不是沿空间路径反复查询阴影的体积雾。它可以保留低成本光束观感，但无法替代 Astra 的所有体积效果或独立水下光束。

### 2.5 压缩顶点到片元的数据

`lib/encoding/face.glsl:139–165` 将法线八面体编码的两分量各量化为 9 位，再与 4 位材质 ID 拼到一个 uint 中；顶点与片元用 `flat out/in uint perFace` 传递（`lit.vsh:80`、`lit.fsh:204`）。

这避免传输一整组浮点法线及单独材质值，但实际接口布局与收益取决于驱动。它假设面内法线一致；模组的平滑法线不能沿用该假设，材质数量也不能超过 4 位的表达范围。

## 3. 与 Mellow、Astra 比较时必须保留的差异

Mellow 对照对象为前次下载的 3.4.1a，Astra 对照当前默认 / BALANCED。这里只描述包内原始选项。

| 项目 | Steadfast 0.8.0 | Mellow 3.4.1a | Astra 当前默认 |
|---|---|---|---|
| 阴影分辨率 | 1536 | 512 | 2048 |
| 阴影距离 | 160 | 96 | 256 |
| 实体阴影距离配置 | 比例 0.25 | 比例 0.125 | 独立 64 格选项 |
| 阴影采样 | 四次硬件过滤比较 | 默认 512 对应 SIMPLE 分支 | 中档成对深度 / 颜色过滤，8 角点 |
| 云 | 关闭 | 有云系统，可配置 | 默认平面云，半分辨率生成 |
| Bloom | 无该链路 | 默认开启 | 默认开启 |
| 抗锯齿 | 无 TAA 链路 | `TAA_MODE=0` | 默认 FXAA；TAA 可选 |
| 维度 | 主世界优先，作者注明其它维度未调好 | 提供下界 / 末地效果 | 三维度各有专门效果 |

Mellow 依据：`_analysis/video-2026-10-01/mellow/source/shaders/lib/settings.glsl:163,231,274–287`。Astra 依据：`Astra/shaders/lib/settings.glsl:69–100`、`Astra/shaders/shaders.properties:426`。

Steadfast 默认阴影比 Mellow 默认更大，所以“它更快是因为阴影规格更低”不成立。与 Astra 相比，1536² 的阴影纹素数是 2048² 的 56.25%；影距、绘制倍率及实体范围也更紧。纹素数量与绘制范围的差别可以解释部分开销，但不能直接换算成固定 FPS。

## 4. 已知未完成部分与源码风险

### 4.1 作者明确承认的内容

| 问题 | 触发条件 / 影响 | 来源与结论边界 |
|---|---|---|
| 默认配置水下有问题 | 摄像机进入水中后的默认观感 | 包内 `README.md` 的 Current limitations 明确说明，未给出所有症状细节 |
| 下界 / 末地未专门调校 | 切换到其它维度 | 同上；可以运行不代表有完善的光照与效果设计 |
| 流水和侧水失去高级水体身份 | `worldNormal.y <= 0.9999` 的水面 | `lit.fsh:303–306` 直接将 WATER 改为 GENERIC；随后水专属反射、折射等分支不再按水运行。包括倾斜流水顶面，属于主动功能降级 |
| 倾斜水法线的反射 / 折射不正确 | 水法线计算面对非水平表面 | `translucent.glsl:124–133` 只做固定 XZY 变换，作者 TODO 指出问题；常规入口的材质降级又使许多此类水面不会进入该函数 |
| DH 近远景水体雾存在断层 | 近处水反射远景，与远处水反射远景相接 | `lit.fsh:110–113` 明确 TODO，不能视为已经无缝支持 DH |
| DH 非高级透明材质被混合两次 | DH 与原版地形重叠区，关闭高级透明效果 | `lit.fsh:454–455` 明确注明会破坏 Retro / 原版水的效果 |
| DH 水被强制全反射 | DH 的无原纹理透明入口 | `lit.fsh:369–375` 强制 WATER、颜色置零、反射强度 1；近远处水的材质表现可能不同 |
| 模组平滑法线不受支持 | 如 PhysicsMod 的雪面 | `lit.vsh:273–277` TODO + flat 法线传递；可造成面间光照分段 |

### 4.2 本次从源码定位的数值问题

**SSR 厚度上限在首次命中前除以零。** `lib/raytrace.glsl:110` 将 `refinementRounds` 初始化为 0，`:143–145` 在增加轮数之前执行 `MAX_THICKNESS / refinementRounds`。代码可能意图借助正无穷使 `min` 保留当前厚度，但这份包声明的是 GLSL 1.50，除零结果不能依赖为固定值。按 [Khronos GLSL 1.50 §5.9](https://registry.khronos.org/OpenGL/specs/gl/GLSLangSpec.1.50.pdf)，除零不引发异常，结果未指定。这是明确的数值边界风险，不能仅据此断言某个显卡一定出现反射黑块。修正思路是在零轮时显式使用当前厚度，只有轮数大于零才执行除法。

**水面视差没有保护掠射角除法。** `environment/water/parallax.glsl:68` 使用 `viewVector.xy / abs(viewVector.z)`，水平视线使分母趋近零，可产生非常大的采样位移；精确为零时结果同样没有保证。外层的距离和水平面条件不能限制该角度。合理方向是对掠射视线衰减视差，同时限定步幅；只加入极小分母仍可能留下不合理的大位移。

以上为源码条件推导，尚未确认用户看到的具体画面是否由这两处导致。

### 4.3 还有优化空间的两处

1. `copy_and_fog.fsh:67–75` 先求完整天空，再算雾。原始默认启用折射辅助吸收，普通不透明地形走这一全屏入口，近距离雾为零、水 / 岩浆或失明时仍可能支付天空计算成本。相反，`lit.fsh:560–566` 已先判断 `skyFogStrength * fogOpacity`，说明优化没有贯彻到所有入口。Astra 当前 `program/scene.glsl` 已有低雾贡献返回，不能把旧包装函数重新移植回来。
2. `translucent.glsl:438–450` 对所有近景 SSR 失败都尝试 DH 查询，作者 TODO 也要求按深度失败原因区分。需要区分离开屏幕、方向拒绝、深度未命中等原因；两套投影不同，也不能直接把所有离屏情况一概删除。

### 4.4 半浸水处理有特殊几何补偿

`program/world/lit.vsh:301–392` 为接近水面且眼睛尚未被判定在水中的视角做近裁剪补偿，特定水平水顶面顶点会被推到近裁面，并将屏幕 y 扩展到 -1000。这用于防止水面被裁掉后，屏幕下半部水下地形突然不受吸收而发亮。

它不是没有考虑半浸水，也不能仅因坐标特殊就判定为 bug。但它依赖水平法线、方块属性和观察介质状态，不能替代 Astra 已有的界面 / 水段 / 遮挡关系。默认水下的作者已知问题也不能全部归因于这段补偿。

### 4.5 雨天粒子

在这份包的 `gbuffers_textured.fsh`、`gbuffers_textured_lit.fsh` 和共享 `lit.fsh` 中没有找到针对雨滴溅落粒子的专门身份或颜色过滤。因此它没有提供一套可直接取代 Astra 当前雨滴溅落过滤的方法；雨雪条带与粒子也不是同一个入口。

## 5. 适合 Astra 的部分与实际优先级

Astra 已经参考过 Steadfast：方块光 / 部分直射光、阴影扭曲、雾曲线、水面波形、光束，以及部分 CPU uniform 都有现有实现和来源登记。当前 `water_buffer_formats.glsl` 还已经把 `colortex0/2/4/7` 设为紧凑 RGB HDR。上述内容是已有能力，本次没有重复计作新优化。

| 优先级 | 后续方向 | 当前状态 / 适用边界 |
|---|---|---|
| 高 | 减少主世界可选效果的辅助缓冲读写 | Astra 比 Steadfast 多云、TAA、反射历史和表面信息。云 / 雾分辨率、关闭 TAA 时的资源调度已有优化；进一步应围绕每个资源的真实消费者裁减。`colortex3` 同时携带手持标志、水湿法线和积水覆盖，不能直接降成 Steadfast 的 R8 天光 |
| 高 | 继续把共享光照 / 大气表达式转为 CPU uniform | Astra 已有风相位、日月方向、调色及直射门限；仍可研究公共源强与不依赖视线的方向归一化。Minishita 的日夜权重、截断后的源方向和源强仍在 GPU 构造，但仅在选择该天空模型时有收益，默认渐变天空不会因此直接变快 |
| 中 | 提供更紧的主世界阴影覆盖组合 | 当前 Astra 的 1536、80 / 112 / 160 距离选项已可表达这类组合。性能档现在是 1024 / 192，不等同于 Steadfast LOW 的 1024 / 80；压缩覆盖能省绘制，但会缩短远景动态阴影，需作为明确画质选项 |
| 中 | 水体高级效果按可见贡献及距离限额 | Astra 的 SSR 当前是 24 粗步 + 6 次细化，并非旧注释里的 96 步。已有远距衰减和早退；可以研究把粗细步骤共享总预算，但要保留首个交点、真实水段及边缘衰减，不能引入 Steadfast 的零轮除法 |
| 中 | 普通方块几何的紧凑 varying | 只限确实面内法线一致的通道。平滑法线、模组实体与需要精确法线的水体保留原方式，材质位数按 Astra 实际语义选择 |
| 已有 | 低成本屏幕空间光束 | Astra `global/post/godrays.glsl` 已有 Steadfast 派生的 8 步径向采样；默认关闭 GODRAYS，完整体积雾与水下光束另有用途，无需再新增重复版本 |
| 不宜直接采用 | 全套水体、DH 衔接、普通维度共用光照 | 未完成部分会影响流水、水下、远景及下界 / 末地；Astra 已有专门链路，应保留 |

对主世界而言，最值得继续做的是缓冲与效果调度，以及帧内一致的光照 / 天空数据共享；单纯照抄它的阴影采样函数，或把流水降成普通透明材质，价值较低。Mellow 的独立调色组织仍适合保留，Steadfast 的带宽与计算分工可以与这套可配置性并用。
