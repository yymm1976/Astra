| 文件 | 负责什么 | 何时更新 |
|---|---|---|
| [当前工作](当前工作.md) | 最新用户反馈、实测读数、待办、技术债、优先级与下一步 | 每轮项目对话结束，按真实变化修准；重要需求变化及时写入 |

| 本文 | 阅读入口及记录维护方式 | 文件职责或位置改变时 |

Agent 接续默认先读「当前工作」，再按问题找相关段落与源码；不要每轮通读整个 docs，也不要把归档的旧“当前”“已修复”或“待批准”当成现态（理由：归档保留原文不改写，见下方「记录方式」，旧结论与现态会共存）。用户的新反馈优先修准工作页；源码已有分支不证明画面恢复或帧率达标。对话没有实质变化时不为凑更新增加流水。

## 记录方式

当前工作页直接修准对应事项；实际解决后退出待办，仍有用的行为说明回到负责它的固定文件。新要求写“待实施”，未知写“待定位/缺事实”，不能以阶段编号、代码完成或推测收益替代实际结果。审查增补有保留原文要求时，只增补对应归档章节，不整份加载或改写作者原文（理由：作者原文是证据，改写会破坏可追溯性）。
