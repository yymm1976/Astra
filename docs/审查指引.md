# Astra 审查指引

更新日期：2026-10-16。代码审查、外部报告核验及据报告修复前必读；同一任务已读且内容未变时沿用。本文合并历轮审查中可复用的教训，不保存作者评分、问题数量排名或逐条旧报告。现行行为与保留要求见[实现与限制](实现与限制.md)，实际未完事项只在[当前工作](当前工作.md)维护。

## 判断原则

曾经的主要失败不是少读文件，而是从“存在这行代码”直接跳到画面后果，漏掉条件作用域、后续赋值、编译条件、执行顺序和单位。读过多少文件、多少执行者同意，都不能证明结论正确。

确认缺陷需要正向证据：所述条件能成立，相关路径确实执行，错误结果违反已确认的行为或要求。主动寻找后续覆盖、互斥条件、备用路径和现行说明中的反证；“暂时找不到反证”本身不构成证明。注释提供意图线索，但仍须与实现核对；外部包做法不同也不自动构成 Astra 缺陷。

旧结论可以被新证据推翻，不能仅因本文收录过就拒绝重查。源码、引擎版本或用户要求改变后，应先核对变化是否影响适用条件。

## 每个候选必须回答的问题

1. **究竟违反什么要求？** 区分错误、已选取舍、能力限制、维护问题和功能建议。用户反馈的白边、闪烁或低帧率是真实待处理事项，即使某份报告的根因被否决，也不能宣布反馈消失。
2. **路径能否到达？** 核对相关维度、宏开关、选项、相机介质和必要视口条件。涉及顶点裁剪时，对照同一次绘制的 `.vsh` 与 `.fsh`；被整次裁掉的绘制没有片段消费者。只展开影响当前结论的组合，复杂时才列小表。
3. **条件实际控制什么？** 读到配对的大括号或 `#endif`，确认不带括号的 `if` 究竟控制哪条语句。沿当前程序和调用路径找相关变量的初始化、赋值、后续覆盖、早退及失败处理；不能只看第一个赋值或条件开头。
4. **数据在哪里、何时写读？** 对跨阶段缓冲确认入口、附件映射、实际格式、通道、混合、清空、完整覆盖、执行顺序与读写纹理切换。同帧后续阶段可能读到新值，但不是所有 `colortex` 都可一概视为本帧或上一帧。
5. **单位和坐标是否一致？** 区分世界格数、纹理像素、归一化坐标、视图深度和相机距离。代入实际分量与系数；涉及数学变换时推导完整正反变换，不能凭公式外形删平方或判量纲错误。
6. **后果证明到哪一层？** 源码可证明错误计算或读写；画面形状、严重程度和实际耗时需独立依据。区分已有实现、此次实际改动、独立呈现和游戏观察，不能把局部推断升级为整体结论。

这是判断要求，不是固定产物清单。不要求每次为全包生成宏组合表、变量台账或大段源码摘录；只保留足以复核结论的关键片段、条件和位置。

## 历轮反例：哪些推理不能再直接采用

### 条件、赋值和像素配对

| 容易出现的判断 | 必须补上的核对 | 代表位置 |
|---|---|---|
| `sourceVisibility > 0` 不成立，所以没有写太阳可见度 | 该条件只控制云采样；后面的 A/G 通道赋值仍执行。薄水层走空气分支，不能把普通水体的距离 alpha 同时套进去 | `program/scattering.fsh` 的 `main`、`scattering.vsh`、`display.vsh` |
| 新增早退必然改变画面 | 对照修改前的完整条件和初始化；旧云程序已经在失明等条件下禁止云采样，把判断提前不等于从非零改为空 | `program/cloud_screen.fsh` 及实际改动 |
| 高档云删掉网格偏移会错位 | 先代入当前档位；相关高档组合的偏移函数恒返回零，不能仅凭读端少了一次减法认定错位 | `lib/cloud_sample_grid.glsl`、`global/atmosphere/clouds_screen.glsl` 及写端 |
| 多层水面会按透明度把高度平均 | 水记录的 alpha 是固定的有效标志1；`SRC_ALPHA` 取 A，不取 R。代入后是新记录乘1、旧记录乘0。该结论不证明任意多层透明排序正确 | `program/lit.fsh` 的水记录输出、`shaders.properties` 的附件5混合 |
| 边缘混合修改 UV 后，深度仍来自旧像素 | 查看顺序：先混合 UV，再求像素和取深度；拒绝位移时，原位置和原深度一起返回。不同水面路径不能串接成一条调用链 | `global/water/refraction.glsl` 的 `water_refracted_uv`、`program/water.glsl` 的实际调用方 |
| 某阶段算出的值已无用途，可以删掉 | 查所有可达消费者与失败路径；主世界水下的 `litWater` 仍用于倒影未命中时的填色，其他维度结论不能直接套用 | `program/water.glsl` 的 `astra_underwater_interface` |

### 单位、数学和过滤

| 容易出现的判断 | 必须补上的核对 | 代表位置 |
|---|---|---|
| 波场原点按16格跳动 | `16纹理像素 × 0.0625格/像素 = 1格`；坐标中的16不是世界距离 | `program/itt_water_normal_cache.vsh`、`lib/itt_water_field.glsl` |
| 波场移动且取消清空，所以边缘保留上一帧内容 | 有效绘制时整张图重新生成；跳过生产时核对消费者也是否跳过。再看有效采样区和过滤范围，不能从窗口移动推断部分更新 | `program/itt_water_normal_cache.vsh/fsh`、`global/water/light_shafts.glsl` |
| 植物锚点符号反了、径向平方是重复乘法 | 先确定向量方向；`at_midBlock` 从顶点指向中心，上部顶点Y为负。径向变换 `q=p/(length(p)+a)` 的反变换半径为 `a*r/(1-r)`，对r求导为 `a/(1-r)^2`，平方有数学来源 | `program/shadow.vsh`、`lib/distort.glsl`、`global/lighting/shadowmap.glsl` |
| `textureGather` 的起点只能靠画面猜 | 规范定义其2×2取样位置；用线性取样足迹的 `floor(u*宽度-0.5)` 推导，另核对分量顺序、像素中心、边界和尺寸。不要在两个未经依据的公式间猜选 | `global/post/fxaa.glsl`、[GLSL规范](https://registry.khronos.org/OpenGL/specs/gl/GLSLangSpec.4.60.html)的纹理抓取部分 |

第二轮 FXAA 的过滤疑点已有版本限定证据：本机已安装的 Iris 1.11.2（mc26.2）字节码中，`IrisSamplers.addWorldDepthSamplers` 与 `addCompositeSamplers` 为 `depthtex0` 绑定 `GlSampler.NEAREST`，即最近邻读取。[在线26.1分支的对应实现](https://github.com/IrisShaders/Iris/blob/26.1/common/src/main/java/net/irisshaders/iris/samplers/IrisSamplers.java)作为定位入口，不能冒充本机版本或运行状态。引擎升级或绑定改变后需重查，不再把“光影包未声明过滤模式”直接等同于“静态无法确定”。

### 引擎、维度和读写时机

| 容易出现的判断 | 必须补上的核对 |
|---|---|
| 包内没有读这个选项，所以它无效 | 查引擎读取，例如 `entityShadowDistanceMul`；同时区分引擎预处理提供的 `MC_GL_*` 宏与驱动的 `GL_*` 宏。不能只搜索光影包的引用 |
| 不同维度有同名附件声明，所以冲突；缺入口，所以无功能 | 按安装版本核对各维度程序组和回退；Iris 1.11.2 的维度声明独立，`shadow_solid` 可在本维度回退到 `shadow`。全包文本计数或只找显式文件不足以判错 |
| `composite3/4` 读的水状态必然是上一帧 | 水状态的生产阶段在前，本例后续读取本帧结果；显式历史回退另算。检查读写纹理切换后再定时序，不推广为所有缓冲的规则 |
| 手部与 deferred 的顺序未定，因此透明水体顺序也未知 | 分别核对两条绘制路径；旧问题描述不能替代对应引擎调用证据。取消清空是否新增风险，还需与原来的先写后读依赖比较 |
| 维度切换必然复用云历史 | 查引擎流程销毁与重建；正常维度标识变化，与相同标识跨存档是不同问题。前者的已有保护不能证明后者异常，也不能证明后者已解决 |
| 工具报同名重复，必须改源码消除 | 先区分同一程序内冲突、互斥宏分支和独立维度；文本扫描的告警不自动成为运行缺陷，不为工具误判改坏正确实现 |

引擎行为优先核对安装版本的源码或可读取的字节码；在线分支和历史摘录注明适用范围。源码足以回答的条件、绑定和调用问题，不能一概标为“只能看运行画面”；源码不能证明的运行状态也不能冒称已观察。

### 设计取舍和实际结果

- 普通水雾的完整水路吸收，与近处光束的有限计算范围职责不同。不能为让两个上限相同而截短真实水路；既有理由见 `lib/solas_water.glsl` 及[实现与限制](实现与限制.md#水下介质与光束)。若质疑取舍本身，写清违反的要求或具体偏差，作为设计意见单独说明。
- Bloom与显示阶段可能按开关互斥地承担水下合成；看到两处施雾代码不证明同一水段执行两次。末地未采用主世界的批量FXAA读取，也不等于末地没有FXAA。由入口和编译分支判断功能，不由某个优化符号判断。
- 数组容量要按现行循环、最大索引、元数据占位和分配大小核算；假设以后修改参数可能越界，不构成当前越界。极小视口重复取样、罕见无效数或未来新增消费者同理：先确认可触发路径及具体损害，不预防性扩建。
- 减少采样、共享计算或删除不可达分支，只能直接说明少做了哪些操作；不能据此宣布整帧提速。循环次数的上限与每像素实际执行次数不同，也不能从两个场景的帧率差值反推某个模块耗时。
- 有意保留高档云质量，即使增加某个预算档的开销，也不直接构成功能错误；先对照已确认要求。远雾残余段改取中点，只修正单段代表位置，不能据此宣称已经做了完整分段积分或消除了全部误差。
- 旧日志、旧截图与旧数字只覆盖当时的源码和配置；文件日期只能帮助发现不匹配，不能代替内容与来源判断。未确认性能目标达到，不等于已经证明目标失败。没有核实切档会比较什么，不把切档比较包装成确定建议。
- 实例目录内容较旧，只能证明该目录内容较旧；游戏保存的包名、复制完成或目录差异，都不能单独证明当前实际加载来源，更不能断言改动从未运行或任何截图必然来自旧版。
- 另一光影包公式不同不证明 Astra 错误；参考算法先核对坐标、单位、前提和实际消费者。代码来源与许可另按实际片段维护，不能由包级许可推定所有片段归属。

## 报告表达和纠错

每条结论给出当前源码位置、必要条件、具体后果与证据缺口。摘录足以证明判断的关键代码即可，不以文件数量、行号列表或多模型一致代替论证。

结论分类保持一致：已确认缺陷、部分成立、误报、证据不足或设计意见。另行说明证据来自源码、引擎实现、独立呈现还是游戏观察；同一条可以是“源码已确认错误计算，游戏画面幅度未知”，不必用一个含混标签覆盖两层事实。

正文撤销的候选退出缺陷计数，摘要、严重度和处理建议同时修准。排除项只保留能防止再次误判的理由，不继续包装为待修问题；多个表现同一根因先合并，多处表现相似也不自动认定同根因。

已有裁决先复用；出现新源码、引擎变化、用户要求或反证时才重查。原文被要求保留时只增补裁决，不悄悄改写原结论。审查结论不自动授权代码修改、安装、同步实例、发布或其他工程动作，也不引入项目禁止的流程。
