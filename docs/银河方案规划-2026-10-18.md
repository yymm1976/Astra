## 一、结论先说

Astra **已经有银河带**：`Astra/shaders/global/atmosphere/stars.glsl:75-95` 的 `astra_milky_way()`。它用一条固定倾斜的带（极轴 `vec3(0.42, 0.34, 0.84)`）加现有噪声纹理做出宽窄两层结构和银核暗尘埃。

"不璀璨"的原因不是缺失，是**亮度差三个数量级**：实测的银河带峰值亮度约 `0.016`，而夜晚天顶的天空基色亮度约 `0.47`（线性 HDR，未色调映射）。天空是银河的 **30 倍**，银河加进去只让显示值变化 `0.007`，人眼分辨不出来，等于透明。

参考包（Photon、Solas）的做法是把银河贴图的亮度抬高到与夜空同量级：Photon 的银河贴图实测中位亮度 `0.0066`、90 分位 `0.032`、最亮 `0.91`，再乘强度系数 0.05～1.05；Solas 默认亮度旋钮是 `2.50`（Astra 没有对应旋钮）。

所以主路径是**调亮**，不是重做。代价最小、风险最低，先调亮拿到画面反馈，再决定是否升级到贴图。

## 二、现状（读源码，全部已核对行号）

夜空绘制链（主世界）：

| 位置 | 作用 |
|---|---|
| `Astra/shaders/global/atmosphere/stars.glsl:13-69` | 整数格哈希星表：`astra_star_hash`、`astra_star_cell`（密度档 0.004/0.0058/0.009/0.014）、三色温调色板、逐星闪烁 |
| `Astra/shaders/global/atmosphere/stars.glsl:71-95` | `astra_star_chart` 四角重建、`astra_milky_way` 程序化银道带 + 银核尘埃 |
| `Astra/shaders/global/atmosphere/stars.glsl:97-141` | `astra_star_field`：天球坐标、日月圆盘排除、两张球面海图重叠、可见性包络 |
| `Astra/shaders/program/deferred.fsh:431-439` | 天空像素加星点与银河，星点另写 TAA 反应值 |
| `Astra/shaders/global/dimension/overworld.glsl:95-99` | `astra_overworld_sky` 汇总入口 |
| `Astra/shaders/program/water.glsl:857-863` | 水面反射里加 `astra_star_field`，共用云透过比例，不重做云搜索 |
| `Astra/shaders/shaders.properties:987-1007` | CPU 端天球基向量 `astraStarTangent/astraStarAxis/astraStarTwinkle` 与可见性 `astraStarVisibility` |

关键事实（读源码得出，非推测）：

- `astra_milky_way()` 和点星**共用同一个天球坐标系**（`celestial`）。银道面与星表严格对齐，改亮度不会错位。
- 银河带输出是**连续低频**，而 `pointStars` 只取点星最大值（`stars.glsl:131`），所以银河不会触发 TAA 反应值。银河加亮后如果画面出现拖影，原因在这里，不在银河本身。
- 银河**不写进低频反射缓存**。`lib/sky_reflection_cache.glsl` 生产的是不含星点的天空；`program/water.glsl:858` 注释明确写着反射缓存刻意排除星点。水面是逐像素重新算一遍 `astra_star_field`。
- 银河亮度是 GLSL 里的**硬编码常数**（`vec3(0.009,0.012,0.020)`、`vec3(0.004,0.0038,0.0032)`），`shaders.properties` 里搜 `galaxy\|milky\|nebula` 零命中 —— 用户没有任何调节入口。
- `astraStarVisibility`（`shaders.properties:1007`)：`(1-astraRainFactor) * pow(astraGradientInvNoon2,4) * (1-0.5*astraGradientVisibility)`。正午归零，子夜约 0.75，随雨天归零。这一项没问题。
- 带宽约 12～13 度（`smoothstep(0.035,0.22)`，0.22 弧度≈12.6°）。真实银河带宽 10～30 度，宽度不算窄，形状不是主因。

## 三、实测数值（本会话运行 `galaxy_lum_probe.js` 与公式复算，标注为"实测"）

### 3.1 夜空基色有多亮

复现 `shaders.properties:809-814` 的调色板表达式，取默认 `skyColor` = rgb(0.471, 0.655, 1.0)（原版 0x78A7FF），晴天夜晚：

| 项 | 线性亮度 |
|---|---|
| 天顶夜色 `astraSkyNightUp` 原值 | 0.351 |
| 天顶（含 `astra_get_sky_base` 夜晚增益 1.5−0.5·1+0.4·VdotSM3·1.5） | **0.471** |
| 地平 `astraSkyNightMiddle` | 0.383 |

### 3.2 银河和星点有多暗

| 项 | 线性亮度 | 相对天顶夜色 |
|---|---|---|
| 银河宽带 `vec3(0.009,0.012,0.020)` | 0.0119 | 2.5% |
| 银核 `vec3(0.004,0.0038,0.0032)` | 0.0038 | 0.8% |
| 星点平均（`0.95·rank⁴` 均值） | 0.18 | 38% |
| 星点最亮（含 1.35 亮尾） | 1.22 | 259% |

经 `lib/tonemap.glsl:74` 的 `astra_uchimura_peak`（m=0.22，肩起点 0.532）映射后：天空 0.471，银河 0.0067。**银河对最终画面的贡献是 0.7/255 个灰阶，不可见。**

### 3.3 参考包的银河贴图（实测 PNG 解码统计）

| 贴图 | 尺寸 | 中位 | 90 分位 | 99 分位 | 99.9 分位 | 最亮 |
|---|---|---|---|---|---|---|
| `photon-shader/shaders/image/galaxy.png` | 2048×1024 | 0.0066 | 0.032 | 0.099 | 0.207 | 0.907 |
| `solas-shader/shaders/tex/milkyWay.png` | 512×1024 RGBA | 0（半数为空） | 0.032 | 0.119 | 0.262 | 0.639 |

两张贴图的 mcmeta 都是 `blur: true, clamp: false`（经度环绕、纬度夹紧），Astra 现有 `solas-water-noise.png.mcmeta` 也是同一配置，可照抄。

### 3.4 亮度对照表（决定"璀璨"到什么程度）

设银河带峰值亮度为 `B`，宽带平均约 `0.45B`：

| 带峰值 B | 天顶夜色/带平均 | 带经色调映射后 | 显示上银河比天空亮吗 | 进泛光吗 |
|---|---|---|---|---|
| 0.016（现状） | 30× | 0.024 | 否 | 否 |
| 0.10 | 4.7× | 0.115 | 否 | 否 |
| 0.20 | 2.4× | 0.224 | 否 | 否 |
| 0.35 | 1.3× | 0.374 | 接近 | 否 |
| 0.55 | 0.9× | 0.574 | 是 | 否 |
| 0.90 | 0.5× | 0.924 | 明显是 | 否 |

**这里有一个必须先解释的机制**：泛光（Bloom）的前置过滤门槛是 `BLOOM_THRESHOLD = 1.0`、软膝 `BLOOM_KNEE = 0.5`（`global/post/bloom.glsl:21-23`），也就是说亮度要接近 1.0 才会发光。银河带如果调到 0.9 仍不会发光；而"璀璨"观感的一大半来自发光。要让银河真的"泛出光晕"，带平均至少要 0.4～0.5，即峰值 ≥1.0 —— 这已经比夜空本体还亮好几倍，整条天上会糊成一片白。**这不是应当采用的做法**。

正确路线（推断，但机制清楚）：**银河的璀璨来自"带内密集星点 + 少数亮星泛光"，不来自带体本身发光。** Photon 正是这么做的：`draw_stars()` 的阈值 `1.0 - 0.05·coverage - 0.5·cube(galaxy_luminance)`（`photon-shader/shaders/include/sky/stars.glsl:45-51`），银河亮度直接反哺星点阈值（立方保证只有最亮处起作用），所以银河带上密布星点；带体只做背景底光。Astra 缺的正是这条反馈。

因此推荐目标区间：**带峰值 0.35～0.55（宽带平均 0.16～0.25，约天空的 1/3～1/2，肉眼可辨的乳白光带）**，同时带内星点密度提高 3～6 倍，星点峰值乘 0.82 后越过泛光门槛（现最亮星 1.22，门槛 1.0，`0.82·1.22 ≈ 1.0`）—— 亮星本身已经在门槛上，提高数量即可获得发光星点。

## 四、参考包做法调研（读源码，含在线核对）

### 4.1 Photon（本地副本 v1.3b，2026-10-18 读）

- `shaders/include/sky/sky.glsl:99-119` `draw_galaxy()`：经纬映射 `atan(x,z)`、`acos(-y)` → 1 次贴图采样；sRGB 解码 → 工作色域；强度 `0.05 + 1.0·linear_step(-0.1, 0.25, -sun_dir.y)`（太阳降到 -0.1 以下才从 0.05 涨到 1.05）；色调 `vec3(0.75,0.66,1.0)·GALAXY_INTENSITY`；最后 `mix(vec3(lum), galaxy, 2.0)` 把饱和度提高 2 倍。
- `shaders/include/sky/sky.glsl:130-143`：天球锚定用 `ray_dir · shadowModelViewInverse`，即阴影矩阵的逆，让星象与日月一起转。
- `shaders/shaders.properties:353-354`：`texture.deferred.colortex13 = image/galaxy.png` —— 把贴图挂到一个空闲附件槽当采样器用。
- `settings.glsl:283-286`：`GALAXY` 默认注释掉（默认关），`GALAXY_INTENSITY 1.00` 可调。

### 4.2 Solas（本地副本）

- `shaders/lib/atmosphere/milkyWay.glsl:1-44`：`texture2D(depthtex2, planeCoord·0.5+0.6)`，即银河贴图经 `texture.deferred.depthtex2=tex/milkyWay.png` 绑定（`shaders.properties:128-129`）；密度 `pow(alpha, 6-3·space)`；`nebulaFactor = length(milkyWay.rgb)·(5-space·3)` 反哺星点阈值；水下反射补偿额外 `×3.0`。
- `lib/common.glsl:308-310`：`MILKY_WAY_BRIGHTNESS 2.50`，滑块从 0.25 起。
- 极光遮挡项 `auroraOcclusion` 会压低银河（银河与极光互斥）。

### 4.3 Rethinking Voxels（本地副本）

- `shaders/lib/atmospherics/fractals.glsl:44-77`：曼德勃罗 / 朱利亚集当"银河"，300 次迭代循环，随太阳方向旋转变换。**分形不是银河，且迭代循环成本高。不采用，仅作反例记录。**

### 4.4 Complementary Reimagined（Astra 星空的直系上游）

- 无银河带。只有点星 + 夜星云（`nightNebula.glsl` 三层 fbm），星云亮度反哺星点。Astra 现有程序化带是自建方案。

### 4.5 两条与亮度无关但影响观感的既有差异

- **银道面倾角是固定常数**：Astra 的极轴 `vec3(0.42,0.34,0.84)` 与 `astraStarAxis = (0, sin(sunPathRotation), cos(sunPathRotation))`（`shaders.properties:992`）绑定在同一套天球基上，但天球基只随 `sunPathRotation` 倾斜、随太阳方向自转，**不含"每天多转 361/360 度"的恒星日推进**。末地有 `worldDay/worldTime`（`global/dimension/end_geometry.glsl:24-25,43-45`），主世界星空没接。后果：银道面每晚出现在同一位置。是否算缺陷取决于用户是否要求逐夜变化；本轮列为"可选后续"，不塞进主路径。
- **白天不隐藏**：Astra 的银河与点星同用 `astraStarVisibility`（正午归零），已正确隐藏。Photon 用另一条独立曲线（`linear_step(-0.1,0.25,-sun.y)`）。Astra 现有做法够用，不改。

## 五、方案规划

### 阶段 A（先做，改动最小，拿画面反馈）

只改 `stars.glsl:75-95` 的常数与输出结构，并新增一个用户旋钮。

1. **给银河亮度加统一标量与选项**。把两处硬编码常数提到文件顶部的可调量，走 `shaders.properties` 的 CPU 表达式，新增 `MILKY_WAY_BRIGHTNESS`（0～200，默认建议 100），同时按 `STAR_AMOUNT` 档位联动（稀疏档不该出现浓银河）。
2. **把带体亮度提到实测推荐区间**：宽带项从 `vec3(0.009,0.012,0.020)` 提高约 **×25**（到峰值 0.35 一档），银核项相应提高。先只改系数，让 `galaxy_lum_probe.js` 同一条链路能算出改后亮度，写进 `qa/` 记录。
3. **加"银河 ↔ 星点密度"反馈（本方案的核心增益）**。照 Photon 的机制、不抄表达式：从 `astra_milky_way` 输出带亮度，返回给 `astra_star_field`，用它放宽 `astra_star_cell` 的 `coverage` 判定（例如带内密度乘 3～6，银核最亮处乘更多），使银河带上密布暗弱星点。这需要 `astra_milky_way` 先算、`astra_star_cell` 后取，**注意现在的调用顺序是先星表后银河**（`stars.glsl:124-131`），要调整求值次序并保证早退条件仍然成立。
4. **带体加饱和偏移**：参考 Photon 的 `mix(vec3(lum), galaxy, 2.0)`，让银河偏蓝紫但不纯灰；保持亮度不高于第三点定的上限。

预期结果：晴天半夜天上出现一条肉眼可见的乳白～淡蓝光带，带内星点明显比别处密，少数亮星周围有泛光晕。代价：带体两个系数改动零成本；密度反馈多一次哈希判定（只在 `band>0` 的像素），Astra 本来就有 `if (band <= 0.0) return` 早退，成本限于带内像素。

验收：必须有实机画面。分屏分量法照 `Astra/README.md:77-98`（原天空 / 仅星点+银河 / 完整合成），截图存 `qa/runtime-feedback-YYYY-MM-DD/`。**没有画面反馈不得宣布完成。**

### 阶段 B（A 之后仍不够"璀璨"再做）：换成真实银河全景贴图

- 素材来源（**待用户确认**）：ESO/NASA 的银河全景图多为公有领域或可自由再分发（例如 NGST 2020 Milky Way Replica、NASA All Sky Milky Way Panorama）；**本轮没有联网核实许可条款**，落地前必须逐张确认并登记 `Astra/THIRD-PARTY.md`。另一条路是自写脚本程序化烘焙（工作量大、观感不如真实数据）。**不采用**：直接复制 Photon/Solas 包内的 PNG。
- 投影与采样：沿用现有天球基 `celestial`，经度 `atan(celestial.z, celestial.x)`、纬度 `asin(clamp(celestial.y,-1,1))`，1 次 `textureLod` 采样；mcmeta 用 `blur: true, clamp: false`（与 `solas-water-noise.png.mcmeta` 一致，经度环绕）。
- 贴图通道布局建议：RGB 存星光（sRGB 解码后使用），A 存暗尘埃遮光 —— 与 Solas 同构。若取到三通道+alpha 全景图。
- 绑定方式：Astra 已有 `customTexture` 用法（`shaders.properties:560-583`），直接 `customTexture.astraGalaxyTexture=textures/astra-galaxy.png`，**不必像 Photon 那样借用 colortex 槽位**。
- 与阶段 A 的衔接：把 `astra_milky_way()` 换成贴图版，**保留同一个"带亮度→星点密度"输出**，密度反馈不用重写。带体亮度上限沿用阶段 A 已确认的区间。
- 缓存：贴图采样会提高反射缓存与 `sky_gradient_cache` 的成本。低频反射缓存（colortex11，256×128）目前刻意不含星点；贴图银河是低频内容，**建议**把银河带计入反射缓存的生产端但不计点星，让水面与粗糙反射免费获得银河，避免 `program/water.glsl:859` 逐像素重采样。这一条要按实际生产/消费路径再核对。

### 阶段 C（可选，与"璀璨"关系次于 A/B）

- 逐夜推进（恒星日）：主世界星空接入 `worldDay/worldTime`，末地已有先例。
- 银心方向亮斑与大小麦哲伦星云等标志结构：贴图方案的附带收益。
- 星云（`nightNebula` 类程序化三层 fbm）：会与本方案抢亮度预算，银河做出来再评估。
- 带内星点的大气消光（近地平变暗变色）：Kappa 用同一 LUT 透射，Astra 星点现在只有 `nDir.y·3.0` 线性淡出。

## 六、约束与保留要求

- **性能目标不变**：原生 1080p、平均 ≥144 FPS、95% 常规帧 ≤6.94 ms（`docs/当前工作.md`）。银河是天空像素上的工作，且有 `band<=0` 与 `visibility<=0` 早退；但阶段 B 的贴图采样进反射缓存后要重新估。所有代价数字目前是结构估算，**无实机帧时**。
- **不为此重构 Astra**，不改显示变换/色调映射链（`lib/tonemap.glsl` 门槛与曲线是既定设计）。
- **思路级重写，不复制表达式**：Photon/Solas 许可是有条件再分发（见 `docs/参考与取舍.md` 的 Photon 许可段），代码与素材都不得直接搬；采纳范围必须登记 `Astra/THIRD-PARTY.md`。
- 天空保持既有身份设定：方形日月、块状云、星表与星点运动保持（`docs/实现与限制.md:100` 的"天空"行）。银河改动不能改变点星位置与数量档语义。
- 当前优先级：水面帧率与入水观感仍排在天空之前（`docs/当前工作.md`）。本方案不抢占该优先级，除非用户改变顺序。

## 七、验证工具

- `qa/tools/sync_to_instance.py`：同步到 `qa/local_paths.json` 指定实例。**注意**：配置保存的光影包名不等于运行中实际加载的包；确认画面来自哪一版源码。

### 可取之处与需要更正的依据

| 原规划内容 | 核验结果与处理 |

| 现有银河可见性弱，应先利用现成结构 | 采用程序带优先的路线，保留原天球基底、极轴、星表及噪声素材，增加亮度设置、冷暖中心与较清楚的暗纹。没有游戏画面，不能确认“弱”的唯一原因就是某一个系数 |

| 显示贡献0.0067相当于0.7/255且不可见 | 0.0067×255约1.71；更关键的是应比较完整RGB相加前后的显示结果。对银河单层单独套曲线，再与天空亮度比较，不能给出实际像素增量或人眼可见性 |
| 星点平均0.18、峰值1.22可直接和天空比 | 原星表还乘颜色归一化、星点形状重建权重、闪烁及可见性。对已选星体的排名分布取均值，不是整片天空的空间平均；不能从这组数字决定星点是否跨过Bloom门槛 |
| 银河单独亮度不到1就不会进入Bloom | Bloom前置函数读取合成HDR颜色的最大通道，不是银河单层的Rec.709亮度。需要考虑天空与其他光量相加、最大颜色分量及现有Bloom开关。本轮不改变其曲线、不自动开启Bloom，也不承诺微星必然产生泛光 |
| 带内星点密度反馈 | 采用同一星表中固定的额外候选，密度只控制新增分量的光量。原有候选的排名和亮尾公式保持；不因调亮银河重新计算原星体排名，不增加第二张星表 |
| 密度反馈“只多一次判定” | 不足以说明成本。零权重格点不进入星表计算；新增暗弱候选复用原候选值的低八位，在等亮度的暖金、近白、冰蓝之间插值，原亮星才运行逐星细节与闪烁。候选选择、混色、亮度、密度分支及中心形状运算仍有成本，实际帧时未知 |

### 已落实的第一阶段源码

`MILKY_WAY_BRIGHTNESS`在“天空与云”页，默认100%，0～200%；为编译选项，不新增CPU颜色uniform。0%关闭银河及新增微星，原有星野分量保持；关闭STARS或STAR_AMOUNT为0继续关闭全部星野。稀疏档减弱银河，并将候选上限限制为原2倍；其他非零档最多原4倍。这里是固定候选的概率范围，实际可见数量受密度和亮度影响，不保证画面恰好增加4倍。

用户最新明确要求多彩星空，当前银河沿用原1～2次噪声读取：粗结构混合蓝紫宽带，核心细节兼作玫红色团的权重，中心为暖金色；尘埃最深压低本层70%。静态中心由方向内积及固定乘法形成，无额外噪声和三角函数。各组常量按对应层亮度归一，保留原系数亮度上界，但不声称换色后显示亮度完全不变。新增微星使用固定候选区间及较低光量，颜色复用原候选值的低八位形成暖金、近白与冰蓝差异，无第二次细节求值或逐像素颜色归一除法；原亮星保留各自色温与闪烁。零权重格点跳过，不加第二层球面星表。颜色按天球结构与星点固定，不按时间循环换色。云后合成及水下既有云透过比例继续复用；水下云完全遮蔽的足迹跳过整次星野计算，避免先生成再乘0。

实际落点：`stars.glsl`、`program/deferred.fsh`、`lib/settings.glsl`、`shaders.properties`、两份语言文件和对应包说明。没有新增素材、图像附件、全屏阶段、云搜索或反射缓存生产工作。带内额外候选着色及少量算术仍有成本，尚无改后游戏画面或GPU读数。当前记录“源码已实施”，不把它写成“实际观感已确认”。

### 亮度脚本的用途和本轮输出

脚本保留无外部依赖的8位非交错PNG统计，用途有价值。已修正灰度透明PNG读取不到alpha、调色板透明度被忽略、未知过滤类型被当成Paeth等问题，并补输入结构错误处理。输出新增`rgbWithoutAlpha`；原顶层分位数继续表示线性RGB亮度乘线性alpha，附解释字段，失败文件会使命令返回非零状态。它按sRGB假定解码，不应用PNG的其他颜色配置。

本轮实际执行`node qa/tools/galaxy_lum_probe.js`后：

| 图片 | 未乘alpha的中位 / 90分位 / 最大 | 乘alpha后的中位 / 90分位 / 最大 |
|---|---|---|
| Photon银河PNG | 0.00661 / 0.03181 / 0.90705 | 0.0066 / 0.0318 / 0.9071 |
| Solas银河PNG | 0 / 0.04635 / 0.91076 | 0 / 0.0318 / 0.6393 |

这支持原报告大部分PNG分位数，不能支持Astra运行中夜空亮度的说法。Solas着色还使用alpha的幂及其他颜色、光照系数，普通乘alpha后的统计也不是Solas最终银河输出。外部图像本轮未加入Astra包。
