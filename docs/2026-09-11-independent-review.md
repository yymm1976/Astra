# Astra 独立审查（2026-09-11）

审查范围：用户指定的五份交接/历史/来源文档、当前 GLSL、ITT 3.2 本地参考、指定的三项工具。只审查，不改渲染代码，不同步实例。下面的数值说明逻辑错误，不代表游戏画面已获确认。

结论：当前实现不宜按“已完成”交付。编译通过，但下界传播、水下光束和焦散仍有确定的逻辑缺陷。此前“调整强度后即可”的判断不成立。

## 确定的问题（按优先级）

### R1 / P1：下界普通空气的有效性随奇偶帧翻转

- 写入端：`Astra/shaders/program/shadow.vsh:47-71`。
- 消费端：`Astra/shaders/program/nether_light.csh:19-20,37-56`。
- 图像配置：`Astra/shaders/shaders.properties:320`，clear 为 true。

实际帧戳 `(1u-(frameCounter&1u))<<16` 交替取 65536、0，与“永不为零”的注释相反。每帧清空后，未写入的普通空气 raw=0；偶数帧判为过期，奇数帧判为有效。顶点写入只遍历实际几何，普通空气没有顶点，不会自动得到非零的“本帧已捕获空气”标记。将非发光方块 kind 改成 0 也不能解决这个缺口，因为其 solid 位仍为 true。

按当前 GPU 公式、同一火源、相邻未写入空气、九次传播计算：偶数帧相邻红通道为 **0**，奇数帧为 **1.08**。这解释了为什么修改 kind 或传播距离仍可能无光/闪烁。不能只把帧戳改回非零：那将使普通空气每帧都无法传播。需要同时明确有效区域与空气的表示，不能混用“未写入”“空气”“未加载”。

### R2 / P1：熔岩的发光被自己的 solid 位封住

`shadow.vsh:68` 将熔岩写成 kind=11、solid=true；`nether_light.csh:56` 拒绝任何 solid 邻居，连发光邻居也拒绝。结果熔岩单元有颜色，颜色无法离开单元。

排除 R1、人为给相邻空气有效帧戳后，熔岩源红通道为 **1.5**、相邻空气仍为 **0**。必须区分“不允许穿透实体传播”与“允许实体表面向外发射”。现有火焰用例的 solid=false，覆盖不到熔岩。

### R3 / P1：现有体素模型没有复现 GPU 契约

`qa/tools/nether_voxel_model.py:29-33,92-109,126-185`：

- 模型帧戳为 65536/196608；GLSL 为 65536/0。
- 模型掩码仅有 bit16，奇数帧不可能等于包含 bit17 的 196608。故奇数帧连新写入火源都失效；旧单元消失的用例却会因此通过。
- 空气通过 `v.write(... KIND_EMPTY ...)` 人工写入，实际顶点生产端不生成普通空气。
- 没有验证 solid=true 的熔岩向外发光。

因此四项通过只说明这套人为输入满足模型，不能证明当前渲染链。修正时应让模型读取/共享实际编码契约，并同时包含奇偶帧活跃光源与真实生产端可产生的输入。

### R4 / P1：水下光束的阴影比较反了

`Astra/shaders/global/water/light_shafts.glsl:72` 使用 `1-clamp((storedDepth-receiverDepth)*65536,0,1)`。

接收深度 0.5：存储深度 0.6 表示无遮挡，当前结果 **0**；存储深度 0.4 表示有遮挡，当前结果 **1**。这与本包 `global/lighting/shadowmap.glsl:82-83` 和 ITT `UnderwaterVolumetricFog.glsl` 的 `step(receiverDepth,storedDepth)` 相反。增加平滑、焦散或相函数不能纠正反向可见性；它们只是继续调制错误的受光区域。

### R5 / P1：光束混用轴向深度和沿射线距离

`light_shafts.glsl:55-63`：终止距离使用 `length(viewPos)`，采样点却用 `viewPos*currentDist/(-viewPos.z)`。currentDist 实际成了相机 Z 轴距离。视线与前向夹角余弦为 0.5 时，currentDist=8 对应离眼睛 **16 格**；若最近地形为 10 格，该点已经在地形背后，循环仍会接纳它。

另外步长是 `40/N*0.5`，只执行 N 次，轴向覆盖始终小于 20 格。N=7、dither=0.5 时采样 1.43～18.57 格，所有 `max(3,currentDist*0.1)` 均为 **3**，并没有注释声称的距离变化。dither 可为 0，首点没有严格最小距离。参考 ITT 使用归一化 rayDir 与一致的沿程距离，不能将其 40 格常量单独拼接进当前轴向步进。

### R6 / P1：焦散绕开直射光约束，并丢失太阳投影

`program/lit.fsh:223-228` 在完整着色后把最终 color 乘上焦散，仅检查相机是否在水里。它没有 WATER_CAUSTICS 开关约束，也没有受光/阴影约束；环境光、方块光与发光材质都会被一起调制。在水中看出水外也不能据此认定目标表面浸水。

焦散取值 0.2 时最终乘数为 **0.44**，取值 1.36 时为 **1.252**，并非注释所谓不影响整体照明的中性操作。ITT 将焦散乘在直射阴影项，不能等同于乘最终颜色。

`global/water/caustics.glsl:77-78` 计算的折射太阳方向没有被使用。ITT 的 `GetWavesNormalFromTex` 用高度及折射光方向偏移采样 XZ；Astra 的手算法线替代同时丢掉了这一步。故当前函数在固定位置/时间下不随太阳方向改变投影。0.75 的坡度标定不能补回这一逻辑。床面/光束共用焦散函数，也不等于与 Steadfast 水面实际波法线一致。

### R7 / P2：溅水粒子导数阈值仍不是粒子识别

`program/lit.fsh:91-97` 的导数来自整张图集的归一化 UV，仍依赖图集尺寸和粒子屏幕尺寸。举例：8 像素精灵、256 像素图集、投影宽 4 像素，导数仅 **0.0078125**；1024 图集时为 **0.001953**，均远低于 0.09。此处只是反例，不假定运行中的图集一定是这些尺寸。

因此“单四边形必命中且与图集无关”不成立。阈值会漏掉正常大小的蓝色溅水，并可能误删满足阈值的其他蓝色粒子。它没有材质身份信息，不能据此宣布只删除原版溅水。需要从实际粒子输入/标识找到可靠区分条件，而非继续猜 UV 或颜色阈值。

## 黑洞的四处适配与尺度

- **64→256**：按实际噪声分辨率换算 UV 是必要的，但换了纹理并不保证统计分布/通道关系相同。不能据此声称与 ITT 外观一致；本轮未将其判为确定缺陷。
- **IGN 替代时间蓝噪声**：符合无 TAA 的约束，避免直接引入逐帧随机闪烁，但不等价于参考的时域去噪，静态噪点及运动稳定性仍需用户画面确认。
- **恒星方向**：`end.glsl` 的黑洞位置和地形直射均从 `normalize(view_player(lightVector))` 取方向，调用契约一致。
- **STAR_GAIN=3**：只放大星场，并没有补偿黑洞/吸积盘或地形照明。应标为美术增益，当前没有曝光链推导证明“3 倍补偿正确”。

50 步、0.2 步长、眼点距离 8、起点 3、盘半径 2.25 与宽度 3.5 是参考函数内部的一套空间比例，并非 Minecraft 方块单位。没有理由因渲染距离不同就单独重标定。当前选择了参考关闭 `ACCRETIONDISC_DETAIL_ALONG_LONGTITUDE` 的分支，属于额外的固定功能选择，应登记。

旧版 `exp(-max(angle-SHADOW,0)*k)` 发光实心盘表达式已不在当前实现中，但这不能证明整个视界必黑。当前只依赖盘透射率遮背景；参考本身的所谓 torus 表达式也是先取三维 length 再减 vec2，不能靠“来自参考”和注释就证明环形几何。黑洞视觉仍保留待确认，未宣称其已还原或再次失败。

## 九项决策建议

| 项目 | 本轮建议 | 依据 |
|---|---|---|
| 1. 硬件 PCF | 暂保留 false；不批准只改开关 | 当前 shadowtex0/1 是 sampler2D，手动读取深度/配对染色。硬件比较需要匹配采样器与消费者，不是无代价替换。 |
| 2. RenderMul 1.5→1 | 暂保留 1.5 | 视野外投射体也能向可见区域投影；“看不见所以浪费”不成立，尤其已有远处缺影历史。 |
| 3. Interval 0.5→4 | 暂保留 0.5 | 数值相差八倍不代表顶点工作量相差八倍，不能从参考值推断性能收益。 |
| 4. 大气 LUT | 同意研究现有天空计算复用，否决按当前文档直接移植 | ITT properties:184/187 绑定外部 512×128×33 RGBA32F 3D 数据，约 33 MiB；197 的 2.0×2.0 是放大而非半分辨率。不是“493 行生成半分辨率 LUT”。现有 waterRef 天空是否最大耗时也尚无计时证据。 |
| 5. pass 门控 | 保留已有门控，先核实剩余消费者 | composite2 已按 GODRAYS 或有效水下光束门控。共用 pass 内的水面散射不能一关了之；程序开关也不替代运行时入水状态判断。 |
| 6. 廉价工具箱 | 不整批引入；仅按具体热点选择 | 近似 sqrt/acos 有定义域与误差；Bayer 已有实现；textureSmooth 的纹理尺寸/过滤前提不能忽略。与 TAA 无关不等于无条件安全或更快。 |
| 7. PlanetEnd2 | 本轮不移植，不作为默认内容 | 当前目标清爽、优化，先解决已存在的光照链错误；新增行星需独立美术取舍。 |
| 8. 水下悬浮颗粒 | 保留三档默认关闭 | 符合清爽定位，当前没有要求改回的画面证据。 |
| 9. TAA/GI/FSR/体积云 | 继续不引入，保持三档 | 保持用户明确的实现与性能边界。 |
