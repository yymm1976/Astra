# SC-39：积水反射三次返工记录（2026-09-17 归档补录）

> 本文档补录 2026-09-17 两轮 SC-39 的完整返工链（原始过程仅存在于当日的 `qa/session-log.md` 与 `qa/glsl-sc39-*.log`）。撰写于 2026-09-20 三方审查之后，末尾附审查对最终状态的裁决。

## 背景与目标

雨天积水反射在 09-16 轮的实现有两处错误：门控读的是**广域潮湿掩码**（`surfaceWet`，雨天几乎处处饱和）而非稀疏水坑掩码，导致 96 步反射跑遍全湿世界；涟漪振幅与积水宽度的联动也未接。SC-39 的目标是把昂贵的 `puddle_reflection()`（最多 96 次深度采样 + 6 步细化）收回到稀疏水坑上。

## 三次返工

1. **第一次（错误）**：把 `astra_puddle()` 稀疏掩码写进 `colortex0.a`，注释断言"R11F_G11F_B10F 的 A 通道是未用填充"。**该断言是编造的**——`lib/water_buffer_formats.glsl:12` 明确 colortex0 是 RGB 格式、没有 alpha；写入被丢弃、读取恒为 1.0，门控在所有像素上放行，症状与原错误相同。
2. **第二次（错误）**：改写进 `gl_FragData[1].a`（水 pass 分支），注释称"该槽 a 为常数 1.0、无读者"。**该槽是 colortex5**（水 pass RENDERTARGETS 0,5），其 alpha 是 `water_state.fsh:19` 消费的水面有效性标志——覆写把标志清零，SRC_ALPHA 混合又使 rgb 一并丢失，整条水体状态链断线（2026-09-20 三方审查 F-01 定为最高优先修复项）。
3. **第三次（正确落点）**：掩码改走 `colortex3.a`（RGBA8 默认格式、真有 alpha，唯一读者是 deferred 的积水门）。2026-09-20 审查在其上再补两处：清屏 alpha 从 1.0 改为 0.0（掩码零值语义，F-42），以及把四个权重因子并入门控（`puddle_reflection` 在 mix 实参位置无条件求值的问题，F-15）。

## 教训（延续 09-16/09-17 已立的两条校验）

三处错误的共性仍是"注释描述了意图、代码写了别的缓冲，而验证只看能否编译"。本轮新增的纪律：

1. 数学助手必须与 Python 精确值逐点对拍（09-16 立）。
2. "压缩/上限/不增"类函数必须全量程验证单调性（09-16 立）。
3. **对系统行为的断言必须查声明与消费者**（09-17 立）：colortex 格式与 blend 状态、每个写入通道的读写者、每个 pass 的 RENDERTARGETS。`colortex0.a` 与 `colortex5.a` 两次事故都属于这一类的漏网——正确做法是先 grep 该通道的全部读者再决定载体。
4. （2026-09-20 增补）**清屏值必须等于该通道语义的零值**：colortex3.a 作为 0..1 掩码，清屏 1.0 等于把门默认全开。已修（settings.glsl colortex3ClearColor.a = 0.0）。
