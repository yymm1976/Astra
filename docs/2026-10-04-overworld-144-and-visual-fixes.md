# 主世界 144 FPS 目标与画面修复

用户确认目标为 144 FPS，重点是主世界性能，附带修复水下远处光束噪点、云边缘锯齿，完善银河，并提高下界暗部可读性、限制岩浆的红色和亮度。本轮改动已写入项目光影包；没有新的游戏画面或实时帧率数据，144 FPS 尚未确认。

## 主世界开销

| 渲染链 | 改动 | 画面保留与开销边界 |
|---|---|---|
| 屏幕云 | 从 `prepare1` 移到首个 `deferred` 通道，利用当前不透明地形深度排除被遮挡区域 | 阴影、反射环境仍在原准备阶段生成；屏幕云的步进预算和分辨率不变。遮挡判定覆盖内部深度纹素并扩展轮廓保护范围，遮挡多的视角收益更明显 |
| 天空合成 | 完全不透明的云后跳过天空和星空计算；日月纹理的云遮挡移到同帧合成 | 月相和日月颜色不变；日月透过当前帧的同一片云，避免搬动通道后读取旧云 |
| 地形与云 | 相机和地形终点都低于云层时，跳过云射线重建、区间求解和查询 | 相机位于云层内或云层之上时，继续使用原有裁剪步进 |
| 水下合成 | 透明几何完成后复用 `colortex4`，空气中直接跳过水下通道的场景读写 | 不增加全分辨率缓冲；水下继续全分辨率合成，Bloom、自动曝光和 TAA 消费同一份水下结果，无 Bloom 时保留显示阶段合成 |
| 水下照明 | Solas 水底与水面两套光色的时间、天气、对数、色彩幂次和归一化移到 Iris 每帧表达式 | 保留原公式及两套强度差别；逐像素介质、光照方向、阴影和焦散仍在 GPU 上计算 |
| 阴影几何 | 原生地形背光面跳过无贡献阴影坐标投影；静态不透明投影物跳过不需要的世界位置转换 | 保留花草投影、植被摆动、玻璃响应、水面光学记录；通用实体和末地坐标路径保留原处理 |
| 雨水扰动 | 干燥天气及不消费雨水扰动的几何不计算纹素导数 | 有雨时仍在材质分支和透明度裁剪前计算，保持导数合法性 |

平面云开启时，通道顺序为：屏幕云 → 可选 AO → 可选体积雾 → 场景合成。关闭平面云时保留原来的 AO／体积雾顺序。下界和末地显式关闭新增的主世界专用槽位。

阴影分辨率与距离、阴影滤波数量、水体反射精度、光束采样数和花草摆动保持当前选项值。云遮挡判定增加少量深度读取，云重建增加三个双线性读取，因此不能将这些改动描述为所有视角都获得同样收益。

## 水下远处光束

光束只积分最多 48 方块的窗口，但重建与历史过滤比较的是最多 128 方块的完整场景终点。远处水底的相邻终点差别，可能把实际积分窗口相同的射线互相排除，让第四根压缩存储中的随机采样难以平滑。

空间重建与历史过滤现在都按光束积分范围截断距离比较；范围内的前景遮挡仍参与排除。保留原来的九纹素重建、压缩域平滑、颜色、相位和焦散动态。

另外修复四采样水下光束与空气光束同时开启时的网格不一致：`colortex1` 与同一通道写入的历史 `colortex29` 现在都为半分辨率。单独使用四采样水下光束时，两者仍为四分之一分辨率。

## 云边缘与银河

云的存在由粗噪声决定，但原覆盖率用粗噪声加细节噪声计算。粗噪声刚跨过存在阈值时，细节项可能已将覆盖率推得很高，形成不连续的轮廓。现在粗噪声边界额外使用连续覆盖率，并按投影纹素范围调整边缘宽度。

屏幕云使用正权重二次重建，九个有效纹素权重合并为四次双线性读取；颜色和透明度一起按预乘形式过滤，只平滑云信号。这里针对的是平面云，原版几何云仍由场景抗锯齿选项处理。

银河复用现有噪声贴图，加入低亮度的冷色星带、暖色核心和暗尘结构。只有可见夜空的星带区域读取两次纹理，不增加体积步进或渲染通道。方向随现有天体坐标转动，保留星空开关、密度选项、雨天衰减、地平线衰减与日月避让；银河不会把整片天空标为星点的 TAA 响应区域。

## 下界

普通非发光材质的暗部补光由 `(0.055, 0.065, 0.075)` 调为 `(0.10, 0.115, 0.13)`，继续受原有方向、遮蔽和亮区淡出约束。岩浆、其他发光块和传送门不接受这项提亮。

原生岩浆保留独立材质标记：线性红色分量降低，添加少量琥珀色分量，并采用整体亮度压缩保留动画纹理层次。体素岩浆光源由 `(1.0, 0.18, 0.025)` 改为 `(0.72, 0.24, 0.04)`，减少周围地形上的强红光；下界岩浆内的雾色也改为较暗的琥珀色。其他发光块及传送门不受岩浆专属处理影响。

## 编译与运行边界

相关 GLSL 入口在本机 NVIDIA 驱动下完成编译与链接，包含水下合成、云调度、可选 AO／体积雾／TAA、不同云模式及下界体素计算。安装的 Iris 1.11.2 解析器成功解析通道启停、光束网格与新增的水下光色表达式。

帧率目标尚无新的运行数据；云轮廓、银河和下界亮度也尚无新画面反馈。源码中的无贡献工作裁减可以明确说明，实际帧率增幅不能据此保证。
