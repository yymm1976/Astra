# 水下光束重写意见（step5）

> 标注：**step5**。上一份（step4）是「单张同帧波面光量图 + 固定 Gauss 求积」的落地稿，代码与
> `docs/实现与限制.md` 已实现，但用户实测仍反馈「像柱子、位置乱七八糟、固定且毫无质感」。
> 本文不再是补丁清单，而是逐层拆掉现在这套结构的依据与替代方向；实施顺序、参数落点与验收口径
> 一并给出，供直接据此改源码。
>
> 阅读顺序：先读第 1 节结论，第 2 节是「为什么现在是柱子」的量化归因，第 3 节是与
> ITT 3.2 / Solas 的逐项差异（这部分决定替代方案怎么搭），第 4～7 节是具体改动意见，
> 第 8 节是本次不动的边界。涉及路径相对 `Astra/shaders/`。

## 1. 结论（先读这一节）

现在这套光束的问题不在「透光/遮挡/距离组织」——那部分确实照着 Solas 做了。问题集中在三处，
且都是结构性的，不是调参能救的：

1. **源图里有几个波层被自己的防混叠逻辑抹平了**，剩下的是长周期慢动团块。这是「柱子感」
   最直接的来源：细波峰没了，剩下的轮廓又大又慢，积分起来就是几根竖条。
2. **源图按「体积积分足迹」反推出来的 LOD 选级，与 ITT 的「法线缓存在固定世界密度上逐点
   投影」是两件事**。ITT 的法线缓存每 1 个世界格 10 个纹元，本方案是每 1 世界格 4 个纹元，
   还要再乘一个 6～10 次幂的亮纹包络；细节不是被降采样，是被乘没了。
3. **影图投射与体积接受点各自做一次完整影图查询，中间还夹一次云透射**，等于把
   「沿光束的遮挡」写成了「两端各看一眼」。ITT 是每步都查，Solas 是每步都查且区分
   透明/不透明两套。两端查询在稀疏遮挡（树叶、栏杆）下必然出现「这一格应该被切断却还亮着」
   的硬亮条——用户说的「位置乱七八糟」很大一部分是这个。

因此不建议继续在 `prepare4` + `colortex29` + `light_shafts.glsl` 的结构上加调节项。
第 4 节给出三套可选替代路径，分别对应「最省」「最接近参考」「最保画质」，并说明各自的取舍；
默认推荐 B（重建波面法线缓存，恢复细波层），因为它同时解决 1 和 2，且不动 Solas 侧的
距离/昼夜组织。

## 2. 量化归因：现在为什么是柱子

以下数字都从现有源码直接算出来，用于确认「不是调参问题」。

### 2.1 源图采样密度

`lib/itt_water_field.glsl`：`ITT_WATER_FIELD_SIZE = 512`、`EXTENT = 128` 格，
所以 **1 个源图纹元 = 0.25 世界格**。

ITT 原版 `deferred.fsh` 的法线缓存是 `gl_FragCoord.xy * (50.0 / min(screenSize.y, 500.0))`，
配合 `GetWavesNormalFromTex` 里 `coord * 0.02 → * pixelSize * min(screenSize.y, 500)`，
在 1080p 下 **1 个缓存纹元 = 0.1 世界格**。也就是说 ITT 的法线密度是本方案的 2.5 倍，
而 ITT 还把整个噪声场按 50 格做了 `fract()` 平铺。

### 2.2 六个波层在源图里被抹掉几个

`lib/itt_water_waves.glsl::itt_wave_noise` 的防混叠写成
`resolved = 1 - smoothstep(0.5, 1.25, footprint * frequency)`，而 `prepare4` 调用时
`footprint` 恒为 `ITT_WATER_FIELD_CELL`（0.25）。逐层代入
（`frequency = 64 × max(│transform×jacobian 的列│)`，已是噪声纹元/世界格）：

| 层 | 频率 | 世界周期 | 0.25 格足迹内跨越 | resolved |
|---|---:|---:|---:|---:|
| L1 | 9.28 | 0.108 格 | 2.32 | **0.00** |
| L2 | 4.41 | 0.227 格 | 1.10 | **0.20** |
| L3 | 1.51 | 0.662 格 | 0.38 | 1.00 |
| L4 | 1.41 | 0.709 格 | 0.35 | 1.00 |
| L5 | 0.63 | 1.587 格 | 0.16 | 1.00 |
| L6 | 0.32 | 3.125 格 | 0.08 | 1.00 |

`resolved` 为 0 时函数返回 `vec3(mix(0.5, value, 0), vec2(0))`——**数值退化成常数 0.5、梯度为
零**。也就是说源图里 1、2 层（正是决定「光束内一条条亮纹」的细波峰）被完全抹平，
只剩 3～6 层的长周期起伏。

这里必须说清一件事：**Astra 的六层变换与频率和 ITT 逐项相同**（`p = worldXZ*0.05`、
`transform = mat2(2.0,2.1,0.0,1.2)`、`jacobian = mat2(-0.05,0,0,0.05)` 与
ITT 的 `p*vec2(2.0,1.2)+vec2(0.0,p.x*2.1)` 代数等价）。两家的差别不在波场本身，而在
**承载它的缓存密度**：ITT 的 `deferred.fsh` 法线缓存约 0.1 世界格/纹元，本方案 0.25 世界格/纹元。
ITT 在 0.1 格/纹元下 L1 也有 1.08 纹元/周期，同样低于 Nyquist，但它是 `textureLod` 取
点邻域 + 每步全分辨率查询 + 蓝噪声 TAA 收敛来摊掉的；本方案既没有逐点查询，也没有时间累计，
只剩「在源图上先把细节抹掉」这一条兜底，于是抹掉之后就没有任何东西能补回来。

（补充：本文初稿曾把 L1 的世界周期记成 0.16～0.26 格，那是把 ITT 的 `p` 单位误当世界单位；
按 `frequency = 64 × │transform×jacobian 的列│` 重算后为 0.108 格，结论方向不变——
细层在 0.25 格/纹元下仍然不可表达。）

### 2.3 亮纹包络的 6～10 次幂

`prepare4` 里 `envelope = pow(envelope, mix(10.0, 6.0, clearDay))`，其中 envelope 源
`(broad*30 + wide*20)/45` 的动态范围约 0.21～1.0。看响应：

| envelope 原值 | ^6 | ^10 |
|---:|---:|---:|
| 0.3 | 0.0007 | 0.000006 |
| 0.5 | 0.0156 | 0.00098 |
| 0.7 | 0.117 | 0.028 |
| 0.9 | 0.531 | 0.349 |
| 1.0 | 1.0 | 1.0 |

结果是**接近二值的地图**：极少量孤立亮点接近全亮，其余几乎全黑。多区间积分把这些孤岛
沿视线串起来，就得到「几根边界清晰的竖亮条」。ITT 没有这层幂：它的体积光强直接是
`caustics^3 * shadow`，caustics 本身是 `dist*2.8+0.2` 的连续量，自然形成宽窄不一的纹路。

### 2.4 体积缓冲分辨率

`shaders.properties` 在默认均衡档把 `colortex1` 设成 `0.25 0.25`。1080p 下即 270×152 个
纹元，每个纹元覆盖 4×4 个屏幕像素，而 `water_shafts_view()` 用 `texelFetch` 只取**一个**
端点的深度。等于把原本全屏 256 级的遮挡轮廓压到 270×152 的阶梯上，任何几何边缘、
栏杆、水底落差都会出现块状跳变。ITT 的 `composite5` 是全分辨率。

### 2.5 两端式遮挡

`global/water/light_shafts.glsl::water_shaft_path_visibility` 对每个区间只取首末两个点，
每个点读入口透射（`shadow_coverage` + `shadow_opaque_visibility`，共 2 次影图读取）
和接受点可见性（再 2 次），区间内部线性插值。ITT 是每个步进点都做一次影图查询；
Solas 是每个指数步进点都做一次，且区分 transparent / opaque 两次取样。
当遮挡物小于一个区间长度（3.7 世界格）时，两端查询整体漏掉它。

### 2.6 顺带确认：几何投影本身没错

`entry = worldOrigin + source*(depth/source.y)`、`entryRay = ray - source*(ray.y/source.y)`
这一组等价于对每个体积点做 ITT 式逐点投影（把 `point(d).xz` 沿 `source` 投到水面），
代数上严格相等，所以「位置乱」不是这个投影造成的。光泽方向、消光、距离组织
（近处 0.08 起、14～26 淡出）也都与参考同构。

## 3. 与 ITT 3.2 / Solas 的逐项差异

只列与本次症状相关的差异；完整的参考定位在 `docs/参考与取舍.md`。

| 维度 | ITT 3.2 | Solas V2.2b | Astra 现行 | 症状关联 |
|---|---|---|---|---|
| 波面法线密度 | 0.1 格/纹元，屏幕足迹驱动 | 无水下波面法线 | 0.25 格/纹元 + footprint 收缩 | 细波峰消失 → 柱子感（§2.2） |
| 亮纹成形 | `caustics = dist*2.8+0.2`，`^3`，连续 | 无 | 包络 `^6~^10`，近二值 | 硬边亮条（§2.3） |
| 体积积分位置 | `composite5` 全分辨率，6 步 | `composite` 内指数步进 | `colortex1` 0.25 分辨率，7 区间×4 节点 | 轮廓阶梯化（§2.4） |
| 遮挡取样 | 每步 1 次影图查询 | 每步 2 次（透光/不透明分离） | 每区间两端各 1 组 | 稀疏遮挡漏断（§2.5） |
| 步进偏移 | `BlueNoiseTemporal()` 逐帧抖动，TAA 收敛 | `exp2(dither)` 指数步进 | 固定 Gauss 节点，无抖动 | 细节缺失时无法靠噪声补（§2.3 的必然结果） |
| 相位函数 | `MiePhase(0.7, LdotV)` | 无（VL 单向前向） | Cornette–Shanks g=0.45，40% 方向 + 60% 各向同性 | 方向性被稀释，宽面发灰 |
| 入射光分离 | 无（只有 shadow×caustic） | 显式分离透明透光/无遮挡基础项 | 入口 + 接受点各一次 | 与上一行同源 |
| 强度昼夜 | `colorShadowlight * 0.04 * phase * SUNLIGHT_INTENSITY * UNDERWATER_VFOG_DENSITY`，乘 `globalCloudShadow` | `timeIntensityFactor`、`closedSpaceFactor`、水下单独一套 | `mix(0.32,1.35,clearDay)` + Solas lighting | 已接近 Solas，保留 |

需要特别指出的两点：

- **Astra 的均衡档是 FXAA，水下场景 TAA 退出**（`lib/taa_jitter.glsl`：`isEyeInWater != 0`
  直接返回零抖动）。这使得「ITT 靠逐帧蓝噪声步进 + TAA 收敛」这条路在 Astra 上不可用，
  不能照搬后指望累计恢复细光束。这是第 4 节三条路径都要遵守的硬约束。
- **Solas 的 `volumetrics.glsl` 水下分支本身没有显式半圆锥发射点**，它的水下体积光完全由
  「影图透光 × 沿程衰减」组织。用户所指的「Solas 那种连贯亮纹」实际来自它沿程
  `pow(currentDist/maxDist/sampleCount, vlSamplePersistence)` 的距离权重和
  `closedSpaceFactor` 的距离收缩，不是来自某个发射源。所以「参考 Solas」的正确含义是
  距离/昼夜/封闭空间组织，而不是它的光源形式。

## 4. 三套替代路径

三条路径不是「三份实现一起做」，是按代价排序的备选。默认推荐 **B**。

### 路径 A：保留单源图，只修「被抹平的层」和「过陡的幂」

改动全部局限在 `lib/itt_water_waves.glsl` 与 `program/itt_water_normal_cache.fsh`，
不动 `light_shafts.glsl` 的求积结构。

1. `itt_wave_noise` 的 `resolved` 判据改为**按层频率归一化**，而不是统一拿 0.5/1.25 卡。
   具体做法：把判据从「足迹×频率」改成「足迹相对该层世界周期」，即
   `resolved = 1 - smoothstep(0.5, 1.25, footprint / thatLayerWorldPeriod)`。
   L1 世界周期 0.108 格、0.25 格足迹 → 比值 2.32，仍会被压，但压的是幅度而不是直接清零；
   L3～L6 世界周期 0.66～3.13 格，比值 0.08～0.38，全部保留。
   **注意：放宽判据本身不能创造不存在的信息。** L1 在 0.25 格/纹元下只有 2.32 纹元/周期，
   任何判据都只能决定「压多少」，不能让它变成清晰细纹。真正的恢复只能靠提高密度（路径 B）
   或者接受这一层就是糊的、把观感重心移到 L3～L5。
   更彻底的做法是给 `itt_wave_wave()` 传两个足迹下限：L1/L2 用
   `max(footprint, 0.5)`，L3 以下用 `footprint`。原则只有一条：
   **防混叠只能降幅，不能把某层的均值搬成常数**。
2. ~~把 L1、L2 的世界频率整体降一半~~——**此路不通，已否决**。实测：降到 0.25 倍频后
   L1 世界周期 0.43 格，与 L3 的 0.66 格重叠，两层合并成一个尺度，波层从 6 层退化成 5 层，
   反而更单调。要保留 6 个可分辨的尺度，就不能动频率，只能动密度。
3. 包络幂次从 `mix(10,6,clearDay)` 降到 `mix(3,2,clearDay)`。原意图是「晴天亮纹变宽、
   条数增加」，但 6～10 次幂把宽纹做成了孤岛。改成 2～3 次幂后，同一张噪声的中间调
   会大量保留，亮纹从「点」变成「带」。用户可感知的「条数增加」由包络本身的
   多尺度合成给，不该由幂次数给。
4. `colortex1` 从 `0.25 0.25` 提到 `0.5 0.5`（与粗体积 `program/volume_main.fsh` 的
   目标分辨率一致），端点深度从 `texelFetch` 单点改成与该分辨率匹配的**同一纹元**，
   但仍单点——因为求积本身就是按端点的射线做的，路径不支持重采样。1080p 下 540×304，
   阶梯减半。

代价：§2.1 的密度差仍然存在，细层只是不再被清零、仍是被压幅后的糊状；阶梯化只减半。
这一条路径**不能**恢复 ITT 那种束内细密亮纹，只能去掉「柱状孤岛」这个最刺眼的症状。
如果用户要的是「ITT 那种质感」，必须走 B。

### 路径 B：重建「波面法线缓存」，恢复 ITT 的逐点法线（推荐）

这是唯一能同时解决 §2.1～2.3 的方向，也是用户要求「参考 ITT 重写」的字面解法。

核心思路：**不再从一张光量图滤波求积，而是像 ITT 一样在已知世界密度上缓存波面法线，
在体积积分时逐点投影取样**。

1. 删掉 `colortex29` 的「光量图」定位。新 `prepare4` 写**波面法线 + 碰撞距离**：
   - 分辨率 **1024×1024，覆盖 64 世界格**（1 纹元 = 0.0625 格）。这个覆盖是按
     `WATER_SHAFT_FAR_END = 26` 的一半再留裕量定的：实际积分最远 26 格，加上入口投影
     的水平偏移，64 格窗口（中心 ±32）足够。RGBA16F 静态 8 MB。
   - 该密度下 `resolved` 逐层为：L1 = 0.89、L2～L6 = 1.00（`footprint × frequency`
     分别为 0.58、0.28、0.09、0.09、0.04、0.02）。L1 仍被轻微压幅，但不再是清零。
     如果要求 L1 完全保留，需要 0.05 格/纹元（1024×1024 覆盖 51.2 格），此时 ±25.6 的
     半窗与 26 格积分上限刚好贴边，不如 0.0625 稳妥。
   - 每个纹元存 `RG = 编码法线`、`B = 碰撞点水平距离`（供 caustic 直接取用，省一次
     `refract`），A 备用。
   - 注意：即使提到 0.0625 格/纹元，**1024×1024 的源图生产仍然是一笔成本**（262144 个
     纹元 × 六层解析法线）。与现行 512×512 相比生产量翻四倍。若帧率不允许，退到
     512×512/64 格（0.125 格/纹元，L1 = 0.12、L2 = 0.93），接受 L1 基本无贡献、
     细节由 L2 以下给——这仍比现状好，因为现状 L1/L2 都是 0 或接近 0。
2. `light_shafts.glsl` 的求积从「读光量图」改为「读法线图，就地算 caustic」。
   ITT 的做法是 `CalculateWaterCaustics(worldPos)`：把体积点 `+vec3(0,1,0)` 后取该点
   的波面法线，`refract(vec3(0,1,0), n, 1.0)` 求碰撞点，`dist*2.8+0.2`。这套可以直接
   搬过来，而**不需要 per-sample 的影图查询**——遮挡仍由现有的区间两端查询负责，
   caustic 只提供束内亮暗分布。
3. 亮纹能量的形状改成 ITT 原式：`caustic = 0.2 + 2.8*dist; energy = caustic^3`，
   再 `energy/(1+0.25*energy)` 压峰值（这条 Astra 已有）。**去掉 6～10 次幂包络**。
   波峰的连贯性由 L5/L6 的 `AlmostIdentity` 提供——ITT 的两层 crest 就是它的
   「连贯亮纹」来源，不需要额外的幂。
4. 保留 Solas 侧的一切：`astraWaterShaftRange = 48`、近处 0.08 起、14～26 淡出、
   `solas_water_lighting` 昼夜、`mix(0.32,1.35,clearDay)` 的晴天增强。
   这些不是问题所在。
5. 同时把 §5 的第 3、4 项（分辨率、遮挡密度）一起做，否则细纹会再次被粗端点轮廓吃掉。

代价：每个求积节点从 1 次纹理读取（RGBA16F 光量）变成 1 次法线读取 + 一次 `refract`
（1 次 `sqrt` 与几次乘加）；总纹理带宽下降（法线图可以更小）。源图生产成本略升
（要算六层法线而不是六层能量），但已有的解析梯度本来就是法线形式，不额外增加层数。

### 路径 C：换成屏幕空间步进体积（最接近 Solas 的空气 VL 形式）

彻底放弃「源图」概念，改成像 Solas 一样在合成阶段沿视线指数步进，每步：
- 投影到水面取 caustic（ITT 式，可用 B 的法线图或直接解析算）
- 查影图（1 次）
- 按 `pow(dist/maxDist/steps, persistence)` 累加

代价最高，且水下场景每像素 6～8 次影图查询在 4～5 m 的目标帧率下风险大；
只在 A、B 都不满足时考虑。本文不展开。

## 5. 与本次症状对应的最小改动集

如果只做一件事来解决「像柱子」，按性价比排序：

| 优先级 | 改动 | 文件 | 预期解决 |
|---|---|---|---|
| 1 | 包络幂次 `mix(10,6)` → `mix(3,2)` | `program/itt_water_normal_cache.fsh` | 孤立亮岛 → 连续亮带 |
| 2 | 改 `resolved` 判据为按层周期归一化，使 L1/L2 由「清零」变「降幅」 | `lib/itt_water_waves.glsl` | 束内细层不再整体消失（仍是糊的，见 §4A 代价） |
| 3 | `colortex1` 0.25 → 0.5 分辨率 | `shaders.properties` | 轮廓阶梯化 |

## 7. 验收口径（改完后必须实机确认，不能以源码声称）

1. **连贯性**：站在静水下方，缓慢转视角，亮纹应连续成带、随波峰流动；不出现
   边界清晰的竖直亮条，也不出现孤岛亮点。
2. **数量**：晴天同一机位可见亮纹数量应明显多于阴天，且宽度增加而非数量爆炸。
3. **位置稳定性**：玩家不动、只转视角时，亮纹不整体平移、不绕眼位旋转；
   快速转动时不抽动（这检验窗口跟随与端点重算）。
4. **遮挡正确性**：把水槽放在树冠／栏杆下方，光束应被真实切断，而不是整体保留或整体消失。
5. **帧率**：原生 1080p、均衡档，水下场景需达到既定目标；本次改动若增加影图读取次数，
   必须给出前后对比，不接受「理论上应该更快」。
6. **不回归**：浅水淡青过渡、深蓝遮蔽、近处手与身体不被光束淹没、Bloom 两条路径一致。

## 9. 动手前先确认（成本极低的三个验证）

在改任何源码之前，先用这三件事把上文归因钉死。它们都不需要新工具，只需临时改动与实机看画面。

1. **确认 L1/L2 真的被清零**：临时把 `lib/itt_water_waves.glsl::itt_wave_noise` 最后一行
   的 `resolved` 强制设为 1.0（`return vec3(value, transpose(worldUV)*gradient);`）。
   如果画面亮纹的「细碎感」明显增加且不再呈柱状，归因成立；如果完全没变化，说明问题在
   别处（应当转去查遮挡与端点），不要继续按本文实施。
2. **确认幂次是硬边亮条的主因**：临时把 `program/itt_water_normal_cache.fsh` 的
   `pow(envelope,mix(10.0,6.0,clearDay))` 改成 `envelope`（等于 1 次幂）。若亮条
   从「窄硬边」变「宽软带」，成立。这是单项收益最大、风险最低的一步。
3. **确认阶梯来自分辨率**：把 `shaders.properties` 里水下光束分支的 `size.buffer.colortex1`
   从 `0.25 0.25` 改成 `0.5 0.5` 并同步帧率读数。若轮廓阶梯明显减轻且帧率可接受，
   此项可直接落地；若帧率掉出目标，则必须靠 B 的逐点法线来省带宽，而不是维持高分辨率。

做完这三步再决定走 A 还是 B。第 1 项是分派依据：不成立就整篇重写归因，不要在错误方向上堆改动。

## 11. 复算本文数字的方法

所有频率由 `frequency = 64 × max(│(transform×jacobian)[0]│, │(transform×jacobian)[1]│)`
给出，其中 `jacobian` 初始为 `mat2(-0.05, 0, 0, 0.05)`（即 `dp/dworldXZ`，`p = worldXZ*0.05`
且 `p.x` 已取负），`transform` 为各层的 `mat2(...)`，层间 `jacobian` 依次乘
`0.475 → 0.475×0.67 → ×0.7 → ×0.45 → ×0.5`。GLSL 的 `mat2(a,b,c,d)` 是列主序，
`M×v = v.x×(a,b) + v.y×(c,d)`；`M×J` 的列是 `M` 分别乘 `J` 的两列。
建议独立复算一遍——本文初稿正是因为把列主序弄反而算错过一次 L1 的周期。
