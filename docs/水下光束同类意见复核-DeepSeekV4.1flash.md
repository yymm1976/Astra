## 2. 被数值推翻的说法（4 条）

### 2.1 「软限幅把束内对比抹平」——三方都高估了

- 本文提案原文：「中高坡度段被压成 2.0～3.99 的 2:1 区间，束内碰撞纹理在这一步就丢了」；
- hy4 的 R2/R3（修订版仍保留）：「软饱和…对比压缩约 **300 倍**」「`|slope|≥0.25` 以上的全部明暗塌到同一水平」，列为**必须改**、S2 定为「最关键的一步」；
- GLM 的 P0-4：「源端存原值，三次方移到消费端」。

**复算（128² 格窗口，0.25 格步长）**：`landingOffset` 实际分布 p10=0.031 / p50=0.095 / p90=0.219 / **max=0.582**（远达不到公式允许的 4.0）；`caustic³ ∈ [0.008, **6.13**]`；过 `e/(1+0.25e)` 后 `∈ [0.008, **2.42**]`，**中位数 0.100→0.098 几乎不变**。即软限幅只压缩**高端约 2.5 倍**，动态度仍有 110:1（p99/p1）。同一复算下 ITT 的 `caustic³` 中位数为 0.107——**与 Astra 未压缩前几乎相同**。

**hy4 修订版新增的 §10(d) 表看似有力，但表里的失控段在实际波场上不存在**：该表把 `|slope|` 一路列到 **0.9**（对应 `caustic³ = 143.9`），而同一波场的实测 `|slope|` 是 p50=0.049 / p90=0.111 / **max=0.269**——**0.25 以上几乎不出现、0.4 以上完全不存在**。在它表里最靠边的真实行（`|slope|=0.25`）：`e=4.1`，k=0.25 给 2.02（差 2 倍），不是「塌到同一水平」。

**判定**：hy4 的「300 倍压缩」「≥0.25 全塌」不成立（前者差两个数量级，后者是外推不可达区间），S2 的预期收益被高估；本文提案原先把机制定位在「源端压缩」，同样把后果夸大了。**该项应降为可选低优先，不应作为「S2 最关键一步」的依据。**

**另需撤回本文早前对 GLM P0-4 的一条批评（误读，已更正）**：我原先写「先线性滤波再立方会因 Jensen 不等式让峰值更暗更软」，那是把它读成「缓冲里存三次方值、再滤波后立方」。GLM 的 P0-4 实际是**缓冲里存线性量**（`0.2+2.8·landingOffset`，未立方）、消费端再立方——**这是正确的前置滤波做法**（线性量先滤波、非线性放消费端），与 step5 路径 B「存法线、消费端算 caustic」、grok4.7「存法线」同构。Jensen 只适用于「缓冲里已是三次方值再滤波」的写法。**结论：P0-4 的结构成立**，其收益仍受本节实测限制（软限幅只差 2.5 倍），但不应被否定；真正必要的是它同时提出的「降低 mip 预滤」（见复核 §6 的 A5，以及总结文档里对路径 B 的消费端缺口说明）。

### 2.2 包络的「稀疏小点 / λ 117～235 格」与「30～50 格」——各自测的是不同量

复算结果（同一 128×128 格窗口）：

| 量 | 实测 |
|---|---|
| 包络本身 | mean=0.71，p50=0.75，**28% 面积 ≥0.85** |
| `pow(env,6)` | mean=0.265；`>10%·max` 覆盖 **62% 面积，仅 5 个连通区**；`>50%·max` 覆盖 19.5% |
| `pow(env,10)` | mean=0.168；`>10%·max` 覆盖 40% 面积（19 区）；`>50%·max` 11.5% |
| 特征间距（自相关） | **11.5 格（x）× 25 格（z）**，各向异性 2.2:1 |
| 漂移 | **1.5 格/秒**（≈8 秒走完一个纹距）。两层各自不同：层 5 ≈1.03、层 6 ≈1.73 格/秒，合成场的互相关峰值落在 1.5 |
| ITT 各层「纹理整周期」（另一量） | L1≈6.9、L2≈14.5、L3≈42、L4≈45、L5≈101、L6≈202 格（hy4 原版表中 9.5/20/57/53/117/235，用的是「只取耦合项」的近似范数，故整体偏大 16%～38%，量级一致） |

**判定**：
- hy4 **原版**的 **λ 117/235 格是对的，但那是「噪声整周期」**（该层图案重复一次的距离），不是玩家看到的亮纹间距；由此推出的「窗格里只有 1～2 个峰 → 屏幕上就那么几处」把周期数当成了可见条纹数，实际可见特征间距是 11.5～25 格。**hy4 修订版已把该表换成「特征尺度（格）」并给出 0.71/1.58 一档**，方向与实测一致，但见下一条。
- hy4 **修订版的层号与实测错开一层**（§4.1 详述）：它把 0.711/1.406 归给权重 30 的 crest 层，而按 `itt_water_wave` 的链条，权重 30 层的频率是 **0.633**（胞元 1.58 格）、权重 20 层是 0.32（3.16 格）；0.71/1.41 属于权重 16 层。由此它「主导 crest 层（0.71/1.58）被 0.93 格足迹抹掉」的结论方向也可疑：被 0.93 格消费端足迹抹掉的是 L1～L4，而权重 30/20 的 crest 层 (1.58/3.16 格) 基本存活（resolved 0.96/1.00），被抹掉的主要是它们的**脊宽**而不是整层。
- hy4 的「只剩 3～5 个孤立斑点」在**连通区数量**上接近（pow 6 下 `>10%·max` 确有 5 个连通区），但**不是「孤立斑点」而是**「5 块巨大的连通亮区覆盖 62% 面积」——它更像「几块大亮斑/粗柱」，这个区别决定了修法（去门控 → 恢复幅度调制，而不是「把点做大」）。step5 §2.3 的「极少量孤立亮点接近全亮，其余几乎全黑」同样低估了覆盖：实测 `pow(env,10)` 下仍有 40% 面积在 10%·max 以上、11.5% 在 50%·max 以上，只有 <1% 面积接近全黑。**「其余几乎全黑」与「孤岛」两个说法都应改为「高对比门控 + 大面积暗淡底 + 少数大亮斑」。**
- GLM 的「30～50 格尺度」偏大；与实测的自相关**零点半周期 15.5/35.5 格**量级相当，属同一区间的上界读法。
- 本文提案原先的「5～27 格」接近实测（11.5×25），但**漂移速度写成 0.5 格/秒，实测 1.5 格/秒（差 3 倍）**，已在提案 §11 就地改正。

### 2.3 碰撞距离公式

- hy4 §3.2 推导：「`collisionPoint − worldPos = (−2n.x, 0, −2n.y)`，所以 `dist = 2|n.xz|`，`caustics = 5.6|波面斜率| + 0.2`」；
- 本文提案原先写作：`dist = sqrt(tan²2θ + 4)`。

**复算逐点验证**（0°/5°/10°/20°/30°/40°/44°）：正确闭式是 **`dist = |tan2θ|`**（θ 为波面倾角）——`R/R.y` 的 y 分量恒为 1，与 `lookupCenter.y += 1.0` 恰好抵消，我的「+2 常数」是算错；hy4 的 `2|n_xz|` 是它的**小角近似**，在 θ=10° 时 0.347 vs 精确 0.364（差 5%）、在 θ=30° 时 1.00 vs 1.73（差 73%）。**该波场的实际倾角 ≤15°**（实测 `|slope|` max=0.269 → θ≈15°），此时 `dist` 的误差 <11.5%、但**经立方后能量差约 34%**（`caustic³`：精确 6.06 vs 近似 4.53）——所以该近似在量级与结论上够用（该光量只依赖入口处波面法线、与样点深度无关，可预烘成 XZ 的二维图，双方结论都成立），但引用具体峰值时应用闭式。

### 2.4 本文提案自己的错误

除上面 2.1/2.2/2.3 涉及的两处（软限幅、漂移速度）与公式外，我另在提案里发现了**它此前完全没有识别的一项**（见 §4.1）。这些已在 `docs/水下光束重写改动意见-DeepSeekV4.1flash.md` 的 §11 就地标注并改正，供对照。

## 3. 被代码推翻的说法（4 条）

### 3.1 GLM P0-1「整条射线共用单一水面入口」——前提不成立，落地是空操作

GLM 的定因是「整条射线共用单一 `entry`，束内所有深度共享同一条水面采样直线，入口遮挡沿整条射线恒定」，据此提出 P0-1「改为每采样点独立波面投影」。

**代码事实**：`entry = worldOrigin + source*(depth/source.y)`、`entryRay = ray - source*(ray.y/source.y)`（`light_shafts.glsl:133-135`），而 `entry + entryRay·t` **正是样点 P(t) 的精确入射投影**——hy4 §5.1 已给出这步代数，本次回源复核确认无误（`worldOrigin.xz + ray.xz·t + source.xz·(depth−ray.y·t)/source.y` 展开即 `entry.xz + entryRay.xz·t`）。所以：
- 现实现**已经是**逐样点独立投影（用的是**真实水位**，比 ITT 的 `lookupCenter.y+=1.0`（把投影面设在 y≈0）更准）；
- GLM 在 P0-1 里写的替换式 `waveXZ = worldPos.xz + dBelow·(source.xz/source.y)` 与现式**代数等价**——按它实施等于不改；
- 另一处「入口遮挡沿整条射线恒定」也不准确：入口可见性是在**每个区间端点**各算一次、区间内线性插值（`light_shafts.glsl:148-154,167`），不是全射线恒定。

**判定**：GLM 的 P0-1 应从「结构替换」降为「无需改动」（或仅在改用真实水位这件事上确认现状）。它同一段里「保留 Astra 的真实水位、不要改回 ITT 的 y=0+1」的判断是对的，值得保留。

### 3.2 GLM P0-3「加逐帧抖动、靠 TAA 收敛」——水下没有 TAA 可收敛

代码事实：`lib/taa_jitter.glsl:11,28` 在 `isEyeInWater != 0` 时返回 **零抖动**；`program/taa_resolve.fsh:101-106` 对非空气介质**直接放弃历史**（写出 `-1` 无效标记并返回当前帧）。因此水下加时域抖动只会得到**永久噪点**，不会收敛；GLM 写的「Astra 已有 TAA 基建可用」这一前提在水下不成立（`ANTIALIASING=0` 的 PERFORMANCE/NO_SHADOWS 档更是完全没有 TAA）。

**判定**：P0-3 应驳回。hy4 的「不加时域抖动，改用空间抖动 + 更多步」与本文提案「用 Solas 的几何间距 + 静态空间抖动」是在这个约束下可行的两条替代。

### 3.3 hy4 R4「窗格原点掺水深 → 整幅图案平移/抽动」——不成立

hy4 认为生产者用当帧水深估计算窗口中心、量化到 4 格，水深一抖图案就整体平移。

**代码事实**：`originCell = floor((centre/ITT_WATER_FIELD_CELL − ITT_WATER_FIELD_SIZE*0.5)/16.0)*16.0`（`itt_water_normal_cache.fsh:25-26`），`centre` 是**绝对世界坐标**，故 `originCell` 恒为 16 格的整数倍、**世界原点对齐**（1 格 = 4 格），并且生产者按 `worldXZ = (originCell + gl_FragCoord.xy)*CELL` 写值、消费者按同一绝对格网格取值（`itt_water_field.glsl:12-14`）。**同一世界坐标的取值不随窗口移动而改变**；水深估计变化只改变**覆盖哪一块区域**（以及 4～8 格边缘渐弱与 slab 裁剪的取舍），不会让图案平移或抽动。

**判定**：R4 的机制驳回；但它想修的现象（相机靠近窗口边缘时忽有忽无）确实存在，来源是**边界渐弱 + `water_shaft_wave_segment` 的 4 格 slab 裁剪 + 覆盖预测失准（D03）**，与 GLM 的 P1-2、本文提案 §5.2.5 的「原点只锚相机 XZ」是同一件事。hy4 的 S4「验证：上下移动 2 格光束不应跳」会因为「本来就不跳」而给不出信息。

### 3.4 GLM「colortex1 @ 0.5x」——出厂档实际是 0.25x

`shaders.properties:18-33`：`#if OVERWORLD_BUDGET > 0 → size.buffer.colortex1=0.25 0.25`；PERFORMANCE/NO_SHADOWS/BALANCED/ULTRA 四个档案全部 `OVERWORLD_BUDGET=1`，因此**实际是 0.25×0.25（1080p → 480×270，1/16 像素数）**。GLM 的「0.5x buffer + 全分辨率 resolve → 半分辨率无时域补偿 → 块状图案」把损失少算了一半（hy4 用「低分辨率」带过，本文提案写 0.25×，与代码一致）。这会直接影响「分辨率要不要提」的成本判断（见提案 §7 裁决项 4）。

### 3.5 附：两条应予驳回的次要不一致

- **hy4 §5.1 的备注**「`entryRay` 未归一化导致 `t` 与实际水平位移不成正比」：`t` 是沿射线的三维距离，`entryRay.xz` 非单位正是正确比例（消费端 `sourceFootprint` 用 `stepLength*length(entryRay.xz)` 已正确计入）。**这是误报，不要为它改动**。
- **ITT 的影图分支不可省略**：`UnderwaterVolumetricFog.glsl:63-68` 是 `#ifdef MC_GL_VENDOR_NVIDIA` 用 `shadowtex1`、否则用 `shadowtex0`，而 ITT 自身 `shadowTranslucent=true`，两支不可能等价。GLM 写了「NVIDIA 分支用 shadowtex1」，hy4 的引用（§3.1 代码块与 §6 表）把分支省略成只有 `shadowtex1`——两者引用时都应补上这个分支。

## 4. 本次复算/回源新增的事实（含对已有发现的独立确认）

### 4.1 生产者自身的 Nyquist 滤波砍掉了 ITT 最细的两层（对「毫无质感」贡献很大）

`lib/itt_water_waves.glsl:26-28` 每层都乘 `resolved = 1−smoothstep(0.5,1.25,footprint*frequency)`，而生产者传的 `footprint = ITT_WATER_FIELD_CELL = 0.25` 格。按同一复算逐层求 `frequency = 64·max(|col|)`：

| 层 | 权重 | 频率(周期/格) | 噪声胞元 | **resolved@0.25** |
|---|---:|---:|---:|---:|
| L1 | 1 | 9.28 | 0.11 格 | **0.000（整层滤掉）** |
| L2 | 4 | 4.41 | 0.23 格 | **0.101** |
| L3 | 8 | 1.51 | 0.66 格 | 1.000 |
| L4 | 16 | 1.41 | 0.71 格 | 1.000 |
| L5 | 30 | 0.63 | 1.58 格 | 1.000 |
| L6 | 20 | 0.32 | 3.16 格 | 1.000 |

即：**0.25 格/纹素的载体装不下 0.11/0.23 格的胞元，ITT 层 1 全部、层 2 九成在生产端就被抗混叠滤掉了**——这不是 mip、不是消费端滤波、也不是软限幅能修的；它是「512² 覆盖 128 格」这个选择本身的物理上限。要找回这层细腻流动感只有三条路：图提到 1024²（0.125 格/纹素）、覆盖缩到 64 格保持 512²、或放弃 LUT 改为每样点现场求值。

**归属与差异（本条不是本文独有）**：step5 §2.2 独立复算出**同样的 L1 频率 9.28 / resolved 0.00**，结论一致；hy4 修订版 §3.4/§10(c) 也给出「L1/L2 100% 被滤掉」。三方的差异只有两处小数：**L2 的 resolved**——本文与精确计算是 **0.101**（`footprint·f = 0.25×4.41 = 1.1025`），step5 写 **0.20**；**层号配频**——hy4 的表把频率整体错开一层（§2.2 已述），因此它「主导 crest 层被消费端足迹抹掉」的归属需要按修正后的层号读。**可复现的数值以本文脚本的表为准**（该表用的是代码自己的度量 `64·max(|col|)`，与手算逐层吻合）。

### 4.2 「束形由门控决定」已有量化证据

复算给出 G（`pow(env,6)`）与 R（碰撞光量×透射）的**相关系数 0.046**、动态度 G:R = **4.4×10³ : 1.1×10²**。这比「读起来像」更有力地支持各份文档的共同判断：**调整 R 或软限幅都不会改变束形，只有动门控/换束形来源才有效**。

### 4.3 碰撞光量与太阳方向无关

复算与回源一致：`landingOffset`（因而 `caustic³`）只由波面法线决定，**不含太阳方向**；太阳只通过 `transmission = 1−Fresnel` 与后段相位/色调制参与。含义：**光束图案本身不会随太阳角度改变形状或位置，只有亮度与相位随它变**——这既是 ITT 的既有性质，也说明「随太阳移动而变化」不能作为验收判据，验收要用「遮挡物移动/云影变化时图案是否跟着变」。

### 4.4 R 的结构尺度与「生产者 + 消费端」的两级滤波（本文修正后的逐级核算）

实测 R 的自相关首个局部极大在 **0.5 格**、零点半周期 **2.5 格**；消费端在常见视距下取 `lod≈1.9`（有效核 **0.92 格**）。把两级滤波按层算一遍（`resolved` 判据：`1−smoothstep(0.5,1.25, footprint·f)`），得到**有效细节下限**：

| 配置 | 生产者后 | 消费端有效核 | 消费端后 | 有效下限 |
|---|---|---|---|---|
| 现状（CELL=0.25，`lod≈1.9`） | L3–L6 | 0.92 格（L3 1.40、L4 1.31 均已归零） | **只剩 L5/L6** | **≈1.58 格** |
| 只改生产者（CELL=0.0625） | L1–L6 | `lod` 夹到 3 → 0.50 格（L1 4.64、L2 2.21 归零） | L3–L6 | ≈0.66 格 |
| 生产者 + 消费端 LOD 改屏幕足迹 | L1–L6 | ≈像素足迹（近处 0.01～0.1 格） | L1–L6 | **≈0.11 格** |

**修正说明**：本文早前把消费端预滤的性质写成「真实但有限」，那是只对着 R 的 0.5～2.5 格结构看、没有把两级的层账算全。实际是**串联的两道闸门**：现状的可见细纹其实只来自 L5/L6（1.58/3.16 格），这正是「无质感」的量化含义；只修生产者让下限推进到 0.66 格，**必须同时改消费端 LOD 才能拿到 L1/L2**（0.11/0.23 格）。因此 §6 的 A2 与 A5 是配套项，不能只做一项。

## 7. 仍未验证、需要实机或用户裁决的事项

1. 全部观感判据（束形是否与遮挡对应、柱内是否有随深度的纹理、慢/快成分是否恢复）——必须同机位截图对照 ITT 3.2 / Solas。
2. 帧率：原生 1080p 均衡档平均 ≥144 FPS；各份文档都提出了「成本可能更低」的预期，**没有任何一份有读数**，其中 A2（1024² 生产端 4 倍）是唯一明确增加成本的项。
3. 无 TAA 档的噪点接受度（B2 的静态抖动）。
4. 1024² 光量图的显存与带宽、以及是否需要把覆盖缩到 64 格。
5. 立方对比峰值对 Bloom 的影响（A1/A5 之后亮度分布会变）。
6. 用户裁决：波场是否统一（阶段 D）、`UNDERWATER_SHAFT_DISTANCE` 是改语义还是改标签、Fresnel 因子去留。
