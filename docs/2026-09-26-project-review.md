# 2026-09-26 全项目审查与修复

本轮审查覆盖主世界、下界和末地的渲染入口与共享实现、水体与透明材质、阴影与体素光、大气与云、后处理、材质映射、预设与语言配置、资源引用及项目工具源码。历史报告只作为背景，问题按当前实现判断。以下问题已直接修复。

| 问题与触发条件 | 修复 | 主要位置 |
|---|---|---|
| 开启自动曝光后，历史缓冲沿用引擎默认的逐帧清除，无法保留平滑调整所需的上一帧增益；原来的 8 位格式也会舍掉较小的调整量 | 显式保留 `colortex10`，改用 `RGBA32F`，保留有效标记与接近目标时的吸附；首次在水下载入时写入中性增益 | `global/post/exposure.glsl` |
| 程序生成的太阳和月亮已经在颜色中乘过透明度，随后又经过 `SRC_ALPHA` 混合，边缘与月相暗面被重复压暗 | 输出未预乘透明度的颜色，由混合阶段统一乘透明度 | `program/sky.fsh` |
| 相机进入云层后，地形分支因要求相机位于云层外而跳过云；云层内水平视线也被直接丢弃 | 统一使用云层求交，支持层内与水平视线，保留地形距离截断 | `program/deferred.fsh`、`global/atmosphere/clouds_planar.glsl` |
| 新月之后的第 5–7 月相仍使用新月的月光强度 | 将八阶段月相按新月两侧对称映射，恢复后半周期亮度变化 | `shaders.properties` |
| 下界雾浓度调到 0 时，雾柱、薄雾与顶部烟雾仍保留固定密度 | 所有这些体积雾层共同使用浓度滑杆；默认 70 保持原比例，0 直接返回透明结果 | `global/dimension/nether_volume.glsl` |
| 从水下观察水面时，波浪法线忽略高度和速度滑杆；部分距离计算还包含齐次坐标的 `w` 分量 | 将水下法线接入同一组波浪参数，并只用视空间 `xyz` 计算距离 | `global/water/caustics.glsl`、`program/lit.vsh` |
| 熄灭的红石火把、红石灯、营火和灵魂营火，未激活的红石矿石，以及无浆果洞穴藤蔓仍进入自发光材质组 | 按 `lit`、`berries` 状态分配发光材质；无浆果藤蔓进入普通植物组 | `block.properties` |
| 10003 组的小型植物被体素光写入路径当作完整实心方块，遮挡光传播 | 将该组与其他非完整植物一同排除实心遮挡 | `program/shadow.vsh` |
| 工具先删除块注释时，会把行注释里的 `global/*` 当成块注释开头，吞掉后续有效源码 | 按源码顺序识别注释，并保留字符串、行数与词法间隔；两个使用方共用实现 | `qa/tools/option_matrix.py`、`qa/tools/check_pack.py` |
| 工具把被注释的布尔选项默认值记成开启，并把预设未指定的布尔选项当成关闭 | 从定义状态读取默认值，预设缺省项继承源码默认值 | `qa/tools/option_matrix.py` |
| 中英文选项说明与实现不一致，包括曝光收敛时间、体素光依赖及水下波浪参数；部分源码说明仍写三个预设或旧阴影采样方式 | 同步说明、依赖与四个预设的表述 | `lang/`、`lib/settings.glsl` |

表中的着色器路径均相对于 `Astra/shaders/`。自动曝光缓冲的默认格式与清除行为依据本机 Iris 1.11.2 的渲染目标指令实现；方块状态依据本机 MC 26.2 的客户端资源与实现。

本轮结论来自源码及本机引擎实现审查，没有启动游戏，因此不对本次改动后的画面效果或帧率作结论。Voxy 仍是项目文档已注明的适配骨架。
