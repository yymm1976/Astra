# 第一部分 执行摘要

## 1.1 一句话结论

本轮读了 16 个外部仓库，产出 4 份带行号的源码笔记。**结论不是"Astra 落后"**：Astra 在管线裁剪（127 条 `.enabled`）、缓冲尺寸条件化、调色链完整性、离线烘焙末地光路这四件事上，比本轮读到的多数外部实现更激进。真正值得动的，是三类**有确凿源码证据**的东西：

1. **阴影缺少「接触处锐、远处糊」的机制**——外部两家（Photon、Bliss）都有可变半影，Astra 是固定半径。这与反复反馈的树影闪烁直接相关。
2. **云缺少「厚云内部柔光」**——Photon 用 8 次纯 ALU 迭代（零纹理采样）做出多次散射感，Astra 的云只有两次 2D 密度采样，厚云边缘发硬。
3. **多处"只做了一半"**——下界体积雾模块完整存在却无调用者；体积雾只控步数不控分布；TAA 裁剪远近同一强度。

## 1.2 最值得关注的发现（按对 Astra 的价值排序）

## 1.3 最值得关注的性能发现（按"省掉哪类 GPU 工作"分类）

- **整趟 pass 消失**：Steadfast/Glimmer/ILV 用 `program.<name>.enabled` 在建管线时决定某趟是否存在，比 shader 内 `if` 更彻底。Astra 已有 127 条，**领先，不必学**。
- **每纹素带宽减半**：Steadfast 把只被模糊消费的光柱缓冲从 RG16F 降到 R8，作者明写"不缩放时 8 位与 16 位肉眼无差"（`pipeline.glsl:95-104`）。Astra 已有 R8（`taa_reactive.glsl:7`）、R16（`cloud_shadow_cache.fsh:7`）、RGBA8（`surface_buffers.glsl:17`）三类窄格式，缺的是把这一档用到「只被模糊消费」的光柱/雾缓冲上。
- **40+ 采样降到 8 靠抖动**：Steadfast 用 8×8 Bayer 抖动采样起点（`godrays.slang:59-61`），不用随机噪点，因此不引入帧间闪烁。
- **纹理采样换 ALU**：Photon 云多重散射 8 次迭代全 exp/mix 零采样；piscium 收尾 3 个 exp。**Astra 直接受益**。
- **查询点空间吸附换时间稳定**：MakeUp 的 `SHADOW_LOCK`（默认 0，关闭）与 Miniature 的 `bandify`（`shader.h:28` 的 `SHADOW_PIXEL 16` > 0，**默认开启**）。**两者默认状态相反**，不能一概而论。

## 1.4 已有实现、不需要重复建设

- **管线裁剪与缓冲尺寸联动**：Astra 把 `size.buffer` 与 `.enabled` 写在同一个 `#if`（`shaders.properties:18-44`）。Steadfast/Glimmer 没做到这个耦合度。
- **清屏契约**：`lib/settings.glsl:791-805` 逐条解释"为什么可以不清"，并记录 Iris 解析限制。外部无同类文档。
- **云历史有效性判定**：`cloud_temporal.glsl` 有覆盖率跳变容差、空云权重、天气漂移降权，比 Photon 单一 `world_age_changed` 丢弃更细。
- **末地黑洞**：Astra 是离线烘焙光路 + 查表（`global/dimension/end_kerr.glsl:3-9`）；Solas 是 2D 球极投影、锁死太阳方向（`endNebula.glsl:50-61`）。**差距正向，不要回头抄**。
- **水体吸收**：Astra 有 Beer-Lambert 三段谱 + 真实水柱厚度；Solas 用 `viewPos` 长度近似（`waterFog.glsl:2`）。**Astra 更正确**。

## 1.5 最该优先做

1. **零风险先做**：云多重散射迭代、多散射能量项、TAA 距离自适应裁剪、体积雾幂分布。四条都是纯 ALU 或改分布，不动缓冲结构。
2. **需要前置条件**：像素龄→历史 mip（先给 `colortex24/25` 开 mipmap）、R8 中间量（先确认该缓冲只被模糊消费）。
3. **PCSS 放最后**：要新增遮挡体搜索采样预算，与现有 2×2 lobe 不是叠加关系。

# 第三部分 视觉技术横向研究

按技术主题组织，不按项目罗列。每条给出：外部实现 → 机制 → 代价 → Astra 现状 → 适用性。

## 3.1 阴影：为什么优秀的包看起来"接触处锐、远处柔"

### 3.1.1 可变半影（PCSS/VPS）：两条相反的实现路线

**要解决的问题**：固定半径的 PCF 只有一种模糊程度，要么接触处糊、要么远处硬。真实阴影的半影宽度随「接收面到遮挡体的距离」变化。

**Photon 路线：逐片元即时搜索**

```glsl
// photon-main/shaders/include/lighting/shadows/pcss.glsl:43-55
for (int i = 0; i < step_count; ++i) {
    vec2 offset = vogel_disc_sample(i, step_count, dither * tau) * radius;
    vec2 uv = shadow_clip_pos.xy + offset;
    uv /= get_distortion_factor(uv);
    uv = uv * 0.5 + 0.5;
    float depth = texelFetch(shadowtex0, ivec2(uv * shadow_map_res), 0).x;
    float weight = step(depth, ref_z);
    depth_sum += weight * depth;
    weight_sum += weight;
    depth_sum_sss += max0(ref_z - depth);
}
```

3 个 Vogel 采样（开 SSS 时 12 个）求平均遮挡深度，再算半影：

```glsl
// pcss.glsl:245-252
float penumbra_size = 16.0 * SHADOW_PENUMBRA_SCALE
    * (shadow_screen_pos.z - blocker_search_result.x)
    / blocker_search_result.x;
penumbra_size *= 5.0 - 4.0 * cloud_shadows; // cloud shadow: wider penumbra
penumbra_size = min(penumbra_size, SHADOW_BLOCKER_SEARCH_RADIUS);
penumbra_size *= shadowProjection[0].x;
```

注意力放在三处细节，这些才是"看起来对"的原因：
1. 搜索半径随太阳高度收缩（`pcss.glsl:36-37`，低太阳时因子从 1.0 降到 0.5）——斜射时半影本来就大，不需要精确。
2. 半影上限与搜索半径**共用同一个常量**，逻辑自洽：搜不到的遮挡体不该产生更大半影。
3. 云影里半影放宽到 5 倍（`:249`）——阴天的阴影本就该更糊，这是艺术处理，不是物理。

**Bliss 路线：把搜索预计算到上一帧**

```glsl
// Bliss-Shader-Stable/shaders/dimensions/composite.fsh:511-533
for(int i = 0; i < VPS_Search_Samples; i++){
    vec2 offsetS = CleanSample(i, VPS_Search_Samples - 1, noise) * 0.5;
    float weight = 3.0 + (i+noise) * rdMul/SHADOW_FILTER_SAMPLE_COUNT*shadowMapResolution*distortFactor/2.7;
    float d = texelFetch2D(shadow, ivec2((projectedShadowPosition.xy+offsetS*rdMul)*shadowMapResolution),0).x;
    float b = smoothstep(weight*diffthresh/2.0, weight*diffthresh, projectedShadowPosition.z - d);
    blockerCount += b;
    avgBlockerDepth += d * b;
}
gl_FragData[0].g = avgDepth / VPS_Search_Samples;
gl_FragData[0].b = blockerCount / VPS_Search_Samples;
```

把遮挡体平均深度写进缓冲的 G/B 通道。下一阶段在核内**多次 tap 同一张缓冲**（`composite1.fsh:575` 在 for 循环内），另有 `:587` 的一次直接读。所以准确说法是：**代价从`逐像素做 blocker 搜索`降为`逐采样读一个已算好的值`**，不是零读取。

**Astra 现状（已核）**：全仓无 `blocker`/`penumbra`/`pcss` 的搜索实现（`global/lighting/shadowmap.glsl:220` 的 "blocker" 是注释里的普通词）。过滤是固定 2×2 lobe + 纹元重心插值（`diffuse.glsl:341-354`），半径由 `SHADOW_SOFTNESS`（默认 2）配合世界纹元宽度折算（`:324-327`）。**这是"固定软半径"，不是可变半影。**

**适用性判断**：Astra 的固定半径方案在**近距接触阴影**上反而比 PCSS 更锐（因为没有 3~12 次搜索的平均化）。PCSS 解决的是"远处硬边"。如果要接，建议只对**接收距离超过某阈值**的片元启用，而不是全局替换——这样既保留接触锐度，又不给近景增加采样。这是本轮少数"外部更强但要选择性吸收"的例子。

### 3.1.2 最小滤核 + 反锐化：Photon 抑制闪烁的核心

```glsl
// pcss.glsl:103-111
float distortion_factor = get_distortion_factor(shadow_clip_pos.xy);
float min_filter_radius = 2.0 * shadow_map_pixel_size * distortion_factor;
float filter_radius = max(penumbra_size, min_filter_radius);
float filter_scale = sqr(filter_radius / min_filter_radius);
int step_count = int(SHADOW_PCF_STEPS_MIN + SHADOW_PCF_STEPS_SCALE * filter_scale);
step_count = min(step_count, SHADOW_PCF_STEPS_MAX);
```

关键在于 `min_filter_radius` 是 **2 个纹元**（不是 1 个）。小于这个宽度时不是继续缩小，而是先按最小宽度滤波、再做反锐化：

```glsl
// pcss.glsl:177-183
float sharpening_threshold = 0.4 * max0((min_filter_radius - penumbra_size) / min_filter_radius);
shadow = linear_step(sharpening_threshold, 1.0 - sharpening_threshold, shadow * rcp_steps);
```

**机制解释**：1 个纹元宽度的 PCF 在阴影边缘只有 2 个采样参与，随着相机微动，采样点跨纹元会导致结果跳变——这就是闪烁。强制一个最小宽度，采样点总能覆盖多个纹元，结果连续；再用 `linear_step` 把过渡带压窄，视觉上恢复锐利。**这是「用更多采样换稳定，再用对比度把锐度买回来」**。

**一处必须写准的细节（审计纠正）**：这个最小宽度**不是恒定的 2 纹元**。源码是 `min_filter_radius = 2.0 * shadow_map_pixel_size * distortion_factor`（`pcss.glsl:104`），而 `distortion_factor` 在阴影裁剪空间从圆心的 `(1-0.85)=0.15` 变到边缘的约 1.16（`distortion.glsl:11-14`，`SHADOW_DISTORTION=0.85`）。所以：

- 换算到未畸变空间，最小核宽在 **0.30~2.32 纹元**之间连续变化，不是固定值；
- 在**贴图中心**（畸变最强处），`penumbra_size`（约 0.707 纹元）反而**大于** `min_filter_radius`（0.30），此时走的是真模糊、`t=0`、**不触发反锐化**；
- 只有外围区域 `t` 才大于 0，锐化才生效。

**这对 Astra 的意义**：不能简单说「抄 Photon 的 2 纹元下限」。Astra 的 `spread` 已经是按世界尺寸动态算的（`diffuse.glsl:321-327`），要移植的是「最小宽度 + 反锐化的组合结构」，而最小宽度本身需要按 Astra 自己的畸变曲线重新标定——**这正是这条建议的主要工作量所在**。

**Astra 现状（经补充核对，比初稿更准确）**：

Astra 有两层相关机制，但都不是 Photon 那一种：

1. `diffuse.glsl:321-327` 用「像素覆盖的世界尺寸 ÷ 该处纹元的世界尺寸」算需要几个纹元（`spread = softRadius / worldTexel`），再 clamp 到 `[0.5*spread, spread]`。**目的与 Photon 相同（接触处别过度模糊），手段不同**；但它的下界 `0.5*spread` 是**相对值不是绝对纹元数**，`SHADOW_SOFTNESS=1` 时可低到 0.5 纹元，理论上仍会出现纹元级阶跃。
2. 没有反锐化步骤。

另外要修正一个容易搞错的成本账：Astra 的「四角」是**一次 `textureGather` 取 4 个角点**，不是 4 次采样（`shadowmap.glsl:179-188`）。所以 `SHADOW_FILTER_QUALITY=1` 的实际成本是 4 lobe × 2 gather = **8 次 gather**（约 32 次深度比较），并且全挡/全亮都有提前退出（`shadowmap.glsl:266-277`）。

**结论**：Astra 缺的是「绝对最小纹元数 + 压回锐度」这两点，不是缺整套宽度控制。这是本轮**改动面最小、最直接对应树影闪烁**的一条。

### 3.1.3 叶片阴影：CR 的逐采样深度偏移

```glsl
    vec2 offset2 = offsetDist(gradientNoise + i, shadowSamples) * offset;
    if (leaves) shadowPosZM = shadowPos.z - 0.12 * offset * (gradientNoise + i) / shadowSamples;
    shadow += SampleShadow(vec3(shadowPos.st + offset2, shadowPosZM), colorMult, colorPow);
    shadow += SampleShadow(vec3(shadowPos.st - offset2, shadowPosZM), colorMult, colorPow);
}
```

每个采样点的**深度**也随采样序号漂移，不是只偏移 XY。叶片是薄片，只偏 XY 会在叶片自身深度附近反复穿越遮挡阈值，产生条带；连深度一起推开，相当于给每个采样一个略微不同的"接收面"，把条带打散。

**另一条更贴近根因的做法：在投射端把叶片撑厚**

```glsl
// cr/shaders/program/shadow.glsl:315-323
#ifdef PERPENDICULAR_TWEAKS
    if (mat == 10005 || mat == 10017) { // Foliage
        vec3 normal = gl_NormalMatrix * gl_Normal;
        position.xyz += normal * sign(texMinMidCoord.y) * 0.2 * noonFactor
                      * (1.0 + 0.01 * length(position.xyz));
    }
#endif
```

用「纹理坐标相对纹理中心的符号」决定往法线哪一侧推，±0.2 格，让薄片在**深度方向**有厚度。这样阴影图里叶片的深度不再是一条线，纹元不容易整片跳变。**零额外采样、零额外 pass，改的是投射端。**

**Astra 现状**：两条都没有。Astra 的植物处理在 `shadow.vsh`（投射侧）与 `diffuse.glsl:303` 的 `opaqueFirst` 选择上，接收侧没有逐采样深度偏移，投射侧没有撑厚。

**但要说清 Astra 已经有什么（审计补充）**：Astra 并非完全没有厚度概念。`global/lighting/sss.glsl:170` 有一个**解析厚度项**：

```glsl
// Astra global/lighting/sss.glsl:168-170
// A grazing surface transmits least: the ray crosses more material.
float thickness = mix(0.35, 1.0, clamp(ndotl * 0.5 + 0.5, 0.0, 1.0));
```

它按「掠射时穿过的材料更多、透光更少」给叶片透光一个解析权重，由默认开启的 `SSS_FOLIAGE`（`lib/settings.glsl:96`）消费。**这和 Photon 的 blocker 搜索式厚度估计不是一回事**——它是着色用的解析透光，不影响阴影图里的深度。所以准确说法是：Astra 有「解析透光厚度」，没有「阴影图内的几何厚度」。

**两者取舍**：投射端撑厚更贴近根因（薄片在阴影图里只有 1~2 纹元的厚度），但会改变叶片的视觉厚度，有观感风险；接收端深度偏移不改几何，但对厚阴影无效。**建议先试投射端，因为它的因果链更短。**

**排查方向的修正（主代理已核实）**：A 笔记把「风动在可见 pass 与阴影 pass 不同步」列为最高嫌疑点，我核了两处调用——`shadow.vsh:209` 传 `eyeRelativePos`、`lit.vsh:300` 传 `playerPos`，两者都是相机相对世界坐标，四个布尔参数的分类逻辑也相同。**这条嫌疑排除。**

反过来，Astra 的阴影核是**固定四象限且不旋转**的（证据应引 `diffuse.glsl:345-349` 的四象限偏移构造；`373-375` 那三行在 `SHADOW_FILTER_QUALITY==0` 分支内，不能代表主路径）。因此**树影闪烁不可能来自抖动收敛不足（Astra 根本没有抖动）**，只能来自几何或深度的空间不同步。这进一步抬高「投射端撑厚」的优先级——它直接作用于薄片几何本身。

### 3.1.4 两条容易被忽略的条件边界（来自 E 笔记审计）

**边界一：4-lobe 阴影路径不是全局的。**

```glsl
// Astra program/lit.fsh:6-9
#if !defined DIMENSION_NETHER && !defined DIMENSION_END && !defined ASTRA_WATER_PASS && !defined ASTRA_WEATHER
#define ASTRA_SURFACE_SHADOW_PLANE
#define ASTRA_SURFACE_SHADOW_FRAGMENT
#endif
```

`diffuse.glsl:305` 的 `#if defined ASTRA_SURFACE_SHADOW_FRAGMENT && SHADOW_FILTER_QUALITY > 0` 才启用四 lobe。**水面 pass、下界、末地都不走这条**，走的是 `diffuse.glsl:355` 的 2-lobe 预算支或单 lobe 支。所以讨论「Astra 阴影是 4 lobe」时必须限定主世界不透明地形。

**边界二：预算档会强制关掉硬件比较。**

```glsl
// Astra lib/settings.glsl:407-411
#ifdef ASTRA_OVERWORLD_OPTIMIZED
#define ASTRA_SHADOW_FILTER_MODE SHADOW_FILTER_SOFTWARE
#else
#define ASTRA_SHADOW_FILTER_MODE SHADOW_FILTER_MODE
#endif
```

`OVERWORLD_BUDGET` 默认 1，即 `ASTRA_OVERWORLD_OPTIMIZED` 开启，**用户在设置里选「硬件比较」在主世界预算档下不起作用**。这一点如果不写清楚，会误判 Astra 当前实际走的是软件 `step()` 比较。

## 3.2 云：清晰度与成本的三条不同路线

### 3.2.1 Photon：1/16 像素主渲染 + 棋盘格时域重建

```glsl
// photon-main/shaders/settings.glsl:201
#define CLOUDS_TEMPORAL_UPSCALING 4 // [1 2 3 4]
// shaders.properties:330-331
size.buffer.colortex9  = 0.25 0.25
size.buffer.colortex10 = 0.25 0.25
```

每帧只对 1/16 的像素做 raymarch，靠 4×4 棋盘格在 16 帧内轮转覆盖：

```glsl
// photon-main/shaders/program/d1_clouds.fsh:161-162
ivec2 checkerboard_pos = CLOUDS_TEMPORAL_UPSCALING * texel
    + clouds_checkerboard_offsets[frameCounter % checkerboard_area];
```

重建时**不做双线性放大**，而是按相位整块取历史：

```glsl
// d2_clouds_upscaling.fsh:367-374
ivec2 offset_0 = dst_texel % CLOUDS_TEMPORAL_UPSCALING;
ivec2 offset_1 = clouds_checkerboard_offsets[frameCounter % checkerboard_area];
if (offset_0 != offset_1 && !disocclusion) {
    current = history;
    apparent_distance = min(apparent_distance, apparent_distance_history);
}
```

**代价要说清**：主 raymarch 像素数降到 1/16，但**历史缓冲仍是全分辨率**（`colortex11/12`），带宽没省；重建还要每像素 4 次 `textureGather` 求 4×4 最小值。净收益取决于 raymarch 本身有多贵——对 Photon 那种 40 步 × 每步多次采样是划算的，对 Astra 那种已经用区间二分压缩到 4~16 段的实现，收益会小得多。

**Astra 现状**：高档是"同一像素打 4 条子像素射线"（`cloud_screen.fsh`），不降分辨率；历史在 `colortex24/25`，按覆盖率与天气判定有效性。**这是与 Photon 互补而非重复的设计**：Astra 保清晰度，Photon 保帧率。

### 3.2.2 云的多重散射：Photon 的 8 次迭代（零采样）

```glsl
// photon-main/shaders/include/sky/clouds/cumulus.glsl:164-185
for (uint i = 0u; i < 8u; ++i) {
    scattering.x += scatter_amount
        * exp(-extinct_amount * light_optical_depth) * phase
        * (1.0 - 0.5 * clouds_params.l0_shadow);
    scattering.x += scatter_amount
        * exp(-extinct_amount * ground_optical_depth) * isotropic_phase
        * bounced_light;
    scatter_amount *= scattering_falloff * powder_effect;
    extinct_amount *= 0.4;
    phase = clouds_phase_multi(cos_theta, phase_g);
}
```

**这 8 次迭代不采样任何纹理**，全部是寄存器上的 exp/mix。每次迭代把消光系数乘 0.4、散射量乘衰减、相位函数换成更各向同性的版本——物理上对应"光在云里反弹多次后能量衰减、方向变均匀"。

作者自己在 `common.glsl:66-67` 承认这是艺术近似：`// forwards lobe (max'ing them is completely nonsensical but it looks nice)`。

**Astra 现状**：云光照只有两次 2D 密度采样（`clouds_planar.glsl:501-505`），没有内部柔光项。厚云边缘发硬正是缺这一层。

**适用性**：高。纯 ALU，不新增采样、不新增缓冲，失败模式是"云看起来变糊"，容易回退。

### 3.2.3 水的多次散射：`fMS/(1-fMS)` 闭式解

```glsl
// piscium techniques/atmospherics/clouds/Common.glsl:160-166
vec3 fMS = (sampleScattering / sampleExtinction) * (1.0 - exp(-D * sampleExtinction));
sampleMSIrradiance *= fMS / (1.0 - fMS);
```

几何级数求和：`f` 是单散射反照率经 `(1-exp(-D·extinction))` 调制后的有效值，无穷次散射的能量和是 `f/(1-f)`。**注意**：外部笔记里写的「`f = 0.84 ×` 单散射反照率」在源码中没有依据——piscium 全仓 `0.84` 只命中 `Mediums.glsl:27` 的 `CLOUDS_CI_ASYM` 常量与设置滑条，与本式无关；本式是 **1 个 exp**，不是 3 个。

**归属**：该文件 `:21-24` 注明来源为 [WDT22] 中文技术博客与 [ASH25] HanPi Volume Cloud。**要用必须先过许可并把出处记进 `THIRD-PARTY.md`。**

**Astra 现状**：全仓 grep `multiple scatter`/`scattering_albedo` 零命中。水体与云都缺这一项。

### 3.2.4 对照：不要抄的两种写法

- **Solas 的 bloom**：单 pass 每像素 180 次取样（`computeBloom.glsl:14-19` 六层 × 六次循环）。这是负面证据——它证明"多 pass 金字塔"不是冗余设计。
- **Bliss 的伪 3D 噪声**：用两次 2D 采样伪造 3D（`volumetricClouds.glsl:62-65`，注释明写"避免两次纹理取"）。省了一次采样，但云的自相似结构会周期性重复。

## 3.3 时域与重建

### 3.3.1 像素龄驱动的清晰度分配

```glsl
// photon-main/shaders/include/sky/clouds/sampling.glsl:5-14
float pixel_age = texelFetch(colortex12, ivec2(uv * view_res * taau_render_scale), 0).y;
float ld = 2.0 * dampen(max0(1.0 - 0.1 * pixel_age));
apparent_distance = min_of(textureGather(colortex12, uv * taau_render_scale, 0));
vec4 result = textureLod(colortex11, uv * taau_render_scale, ld);
```

新出现的像素（`pixel_age` 小）取更高 mip 层级，即更糊；积累多帧后（`pixel_age` 大）`1 - 0.1*age` 趋近 0，取 mip 0 全清晰。**这是"用时间换清晰度"而不是"用时间换稳定"的少见写法**——通常时域累积是为了稳定，这里是让刚重建的像素先糊着，避免清晰但错误的像素扎眼。

**Astra 现状与前置条件（重要修正）**：Astra 的云历史权重是常数（`cloud_temporal.glsl:48-52` 的 0.75/0.90），但**这不等于可以直接照搬这条**。我核了 Astra 的 mipmap 启用情况：全仓只有 `colortex29`/`colortex2`/`colortex0`/`colortex11` 开了 `MipmapEnabled`，**`colortex24/25`（云历史）没有开 mipmap**。所以这条在 Astra 落地的前提是：先给云历史启用 mipmap 链，这本身是每帧的 mip 生成开销。**因此它不属"零成本改动"，评级从"最低风险"下调为"需要前置工程"。**

### 3.3.2 距离自适应 TAA 裁剪

```glsl
// photon-main/shaders/program/c4_taa_exposure.fsh:227
float gamma = mix(0.75, 1.25, linear_step(0.25, 1.0, distance_factor));
// :311-312
float blend_weight = mix(0.35, 0.10, distance_factor);
float alpha = max(1.0 / pixel_age, blend_weight);
```

远处用更窄的邻域（gamma 更大 = 裁剪更紧）和更低的混合权重（0.10），近处相反。原因是：近处细节多、需要更多历史来稳定；远处像素在屏幕上移动快、历史更容易失效。

**Astra 现状**：`taa_resolve.fsh:165` 是标量 clamp，远近同一强度。这正是"树叶闪"与"远处云抖"不能同时最优的原因——调紧救近处会让远处更抖，调松救远处会让近处更糊。**这是本轮性价比最高的一条 A 级发现。**

## 3.4 大气、雾与体积光

### 3.4.1 三条大气路线

| 路线 | 代表 | 做法 | Astra 情况 |
|---|---|---|---|
| 预烘 3D LUT | Photon | LUT 文件在 `shaders.properties:408` 绑定为 `depthtex0`，再由**各 pass 自己** `#define ATMOSPHERE_SCATTERING_LUT depthtex0` 启用（`d1_clouds.fsh:106`、`d0_sky_map.fsh:114`）；运行时双光源 4 次采样 | 无 LUT，天空是解析三方向模型 |
| 运行时 LUT | Piscium/Glimmer | compute 每帧刷 256×64 + 32² + SkyView | 同上 |
| 解析近似 | Astra/Solas | 直接算 | Astra 用 Minishita 2 采样球模型 + CR 三方向 |

Astra 的做法不是错误：LUT 的收益在"视线内变化平滑"的量，而 Astra 的天空模型已经用极低采样覆盖了这一点。**只有当真要做空气透视、或需要多套大气参数实时切换时，LUT 才值得。**

**一处必须纠正的表述**：不能说「Astra 的雾仍逐像素解析求值」。Astra 的 `global/atmosphere/volume_fog.glsl:11-12` 自述是 `The ray-marched owner of the ordinary overworld AIR segment when VOLUMETRIC_FOG is on`，即**雾有「解析」与「可选 ray march」两条路**。缺的是「LUT 查表」这一档，不是缺体积积分。Astra 全库 `multipleScattering` / `aerialPerspective` / `skyViewLUT` 零命中，这半句成立。

**机制细节（审计澄清）**：Photon 的 LUT 不是「整包一次绑定、处处可用」。LUT 图本身在 `shaders.properties:408` 声明，但真正启用靠每个 pass 自己的 `#define ATMOSPHERE_SCATTERING_LUT depthtex0`，只有显式定义的 pass 才走查表分支，其余走解析近似（`atmosphere.glsl:182` 的 `#if defined ATMOSPHERE_SCATTERING_LUT`）。这也解释了为什么在 Photon 全库搜不到 `#define ATMOSPHERE_TRANSMITTANCE_LUT`——那是一条默认不编译的分支。

### 3.4.2 体积雾的采样分布

```glsl
// cr/shaders/lib/atmosphere/volumetricLight.glsl:190
nextDistance = pow(t, sampleDistribution) * activeThreshold;
```

把均匀的 `t` 映射成 `t^k`，近处密、远处疏。体积雾的贡献主要来自近处，远处每步的贡献被透射率压得接近零，均匀分布等于在无效区域浪费采样。

**Astra 现状**：`volume_fog.glsl:32-41` 只定义步数（`ASTRA_VOLUME_STEPS` 12/48），步长是等距的。**改成幂分布是小改动，不增加也不减少步数，只是把同样的步数放在更有效的位置。**

### 3.4.3 一个需要修正的对比前提：Photon 水下雾是半分辨率

外部笔记里曾把 Photon 的水下体积雾说成「在 1/1 分辨率跑」，这个说法不成立：

```glsl
// photon shaders/settings.glsl:326
#define VL_RENDER_SCALE 0.50 // [0.50 0.51 0.52 ...]
// photon shaders/shaders.properties:312
size.buffer.colortex6 = 0.5 0.5
```

`c0_vl.fsh:129` 用 `rcp(VL_RENDER_SCALE)` 把全分辨率坐标换算回这半分辨率缓冲。所以 Photon 最贵的那趟也是半分辨率，和 Astra 的光轴档位处在同一量级。**不能用「Photon 全分辨率仍能跑」作为 Astra 需要升分辨率的理由。**

### 3.4.4 体积雾默认是关的（一条容易误读的边界）

`lib/settings.glsl:238` 是 `//#define VOLUMETRIC_FOG // [false true]`——**注释掉的，默认关闭**。整段 `volume_fog.glsl` 都在 `#ifdef VOLUMETRIC_FOG` 内。

所以讨论「Astra 的体积雾如何如何」时，前提必须是这份配置已开启它。Astra 自己的注释也写明：`While enabled it REPLACES the atmospheric distance fog, the rain haze (rainy_air) and the air GODRAYS over the same air segment`，即默认情况下主世界的空气段由解析雾与 godrays 负责。

## 3.5 水体

### 3.5.1 三种波浪模型

| 模型 | 代表 | 每像素采样 | 特点 |
|---|---|---|---|
| 噪声视差 + 4 点差分 | Solas | 16 | 无视差几何、远处走样，靠大 offset 压噪 |
| Gerstner 色散波 | Photon | 约 12（3 次求值 × (3 octave + 1 variation)） | 有 `w=sqrt(g·k)` 物理关系，峰尖谷宽 |
| 值噪声 + 解析梯度 | Astra（Steadfast/ITT） | 更少 | 一次 gather 取四角，无波长-速度关系 |

**Astra 的取舍是对的**：Photon 的 Gerstner 每像素约 12 次噪声采样（3 次高度求值 × (3 层 octave + 1 次 height-variation)，`water_normal.glsl:79-92,145-147`）换来的色散关系，在 Minecraft 的水面尺度上肉眼收益有限。C 笔记建议"接 Gerstner"我不采纳——**这是"外部更物理但不更适合"的典型**。

### 3.5.2 水吸收的正确性

```glsl
// solas shaders/lib/water/waterFog.glsl:2
float absorption = length(viewPos) * 0.01 * WATER_FOG_DENSITY;
```

用 `viewPos` 长度当水柱厚度。斜看浅水时该长度远大于实际水深，会把浅水渲成深水——这是 Solas 水体整体偏青的根源。

Astra 用真实水柱厚度（`program/water.glsl` 注释明确修掉了这个旧错），**比 Solas 正确，不要回退**。

## 3.6 末地与下界

### 3.6.1 末地：Astra 已领先

```glsl
// solas endNebula.glsl:60-61
vec2 sunCoord = wSunVec.xz / (wSunVec.y + length(wSunVec));
vec2 blackHoleCoord = worldPos.xz / (length(worldPos) + worldPos.y) - sunCoord;
```

球极投影 + 与太阳方向相减，所以**黑洞永远在太阳方向**。`hole = pow(pow4(pow32(VoS)), size)` 是锥形衰减，不是引力透镜；光子环是 `pow2(hole*3)` 加阈值。

Astra 是离线烘焙光路 + 运行时查表（`global/dimension/end_kerr.glsl:3-9`：`// The atlas is produced by qa/tools/build_end_transfer.py, never traced per frame.`）。**这不是一个量级的实现，Astra 不需要参考。**

补充一处准确性修正：Astra 的「无逐帧光线追踪」只适用于吸积盘与光子环；末地的远景岛体仍在做逐像素 SDF 行进（7 个体各一次入口求交，命中后最多 96 步，另有 24 步自阴影），这部分成本不在烘焙 atlas 的账上。

若要改善末地，方向是**星场稳定性**而非黑洞：Solas 用 `planeCoord += frameTimeCounter * 0.001` 让星场缓慢漂移避免僵死，Astra 用离线星表 + `colortex31`。

**Astra 现状（需修正一条外部结论）**：`nether_volume.glsl` 确实是死代码，但**不是"接上就有效果"**：

# 第四部分 性能优化专项

按"真实节省的 GPU 工作类型"分类。每条回答：省的是什么、代价是什么、证据强度。

## 4.1 避免无贡献计算

**外部做法**：Photon 的 PCF 先做 4 个 tap，全亮/全暗立即返回：

```glsl
// pcss.glsl:155-160
if (shadow > 4.0 - eps) {
    return color;
} else if (shadow < eps) {
    return vec3(0.0);
}
```

**省的是**：完全在光里或完全在影里的片元，剩余 2~8 个 tap 全部不执行。晴朗无云时地面大部分片元属于这两种，省下的比例很高；只在半影边缘付全价。

**Astra 现状**：`shadowmap.glsl:266-277` 已有等价机制——先查 `shadowtex1`（不透明），全 0 立即返回黑；再查 `shadowtex0`，全 1 立即返回白。

```glsl
vec4 opaqueVisibility = vec4(1.0);
if (opaqueFirst) {
    opaqueVisibility = shadow_surface_visibility_inside(shadowtex1, uv, referenceDepths);
    if (all(equal(opaqueVisibility, vec4(0.0)))) {
        return vec3(0.0);
    }
}
vec4 allVisibility = shadow_surface_visibility_inside(shadowtex0, uv, referenceDepths);
if (all(equal(allVisibility, vec4(1.0)))) {
    return vec3(1.0);
}
```

**结论：已有，且 Astra 的实现更细**（区分了不透明与全部投射体两条序列，还能用 `opaqueFirst` 按天光高低选顺序）。**不需要重建。**

## 4.2 减少重复工作

**外部做法**：Steadfast 把只与时间/视角有关的值搬到 CPU：

```ini
# pipeline/uniforms/uncategorized.properties:567
uniform.float.godraysExposure=godraysBaseExposure * godraysViewAngleFade * godraysOffscreenFade
```

**省的是**：每像素重复的乘法与幂运算，变成每帧一次 CPU 求值。

**Astra 现状**：`scattering.fsh:16-19` 已把 godraysExposure 全部放 CPU 侧，并把强度留到第二阶段合成（"这样调滑块不需要重跑这一趟"）。**已有，且理由写得更清楚。**

**唯一可借鉴的微观清洁**：Steadfast 会把曝光预乘进颜色（`uncategorized.properties:576` 的 `godraysColor`），省掉片元里的一次乘法。Astra 未系统做这类预乘。收益极小，属整理性质。

## 4.3 优化采样与 ray marching

### 4.3.1 幂分布步进

见 3.4.2。**省的不是采样次数，而是"把采样放在无效位置"的浪费**。等距 12 步里有相当比例落在贡献趋零的远端；`pow(t,2)` 把步长前移，同样的 12 步覆盖更多有效区间。

**证据强度**：机制清晰，但"能省多少"取决于雾的密度分布与视线长度，**没有实测，不能给百分比**。

### 4.3.2 抖动采样起点

```glsl
// steadfast/src/program/post/godrays.slang:59-61
uv += step * 1.5 * Bayer8(pixelCoord);
```

用 8×8 Bayer 有序抖动错开每个像素的采样起点，配合后续模糊，把 8 次采样在空间上等效扩展。**用固定抖动矩阵而非随机噪声，因此不引入帧间闪烁**。

**Astra 现状**：`lib/bayer.glsl` 存在，光柱走 1/4~1/2 分辨率。**未核实** Astra 是否把抖动写进采样起点还是最终亮度——这决定抖动图案会不会被带进最终画面。这条列为待验证。

## 4.4 缓冲区与显存带宽

**外部做法**：Steadfast 把光柱缓冲降到 R8，理由写在注释里：

```glsl
// steadfast/shaders/legacy/pipeline.glsl:95-104
// Godrays format is just a single color channel, 8 bits is enough.
// Originally I used 16 bits, but it turns out that if we do not scale the
// result, since we are smoothing the result anyways and the noise acts as a
// dither, there is actually zero noticeable difference between 8 bits and 16
// bits. So switching to 8 bit halves the required memory bandwidth on both ends
// basically for free, compared to using 16 bits.
```

**省的是**：该缓冲的读写带宽减半。前提是**不缩放到 [0,1]**（缩放本身损失精度）且**下游会模糊**（平滑掩盖量化台阶）。

**Astra 现状（审计纠正）**：Astra **不是完全没有 8 位目标**——已有三个：`lib/smaa_buffer.glsl:8` 的 `colortex7Format = RGBA8`、`lib/surface_buffers.glsl:17` 的 `colortex20Format = RGBA8`（法线+资格位+7 位顶点 AO 打包）、`lib/taa_reactive.glsl:7` 的 `colortex16Format = R8`（仅 `ASTRA_TAA` 下编译）。

**缺的是「只被模糊消费的光柱/雾类中间量」用 8 位这一档**：光柱目前是 RG16F，水下光柱升到 RGBA16F（`scattering.fsh:86-99`）。若该缓冲确认只被模糊与合成消费，R8 省一半带宽；失败模式是暗部色带，肉眼可见、易回退。

**一个必须写进结论的坑**：外部三家的格式表——DrDesten `setup.glsl:1-14`、ILV `basics/settings.glsl:8-43`、Rethinking Voxels `pipelineSettings.glsl:1-18`——**全部包在 `/* */` 注释块里，不参与编译**。把它们当「成熟做法」引用会得到错误结论。真正生效的 8 位实践只有 Steadfast 一家（`legacy/pipeline.glsl:104`，无注释块，由 `final.fsh:24` 引入）。

**不适用**：颜色本体缓冲（会色带）、需要 HDR 余量的累积缓冲（尤其 TAA 历史）。

## 4.5 Pass 与程序调度

**外部做法**：三个包都用属性文件关掉整趟 pass（Steadfast `pipeline.properties:29-32`、Glimmer `shaders.properties:117-125`、ILV `shaders.properties:347-354`）。

**省的是**：整趟 draw call + 该趟片元着色。与 `#ifdef` 的差别是：`#ifdef` 仍要编译一个（空）program 并跑光栅化，`.enabled=false` 是这趟根本不存在。

**Astra 现状**：127 条 `.enabled`，且把缓冲尺寸与开关写在同一 `#if`（`shaders.properties:18-44`）。**明显领先，不需要学。**

**唯一可借鉴**：Steadfast 把开关集中在 `pipeline/pipeline.properties` 并逐条注释"为什么这趟可以不存在"。Astra 的开关分散在 1172 行里，且维度三连写（`program.world-1/`、`program.world1/`、`program/`），**有"某维度忘了关"的实际风险**。这是组织收益，不是性能收益。

## 4.6 低成本替代算法

### 4.6.1 屏幕空间光柱代替体积积分

```glsl
// steadfast/src/program/post/noisy_godrays.fsh:20-24
float godraysSample(GodraysSampler sampler, float2 uv) {
    // The sky should have a depth value of 1.0. This is one of the few places
    // where == works reliably.
    return float(texture(sampler, uv).r == 1.0);
}
```

光柱强度 = 沿屏幕射线**天空像素的比例**，与介质密度剖面完全无关。物理上是错的，但结构对、成本极低。

**Astra 现状**：走更贵的真实积分（`scattering.fsh` + `light_shafts.glsl`）。**不建议整体替换**——Astra 的水下光束与树隙光依赖真实遮挡。

**可借鉴的形态**：给最低配置一档"纯屏幕空间近似"的退化路径，而不是只降分辨率。Astra 现在是 0.25/0.5/1.0 三档分辨率，算法不变。

### 4.6.2 空间吸附换时间稳定

```glsl
// makeup shaders/common/solid_blocks_fragment.glsl:224-233
#if SHADOW_LOCK > 0
    vec3 offsetVector = vNormal * 0.002;
    vec3 preSnapPos = vWorldPos + offsetVector;
    float texelSize = SHADOW_LOCK;
    vec3 absPos = preSnapPos + cameraPosition;
    vec3 snappedAbsolute = floor(absPos * texelSize) / texelSize;
```

把阴影查询点吸附到网格，相邻像素查到同一纹元，不产生逐像素抖动。MakeUp 默认 `SHADOW_LOCK 0`（关闭）；但 Miniature 的同类做法 `SHADOW_PIXEL 16` 是**默认开启**的（`shader.h:28`）。**两者默认状态相反**，不能一概而论。

**对 Astra 的潜在用法**：**只对静态方块面吸附，对树叶保留逐像素查询**。这两家都没做这个折中，而 Astra 的 `lit.vsh:143` 已有材质位段（`faceData = pack_octahedral(normal, 9) | (material << 18)`），天然支持按材质分派。**这是本轮最有价值但也最需实测的一条**。

## 4.7 时空复用与重建

见 3.2.1（棋盘格）与 3.3.1（像素龄）。核心判断：

- **Astra 已有历史复用**（云 `colortex24/25`、TAA `colortex15`、水面 SSR 历史），机制完整。
- **缺的是"按像素龄分级"**：Astra 的历史权重不看"这个像素新不新"，一律按常数混合。这是"历史复用"的下一个精细度层次。
- **降分辨率主渲染**（Photon 的 1/16）**不建议**：Astra 的高档云已经是"同像素多射线"，改方向等于重写云管线，且历史缓冲仍全分辨率、带宽不省。

## 4.8 其他经源码证实的项

- **Steadfast 明确记录"没测出差别"**（`pipeline.glsl:125-132`：清屏到零"在该驱动上据说更快，但我没看出差别"）。**这种否证记录比正面宣传有价值**——提醒我们不要把未验证的"优化常识"写成结论。
- **varying 位打包**：Steadfast 把法线+材质压进 1 个 32 位（`face.slang:30-41`，注明借用 Meyer 2010 EGSR）。Astra 已有同款 `faceData`。剩余价值在**审计还有哪些 varying 真需要插值**，不是重做打包。

# 第六部分 Astra 候选改进清单

固定结构。**没有一条被实施**，全部待你审阅。

## C-01 阴影滤核反锐化

**技术名称**：最小 2 纹元滤核 + 对比度回收

**外部参考**：photon `5c79f54`，`shaders/include/lighting/shadows/pcss.glsl:103-111,177-183`。

**核心原理**：给滤波核设一个**最小宽度**（其值随畸变因子变化，在 Photon 里换算到未畸变空间是 0.30~2.32 纹元，见 3.1.2 的纠正），让 PCF 采样点总能覆盖多个纹元、结果随相机微动而连续；当实际需要的半影窄于这个下限时，不是继续缩小核，而是先按下限滤波、再用 `linear_step` 把过渡带压窄，把变宽损失的锐度买回来。窄于下限时阈值最大、斜率最陡；半影大于下限时阈值归零、退化为恒等。

**Astra 当前状态**：**部分已有**。`global/lighting/diffuse.glsl:324-327` 有世界纹元宽度折算与"至少半个纹元"下限（`max(0.22, 0.75*sqrt(...))`），但缺反锐化步骤。

**拟改进位置**：`global/lighting/diffuse.glsl:341-354`（四 lobe 加权完成后），对 `filtered` 结果施加阈值收缩。

**预期视觉价值**：树影与叶隙边缘在移动时更稳定，同时不牺牲接触处锐度。直接对应已知的 W13 树影闪烁。

**性能影响**：**不减少也不增加采样**，只增加每像素几次 ALU（一次 `linear_step`）。属零采样成本改动。

**副作用和风险**：锐化过度会让阴影边缘出现"硬切"，在半影宽的部位可能显得假。阈值系数（Photon 用 0.4）需要按 Astra 的实际纹元密度重标定，不能照抄。

**实施难度**：低。

**依赖条件**：无。不需要新缓冲、不需要改管线。

**证据等级**：**A**（外部实现已逐行核实；Astra 的下限机制已核实；差异点明确）。

**推荐结论**：**优先尝试**。

## C-02 TAA 距离自适应裁剪

**技术名称**：按距离因子调节邻域裁剪强度与混合权重

**外部参考**：photon `5c79f54`，`shaders/program/c4_taa_exposure.fsh:227,311-312`。

**核心原理**：远处像素在屏幕上移动快、历史更容易失效，因此用更紧的邻域裁剪（gamma 更大）和更低的混合权重；近处反之。`float gamma = mix(0.75, 1.25, linear_step(0.25, 1.0, distance_factor));`

**Astra 当前状态**：**已实现但无分级**。`program/taa_resolve.fsh:165` 是标量 `clamp(historyColor, lo, hi)`，远近同一强度。

**拟改进位置**：`program/taa_resolve.fsh` 的裁剪与混合两处。

**预期视觉价值**：近处细节保留更多历史（更稳），远处云与地形减少拖影。可能同时缓解"树叶闪"与"远处云抖"这对矛盾。

**性能影响**：纯 ALU，无采样变化。收益不是性能而是"同一成本下的两处质量同时改善"。

**副作用和风险**：距离阈值的划分若不当，在中距离可能出现"裁剪强度跳变"，表现为一道环形痕迹。需要平滑过渡而非硬阈值。

**实施难度**：低-中。

**依赖条件**：需要深度或距离因子在 TAA pass 可用（Astra 已有深度读取）。

**证据等级**：**A**。

**推荐结论**：**优先尝试**。

## C-03 体积雾幂分布步进 —— **已撤销（重复建设）**

**技术名称**：`pow(t, k)` 采样分布

**外部参考**：cr `c09950d`，`shaders/lib/atmosphere/volumetricLight.glsl:190`。

**撤销理由（报告审计结论）**：Astra **已经实现**了同一件事，而且是默认开启的。

```glsl
// Astra global/atmosphere/volume_fog.glsl:160-165
#ifdef VOLUME_FOG_ADAPTIVE
// Quadratic boundaries favour near-camera detail. Each actual segment
// length enters extinction and scattering, retaining the full ray length.
left *= left;
right *= right;
#endif
```

并且 `lib/settings.glsl:247` 是裸 `#define VOLUME_FOG_ADAPTIVE`（默认开启），`:151-153` 还额外按实际 march 长度缩减步数。**这条候选属重复建设，已从清单移除。**

**保留价值**：它是一条反面教材——外部笔记把「Astra 只控步数、步长等距」写成了结论，而源码里二次分布就在 5 行之内。**这类错误只有回源才能发现。**

## C-04 云内部多重散射（8 次迭代）

**技术名称**：零采样迭代式多次散射近似

**外部参考**：photon `5c79f54`，`shaders/include/sky/clouds/cumulus.glsl:164-185`。

**核心原理**：在云体光照里做 8 次寄存器迭代，每次把消光系数乘 0.4、散射量乘衰减、相位函数换成更各向同性的版本。物理上对应"多次反弹后能量衰减、方向变均匀"。**全程不采样纹理**。

**Astra 当前状态**：**未实现**。`global/atmosphere/clouds_planar.glsl:501-505` 只有两次 2D 密度采样算 `light`，没有内部柔光项。

**拟改进位置**：`clouds_planar.glsl` 的 `light` 计算之后、颜色合成之前。

**预期视觉价值**：厚云边缘不再"一刀切"发硬，云体内部有柔和过渡。这是"云看起来像体积而不是贴片"的关键一层。

**性能影响**：**零纹理采样**，只增加 ALU（8 次 × 若干 exp/mix）。对现代 GPU 属可忽略量级，但**未实测，不给数字**。

**副作用和风险**：作者自己注明是艺术近似（`common.glsl:66-67`）。迭代次数与衰减系数若照抄 Photon，在 Astra 的不同密度标定下可能过亮或过糊。需要按 Astra 的 `ASTRA_CLOUD_DENSITY_EXTINCTION`（`clouds_planar.glsl:67`）重标定。

**实施难度**：中（要重标定参数，不是纯搬运）。

**依赖条件**：无新增缓冲。

**证据等级**：**A**（外部机制已核实；Astra 缺此项已核实）。

**推荐结论**：**优先尝试**（但需接受参数重标定工作量）。

## C-05 水体/云的多重散射能量项

**技术名称**：`fMS/(1-fMS)` 几何级数闭式解

**外部参考**：piscium `f2401e9`，`techniques/atmospherics/clouds/Common.glsl:160-166`。

**核心原理**：单散射反照率 `f = 0.84 × scattering/extinction`，无穷次散射能量和为 `f/(1-f)`。3 个 exp、零采样。

**Astra 当前状态**：**未实现**。全仓 grep `multiple scatter`/`scattering_albedo` 零命中。

**拟改进位置**：`global/water/absorption.glsl`（水体散射项）与云的颜色合成。

**预期视觉价值**：水体在散射占优的深度不再"越深越死黑"，云在厚部不会一味变暗。是"介质看起来有体积"的物理依据。

**性能影响**：3 个 exp，零采样。

**副作用和风险**：**许可**。该实现注明来自 [WDT22] 中文博客与 [ASH25] HanPi。要用必须查明原始出处与许可，并记入 `THIRD-PARTY.md`。**在许可未清前不得搬运。**

**实施难度**：低（算法简单），但许可核查是前置。

**依赖条件**：许可确认。

**证据等级**：**B**（机制已核实；许可与 Astra 参数适配未完成）。

**推荐结论**：**值得深入研究**（先解决许可）。

## C-06 叶片阴影逐采样深度偏移

**技术名称**：按采样序号的深度漂移

**外部参考**：cr `c09950d`，`shaders/lib/lighting/shadowSampling.glsl:56-61`。

**核心原理**：PCF 采样不只偏移 XY，深度也随采样序号漂移（`shadowPos.z - 0.12 * offset * (gradientNoise+i)/shadowSamples`）。叶片是薄片，只偏 XY 会在自身深度附近反复穿越遮挡阈值产生条带。

**Astra 当前状态**：**未实现**。接收侧无逐采样深度偏移。

**拟改进位置**：`global/lighting/shadowmap.glsl` 的 `shadow_surface_reference_depths` 与 `diffuse.glsl` 的四 lobe 循环。

**预期视觉价值**：树叶自阴影条纹减少。

**性能影响**：零额外采样，纯 ALU。

**副作用和风险**：深度偏移会让叶片的阴影"变厚"，可能造成轻微漏光或接触阴影变浅。只应对 `SSS_FOLIAGE` 材质启用。

**实施难度**：低-中（Astra 已有材质位段可判叶片）。

**依赖条件**：需确认四 lobe 结构能容纳逐 lobe 深度差。

**证据等级**：**A**（外部已核实；Astra 缺此项已核实）。

**推荐结论**：**优先尝试**（比初稿上调）。理由是：Astra 的阴影核固定不旋转、也不依赖 TAA，所以树影闪烁只能来自几何/深度的空间不同步，而投射端撑厚正是直接作用于几何本身的做法；接收端深度偏移对厚薄片无效。

## C-07 像素龄驱动的历史清晰度

**技术名称**：新像素取高 mip、老像素取 mip 0

**外部参考**：photon `5c79f54`，`shaders/include/sky/clouds/sampling.glsl:5-14`。

**核心原理**：`ld = 2.0 * dampen(max0(1.0 - 0.1 * pixel_age))`，历史帧数少的像素取更高 mip（更糊），积累后取 mip 0。

**Astra 当前状态**：**未实现，且有前置障碍**。`cloud_temporal.glsl:48-52` 权重常数；**`colortex24/25` 未启用 mipmap**（全仓仅 colortex0/2/11/29 启用）。

**拟改进位置**：`cloud_temporal.glsl` 的混合权重处 + `shaders.properties` 的 mipmap 声明。

**预期视觉价值**：刚重建的云像素先糊着，避免清晰但错误的像素扎眼。

**性能影响**：**增加**——历史缓冲要生成 mip 链，是每帧的新增带宽。收益需与这个成本相抵。

**副作用和风险**：mip 生成本身有开销；若 mip 层级选择不当，静止画面也会显得糊。

**实施难度**：中。

**依赖条件**：给 `colortex24/25` 启用 mipmap（新增每帧成本）。

**证据等级**：**B**（外部已核实；Astra 前置条件改变成本判断）。

**推荐结论**：**暂缓**（前置成本未量化前不值得）。

## C-08 R8 光柱缓冲

**技术名称**：只被模糊消费的中间量降到 8 位

**外部参考**：steadfast `b0bebea`，`shaders/legacy/pipeline.glsl:95-104`。

**核心原理**：不缩放数值的前提下，8 位与 16 位在"会被模糊"的缓冲上肉眼无差；带宽减半。

**Astra 当前状态**：**部分已有**。已有窄格式 R8/R16/RGBA8，但光柱仍是 RG16F（`scattering.fsh:86-99`），未把 8 位用到这类「只被模糊消费」的缓冲上。

**拟改进位置**：`scattering.fsh` 的格式声明。

**预期视觉价值**：无（画质应不变）。

**性能影响**：该缓冲读写带宽减半。**具体比例取决于该缓冲的读写次数，未实测。**

**副作用和风险**：若下游对该缓冲做硬阈值判断（而非模糊），8 位台阶会暴露。

**实施难度**：低（改一行格式 + 验证下游）。

**依赖条件**：确认消费链只有模糊与合成。

**证据等级**：**B**。

**推荐结论**：**值得深入研究**。

## C-09 静态面片阴影查询空间吸附

**技术名称**：只对静态方块面吸附查询点

**外部参考**：makeup `13ac348` `solid_blocks_fragment.glsl:224-233`；miniature `bdb6e00` `math.glsl:50-52`。

**核心原理**：把查询位置吸附到网格，相邻像素查到同一纹元，消除逐像素抖动。**外部两家都默认关闭**。

**Astra 当前状态**：**未实现**。

**拟改进位置**：`program/lit.vsh` 的阴影坐标计算，按 `faceData` 的材质位段分派。

**预期视觉价值**：静态方块面的阴影在移动时完全不闪。

**性能影响**：零（几次 floor）。

**副作用和风险**：吸附会让阴影出现与网格同尺度的错位；只对静态面做、树叶不做的折中**没有先例**，属自创组合，风险未知。

**实施难度**：中。

**依赖条件**：材质分派（已有）、网格尺度选择。

**证据等级**：**C**（外部实现已核实，但"只对方块吸附"的组合无外部验证）。

**推荐结论**：**暂缓**（先做 C-01，它用更小的改动解决同一问题）。

## C-10 下界体积雾接入

**技术名称**：启用已存在的 `astra_bliss_fog`

**外部参考**：Astra 自身 `global/dimension/nether_volume.glsl`（Bliss 派生，`THIRD-PARTY.md` 已有归属）。

**核心原理**：16 步 march + plume/haze/ceiling 三密度层。

**Astra 当前状态**：**模块完整但无调用者**（死代码）。

**拟改进位置**：需要新增生产 pass 与 composite 消费接线。

**预期视觉价值**：下界空间层次显著改善。

**性能影响**：**新增**整个体积雾 pass，成本未量化。

**副作用和风险**：属"新增效果"而非修 bug；可能影响下界帧率。

**实施难度**：中。

**依赖条件**：你的授权（本轮明确不新增特效）。

**证据等级**：**A**（死代码状态已核实）。

**推荐结论**：**暂缓，待授权**。

# 第七部分 优先级与后续开发路线

## P0：高价值、低风险，或直接消除明显冗余

**P0-1 C-01 阴影滤核反锐化**
理由：不增加任何采样，只加一次 `linear_step`，且 Astra 已有按世界尺寸算的 `spread`（相当于"宽度控制"已经在了）。直接对应已知的树影闪烁。**改动面小、证据强**；主要工作量在把最小宽度按 Astra 自己的畸变曲线重新标定，不是照抄数值。

**P0-2 C-02 TAA 距离自适应裁剪**
理由：纯 ALU，同一成本下同时改善近处稳定与远处拖影。

**P0-3（已撤销）C-03 体积雾幂分布**
撤销理由：Astra 的 `volume_fog.glsl:163-164` 已有二次分布且默认开启，属重复建设。**这一格由 C-01/C-02 之外的空缺填补，不再作为候选。**

这三条的共同点：**不新增缓冲、不新增采样、不改管线结构**，失败都能单点回退。

## P1：视觉收益明显、工程可行

**P1-1 C-04 云多重散射八次迭代**
依赖：无。难点在参数按 Astra 密度标定重标，不在代码。

**P1-1b C-06 叶片投射端撑厚 + 采样深度偏移**
依赖：材质位段（已有）。**这条在核实风动同步后上调**：Astra 阴影核不旋转、不依赖 TAA，闪烁只能来自几何/深度不同步，投射端撑厚直接作用于该根因。建议与 P0-1 一起验证：两者一个管几何（撑厚），一个管过滤（反锐化），作用在不同环节。

**P1-3 C-08 R8 光柱缓冲**
依赖：确认消费链。改一行，收益是带宽。

## P2：需架构调整、存在质量风险或收益不确定

**P2-1 C-05 多散射能量项**
阻塞在许可核查，不在技术。

**P2-2 C-07 像素龄历史清晰度**
阻塞在 mipmap 前置成本。

**P2-3 可变半影 / PCSS**
改动面最大：要新增遮挡体搜索的采样预算，且与现有 2×2 lobe 不是叠加关系。建议在 P0/P1 落地并取得画面反馈后再评估。

## P3：代价过高、方向冲突或证据不足

- **C-09 静态面片吸附**：用 P0-1 能以更小改动达成同一目标，且"只对方块吸附"的组合无外部先例。
- **C-10 下界体积雾**：属新增效果，需单独授权。
- **Gerstner 水波**：约 12 次噪声采样/像素换有限收益，与 Astra 现有解析梯度路线冲突。
- **1/16 棋盘格云**：历史仍全分辨率，带宽不省；与 Astra 多射线路线冲突。
- **大气 3D LUT**：仅当真要做空气透视时值得。

## 技术依赖关系

```
C-01 (滤核反锐化) ──┐
                    ├─→ 阴影稳定性验证（同一批画面反馈）
C-06 (叶片深度偏移) ─┘

C-02 (TAA 距离裁剪) ──→ 独立验证，不依赖其它

C-03 (雾分布) ──→ 独立验证

C-04 (云多散射) ──→ 与 C-07 (像素龄) 同属云质量，但 C-07 有 mipmap 前置

C-05 (多散射能量) ──→ 许可核查 ──→ 才能进入实施

PCSS ──→ 建议在 C-01/C-06 取得反馈后再评估
```

## 建议顺序

1. 先做 **P0 三条**，一起改、分别验证，因为它们互不干扰且都能单点回退。
2. 取得画面与手感反馈后，再做 **C-04**（云柔光）与 **C-06**（叶片）。
3. 许可问题能解决的条件下插 **C-05**。
4. **C-07 与 PCSS 最后**，因为它们都需要额外的结构性成本（mipmap 生成、遮挡体搜索预算）。

## 8.2 尚未验证的算法行为

- ~~**Astra 的抖动写入位置**~~：**已核实（审计补证）**——抖动确实写在**采样起点**：`global/post/godrays.glsl:167` 的 `texCoord += deltaTexCoord * 1.5 * bayer8(gl_FragCoord.xy);` 与 `global/atmosphere/volume_fog.glsl:167` 的 `float t = mix(left, right, jitter) * marchLength;`。因此 Steadfast 的 Bayer 抖动范式 Astra **已经在用**，不属缺口。
- **Astra 的折射是否为增量式**：C 笔记建议"用波法线减几何法线"，但未确认 Astra `program/water.glsl` 当前是全量还是增量。
- **各家的"每像素采样次数"**：全部为静态代码统计，**没有 GPU 抓帧或计时**。报告中所有"减少多少次采样"均为源码计数，不是实测。
- **Photon 的 `ATMOSPHERE_TRANSMITTANCE_LUT`**：全仓确认 **0 处 `#define`**（已从「未验证」升级为确认）。`atmosphere.glsl:501,527` 的守卫因此恒不成立，Chapman 分支（`:538-568`）默认不编译。实际生效的是 `ATMOSPHERE_SCATTERING_LUT`，由各 pass 自行 `define`。

## 8.3 缺少性能实测支撑的结论

本报告**没有任何 FPS、毫秒或百分比**。以下结论属于"机制清晰、幅度未知"：

- 幂分布雾能省多少（取决于雾的密度分布与视线长度）。
- R8 缓冲实际省多少带宽（取决于该缓冲的读写次数）。
- 云多散射的 ALU 成本（8 次迭代 × 每像素，但只在云的 raymarch 命中段执行）。
- 下界体积雾接入后的成本。

**这些都必须先有帧时间或抓帧数据，才能变成可承诺的收益。**

## 8.4 需要运行时数据才能判断的优化

- **TAA 距离阈值的具体取值**：Photon 用 `linear_step(0.25, 1.0, distance_factor)`，但 Astra 的 `distance_factor` 定义与 Photon 不同，阈值不能照搬。
- **反锐化的阈值系数**：Photon 用 0.4，Astra 的纹元密度与软半径标定不同，需重标。
- **空间吸附的网格尺度**：需要知道 Astra 阴影纹元在屏幕上的实际覆盖。

## 8.5 与 Iris/驱动/硬件相关的风险

- **`colortex24/25` 启用 mipmap**：Iris 支持该声明，但会改变缓冲的内存布局与生成时机；未在本机 Iris 1.11.2 上验证过实际行为。
- **R8 格式**：Iris 支持，但若该缓冲参与 mipmap 生成，8 位的舍入可能在 mip 链上累积。
- **下界 compute 的 `imageAtomicMax`**：Astra 已有依赖 GLSL 420+，新增下界体积雾不改变这个前提。

**由审计改变的三处判断**：

1. **Photon 水面法线是约 12 次采样，不是 27 次**（`water_normal.glsl:79-92,145-147`：3 次高度求值 × (3 octave + 1 height-variation)）。报告原先 4 处引用了错误数字，已全部改正。这削弱了「Gerstner 太贵所以不抄」的论证强度——它其实没那么贵，不做的主要理由应是「与 Astra 解析梯度路线冲突、收益有限」，而不是成本。
2. **Photon 水下雾是半分辨率**（`settings.glsl:326` 的 `VL_RENDER_SCALE 0.50`），不是全分辨率。不能用「Photon 全分辨率仍能跑」当作 Astra 需要升分辨率的理由。
3. **末地「无逐帧光线追踪」只适用于吸积盘与光子环**；岛体仍在做逐像素 SDF 行进（7 体入口求交 + 最多 96 步 + 24 步自阴影）。报告已收窄表述。
4. **Photon 的最小滤核不是固定 2 纹元**。它乘了畸变因子（`pcss.glsl:104`），换算到未畸变空间是 0.30~2.32 纹元；而且贴图中心处 `penumbra > minR`，走真模糊、不锐化。这直接改变了 C-01 的工作量估计——移植的不是一个常数，而是一套要按 Astra 自己的畸变曲线重标定的结构。
5. **Astra 有解析厚度项**（`sss.glsl:170`，默认开），准确说法是「有解析透光厚度、无阴影图内几何厚度」，不是「完全没有厚度概念」。
6. **外部三家的「缓冲格式表」全部在注释块里，不参与编译**（DrDesten `setup.glsl:1-14`、ILV `basics/settings.glsl:8-43`、Rethinking Voxels `pipelineSettings.glsl:1-18`）。这推翻了一个隐含前提：不能把它们当成「多家共有的成熟做法」。真正生效的 8 位实践只有 Steadfast 一家。这条对任何「按外部实践调整缓冲格式」的建议都是前置警告。
7. **Astra 不是「没有 8 位目标」**：已有 `colortex7`(RGBA8)、`colortex20`(RGBA8)、`colortex16`(R8)，缺的只是「只被模糊消费的中间量」这一档。
8. **Astra 的雾不是「纯解析」**：`volume_fog.glsl:11-12` 自述是 ray-marched，缺的是 LUT 档而非体积积分。
9. **C-03「体积雾幂分布」整条撤销**：Astra 的 `volume_fog.glsl:163-164` 已有 `left *= left; right *= right;` 的二次分布，且 `VOLUME_FOG_ADAPTIVE` 默认开启。这条候选原本是重复建设。
10. **「Astra 不用方差裁剪」是错的**：`taa_resolve.fsh:162-164` 就是 `lo = max(lo,mean-1.25*sigma)`，与 Photon 同类；差别只在 σ 系数是否随距离变化。
11. **Miniature 的坐标吸附默认是开的**（`SHADOW_PIXEL 16`），MakeUp 的才是关的；此前把两者一概说成「默认关闭」不成立。
12. **抖动已在采样起点**（`godrays.glsl:167`、`volume_fog.glsl:167`），原先标「未核实」的缺口其实 Astra 已经在用。

**未采纳的审计意见**：B 笔记审计指出其 L497 的 bloom pass 计数少一趟（应为 14 不是 13），但报告未采用该计数，故不改报告；D 笔记的引文审计实例失败，其结论仍只依赖此前 6 条手工抽查。
