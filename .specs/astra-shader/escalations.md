# Astra 上报处理流程与台账（五档共用）

> 适用：Z/B/C/D/E 全部档位。触发条件：规格含糊、需要决策、卡住两轮无进展、跨模块纠缠、架构变更请求。
> 原则：**上报必须带作业证据（防重复劳动），结论必须落档（防口头决议），任何升级路径的终点是用户。**

## 处理流程

1. **登记**：上报方在本文件台账追加一行（编号 SC-递增），必填：来源任务、问题一句话、**已尝试方案与失败证据**、候选方案 ≥2 个（含推荐）、影响面。同时把原任务状态列改为 🔶 上报中——不得留 ⬜ 或 ✅。
2. **认领**：各档模型每次开工先扫台账，认领匹配本档职责的未决项并在该行标注处理人。分工：模块问题由高一档处理；架构问题只有顶级Ⅱ（E 系）可决。
3. **结论**（三选一，写进台账"结论"字段）：
   - **指令下放**：写明让原任务怎么改，原档执行后任务状态改回 ⬜ 续做或 ✅ 关闭；
   - **架构决议**：在 design.md 对应章节落"决议："一行，台账行注明章节号，相关任务继续；
   - **继续升级**：本档两次处理仍未收敛 → 填升级理由转上一档；顶级Ⅱ也无法收敛 → 状态改"⏸ 待用户拍板"，附选项与推荐，**停止消耗额度等用户**。
4. **闭环**：每档收尾时核对台账——无"待用户拍板"之外的长期滞留项（无结论且跨里程碑）即视为干净。
